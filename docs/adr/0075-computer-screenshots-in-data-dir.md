# 0075 computer use のスクリーンショットをデータ置き場に保存し、結果の印の行で履歴から引く

- 状態: 承認（2026-10-01）

## 状況

会話の中に、エージェントが撮った画面を残したい。しかし、ツールの結果の画像は 3 つのエージェントで扱いがばらばらで、どれも Pleiad の履歴に残らない。

- Claude の正規化は `tool_result` の image ブロックを捨てる。
- Codex は MCP の結果を JSON の文字列にして 2000 字で切る。
- agy は stream-json の出力の形が違い、画像が残るかも分からない。

履歴の読み直し（エージェントの transcript から作り直す）でも同じに出なければならない。

## 決定

- MCP の橋（Pleiad の持ち物）が、モデルに渡したのと同じ JPEG を `AGENT_HOST_DATA/computer-use/shots/<id>.jpg` に保存する。id は乱数 128bit の hex。索引は `AGENT_HOST_DATA/computer-use/shots.json`（`{ version: 1, shots: { <id>: { session, at, bytes } } }`）。
- 結果の text の最後の行に印の行 `[ply_computer] {"v":1,…}` を入れる。項目はツール名・状態（`ok` / `failed` / `stopped` / `waiting`）・理由・title・アプリ名・ディスプレイ・スクショの id と大きさ。
- 各エージェントの正規化と履歴の読み直しは、共通の関数でこの行を読み、`tool.result` に `images`（`/computer-shot/<id>.jpg`。Codex の画像生成と同じ項目）と `computer`（印の中身）を足す。画像そのものは各エージェントの結果から拾わない。
- 配信は `GET /computer-shot/<id>.jpg`（今の画面の配信と同じトークンの認証）。`/local-file` は使わない（ADR 0050 でデータ置き場は除外）。
- 上限は 1 会話 300 枚・全体 1GB。超えたら古い順に消す。会話を消したらその会話の分も消す。値は定数で、設定に出さない。

## 理由

text は 3 つのエージェントのどれでも履歴に残るので、印の行を読めば同じ表示を作れる。画像を Pleiad が持てば、エージェントの形の違いや切り詰めに左右されない。モデルにも見える行なので、短く意味の分かる形にした。

## 影響

- データ置き場に `computer-use/` が増える。画面に映った個人情報が残るので、上限と会話の削除で消し、配信はトークンで守る。保存しない設定が要るかは運用を見て決める。
- 正規化イベントの `tool.result` に任意の `computer` が増え、`images` を MCP にも使う。
- モデルの文脈に印の行の分のトークンが増える（1 回あたり数十トークン）。
