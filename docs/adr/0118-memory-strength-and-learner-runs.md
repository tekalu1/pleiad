# 0118 bot の記憶に種類と重みを持たせ、強さ（重み × 新しさ）で核の写しを選ぶ。夜の整理はほかのターンを待たない

- 状態: 提案
- 「1 回に 40 束（5 件ずつの束が学習の会話 1 回）・200 件まで」は [ADR 0127](0127-hidden-conversations-quiet.md) が置き換える（40 件ずつ 5 回の呼び出し。200 件は同じ）

## 状況

[ADR 0110](0110-bot-memory.md) の記憶は、核の写し（会話の始まりに渡す記憶）を「人の行を先に、それぞれ新しい更新から」選んでいた。どの記憶も同じ重さで、古い約束・やめたことが新しい細かいメモに押し出され、逆に古いメモはいつまでも残る。2026-10-04 にユーザーは、bot が人のように「最近のこと」と「古くても印象的なこと」を覚えている、自然な相手であってほしいと決めた（「最近」と「印象的」の区別を足す）。

同じ日の調べで、夜の整理（`core/memory/learn.mjs`）が一度も完了していないことが分かった。データ置き場の進み（`memory_state`）が 0 行で、学習用の会話も 1 つも無い。予定の確かめ（`runIfDue`）が `host.runtime.turns.size`（Chats・委譲の子・bot を含む全部の走っているターン）が 0 でなければ「busy」で飛ばしていた。委譲の子や bot がいつもどれか動いているので、毎分の確かめでもずっと飛ばす。飛ばしたことは `console.error` だけで、ファイルにも画面にも残らない。

ADR 0110 の「記憶は毎ターン更新し、ターンの末尾に置く」は、末尾に**差分を毎ターン渡す**（読む側）として実装されている。ターンの終わりに記憶を書く処理は無く、書くのは bot の `memory.write` と夜の整理だけ。

## 決定

- **記憶の行に、種類 `k`・重み `w`・状態 `st` を持たせる（どれも任意）。** 種類は `stop`（やめたこと）・`promise`（約束）・`decision`（決めたこと）・`share`（分担）・`pref`（好み・直し）・`note`（その他）。重みは 1〜3（印象の強さ）。状態は約束の `open`・`done`。置き場は markdown の行末のメタの JSON（`<!-- {"id":…,"k":"promise","w":3,"st":"open"} -->`）。`memory.write`・`memory.edit` の入力 `kind`・`weight`・`status`、返りの行にも同じ名前で出す。
- **強さ ＝ 重み × 0.5^(経過日数 ÷ 半減期)。** 保存せず、読むたびに今の時刻から計算する（`core/memory/strength.mjs`）。経過は最後に書いた・直した時刻から。
  - 重みの既定: 行に `w` が無ければ、人が書いた・直した行（`by.kind === 'human'`）は 3、ほかは種類の既定（やめたこと・約束・決めたこと 3、分担・好み 2、その他 1、種類なし 2）。
  - 半減期: 人の行・やめたこと・まだの約束は薄れない。決めたこと 180 日、分担・好み 60 日、その他 30 日、種類なし 60 日、済んだ約束 7 日。
- **核の写しは強さの順に入れる。** 層ごとの目安（1200 トークン）まで、強い順（同じ強さなら人の行を先に、それから新しい更新から）。強さが 0.5 未満の記憶は**薄れた**として入れない。消さない: `memory.search`・関係する記憶（毎ターンの末尾）では出る。写しの中は種類の順（やめたこと → 約束 → 決めたこと → 分担 → 好み → その他 → 種類なし）に並べ、行の頭に種類を書く（`- [約束] …`）。人の行は重み 3 で薄れないので、ADR 0110 の「人の行を先に」は保たれる。
- **AI の重み 3 は根拠が要る。** AI（bot・夜の整理）が付けた重み 3 は、種類がやめたこと・約束・決めたことのとき、または根拠に挙げた人の発言に強い合図（「覚えて」「忘れないで」「絶対」「必ず」「二度と」「やめて」「〜ないでほしい」など）があるときだけ通し、それ以外は 2 に下げる（`guard.capWeight`）。人は 1〜3 をそのまま付けられる。**人が書いた行の種類・重み・状態を AI が変えるのは、本文と同じく guarded**（承認カード）。その記憶が会話の始まりに渡るかを決めるため。
- **本文の変わらない直しでは、行の書き手（`by`）を替えない。** `by` は今の本文を書いた者。理由・種類・重みだけの直しや同じ本文の直しで、AI が人の行を自分の行にできてしまい、次から承認なしで本文を書き換えられたため。直した者は `log.jsonl` の `by` に残る。
- **markdown の知らないキーを捨てない。** `parseLayer` は知らないキーを行に持ち、書き直しでそのまま戻す（忘れて戻したときも）。版の印 `pleiad-memory v1` は変えない。`k`・`w`・`st` の無い行（前の版が書いた行）はそのまま読め、上の既定で扱う。前の版がこの版の行を読むと、`k`・`w`・`st` を捨てて書き直す（重みが既定に戻るだけで、記憶は失わない）。
- **夜の整理は、ほかの会話のターンを待たない。** learner は自分の隠れた会話で走り、ターンの同時の数に上限は無いので、ほかの会話を止めない。予定の時刻を過ぎてその日の分がまだなら走る。待つのは、learner 自身が走っている間・止めている（`memoryLearnPaused`）間・失敗の後の間隔だけ。走っているターンの会話だけは読まずに次の回へ回す（カーソルを進めない）。予定の回の `lastRunAt` は**始めた時刻**にする（走っている間に更新された会話・後へ回した会話を次の回で読み落とさない）。
- **失敗したら間隔を空ける。** 15 分から倍に、6 時間まで（毎分の確かめで、失敗するたびにモデルを呼び続けないため）。
- **読む量に上限を置く。** 最後まで読んだ会話は、その時の更新時刻（`memory_state` の `cursor.seen`）から変わるまで読み直さない（以前は 5 件の束ごとに全部の会話を読み直していた）。読むのは 14 日以内の発言・投稿だけで、一度も走っていない置き場の最初の回は 3 日。1 回に 40 束（200 件）まで読み、残りはカーソルから次の回に読む（`lastResult.more`）。
- **走った・飛ばした・失敗したことを見せる。** DB の `memory_state` の `meta` / `status` の 1 行に、最後の結果（時刻・読んだ数・覚えた数・後へ回した会話の数）、その日の予定を飛ばした印（理由・回数。回数は予定の回ごとに 1 回で、毎分は数えない）、失敗（理由の文・回数・次に試す時刻）を持つ。成功で飛ばした印と失敗を消す。`memory.learnStatus`（read。画面・MCP・CLI `pleiad memory learn-status`）が返し、bot のページの記憶の欄の頭に 1 行で出す（「夜の整理: 02:00 に 3 件覚えた · 次は 10/5 02:00」。失敗・飛ばした回は目立たせる）。記憶の一覧の各行には種類の札と、薄れた記憶の「薄れた」の印を出す。
- **対象を絞って呼べる。** `runNow({ scope: { sessionIds, channelIds } })` はその会話・チャンネルだけを読み、予定の回には数えない（`lastRunAt` を進めない）。スレッドが静かになった後の整理（次の段）がこの口を使う。

## 理由

- 人の記憶は、新しいことと、古くても印象の強いこと（約束・やめたこと・強く言われたこと）を覚えていて、細かいことは薄れていく。重みと半減期の 2 つで、その形を少ない状態で作れる。強さを保存しないので、時間が経つたびに書き直す必要が無い。
- 消さずに写しから外すだけなら、誤って薄れた記憶も検索で戻り、人の［忘れる］だけが消す（ADR 0110 の安全弁のまま）。
- AI が全部を重み 3 にすると、人の記憶や本当に大事なものが押し出される。根拠の人の発言で上限を決めれば、出どころの検査（ADR 0110）と同じ考えで抑えられる。
- learner はほかの会話の文脈を使わず、自分の会話で走るので、ほかのターンと並んでも壊さない。待つ条件を「全部のターンが 0」にすると、委譲の子や bot が多い使い方では永遠に来ない。
- 飛ばしたこと・失敗したことが見えないと、走っていないことに誰も気づけない（今回がそうだった）。
- 2026-10-04 の実データの写しでは、Claude の会話 861 本に人の発言が約 2,700（14 日で約 2,100、1 日に約 150）あった。全部の会話を 1 回読むのに 35 秒かかり、束ごとに読み直す前の作りでは、最初の回が 547 束 × 35 秒（5 時間あまり）と 547 回の学習の会話になる。読む範囲と回ごとの上限が無いと、直した後の最初の夜にこれが走る。

## 影響

- 記憶の markdown のメタに `k`・`w`・`st` が増える。前の版に戻すと、書き直しの時に消える（重みが既定に戻る）。データ置き場の形式番号（`DATA_SCHEMA`）は変えない（DB の表は変わらず、`memory_state` に `meta` / `status` の行が 1 つ増えるだけ。前の版はこの行を読まず、消しもしない）。
- `memory.list`・`memory.search` の行に `kind`・`weight`・`status`・`strength`・`faded` が増える。`memory.learnStatus` が増える（`tests/ops-surface.snap.json`）。
- 夜の整理が実際に走るので、モデルの呼び出しが増える（新しい人の発言が無ければ呼ばない。5 件ずつの束ごとに 1 回、1 回に 40 回まで。上の使い方なら 1 晩に 30 回前後）。束ごとに学習の隠れた会話が 1 つ増える（Chats の一覧には出ない）。
- 14 日より古い発言は覚えない（その間に走れなかった分は取りこぼす）。
- 本文の変わらない直しで `by` が替わらなくなったので、夜の整理が人の行に「新しい記憶で置き換わった」の印（理由の直し）を付けても、その行は人の行のまま核の写しに残る（人が［忘れる］で消す）。
- 次の段で足すもの: 思い出すと強まる（`memory.search`・関係する記憶に出た時刻を DB に持ち、`strengthOf` の `recalledAt` に渡す）、まとめ直し・忘れる候補の印、スレッドの要約と新しいスレッドへの申し送り、スレッドが静かになった後の整理（`runNow` の `scope`）、投稿のリアクションを重みの手がかりにすること。
