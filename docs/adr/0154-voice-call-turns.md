# 0154 通話モードの区切り・送信・割り込み: まとめ待ち・入力欄を通さない送信・話して止める・効果音

- 状態: 承認（2026-10-07）
- 一部を置換: [0150](0150-voice-call.md) の「割り込み: 話して割り込むのは 2 段目」「ユーザーの発言は今の送信の経路（会話は `submit`）」

## 状況

通話を実際に使った利用者の困りごとが 3 つあった（調査: 2026-10-07）。

1. **話の途中で区切られる。** 1 つの文が「で、あのー、」「あ、なんか、」のように何通にも分かれて届いた。原因は、ホストが無音約 0.68 秒で発話を確定し（`cutter.mjs` の `endSilenceMs`）、画面が確定ごとに即送っていたこと。10 秒を超える話は最初の短い無音で割られ、言いよどみだけの確定も単独で送っていた。区切りの長さは設定から変えられなかった。
2. **すぐ届くメッセージと送信待ちが混ざる。** 画面が共有の入力欄に書いて `submit()` を呼んでいた。送信中なら `submit()` は黙って return して 2 通目が入力欄に残り、1 通目は await のあとで入力欄を読むので 2 通目が混ざった。書きかけの文にも触れた。
3. **読み上げ中に話しても認識されない。** 読み上げ中とその後 700ms はマイクの音声を捨てていた（半二重）。止める手段はボタンだけで、読み上げ直後の話し出しの頭も欠けた。

0150 は割り込みを「2 段目」としていた。

ユーザーの承認（2026-10-07）: モックの 01〜06 の形。区切りの既定は標準 1.2 秒、話して止めるは既定オン（エコー除去が効いているときだけ）、効果音は入れるが既定オフ。

## 決定

- **まとめ待ち**: ホストの発話の区切り（無音 600ms）は細かいまま先に認識へ回し、確定の文字を**クライアントで溜めて 1 通にする**（`web/voice/turn-hold.mjs`）。最後の声から待ち時間（設定の「話の区切り」。短め 0.7・**標準 1.2**・長め 2.0 秒）が過ぎ、ホストの `busy`（話している・確定を待っている）が閉じたら送る。声が戻れば数え直す。末尾が「、」・つなぎ語・助詞なら 1.5 倍、文末なら 0.65 倍、言いよどみだけは 2 倍で待ち、次が無ければ捨てる。10 秒で割る扱いは外し、最長を 30 秒にした。［いま送る］［取り消す］と、吹き出し・マイクの縁の弧での残りの表示。「考え中」は送ったあとだけ。
- **送信**: 声の発言は入力欄を通さず、直列のキューで会話へ送る（Chats は `sendMessage` に直に渡し、会話の行に置く）。声の行の状態は「AI に渡しました」「差し込み待ち」「送信待ち ＋［取り消す］」の 3 つにそろえる。入力欄から送った発言の言い方は変えない。
- **話して止める**: 設定が入っていて、エコー除去が効いているとき、読み上げ中もフレームを捨てず、通常の 3 倍の閾値を 250ms 超えたら読み上げを止める（`barge`）。止める前の約 0.6 秒を持っておき、頭から送る。止めた場所に「ここで読み上げを止めました · 続きを読む」。効かないときは今までの半二重で、終わってから聞き始めるまでを 700ms から 300ms に縮める。
- **続きを読む**: ホストが止めた文と、止めている間に届いた文を覚え、`resume` で止めた文から読み直す。
- **効果音**: 設定 › 通話の「効果音」（オフ・少なめ・すべて。既定オフ）。少なめは送った音と止めた音だけ。
- 設定（`voice`）に `turnHold`・`bargeIn`・`sounds` を足す。`ready` が `turnHoldMs`・`bargeIn` を渡し、ホストは聞き取りの `busy { on, last }` を足す。

## 理由

- 区切りをホストで延ばすと、確定が待ち時間のぶん遅れる（STT の往復が待ちに隠れない）。クライアントで溜めれば、認識は待ち時間の間に済み、返事の始まりは「待ち時間と確定の遅い方」で済む。
- 待ち時間を設定にしたのは、言いよどむ人と、短い指示をテンポよく言う人で、よい長さが違うため。標準を 1.2 秒にしたのは、「で、あのー、」の間（0.7〜1 秒）を越え、返事の遅れを約 0.5 秒に収められるため。末尾の規則は、待ち時間の長さだけを動かす（送る・送らないを決めない）ので、外れても害が小さい。
- 入力欄を通すのをやめたのは、書きかけの文・送信中の再入・次の発言の混入を、通話の側で防ぎようがないため。会話の行にそろえると、「届いたのか待ちなのか」が 1 か所で分かる。
- 「差し込み待ち」は誤りではなく実際の状態（Claude の途中送信は次のツール結果の区切りで折り込まれる）。誤りだったのは、折り込まれたあとも言い方が替わらなかったことで、替わる瞬間（`userMessage.delivered`）を 3 つの言い方につなげた。
- 話して止めるを、エコー除去が効くときに限るのは、スピーカーの音を自分の発言と取り違えて勝手に止める・送る事故を防ぐため（0150 の半二重の理由）。誤って止まっても［続きを読む］で戻れる。
- 効果音を既定オフにしたのは、画面を見ない使い方が分かってから既定を見直すため。

## 影響

- 返事の始まりが、待ち時間の分だけ遅れる（標準で約 0.5 秒。短めなら今とほぼ同じ）。
- 閾値（`BARGE_THRESHOLD` 0.036・`BARGE_MS` 250）は実機のスピーカーで確かめていない。外れたら 2 つの定数と設定で調整する。
- 通話を終えたとき、まとめ待ちの途中の言葉は送らずに捨てる。
- Claude の「差し込み待ち」の長さ（区切りにわずかに間に合わないと次のツールが終わるまで）は CLI の仕様で、縮められない。
- テストは `tests/unit/voice-turns.mjs`（新規）と `tests/browser/voice-call.mjs`（まとめ待ち・取り消す・3 回話す・送信待ち・止める → 続きを読む）。fake バックエンドの `AGENT_HOST_FAKE_VOICE_REPLY` は `script` と配列を受ける。
