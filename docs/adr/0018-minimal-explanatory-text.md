# 0018 説明文は最小限

- 状態: 承認（2026-09-23）

## 状況

互換の接続先（0011）の画面を作ったとき、仕組みの説明の段落と欄の下の補足を多く置いた。利用者から「説明文が多すぎて読めない」と言われた。

## 決定

- 見出し・ラベル・ボタン・状態・プレースホルダーで伝わることは、段落や補足で繰り返さない。
- 文として残すのは「知らないと事故になること」（料金がかかる、選び直しが要る、暗号化できない、など）と「失敗の理由」だけ。どれも 1 行の短文で、同じことは画面の中で 1 回だけ。
- 仕組みの説明（どの URL に何を送るか、なぜそうなっているか）は画面に書かず、docs に書く。既定のまま使うことが多い設定は「詳しい設定」に畳む。
- その状況のときだけ出す文は、状況が無ければ出さない。

## 理由

- 説明が多いと、事故を防ぐための一文まで読まれなくなる。
- 仕組みは画面を使う人ではなく、作る人が知っていればよい。

## 影響

- design-system.md §2.7 がこの規則の置き場。全画面の文言に効く。文書にも同じ考えを当てる（0001）。
