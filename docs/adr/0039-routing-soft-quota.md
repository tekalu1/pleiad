# 0039 委譲先の使用量を後回しの条件にする

- 状態: 置換（0040）
- 置き換えた: 0022
- 置き換えられた: 0040

## 状況

0022 の規則では、使用量が避ける線を超えた候補を除き、基準の段から上だけを見ていた。design × mid の t4 で Claude の全アカウントが線を超えると、Codex や Antigravity に空きがあっても「使える委譲先がありません」で止まった。エラーは Claude の最初のアカウントの理由しか示さず、線の値も示さなかった。

## 決定

- 候補をアカウント単位で「余裕あり」「余裕が少ない」「使えない」に分ける。100% 以上、利用不可、モデル不明、委譲先での再確認による拒否だけを除く。`avoidPercent`、週次ペース、使用量の不明・古さは後回しにする条件とする。
- 基準の段から上の余裕ありを優先し、無ければ同じ範囲の余裕が少ない候補を段ごとに選ぶ。全員使えなければ基準より下へ 1 段ずつ降り、各段で同じ順を使う。tv は tv だけを見る。
- 余裕が少ない候補は、使用量が分かるもの、効く枠の最大使用率が低いもの、週次ペースが低いもの、段内の並び順の順で選ぶ。Claude の余裕ありアカウントは従来の週次ペース・5 時間の順を保つ。
- 選択時の後回しの理由と枠、基準より下の段、見送った候補を `routing` と委譲カードに残す。使えない候補しか無い場合のエラーには、後回しの線と Claude のアカウントごとの理由を出す。設定と再試行でも余裕が少ない候補を選べるようにする。

## 理由

避ける線は枠の逼迫を表すが、100% 未満なら作業を受けられる。段を下げても委譲を続ける方が、空きのある別のエージェントを使える。上の段の余裕が少ない候補を下の段の余裕あり候補より先にすることで、表が示す仕事の難しさを優先する。

## 影響

- 0022 の「使用量の線で飛ばす／上の段が全部だめならエラー」を置き換える。判定器と種類・難しさの規則はそのまま。
- 現行仕様は [agent-delegation.md](../agent-delegation.md) と [design-system.md](../design-system.md) に記す。
- 追加仕様（2026-09-27、[ADR 0041](0041-account-level-delegation.md)）: Claude の異なる認証は重複をまとめた後、カード・設定・エラー・再試行で別々の候補として扱う。
