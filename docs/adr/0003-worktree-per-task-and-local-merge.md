# 0003 作業ごとの worktree と main へのローカルマージ

- 状態: 提案

## 状況

複数のエージェントが同じリポジトリで並んで作業する。main の作業ディレクトリで直接直すと、互いの未コミットの変更を踏み、どの変更が検証済みかが分からなくなる。
実際に起きたこと: worktree を編集しながら main でテストを走らせ、通ったことにした。ポート番号で PID を引いて止め、別の作業のサーバーを止めた。
この ADR は AGENTS.md「開発規則」で運用している決まりの理由を残す。

## 決定

- 作業ごとに最新の main から専用ブランチと worktree を作る。置き場はメインの作業ディレクトリ配下の `temporary/worktrees/<作業名>`。
- 実装・テスト・コミットは worktree の中で行う。テストは必ず worktree で走らせる。
- 検証が通ったら、メインの作業ディレクトリで main にマージする（都度の確認は要らない）。直前に main を確かめ、進んでいれば worktree に取り込んで検証し直す。
- 他の変更を巻き込む操作（stash・破棄・上書き）、履歴の書き換え、強制削除はしない。push はユーザーに頼まれたときだけ。
- 終わったら worktree を `git worktree remove`、ブランチを `git branch -d` で消す。

## 理由

- 並んで動くエージェントの変更が互いに混ざらず、どの変更が何で検証されたかが追える。
- ローカルの main に積むだけにしておくと、公開（push・リリース）は人間が決められる。
- 採らなかった案: エージェントごとに clone を分ける（依存の導入と同期が重い）、PR を経由する（一人の開発で待ちが増える）。

## 影響

- worktree には `node_modules` が無いので、依存が同じならジャンクションを張る（AGENTS.md）。
- サーバーの再起動は実行中のターンを終わらせるので、止める前に実行中が 0 件であることを確かめる。
