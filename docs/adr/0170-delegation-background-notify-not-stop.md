# 0170 委譲の子の裏の作業は止めず、依頼元に知らせる

- 状態: 承認（2026-10-08。利用者の決定）
- 置き換えた: 0048（「委譲の子の報告後の片付けは残す」の項。返答後の裏の作業を 10 分で止める）
- 関連: [0138](0138-quiet-wait-notices.md)（待っているだけの子に「止まっている可能性」を出さない）、[0057](0057-deliver-completion-notice-live.md)（完了通知の届け方）

## 状況

- 2026-09-27: 完了報告を出した Claude の子が裏のコマンドを残したまま終わらず、タスクが `running` のままになり、依頼元に完了通知が届かなかった。[ADR 0048](0048-delegation-silence-notice.md) は、main が返答を終えて裏の作業だけを待つ状態（`phase: waiting`）が `AGENT_HOST_DELEGATION_BACKGROUND_WAIT_MS`（既定 10 分）続いたら、サブエージェント以外の裏の作業を止める、と決めた。
- 2026-10-08: 子が 20 分ほどかかる試験を裏で走らせ、「まだ走っています。終わったら報告します」と返した。10 分たつと Pleiad が試験を止めた。止める前の返答と、止めた後に main が足した一言が結果になり、コミットが 0 件のまま依頼元に「完了」として届いた。依頼元は作業が終わったものとして次へ進んだ。
- Claude Code の Bash の 10 分の上限は問題にならない。上限を超える作業は裏へ回せば続くからだ。Pleiad の片付けが、その裏の作業を 10 分で止めていた。
- 時間だけでは、意図した長い作業と止め忘れた常駐のサーバーを見分けられない。

## 決定

1. **返答後の裏の作業を Pleiad は止めない。** `AGENT_HOST_DELEGATION_BACKGROUND_WAIT_MS` と、止めた作業を記録する `stoppedBackground` は廃止する。
2. **止める代わりに、依頼元へ裏作業通知を送る**（`agent:delegation.backgroundNotice`）。通知には次を書く。
   - 待っている裏の作業の見出し。
   - タスクは実行中のままで、作業が終わり子が返答を終えたら完了通知で結果を届けること。
   - 止めるなら `ply_task_cancel` か作業ダイアログの停止ボタンを使うこと。
   - 最初の通知にだけ、子のここまでの返答を添える。
3. **最初の通知は、待ち始めて 1 分たってから送る**（周期が 1 分より短ければ周期の長さで）。まだ走っていれば、`AGENT_HOST_TASK_BACKGROUND_MINUTES`（既定 30 分。`0` で送らない）ごとに「まだ走っている」と送り直す（`backgroundStillNotice`）。
4. **待っている間は、無音の通知もコマンドの 5 分の通知も送らない。** 裏作業通知が同じことを伝えるため。
5. **タスクは `running` のまま。** 裏の作業が終わると main が再開してターンが終わり、結果（最後の返答）を今までどおり完了通知で届ける。
6. 届け方は無音・コマンドの通知と同じで、依頼元が新しいターンを受けられるときだけ送り、走っているターンへの途中送信はしない。
   - 送る前に、送ったことをタスクの行に保存する。
   - 待ち始めた時刻は札（turn card）に載せる。無停止の更新の後も、最初の通知からやり直さない。
   - ホストに任せたタスクの依頼元（リモート）には送らない。
7. Codex のバックグラウンド端末（ターンの外に残り、結果は端末を待たない）は今までどおり。

## 理由

- 利用者の決定（2026-10-08）は「止めずに、依頼元に知らせるだけにする。間隔は長くてよい」。
- 止めると意図した作業の結果が失われる。しかも「完了」として届くので、依頼元は失敗に気づけない。知らせるだけにすれば、止めるかどうかを依頼元とその先の利用者が決められる。返答前のコマンドについて 0048 が採った方針（時間で止めず、知らせて判断を任せる）を、返答後にも広げる形になる。
- 2026-09-27 の不具合（依頼元が何も知らないまま待ち続ける）は戻らない。依頼元は通知で状態を知り、止め忘れのサーバーなら `ply_task_cancel` で止められる。
- 最初の通知を 1 分待つのは、すぐ終わる裏の作業のたびに依頼元を起こさないため。周期を長くするのは、依頼元のターンを起こすたびに費用がかかるため。
- 無音・コマンドの通知を止めるのは、同じ待ちを違う言い方で重ねて知らせないため。

## 影響

- 止め忘れた常駐のサーバーを抱えた子は、依頼元か利用者が止めるまで `running` のまま残る。その間、子の会話・プロセス・同時に走らせられる枠を使い続ける。依頼元が通知を受けられない間は、通知も保留になる。
- 待ちが続くかぎり、依頼元のターンが 30 分ごとに 1 回起きる。
- `ply_task_status` / `ply_task_list` のタスクに `backgroundWaiting`（`{ minutes, tasks }`）を載せる。待っている間は `silenceMinutes` を null にする。古い行に残った `stoppedBackground` は、次に結果を書くときに消える。
- 結果は子の最後の返答になる。止める前の返答を結果の先頭に残す処理は無くした。
- 試験では fake の台本 `bg-shell gate:<名前> <本文>` を使う。ゲートを開くと裏のコマンドが終わるので、通知・送り直し・止めないこと・完了を確かめられる（`tests/unit/server-delegation-background.mjs`）。
- 0048 の本文は書き換えず、状態の行に置き換えを書き足す。
