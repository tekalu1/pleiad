# 0078 内蔵ブラウザーのプロフィール（保存領域を複数に）と、AI が選べるプロフィール

- 状態: 置換（0148）

## 状況

内蔵ブラウザー（ADR 0041）の保存領域は `persist:pleiad-browser` の 1 つだけで、すべてのタブ・会話・エージェントが同じログインを使う。仕事と個人、顧客ごとの Google アカウントのように「どのログインで開くか」を分けたい。今はどのログインで開いているかも画面に出ない。

エージェントの CDP 中継（ADR 0043）はタブの webContents を直接触るので、session が違っても動く。ただし会話のタブを `sessionId` だけで決めているので、プロフィールの違うタブを同じ会話に混ぜると、エージェントからはどのタブがどのログインか見えず、`Target.createTarget` のタブのプロフィールも決まらない。サイトの利用の確認（ADR 0042）の「このサイトは常に」も agent + origin が鍵で、プロフィールを区別しない。

ユーザーは形をモック（2026-10-02 承認。タブの列の左端の案）で承認し、エージェントが仕事に合わせてプロフィールを自分で選べることを足した。PC の Chrome のプロフィールにつなぐ部分は別に試作中で、今回は作らない。

## 決定

- **プロフィール**: 名前を付けて作れる保存領域。今の `persist:pleiad-browser` はそのまま 1 つめのプロフィール「メイン」（id `main`）にし、移行では何も動かさない。ほかは `persist:pleiad-browser-<id>`（id は `p` + 16 進）。メインは削除できず、既定のプロフィールも削除できない。見分けは頭文字のモノグラムと名前で、色は使わない（有彩色の面は `--fill-primary` だけ、design-system）。一覧・名前・用途のメモ・既定・新しい会話の規則はサーバーの `prefs.json`（`browserProfiles`・`browserDefaultProfile`・`browserNewProfile`・`browserLastProfiles`）に置き、main には使える id と既定だけを渡す。保存領域の削除は Electron に API が無いので、中身を空にしてタブを閉じ、ディレクトリは次の起動で session を作る前に消す。
- **session ごとの設定**: 権限を断る・UA から印を外す・ダウンロードの置き場は、プロフィールの session を初めて使うときに 1 回かける。`window.open` のポップアップの窓とサイトのデータの消去は、開いた元のタブの session を使う（ログインのポップアップが別のプロフィールの Cookie で動かないように）。
- **1 会話 1 プロフィール**: 会話は「今のプロフィール」を 1 つ持つ。パネルのタブの列と、中継の `tabsFor`・`createFor`（画面の転送の `pickTab` も同じ口）はそのプロフィールのタブだけを見せる・作る。切り替えても前のプロフィールのタブは閉じずに残り、戻すとまた並び、選んでいたタブも戻る。中継の接続は保ったまま、前のプロフィールのタブを `Target.detachedFromTarget`・`Target.targetDestroyed` で外し（操作中のタブの接続も切れる）、新しいプロフィールのタブを `Target.targetCreated` で見せる（無ければ 1 枚作る）。
- **今のプロフィールの置き場は会話のメタ**（`sessions.json` の `browserProfile`。`store.setSessionData`）。新しい会話は作るとき（`newSession`）に決める: 引き継ぎ元があればそのもの、無ければ設定の規則（既定は「作業フォルダーで最後に使ったもの」、もう一方は「既定」）。持たない会話（この機能より前の会話）は初めて引いたときに同じ規則で決めて残す。消えたプロフィールを指していれば規則で決め直す。main は会話の今のプロフィールを覚えるだけで、知らない会話はサーバーに引く（`browser-profile-resolve`）。ターンの開始では中継の準備（`agent-browser-endpoint`）にプロフィールを添える。
- **人の切り替え**: タブの列の左端の pill（モノグラム＋名前＋▾）のメニュー。エージェントが中継で操作中は、ほかのプロフィールを押せない（理由をメニューの頭に出す）。切り替えたら一度だけ知らせを出し、会話に残す（`setBrowserProfile`）。
- **AI が選ぶ**: 専用の MCP サーバー **`ply_browser`**（`/mcp/browser`）を足す。ツールは `list_browser_profiles`（id・名前・既定か・今のものか・ユーザーが書く用途のメモ）と `use_browser_profile`（id か名前）。内蔵ブラウザーを渡すターン（デスクトップ版で中継がある＝`browserEnv` がある）にだけ、3 つのバックエンドへ渡す: Claude は `mcpServers`、Codex は `mcp_servers`（自動で承認）、Antigravity は stdio の中継（`core/agy-context-relay.mjs --browser`）。口は会話ごとに Bearer の鍵で開き、会話のあいだ同じ値を使う（agy は起動時にしか渡せない）。Claude ではツールごとの承認を出さない（中身はプロフィールの切り替えだけで、サイトの利用の確認はプロフィールごとに中継が行う）。エージェントが切り替えると、画面に「<エージェント名> が『…』に切り替えました」を出し、会話のツール履歴にも残る。エージェント向けの指示（`browser.instructions`）に、プロフィールがあること・ログインが要るサイトは用途のメモで選ぶこと・理由なく切り替えを繰り返さないことを足す。
- **確認の鍵**: 「このサイトは常に」は エージェント + プロフィール + origin で覚える。プロフィールを持たない古い記録はメインのものとして読む（書き換えない。メインの行は今後も `profile` を持たない）。確認のカードの文には、プロフィールが 2 つ以上あるときだけ「プロフィール: <名前>」を添える。プロフィールを消したら、その「常に」と既定を片付ける。
- **Chrome の Cookie は写さない**（ADR 0041 のとおり）。PC の Chrome のプロフィールを使う道は、Cookie の取り込みではなく Chrome へ直接つなぐ形で別に検討する（今回は作らない）。

## 理由

- 保存領域を Electron の partition で分けるのが、ログインを分ける一番小さく確かな方法。メインを今の名前のまま残せば、移行も巻き戻しも要らない。
- 1 会話 1 プロフィールにすると、中継は「会話の今のプロフィールで絞る・作る」だけで済み、エージェントが別のログインのタブを取り違える事故（同じ origin のタブが Cookie を共有しない）が起きない。混ぜる案は `targetInfo` にプロフィールを載せ `createTarget` に `browserContextId` を許す必要があり、エージェントに区別を任せることになる。
- 置き場を会話のメタにしたのは、値が会話ごとで、会話と一緒に消え・引き継がれるため。prefs に会話 ID → プロフィールの表を持つと、会話の削除で片付ける処理が別に要り、prefs が会話の数だけ太る。main（userData）に持つと、サーバーの ply_browser と新しい会話の規則が main に問い合わせることになり、リモートから見るときも main 頼みになる。作業フォルダーの「最後に使ったもの」は会話をまたぐので prefs に置く（100 件まで）。
- `ply_browser` を専用のサーバーにしたのは、既存の口がどれも全バックエンドに必ずは届かないため: `ply_agents` は Claude・Codex にしか渡らず（Antigravity は委譲の口を持たない）、`ply_context` はコンテキストを Pleiad が担当する会話にしか開かない。内蔵ブラウザーがあるかどうかで出し入れする条件も中継（`browserEnv`）と同じにしたい。`ply_computer`（ADR 0070）と同じ型（会話ごとの Bearer の HTTP、agy は stdio の中継）なので、渡し方の仕組みを増やさない。ツール名は他のサーバーと衝突しにくいので、agy でも付け外ししない。
- 確認の鍵にプロフィールを足すのは、プロフィール A で許したサイトを B（別のアカウント）でも黙って通すのを防ぐため。古い記録をメインとして読めば、今の許可は何も失わない。

## 影響

- 中継は会話の今のプロフィールに従ってタブの集合を替える。agent-browser は操作中のタブが消えると、`tab list` か `open` からやり直す（ツールの返り値と指示で伝える）。
- プロフィールの削除は、再起動するまでディスクに残る（中身は消す）。
- PC の Chrome のプロフィール（モックの 03・05 の Chrome の部分）は、別の ADR で決める。
