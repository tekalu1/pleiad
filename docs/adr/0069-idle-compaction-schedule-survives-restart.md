# 0069 放置圧縮の予約を再起動後に戻す

- 状態: 提案
- 置き換えた: 0039（予約をメモリだけで持つこと）

## 状況

0039 は、予約をメモリだけで持ち、Pleiad の再起動で消えると決めた。更新の再起動で、放置していた会話の予約が消えて圧縮されない。150k トークン以上の放置で圧縮されなかった分の一部は、これによると見られる（未確認）。

プロンプトキャッシュはサーバー側に残る。予定の時刻（猶予の 8 分以内）に圧縮すれば、再起動をまたいでも得が保たれる。

## 決定

- 見えている予約を `AGENT_HOST_DATA/compaction-schedule.json` に `{ version: 1, entries: { <会話 ID>: { at, backend, usedTokens } } }` で保存する。予約・取り消し・発火の開始で書き直す。同じティック内の連続した変更は 1 回にまとめ、`core/atomic-file.mjs` で置き換える。保存の失敗は予約を止めず、標準エラーに 1 行出す。
- サーバーの起動時、設定とバックエンドが揃った後にファイルを読む。予定の時刻から猶予（`core/compaction-scheduler.mjs` の 8 分）以内のものだけ、残りの時間で予約し直す。会話が無い、バックエンドが変わったものは捨てる。猶予を過ぎたものは捨て、ファイルからも消す。ファイルが無い・壊れているときは空として扱う。
- 発火時の確認（`canRun`）は今までどおり全条件を見る。

## 理由

予約は小さなデータで、会話の正本ではない。戻せなくても失うのは圧縮の機会だけなので、保存の失敗や壊れたファイルで起動や予約を止めない。猶予を戻す側でも使うので、値は scheduler から取る。

## 影響

- データ置き場に `compaction-schedule.json` が増える。消しても起動できる。
- 更新の再起動が予定の時刻を過ぎて 8 分以上かかった予約は戻らない。
- 再起動の直後に予定の時刻を過ぎていた予約（猶予以内）は、起動後すぐに圧縮を試みる。
