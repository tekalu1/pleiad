# 0136 bot が自分で決めた時刻に起きる予約

- 状態: 提案
- [ADR 0126](0126-bot-pulse-and-stream.md)（心拍）の「予約した時刻」を、心拍を入れていない bot にも使える 1 回きりの予約として外に出す。起こし方は [ADR 0126](0126-bot-pulse-and-stream.md) の引き継ぎ、予算は [ADR 0119](0119-channel-budget-and-resting.md)、取りこぼしの決まりは [ADR 0112](0112-routines.md) に合わせる

## 状況

2026-10-04 の明け方、bot が会話の中で仕掛けたタイマー（Claude Code の Cron。5:13〜7:47 の 5 件）が 1 回も動かず、朝には消えていた。会話の中のタイマーは、その会話のプロセスが動いている間しか鳴らない。bot のターンは返事を書くと終わるので、夜のあいだはまず鳴らない。bot には「確実に後で起きる」手段が無かった。

設計案（`bot-brain-design.md` §4.4）の段階 2 は、「自分で予約した時刻・気がかりに関係する出来事でも起きる（一定間隔の見回りはしない）。自発的に起きる分も予算に含める」。心拍（ADR 0126）は一定間隔の見回りで、既定は OFF。ルーティン（ADR 0112）は繰り返しの実行で、毎回チャンネルに根の投稿が立つ。どちらも「この会話で、この時刻に、このメモを持って 1 回起きる」には重い。

## 決定

- **予約は Pleiad 本体（サーバー）が持つ。** `core/brain/wakes.mjs`。DB の行（`brain_wakes`。[ADR 0115](0115-records-in-sqlite.md)。後から足す表の仲間で形式番号は変えない）。1 件 = id・bot・時刻・メモ（500 字）・行き先の会話（sessionId・チャンネル・スレッド）・状態（`pending` 待っている・`fired` 起きた・`cancelled` 取り消した・`dropped` 起こせず閉じた）・`taint`。再起動しても残る。心拍の ON・OFF には依らない。
- **作れるのは bot のスレッド・DM の会話の AI だけで、行き先はその会話**（`brain.wakeAdd { at | inMin, note }`）。人の画面・Chats の AI・隠れた会話（心拍・夜の整理）・ルーティンの会話からは作れない（`WAKE_CONVERSATION`）。時刻は今から 1 分後〜30 日後。1 回きり（繰り返しはルーティン）。待っている予約は 1 体 20 件まで（`WAKE_LIMIT`）。一覧は `brain.wakeList`（read）、取り消しは `brain.wakeCancel`（write）。どちらも bot 自身と人が使える。終わった予約は 7 日で消す。
- **危険度は write で、読み取りのモードの bot も使える**（`modeGate: false`。`channels.post` と同じ）。今は何も走らせず、起きたターンはその会話のモード・承認のまま走る。bot が自分の会話を後で続けるのと同じなので、承認は求めない。
- **起こし方は心拍の引き継ぎと同じ道**（`dispatch.wakeReserved` → `inbox` の `inner`（`kind: 'wake'`）→ `pump` → `startTurn`）。本文は `<pleiad-inner kind="wake">`（予約した時刻になったこと・予約のメモ・遅れたならその旨・黙って終えてよいこと・続けるならもう一度予約すること）。走っているターンには途中送信せず、終わってから新しいターンで渡す。承認・強い bot の確認・［止める］・休憩中はそのまま効く。履歴の行の見出しは「予約した時刻に起きました」。
- **Pleiad が止まっていた間に時刻を過ぎた予約は、起動後に遅れて 1 回だけ起きる。** 同じ会話の予約が重なっていたら、メモを並べて 1 回にまとめる（何十回も重ねない）。本文に「遅れて起きた」と予定の時刻を書き、行に `late`・`merged` の印を残す。起動の直後に 1 回確かめ、その後は次の予約の時刻まで（長くても 30 秒）眠る。
- **予算: 自発の分として数える。** スレッドならそのチャンネル、DM なら bot の家のチャンネル（心拍と同じ `pickHome`）の今日の分に入れる（`budget.allowsBrain`・`chargeBrain`。bot ごとの 1 日のトークンの上限も効く）。家のチャンネルが無い DM だけの bot は、チャンネルの % を足す先が無いので、bot の 1 日のトークンの上限（`BRAIN_DAILY_TOKENS`）だけを見て数える（`allowsBrain`・`chargeBrain` に channelId を渡さず botId だけ）。上限に掛かったら起こさず、予算が無いときと同じに待つ。
- **予算が無い・休憩中は捨てずに待つ**（`waiting`。10 分ごとに見直し、戻ったら遅れて起きる）。止めたスレッド・アーカイブしたチャンネル・消した bot・その bot の会話でなくなったものは、起こさずに理由を付けて閉じる（`dropped`）。bot を消したら予約も消す。
- **案内**: bot の指示文（`guide.bot.wake`）に、「後で起きる必要があるときは、会話の中のタイマー（Cron・sleep・ScheduleWakeup など）ではなく `brain.wakeAdd` で予約する」と 1 段落足す。会話の中のタイマーの道具は止めない。

## 理由

- **本体が持つ**のは、会話のプロセスに頼る限り「止まっている間は鳴らない」から。データ置き場の DB に置けば、PC やアプリの再起動をまたいでも残る。
- **心拍の引き継ぎと同じ道にした**のは、承認・強い bot の確認・［止める］・予算・休憩中を作り直さないため（ADR 0126 の理由と同じ）。ルーティンにしなかったのは、根の投稿が流れに立つうえ、1 回きりの予約には定義・トリガ・一時停止が要らないから。
- **行き先をその会話に限った**のは、「このスレッドで、このメモを持って起きる」が望む形で、別の会話へ起こす道を足すと bot が bot を起こす新しい経路（起こし合いの歯止めの外）になるから。
- **重なった遅れを 1 回にまとめる**のは、ルーティンの「取りこぼしは最新の 1 回だけ」と同じ考え。予約はそれぞれ 1 回きりなので捨てずにメモを並べ、起きた bot が要るものだけ拾う。
- **家の無い DM の bot もトークンの上限で止める**のは、予約が bot の自発の経路だから。人が呼ぶ DM は予算の対象外でよいが、数えないままだと、予約したターンの中でまた 1 分後の予約を足し、自分を起こし続けられる。心拍は同じ状況で動かない（`noHome`）。予約まで作らせない案より、心拍の仕組み（家・予算の数え方）を増やさずに済む。
- **予算なしで捨てず待つ**のは、予約の多くが人への約束（「17:05 に確かめます」）で、黙って消えると心拍の「静か」と違い、約束が破られて見えるから。待っている間は何も呼ばないので費用は無い。
- **会話の中のタイマーを止めず、案内だけにした**のは、短い待ち（ターンの中の数分）には会話のタイマーが合う場面もあり、道具を外すのはバックエンドごとに作りが違うから。

## 影響

- `brain_wakes` は古い版が知らない表。古い版に戻しても害は無い（表は読まれず、予約は起きない）。
- bot の指示文が 1 段落（約 120 トークン）伸び、全 bot の次のターンで指示文のキャッシュが 1 回書き直される。
- 予約で起きたターンは、心拍の引き継ぎと同じく思考の流れ（活動メモ）に結果の 1 行が残る（心拍を入れた bot だけ。`meta.by: 'wake'`）。
- 人の画面（bot のページ）には予約の一覧をまだ出していない。人は `brain.wakeList`・`brain.wakeCancel`（CLI の `pleiad brain wake-list` など）で見られる・取り消せる。画面に出すかは使ってから決める。

## 採らなかった案

- 心拍の `reservedAt`（安いモデルが決める次の時刻）を使い回す: 心拍を入れた bot にしか効かず、時刻になっても安いモデルのふるいを通るだけで、賢いモデルの会話に戻る保証が無い。
- ルーティン（1 回きりのトリガ）を足す: 根の投稿が流れに立ち、作るのが AI だと承認が要る（ADR 0112）。
- 家のチャンネルが無い DM だけの bot には予約を作らせない（`WAKE_NO_HOME`）: DM で頼まれた約束（「明日確かめます」）が守れなくなる。1 日のトークンの上限で止めれば足りる。
- 遅れた予約を、それぞれ別のターンで起こす: 夜のあいだに溜まった数だけ続けて起き、同じ確かめを何度もする。
- 会話の中のタイマーの道具（Claude Code の Cron など）を bot の会話で外す: バックエンドごとに作りが違い、ターンの中の短い待ちまで使えなくなる。
