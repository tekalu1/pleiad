# 0052 Claude の使用量はターン開始時の累計からの差分で記録し、既存の記録を一度だけ直す

- 状態: 承認（2026-09-28）

## 状況

設定の「使用量」にある「この Pleiad での実績」は、`usage.json` に残したターンごとの記録を窓の中で足している。Claude の記録には、SDK の `result` の `modelUsage` と `total_cost_usd` をそのまま入れていた。

同梱の CLI が 2.1.280 になった 2026-09-22 16:39Z から、CLI は query の終わりに transcript へ `cost-state` 行（会話の累計）を書き、resume のたびに最後の `cost-state` を読み戻す。Pleiad はターンごとに resume するので、`result` の値はそのターンの分ではなく会話を作ったときからの累計になった。その累計を足していたため、同じ使用量を何度も数えていた。

2026-09-28 昼の時点で、7 日の窓は表示 $30,954（入力 62.2G）に対して実際は $3,301（入力 6.75G）だった（約 9.4 倍）。5 時間の窓は表示 $1,610 に対して実際は $126 だった。記録には会話の id が無く、transcript の `cost-state` と突き合わせないと会話に結び付けられなかった。

## 決定

- 今後の記録: ターンを始める前（resume する前）に、その会話の transcript の最後の `cost-state` を開始時点の累計として読む。`result` の累計から開始時点をモデルごとに引いて合計し、その値を記録する。
  - 差分が負になった値は null にする。開始時点が読めなかったターン（`cost-state` の形が違う、`cost-state` を書く版なのに見つからない、transcript が見つからない）は、数値をすべて null にする。形の違いは `backend-shape-errors.log` に残す。
  - 新しい会話、分岐で写した会話（`forkedFrom` の付いた行。`cost-state` は写されない）、`cost-state` を書かない版の会話は、CLI と同じく 0 から数える。
  - 記録には、会話のネイティブ id（`nativeSessionId`）と、開始・終了時点の累計（`cumulativeStart`・`cumulativeEnd`）も残す。
- 既存の記録: 起動時に一度だけ直す。
  - 対象は 2026-09-22 16:39Z 以降の Claude の記録。
  - 記録の費用・入力・出力が transcript の `cost-state`（`totalCostUSD` と `modelUsage` の合計）と完全に一致したら、その会話に結び付ける。その `cost-state` の 1 つ前（CLI がそのターンの開始時に読み戻した値）からの差分に置き換える。
  - 同じ値の `cost-state` が続くときは、記録の時刻順に前から割り当てる。
  - 候補の会話が 2 つ以上ある記録と、結び付かない記録は触らない。
  - 書き直す前の `usage.json` を `usage.v1-backup.json` に写し、元の値はそこに残す。直した記録には元の累計も `cumulativeEnd` として残る。
  - 済んだことは `usage.json` の `migrations`（`claude-cost-delta`）に残し、二度は直さない。新しく作る `usage.json` には最初から付ける。
  - 直した件数・結び付かなかった件数・候補が複数の件数を、サーバーのログに出す。
- `usage.json` の `version` と `data-schema.json` の形式番号は上げない。記録の形は変わらず、足した項目は古い版が無視できるため。形式番号を上げると、古い版が同じデータ置き場で起動できなくなる。

## 理由

`cost-state` は、CLI が resume で読み戻すのと同じ値である。そこから引けば、query の中で `result` が何度出ても、圧縮・アカウントの切り替え・モデルの切り替えがあっても、CLI の累計と同じ基準でターンの分が出る。実験的な API（`usage_EXPERIMENTAL_…`）に聞く方法は、ターンごとに使用枠の照会が増える。SDK の `assistant` メッセージを足し上げる方法は費用が出ず、圧縮などの内部の呼び出しも入らない。

既存の記録は、放っておいても 7 日で窓から外れる。ただし、その間の表示は約 10 倍のままになる。本番のデータの写しで試すと、切り替え後の記録 716 件のうち 699 件が一意に結び付いた。7 日の窓は $30,992 から $3,317 になり、調査の見積もりと合った。結び付かない 17 件の多くは、値の無い記録である。

## 影響

- `cost-state` は文書に無い CLI の内部の形である。形が変わると、そのターンの記録は null になり、画面は「一部」と表示する。数えすぎはしない。
- 型定義の「resumed sessions start fresh」に実装が合わせて変われば、開始時点は 0 のまま引き算も 0 になり、そのまま正しく動く。
- 移行の後にインストール版など古い版が同じデータ置き場へ書いた記録は、累計のまま残る。
- 移行は起動を待たせず、transcript を一度読む（本番の写しで約 1 秒）。記録の書き込みとは直列にする。
