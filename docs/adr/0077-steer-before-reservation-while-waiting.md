# 0077 裏だけを待つ間は、次のターンの設定の予約より途中送信を先にする

- 状態: 提案

## 状況

実行中に作業ディレクトリ・モデル・エフォート・承認モード・アカウント・エージェントのチップを変えると、次のターンの設定の予約（`nextSettings`）が立つ。予約は次のターンの開始で適用して消える。これまでは、予約がある会話の送信は途中送信（`control.steer`）をせず、ターンの終わりを待ってから新しいターンで送った（送信がその設定で走るように）。

Claude では main が返答を終えても、終わらない裏のコマンド（headed のブラウザー・`npm run dev`）が残るとターンが閉じず、`phase: waiting` のまま開き続ける（[multi-backend.md](../multi-backend.md) §2.2）。この間に予約があると、送信待ちは「作業が終わると自動で送信」のまま、裏を止めるまで送られない（2026-10-02 に実例。作業ディレクトリを変えた会話で、受理から約 28 秒後に裏を止めて初めて届いた）。

## 決定

- `phase` が `waiting`（main が止まっていて、裏だけを待っている）の間は、予約があっても途中送信する。送信は今のターンの設定のまま処理され、予約は消さずに次のターンから効かせる。
- `phase` が `active`（main が動いている）の間は、今までどおりターンの終わりを待つ。ターンはすぐ終わるので、予約の設定で走らせたい意図を守れる。送信待ちの理由は `{ reason: 'turn', detail: 'reserved' }` で、表示は「今の返答が終わると自動で送信」。
- `active` から `waiting` に変わった時点で、サーバーが送信待ちをもう一度流す。
- `waiting` の間は、入力欄の上の「次のターンから適用」に、今の送信は今のターンの設定で処理されることを添える。どの予約が効かないかは、同じ欄の変更の列挙（作業ディレクトリ・モデルなど）が語る。
- ほかの場面（`turn.blocked`・`steer` を持たないバックエンド・未送信の会話）は変えない。完了通知・追加指示の `canSteerNotice` も変えない（依頼元・子の裏の扱いは別の決定にする）。

## 理由

- 予約の本来の意味は「次のターンから」であって、「この送信から」ではない。ターンが終わらない限り次のターンは来ないので、`waiting` で待たせると、利用者の送信が無期限に届かない。
- 画面は「作業が終わると自動で送信」のままで、止まっているように見えるのに、利用者が裏を止めるまで手がかりが無かった。
- `active` の間は、main の返答がすぐ終わる。そこで待つ分には、予約の設定で走らせたい（作業ディレクトリを変えて頼む）という普通の使い方を損なわない。

## 影響

- 作業ディレクトリを変えて「そこで頼む」つもりで、裏を待っているターンへ送ると、今の作業ディレクトリのまま処理される。入力欄の注記で、送る前に分かるようにした。新しいターンで頼みたいときは、裏を止めてから送る。
- 予約が `waiting` で消えないので、次のターンの開始で適用される（`runTurn`）。
- 完了通知・追加指示は、予約があると今までどおり途中送信せず、空いてから新しいターンで送る（`canSteerNotice`）。終わらない裏のコマンドが残る依頼元では、通知も同じ理由で届かないことがある。必要になったら別の決定で、`phase` を見る条件に広げる。
