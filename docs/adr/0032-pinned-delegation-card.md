# 0032 委譲先を指定した委譲のカードを自動と同じ形にし、委譲先のロゴを付ける

- 状態: 承認（2026-09-27）
- 置き換えた: design-system.md「委譲カード」（2026-09-26）の「`backend` を書いた固定の委譲は今までの見た目のまま」

## 状況

会話の中の `ply_delegate` のカードは、委譲先を自動で選んだとき（`routing.mode: auto`）だけ「委譲」と 1 行の理由・内訳を出し、依頼元が `backend` を書いた固定の委譲は MCP のツールカードのまま（見出しは「MCP」、開くと入力と返り値の JSON）だった。
2026-09-27 の UX 監査（sidebar#5）で、固定の委譲では何をどこへ頼んだのか・「開く」でどの子へ行くのかが読めず、会話の中で委譲の箇所を見つけられなかった。
ユーザーはレビューで方向を採り、委譲先に応じたアイコンを付けてひと目で分かるようにする（自動で選んだカードも同じ）ことを加えた。

## 決定

- 固定の委譲（`routing.mode: pinned`。routing の無い古いタスクで入力に `backend` があるものも）も見出しを「委譲」にし、1 行「種類 → 委譲先」（「実装 → Codex」、モデルを書いたときは「実装 → Codex gpt-6-sol」）を付ける。難しさは判定していないので出さない。「自動」の印は付けない。
- 1 行の頭に委譲先のエージェントのロゴ（脇の一覧・バックグラウンドと同じ `backendLogo`）。自動のカードにも付ける。ロゴは読み上げに出さない（名前は 1 行の字にある）。
- 開いた内訳の先頭に「依頼」の文（4 行で切り、はみ出すときだけ「全文を表示」）。自動・固定の両方。
- 固定の内訳は、種類・委譲先「Codex（依頼元が指定）」・承認モード・作業場所の格子だけ。判定・候補・「別の候補でやり直す」は自動のときだけの部品なので出さない。
- 入力・出力の JSON は「入力・出力（JSON）」の折りたたみの奥へ移す（消さない）。自動・固定の両方。

## 理由

- 固定でも、利用者が知りたいのは「何を・どこへ頼み・どれを開くか」で、自動と変わらない。形を分ける理由が無い。
- 委譲先はロゴで見分けるのがいちばん速い。脇の一覧・バックグラウンドの一覧は既にロゴで見分けているので、カードも同じ印にそろえる。
- 自動のときだけの部品（「自動」・判定・候補・やり直し）を固定に持ち込むと、判定していないのに判定したように読める。
- 採らなかった案: 見出しに子の状態（実行中・完了・失敗）も出す。自動のカードにも同時に入れ、ターンの後も状態を追って書き直す必要があり、入力欄の上の「バックグラウンド N」と一覧で既に追える。

## 影響

- 画面は design-system.md「委譲カード」。実装は `web/client.mjs` の `decorateDelegateCard`、文と内訳は `web/delegation-routing-view.mjs`（`routingLine`・`pinnedDetail`）。
- ツールの結果を描き直したときも JSON は折りたたみの中に入る（`web/render.mjs` の `applyToolResult` が `.tc-json-body` を優先する）。
