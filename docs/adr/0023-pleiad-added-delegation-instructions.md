# 0023 委譲の指示は Pleiad が入れ、コンテキストの画面に見せる

- 状態: 承認（2026-09-26）

## 状況

委譲先の自動振り分け（0022）を入れた後も、委譲の使い方（委譲を基本にする・この会話で自分でやること・`kind` を付けて `backend` を書かない）は利用者が各自の指示ファイルに書いていた。振り分けの設定と文面がずれ、委譲された子の会話にも同じ指示が入るので、子がさらに委譲する。
コンテキストの担当（0014）の既定は「エージェントに任せる」で、そのとき Pleiad は指示ファイルを渡さない。指示ファイルの経路に載せると既定の利用者には届かない。

## 決定

- Pleiad が委譲の指示を入れる。文面は辞書（`agent:guide.*`）の 1 か所で、会話の言語で引く。
  - 依頼元の会話: 1. 委譲を基本にする 2. この会話でやること・任せること 3. `kind` を付け `backend` は書かない（委譲先の自動選択が無効なら 3 を入れない）。
  - 委譲された子の会話（会話の記録に `delegation` がある）: 「さらに委譲しない」の 1 行だけ。
  - 読み取り・計画モードの依頼元には入れない（`ply_delegate` を受け付けないため）。
- **経路は `ply_agents` の instructions と同じ、システムの指示欄**（Claude は `systemPrompt.append`、Codex は `developerInstructions`）。担当によらず毎ターン渡っている経路で、その後ろに足す。MCP の initialize の instructions とツールの説明には入れない（二重にしない）。
- 入れるかどうかはスイッチ 1 つ（既定で入れる。`prefs.json` の `addedContext`）。すべての場所に共通。置き場は設定 › コンテキストの末尾のカード「Pleiad が入れる指示」で、行に「Pleiad が追加」の札。中身は編集させず、行を押すと依頼元・委譲された会話に入る文を出す。
- 会話の右パネルに「Pleiad が追加」の面を置き、直前のターンで入れた文（入れなかったら理由）を出す。
- 設定の変更は、始まっている会話にも次のターンから効く（0014 と同じ）。

## 理由

- 指示欄はターンごとに組み立て直している（Claude はターンごとに `query()`、Codex は `thread/resume`）。ここに足せば担当によらず届き、次のターンから切り替わる。
- MCP の initialize の instructions は、橋を会話ごとに 1 回開くので会話の途中で変えられない。agy はそもそも読まない。ツールの説明は、Claude が MCP のツールを遅延読み込みにすると本文が届かない（ツールを探すまで名前だけ）。
- 子かどうか・振り分けの有無・承認モードは Pleiad が知っている。エージェントに条件文で判断させず、機械的に切り替える。
- 文面を利用者の指示ファイルに残すと、振り分けの設定と食い違っても気づけない。Pleiad が持ち、画面で見せる（0007: 黙って入れない）。

## 影響

- `ply_agents` を持たないバックエンド（antigravity）には入らない（委譲できないので要らない）。
- Codex のロード済みのスレッドは `thread/resume` で指示欄を変えられないので、指示が変わったスレッドは外してから読み直す（接続先を変えたときと同じ。外せなければ前の指示のまま続ける）。
- 指示欄の中身が変わるのはスイッチ・振り分け・承認モードを変えたときだけ。変えなければ同じバイト列でプロンプトのキャッシュを外さない。
- 仕様は context-runtime.md「Pleiad が入れる指示」、画面は design-system.md §9「コンテキスト」、委譲の側は agent-delegation.md。
