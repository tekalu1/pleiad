# 0005 セッションの正本の所在

- 状態: 承認（2026-09-26）

## 状況

v1 では「SDK が持っているものは SDK に持たせる」とし、一覧・タイトル・状態の正本を `~/.claude` に置き、Pleiad は SDK に無い差分（変更履歴・親・状態を変えた時刻）だけを sidecar に持っていた（design.md §5）。公式の CLI・VS Code 拡張とタイトル・状態が共有される利点があった。
バックエンドを並べると（0004）、Codex には等価物が無く、Antigravity は分岐の口も一覧の控えも持たない。

## 決定

- セッションの一覧は**各バックエンドのネイティブの一覧 ∪ sidecar**。sidecar の `sessions.json` がバックエンドを横断する索引。
- タイトル・状態は、**バックエンドがネイティブに持てるならそれが正本**（Claude: customTitle / tag、Codex: thread name）。持てないものは sidecar が正本。書くときは両方に書く。
- 変更履歴・親・状態を変えた時刻・モード・モデルなどは sidecar。
- セッション id はバックエンドのネイティブの id をそのまま使い、行に `backend` を付ける（複合キーにしない）。
- 途中でバックエンドを切り替えた会話は例外で、会話 id とネイティブの id を分け、**本文の正本を Pleiad（`<data>/conversations/`）に移す**。実行区間ごとに `{ backend, nativeId }` を持つ。

## 理由

- 「ネイティブに持てるなら持たせる」を残すと、公式クライアントとの共有の利点を捨てずに済む。
- 切り替えた会話は複数のネイティブのセッションにまたがるので、どれか 1 つを正本にできない。
- id をそのまま使うと、画面の `s.id` への依存を壊さない。衝突は実質起きない（どれも UUID 系）。

## 影響

- 詳しい表は multi-backend.md §2.1、切り替えは backend-handoff.md。
- 切り替えた会話は、ネイティブの CLI からはその実行区間しか見えない。
