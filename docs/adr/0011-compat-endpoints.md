# 0011 互換の接続先（procway-code の対応を終える）

- 状態: 承認（2026-09-23）

## 状況

公式以外のモデル（OpenRouter・Z.ai・Kimi・DeepSeek・ローカルの Ollama など）を使うため、procway-code をバックエンドとして並べていた。別の CLI を 1 つ抱えるより、Claude Code と Codex が元から持つ「接続先の URL を変える」口を使うほうが、同じ画面・同じ道具のまま使える。

## 決定

- procway-code への対応を終え、Claude Code と Codex それぞれで互換の URL の接続先を登録し、会話ごとに選べるようにする。
- 画面は承認済みの案: 入力欄のモデルの面に「接続先」の節、登録は設定 › エージェント設定の各エージェントの行の「接続先」。3 つのチップの形は変えない。
- **形式はエージェントで固定。** Claude Code は Anthropic Messages 互換、Codex は OpenAI Responses 互換だけ（Chat Completions だけの先は理由を付けて断る）。
- **保存できるのは確認が通った接続情報だけ。** 確認は本物の 1 リクエストで、受領証（15 分・1 回限り）を経て保存する。
- 確認に失敗した・削除された接続先を指す会話は、送信を止めて理由を出す。**黙って公式に戻さない。**
- **新しい会話の既定**は、設定で「既定にする」を押した接続先だけ。入力欄で選んでも既定にならない。
- 公開のアドレスへの http は断る。リダイレクトは追わない。キーは画面・ログ・エラー文に出さない。

## 理由

- 黙って公式に戻すと、利用者が気付かないまま別の料金・別のモデルで動く。
- 入力欄で選んだものを既定にすると、サブスクを使っているつもりでキー課金になる事故が起きる。
- 確認を保存の条件にすると、壊れた接続先で会話を始めてから失敗することがない。

## 承認後に案から変えたこと

- 説明文を最小限にした（0018）。「思考を送る」を Claude の接続先の詳しい設定に足した。Codex の追加にも認証の送り方を出す。使用量の画面は接続先ごとに一文だけ。
- Claude のアカウントの節は、アカウントを登録している会話だけに出す（案では常に出していた）。公開のアドレスへの http を断るのは案に無かった安全策。

## 影響

- 仕様は design.md「互換の接続先」、画面は design-system.md「入力欄の設定」「互換の接続先の管理」。キーの渡し方は 0012。
