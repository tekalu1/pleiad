# 0153 Chrome への初回の接続は無期限に待ち、OS ごとの層に閉じ込める

- 状態: 承認（2026-10-06）。接続を持つプロセスは保持役の子（0167）。OS の層は main のまま。無停止の更新は Pleiad の終了に当たらず、出ている確認を閉じない

## 状況

[ADR 0148](0148-agent-browser-in-chrome.md)（承認の同じ日）の実装に入る前に、ユーザーが 3 点を決めた。0148 は次のように書いていた。

- 初めてつなぐときの状態 C は「約 5 分で打ち切られた、または利用者が『キャンセル』を押した」で、5 分で切れたときは残った確認を `WM_CLOSE` で閉じ、利用者に「もう一度」か「やめる」を選ばせる。
- OS を限る記述は無く、Windows の前面化・`WM_CLOSE`・`GetLastInputInfo` を前提に書いている。
- サイトの利用の確認のカード（[ADR 0042](0042-preview-loads-external-by-default.md)）は「変えない」としたが、今のカードには GitHub のアカウント名を出す「ログイン済み」の行がある。

実機で分かっていること（`temporary/` の確認。Chrome 154）: 許可の確認は接続 1 本ごとで、約 5 分で Chrome が打ち切り、確認の窓は残る。残った確認は `WM_CLOSE` で閉じられ、閉じると接続は約 10〜20 ms で失敗（1006）する。閉じても再び接続すれば新しい確認が出る。

## 決定

### 1. 初めてつなぐときの待ちは無期限

- 許可待ち（B）は時間では終わらない。続けるのは「許可する」が押されるか、利用者が「やめる」を押すか、接続を切るまで。利用者が気づかないまま打ち切られて終わる形は作らない。
- **Chrome の約 5 分の打ち切りは、Pleiad が覆う。** Chrome が打ち切る前に、Pleiad が古い確認を `WM_CLOSE` で閉じてつなぎ直す（新しい確認が出る）。利用者の画面は B のまま変わらない。**状態 C は利用者が「キャンセル」を押したときだけ**入る（0148 の C の「約 5 分で打ち切られた」を置き換える）。
- 出し直した確認で利用者の作業を邪魔しない: Pleiad が確認を前に出すのは、B に入った最初の 1 回と、利用者が「ダイアログを前に出す」を押したときだけ。出し直した確認が前面を取ったら、前にいた窓へ返す。
- **エージェント側の待ち**: 接続が無いままエージェントがブラウザーを使うと、中継は約 20 秒だけコマンドを抱える（agent-browser の CLI は約 30 秒で読み取りを打ち切るため）。つながらなければ「Chrome の許可を待っています。`hand_to_user` を呼んで待つこと」で失敗を返す。エージェントは `hand_to_user` を、バックエンドの 1 回の呼び出しの上限ごとに区切って呼び直して待つ（返り値は「まだ待っています。もう一度呼ぶこと」）。エージェントがターンを終えていたら、つながったときに決まった 1 文を人の送信として会話に送って続ける（0148 の「Claude に戻して続ける」と同じ形）。人が会話を中断したら待ちを外す。
- ツールは 0148 の 4 つのまま増やさない。

### 2. 対応は当面 Windows だけ。OS に依存する部分は層に閉じ込める

- 窓を前に出す・最小化・窓の対応づけ・人の入力の検出・確認の窓の操作は、**OS ごとの層**（口の定義は core、実装は Electron main の OS ごとの 1 ファイル）に閉じ込める。Chrome への接続・中継・映像・止める・操作待ちは OS に依存させない（OS で違うのは Chrome の `User Data` の場所の表と、層の実装だけ）。
- 実装は Windows だけ。ほかの OS では層が「使えない」を返し、エージェントのブラウザーは「この OS ではまだ使えません」になる。macOS・Linux は、層の実装と場所の表を足せば、接続・中継・映像を変えずに広げられる。
- Electron の無いホスト（`npm start`）でも使えない。

### 3. サイトの利用の確認のカードから「ログイン済み」の行を外す

- Chrome の Cookie・アカウントを読まない（Pleiad が読む Chrome のファイルは `DevToolsActivePort` のほかは、プロフィール名の一覧に要る `Local State` の名前の項目だけ）ので、カードに出せない。確認の本体（確認が ON のときだけ・「このサイトは常に」・委譲元にも出す）は変えない。

## 理由

- 5 分で切れて「やめた」扱いになると、利用者が席を外していた間に、エージェントの仕事が許可を得られないまま終わる。許可は接続ごとにしか出せず、出し直しは利用者に見えないので、Pleiad が覆うのが最も驚きが少ない。「キャンセル」だけが利用者の意思として確かな拒否。
- 前に出すのを最初の 1 回とボタンに限るのは、約 4.5 分ごとの出し直しが、別の作業中の利用者の前面を奪い続けないため。
- 20 秒で失敗を返して `hand_to_user` に待たせるのは、CLI の 30 秒の打ち切りと、MCP の呼び出しの上限（Codex・Claude・agy で違う）の内で、無期限の待ちを成り立たせるため。ターンを終えたエージェントを許可で起こすのは、`ply_computer` の待ちや「Claude に戻して続ける」と同じ形。
- OS の層に閉じ込めるのは、Chrome の CDP 自体は OS に依らず、依存するのは窓の操作だけで、そこを分けておけば広げるコストが層 1 つになるため。当面 Windows だけなのは、実機で確かめられているのが Windows だけだから。
- 「ログイン済み」の行は、Cookie を読まない（0148 が Cookie を写す道を退けた理由と同じ）以上、出せない。

## 影響

- 0148 の次の部分を置き換える: 状態 C の「約 5 分で打ち切られた」（C は「キャンセル」のときだけ）、B の「Pleiad が前に出す」（前に出すのは最初の 1 回とボタンだけ）、OS を限らない前提（当面 Windows だけ）。サイトの利用の確認の「変えない」は、「ログイン済み」の行を除く。0148 の本文は書き換えず、状態の行に追記する。
- `core/chrome/` は OS の値（窓のハンドル・`process.platform` による分岐）を持たない。OS の層は `desktop/chrome-os/`。
- Windows 以外では、第 7 段の切り替え（内蔵のエージェント操作の削除）の後、エージェントのブラウザーが無くなる。リリースノートに書く。
- 待ちが無期限になるので、設定・パネル・カードのどれにも「やめる」を置く。接続を切る・Pleiad を終了するときは、出ている確認を閉じて、Chrome に確認を残さない。
