# 0064 会話の地図を「筋と節」にする

- 状態: 承認（2026-09-30）
- 置換: [ADR 0063](0063-conversation-navigation.md) の B「会話の地図」の見た目の部分（帯の面・幅の変化・◆⋮⑂◉ の文字の印）。A・C・D と、地図の操作・浮く面の中身・出る条件は 0063 のまま

## 状況

0063 の地図は、右端に帯の面（普段 14px、触れると 28px に広がる `--surface-1` の pill）を置き、その上に範囲の面（20px）と文字の印（◆⋮⑂◉）の点を載せていた。使ってみて、利用者から次の 3 点の指摘があった。

1. 可視化の印 ◉ が、印ではなく大きい点に見える。
2. 触れると帯が右端を固定したまま左にだけ広がり、範囲・点の中心と揃わない。
3. 範囲の面が、普段から帯より左右 3px ずつはみ出している。

利用者が、モックで 3 案（A 広げない・B 中心から広げる・C 筋と節にする）を比べ、C を選んだ。加えて「可視化の印は作らない」「普段は淡く、触れている間だけ濃く」を指示した。

## 決定

地図を、会話の筋と同じ 1px の縦線に節を並べた形にする（数値・色・時間は [design-system.md](../design-system.md)「会話の移動」）。

- 帯の面をやめる。線 1px に節を置き、今見えている範囲は線の後ろの淡い pill（幅 11px。線を中心に左右 5px ずつで対称）。押せる領域は幅 23px（線を画素の中央に置くため奇数）で、触れても幅は変えない。帯・範囲・節の中心は一致する。
- 印は線画（SVG）にする。ふつうの発言 = 5px の丸、今のターン = 7px の輪、承認待ち = ◆、圧縮の境目 = 線を横切る横棒、分岐 = 線から右へ伸びる枝。触れた節は 1.4 倍。印の内側は下の面の色で塗り、線を通さない。
- 可視化の印は作らない。区別する印は承認待ち・圧縮の境目・分岐だけ。読み上げ名・凡例・辞書のキー（`nav.rail.kind.visual`）からも外す。
- 普段は淡く、地図に触れている間（ホバー・フォーカス・ドラッグ）だけ濃くする（120ms）。承認待ち ◆ と今のターンの輪は、普段から今の色のまま。
- 触れている間だけ、浮く面の下端に凡例を 1 行出す（その会話にある印と「今」だけ。触れている節の語だけ濃い）。

## 理由

指摘 2・3 は、スクロールバーに見える帯の面と、その上に載る別の幅の面が同居していることが元だった。C は帯の面そのものを無くすので、範囲が帯からはみ出す・左にだけ伸びる、が起こりようがない。会話の左の溝で使っている語彙（筋・節・今いる枝の青い輪）を右端にも使うので、地図が「同じ会話の筋を縮めたもの」と読め、新しい見た目を足さない。幅が動かないので、触れた瞬間に本文の右端がちらつかない。指摘 1 は、可視化の印そのものをやめる。地図は戻る先を探す道具で、印は探す手掛かりになる 承認待ち・圧縮の境目・分岐 だけに絞ったほうが節の並びが読みやすい。普段を淡くするのは、読んでいる間は本文が主で、地図は探すときだけ目に入ればよいため。

採らなかった案:

| 案 | 理由 |
|---|---|
| A 広げない（帯 14px のまま、触れると面が一段沈む） | 変更は最小だが、触れた合図が面の階調だけで弱い。14px の帯に 12px の印は窮屈で、拡大した節が帯からはみ出す。 |
| B 中心から広げる（触れると帯・範囲が左右 4px ずつ広がる） | 触れた合図ははっきりして対称だが、幅が動く部品が残る。22px の帯は本文の右の余白に食い込み、重く見える。 |

## 影響

- C の短所として、押せる幅（23px）が普段は見えにくい。節に触れた時点で浮く面が出るので実害は小さいと見る。ダークで普段の線と節が淡いが、40 ターン程度の節は見分けられることを撮影で確かめた。
- 0063 の性能の条件（スクロールでは DOM を読まない・確定中は同期をまとめる）は変えない。濃さの切り替えは地図の `:hover` / `:focus-within` の CSS だけで行い、節を 1 つずつ書き換えない。
- `web/conversation-nav.css` の帯の面（`.nav-rail-surface`）と文字の印を廃し、線（`.nav-rail-line`）と SVG の印に替える。
