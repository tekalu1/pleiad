# 0138 「止まっている可能性」の通知は、待っているだけの子には出さず、出すなら同じ子・同じコマンドで 1 回だけ

- 状態: 提案

## 状況

[ADR 0048](0048-delegation-silence-notice.md) は、委譲の子が 5 分黙る・1 つのコマンドが 5 分に達するたびに、親へ「止まっている可能性があります」と知らせると決めた。出力や別の活動では期限を延ばさず、コマンドごとに別の通知 ID を持つ。

テストや CI の終わりを待つだけの子（`until gh run view …; do sleep 30; done`・`gh run watch`・`npm test`）でも、通知が 5〜10 分おきに親へ届いた。親がチャンネルの bot だと、通知のたびに起きて投稿する。待っているだけなので通知に価値が無く、止まっていない子まで疑われる。

また、**終わったコマンドが「裏で動いている」まま残り、5 分後に通知が出る**不具合があった（2026-10-04）。Claude の結果文から「Command running in background with ID: …」を探す正規表現が文頭に固定されておらず、`cat` や `grep` が表示した別のファイルの中の同じ文字を、起動の知らせと取り違えた。

ユーザーの依頼（2026-10-04）:「待っている先が動いている（出力が伸びている・明らかに待つためのループである）なら控える。出すなら最初の 1 回だけ（同じ子・同じコマンドで繰り返さない）。完了・失敗・承認待ちの通知は今まで通り」。

## 決定

- **長時間のコマンドの通知（`commandNotice`）を控える場合。**
  - 待つためのコマンド（`until`/`while` のループ・`sleep`・`Start-Sleep`・`gh run watch`・`gh pr checks --watch`・`--watch`・`tail -f`・`wait`・`timeout /t`・`ping -n`。`core/task-commands.mjs` の `isWaitingCommand`）。
  - 出力が伸びている間。最後の**実際の出力**から 1 分以内（`task.activity` に `output: true` を付けるのは Codex のコマンド出力と Antigravity の各ステップ。Claude の `tool_progress` は経過を知らせる心拍で出力ではないので付けない）。出力が止まって 1 分たち、なお終わらなければ、そのとき 1 回だけ知らせる。
  - 裏（`background`）のコマンドは、子が別の道具・出力で動いている間（最後の活動から 1 分以内）。
- **無音の通知（`silenceNotice`）を控える場合。** 待つためのコマンドが走っている間。
- **出すなら 1 回だけ。** 子ごとに、通知したコマンド（空白を詰めた本文の頭 300 字）と、通知したときの無音の状態（走っているコマンドの本文の組。コマンドが無ければ空）を、行の `noticedCommands`・`noticedSilence`（上限 50。古いものから捨てる）に持つ。同じ印のものは、動きが戻って再び黙っても、同じコマンドをやり直しても、もう知らせない。別のコマンド・別の状態になれば知らせる。配送が `requeue` で親に届かなかったときは印を外し、次の機会に送り直す（受領が不明な失敗は ADR 0048 のとおり再送しない）。
- **終わったコマンドを裏に残さない。** 起動の知らせは結果の**文頭**にあるものだけを見る（`core/backends/claude-normalize.mjs`）。
- **変えないもの。** 完了・失敗・承認待ちの通知、`ply_task_status` / `ply_task_list` の `activeCommands`・`silenceMinutes`、環境変数 `AGENT_HOST_TASK_SILENCE_MINUTES`・`AGENT_HOST_TASK_COMMAND_MINUTES`（`0` で無効）、コマンドを自動で止めないこと。ADR 0048 の「出力や別の活動では期限を延ばさず」は、この ADR の「出力が伸びている間は控える」で置き換える（5 分の下限は変わらない）。

## 理由

通知の目的は「止まっているかもしれない子を、親に気づかせる」こと。待つためだけのループや、出力が出ている子は止まっていない。子の状態は [ADR 0139](0139-thread-subagents.md) のサブエージェントの一覧で見られるので、通知は最初の 1 回で足りる。1 回だけにすれば、チャンネルの bot が同じ子のために何度も起きて投稿することもなくなる。

## 影響

- 待つためのコマンドの判定は文字列のパターンで、網羅ではない。当たらない待ち方（独自のスクリプトなど）は、今までどおり 1 回だけ通知される。
- 子の行に `noticedCommands`・`noticedSilence` が増える。公開する形（`ply_task_status` など）には載せない。
- Claude の長い前景コマンドは出力を見られないので、待つためのコマンドでなければ、5 分で 1 回だけ通知される（ADR 0048 と同じ。違いは繰り返さないこと）。
