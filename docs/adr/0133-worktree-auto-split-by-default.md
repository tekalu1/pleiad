# 0133 人が始めた会話がぶつかるときは、選ばせずに分けた作業場所で始める

- 状態: 承認（2026-10-04）→ 置換（0136）
- 置き換えた: 0089 の決定 2（入力欄の上の 1 行で選ばせる）

## 状況

[ADR 0089](0089-worktree-on-demand.md) の決定 2 は、人が始めた会話が別の会話とぶつかったとき、入力欄のすぐ上に 1 行「『…』が同じリポジトリで作業中 [分けて始める] [このまま] いつも分ける」を出して選ばせ、「いつも分ける」は既定オフの設定にした。選ばずに送れば「このまま」（同じ作業ツリーに 2 つの会話が書く）で、ホストは警告も止めもしない。

この 1 行は、判断の場面が少ないのに、出ている間は入力欄の上に最大 3 段（文脈の帯・この行・次のターンの行）を積み、390px では折り返して約 70px を取る。「このまま」はメモリだけの記憶で、読み直すとまた出る。選ばなかった人は、黙って同じ作業ツリーへの同時の書き込みになる。

## 決定

1. **既定を「ぶつかるときは自動で分ける」にする。** 人が始めるターン（内部のターン・圧縮・中断を除く）で、書き込みの範囲のモードかつ同じ Git ルートで別の会話が書き込みのターン中なら、確かめずに分けた作業場所で始める。ぶつかっていなければ分けない。人が選んだ値だけを尊重する。台帳（`worktrees.json`）の `settings` は、人がスイッチを押したときに `chosen: true` を付けて `always` を書く。読むときは `chosen` が true の `always` だけを使い、それ以外は既定（オン）にする。
2. **入力欄の上の 1 行を消す。** 「分けて始める」「このまま」「いつも分ける」の操作と題は持たない。
3. **ぶつかる間の知らせはチップだけ。** 送ると自動で分けて始める間（ぶつかっていて、設定がオンで、この会話が走っておらず、今回だけ元の場所と決めていない）、入力欄の作業場所のチップの末尾に「· 分けて始めます」とだけ出す（`--ink-blue`。狭いと「· 分けた作業場所」と一緒に最初に畳む）。誰が作業中かは title と読み上げに出す。
4. **今回だけ元の場所で始める口は、作業場所の面にある。** 自動で分ける予定の間、面の末尾の「分けた作業場所で始める」は「このまま元の場所で始める（今回だけ）」に替わる。押すとその会話×場所の組の次の 1 回の送信だけ分けない（`sendMessage` の `keepPlace`。サーバーは付いた送信だけ自動で分けない）。記憶は画面のメモリだけで、送ったら外れる。自動で分ける予定でない間は、今までどおり「分けた作業場所で始める」（手で分ける）が末尾にある。
5. **分けたら、会話の静かな 1 行を残す。** 今ある「分けた作業場所で始めました（…が作業中）[元の場所に戻す]」と、戻した後の「もう一度分ける」はそのまま。これが取り消しの経路になる。
6. **設定は作業場所の設定として見つけやすくする。** 委譲の末尾から外し、設定 › エージェント設定の末尾の節「作業場所」に置く。名前は「ほかの会話が同じリポジトリで書いている間は、分けた作業場所で始める」（既定オン）、説明は「分けたときは、会話の一行から元の場所に戻せます。」だけにする。オフにすれば今までの「選ばずに送れば元の場所」と同じ（0089 のとおり警告も止めもしない）。

委譲（`ply_delegate`）の自動判定（0089 の決定 3）、置き場・片付け・退避・台帳（決定 4〜7）、WS のコマンド（決定 8）は変えない。`worktreeCheck` の `always` は「自動で分けるか」を表す。

## 理由

- 判断の場面を無くしつつ、同じ作業ツリーへの同時の書き込みを黙って起こさない。0089 が既定を作らないとしたのは、分けた先に依存（`node_modules` など）が無く、パスが変わり、取り込みの手間が増えるという驚きのためだった。その驚きは残るが、2 人目が書く瞬間に限る・会話の 1 行で何が起きたか分かる・「元の場所に戻す」でやり直せる・設定でオフにできる、の 4 つで受けられる範囲になった。
- 入力欄の上の面積を会話に返し、390px で約 70px の折り返しを無くす。
- 選んだ値だけを尊重するのは、一度オフにした人の選択を既定の変更で上書きしないため。旧版の台帳は、作業場所の行が変わるたびに選んでいなくても `settings.always: false` を書き直していたので、印の無い値を信じると既存の利用者に既定が効かない。
- 「今回だけ」を面の末尾に置くのは、普段は要らず、要るときにはチップを押す動機（「· 分けて始めます」を見て止めたい）があるため。

## 影響

- 旧版で人が明示的に「いつも分ける」をオフにしていた場合も、印が無いので区別できず、オンに戻る（必要なら設定でオフにし直す）。
- 保存された値がない既存の利用者は、次にぶつかったとき、確かめずに分けた作業場所で始める。分けた先には依存が入っていないので、書き込みの多い会話は最初のターンで入れ直すことがある。変更が残れば右パネル「git」の「残っている作業場所」に出る。
- `docs/design-system.md`「分けた作業場所」と `docs/design.md` を今の形に書き直す。0089 の決定 2 は置き換える（0089 の状態行と関係の行に追記）。
- 操作 `worktrees.setSettings` / `worktrees.settings` の意味は「自動で分けるか」になる（名前・入出力は変えない）。

採らなかった案:

- 既定を「分けない」のまま行だけ消す案（同時の書き込みが黙って起こる）。
- チップに小さな印だけ足す案（気付く経路は残るが、既定の挙動を決めていない）。
