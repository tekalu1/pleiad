# 0041 Claude の認証を委譲先の候補として個別に見せる

- 状態: 承認（2026-09-27）
- 置き換えた: 0040

## 状況

0039 と 0040 で Claude の認証は個別に判定し、週次の余裕を優先して選ぶようにした。しかし記録・エラー・画面にはモデルごとの代表理由だけが出ていた。認証によって週次と 5 時間の枠の状態が異なると、どの認証が使えず、どれが後回しになったか分からなかった。再試行でもモデルだけを選び、認証は指定できなかった。

## 決定

- 0040 の候補の三分類、5 時間枠を 100% の不可判定と最後の同点決めにだけ使う規則、週次を優先する並べ方、段を上から探して必要なら下へ降りる規則を保つ。
- Claude は同一人物と確認できた重複認証を 1 つにまとめた後、残った認証ごとに判定と表示を持つ。`routing.skipped` に認証ごと 1 行の `account`・伏せた `accountLabel`・理由・枠を残す。選ばれなかった余裕ありの認証には `lower_priority` を記録する。選んだ認証の伏せた表示名も `routing.target.accountLabel` に残す。
- 委譲カード、設定の候補状態、使える候補が無いときのエラーと画面は Claude の認証ごとに行を分ける。エージェント向けエラーの行は `- claude:model [伏せた表示名] (段): 理由 …` とし、ほかの候補の行は従来の形を保つ。
- 再試行では Claude の使える認証を別々の選択肢にし、`retryAgentTask` に `account` を渡す。同じ backend・model・account の組だけ除き、サーバーで指定した認証の現在の状態を再確認する。

## 理由

認証ごとの使用量が違うため、モデル単位の代表理由では選択の根拠を説明できない。認証を選べる再試行と個別の表示を同じ判定結果から作れば、画面とサーバーの選択が一致する。表示名は `ply_usage` と同じ方法でメールアドレスを伏せる。

## 影響

- 0040 の認証をまとめて記録・表示する部分を置き換える。現行仕様は [agent-delegation.md](../agent-delegation.md) と [design-system.md](../design-system.md) に記す。
