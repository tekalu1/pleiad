# 0159 通話モードの失敗の知らせ: その場の失敗と通話の状態に分ける

- 状態: 承認（2026-10-07）
- 一部を置換: [0156](0156-voice-call-turns.md)・`docs/design-system.md`「通話モード」の「聞き取りの失敗も同じ 1 行」

## 状況

聞き取れなかった・読み上げられなかった・権限なし・キー不足・上限・つながりの切れが、すべて入力欄の下の同じ 1 行に出て、次に通話を始めるまで消えなかった。1 回の発話だけの失敗が、次の発話が届いても、通話を終えても、別の会話へ移っても残る。どの発話の失敗かも、続けて何回失敗しているかも、キーが拒否されているのかも分からなかった。

## 決定

失敗を **その場の失敗**と **通話の状態**に分け、前者は起きた場所に出して短い寿命で消し、後者は入力欄の下に残して消える条件を決める。時間では消さない。

- **聞き取れなかった** = 会話の末尾（声の吹き出しが出るはずだった場所）の、面を塗らない 1 行。別の発話の吹き出しが出ているあいだは、その吹き出しの中の 1 行。次に話し始めたら畳み、通話を終えたら消える。続けて失敗したら同じ行を「続けて N 回」に更新し、2 回目から手がかりと［設定を開く］。何か聞き取れたら回数を戻す。キーが拒否された（HTTP 401・403）ときは 1 回目から別の文。
- **読み上げられなかった** = 返事の下の一行（`.vc-hint` の `fail`）。次の発言を送ったら消える。
- **通話の状態**（権限・マイク・キー・上限・始められない・声が聞こえず終了・つながりの切れ）= 入力欄の下の 1 行に × を付ける。状態は原因が解けたら、終わった理由は別の会話へ移ったら、どちらも ×・次の通話で消える。別の会話へ移ったことは、通話が終わったあとも 500ms ごとに見る。
- ホストが画面へ渡す聞き取りの失敗に、失敗の種類（`kind`・HTTP の `status`）を足す。本文・キー・応答の中身は渡さない（`core/voice/session.mjs` の `error`）。
- 出し分けと消える条件は DOM を持たない `web/voice/notices.mjs` に置く（`tests/unit/voice-ui.mjs`）。

## 理由

- 聞き取りの失敗は、その発話の文字が 1 つも出なかったときだけ通知になる（`core/voice/stt.mjs`）。つまり通知が出る場面には普通、声の吹き出しが無い。吹き出しが出るはずだった場所に出せば、どの発話のことかが分かり、次に話し始めた瞬間に吹き出しへ替わる。
- 通話の状態は、別の発話が届いても変わらない事実なので、入力欄の下に残す。入力欄は会話によらないため、権限・キーは別の会話へ移っても残し、終わった通話の理由だけは、その会話を離れたら消す。
- 時間で消すと、目を離している間に終わった通話の理由を、戻って読めなくなる。
- キーの拒否は待っても直らないので、「もう一度話してください」を繰り返さず、行き先を出す。ホストが種類だけを渡すのは、本文やキーを画面へ流さずに分岐できるため。

## 影響

- 聞き取りの失敗が入力欄の下から会話の末尾へ移る。通話の状態だけの欄になるので、権限・キーの一行は、会話の中の行と取り違えられない。
- 送れなかった声の発言（`sendFailed`）は、この変更の範囲外。これまでどおり入力欄の下の一行（× が付くだけ）。声の吹き出しが消え、言った内容が画面に残らない問題は別に扱う。
- 設定が変わったとき（キーの登録・上限）にキー不足・上限の一行が消える。`voiceChanged`・`settingsChanged`（voice）が届いた画面の更新（`refresh({ changed: true })`）で消す。
