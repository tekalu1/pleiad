# 0033 初回の案内で作業ディレクトリを選べるようにする

- 状態: 承認（2026-09-27）
- 置き換えた: docs/desktop-onboarding.md の「作業場所（フォルダー）は初期ダイアログから撤廃され、未設定時は自動的にホームディレクトリが設定される」

## 状況

初回の案内（「Pleiad へようこそ」）ではエージェントだけを選ばせ、作業ディレクトリはホームに自動で決めていた（docs/desktop-onboarding.md の当時の決定。会話画面で変えられる）。
2026-09-27 の UX 監査（setup#3）で、初回の人は入力欄の小さなチップ（「hikaru」とだけ出る）に気づかず、プロジェクトの依頼をそのまま送るとホーム全体を作業範囲として渡すことが分かった。
モックでは「最初の会話でだけ入力欄の上に一行」を出す案を示したが、ユーザーはレビューでそれを採らず、初回の案内の中で作業フォルダーを選べるようにすることを選んだ。

## 決定

- 初回の案内のエージェントの一覧の下に「作業ディレクトリ」の行を置く。フォルダーのアイコン・等幅のフルパス（ホームなら弱い字の「ホーム」）・「フォルダーを選ぶ…」。下に弱い字の一文「エージェントはこのフォルダーの中のファイルを読み書きします。」。
- 既定はホームのまま（前に「会話を始める」で決めたものがあればそれ）。選ばなくても始められる。
- 「フォルダーを選ぶ…」は入力欄の作業ディレクトリの面と同じ: デスクトップ版は OS のダイアログ（`plyDesktop.chooseFolder()`）、ブラウザー版（リモートの窓も）は案内の中に簡易ブラウザー（`listDirs`。`..`・ドライブ・「このフォルダーにする」）。部品は `web/composer-controls.mjs` の `folderBrowser` を共有する。
- 「会話を始める」は選んだフォルダーを `completeSetup` の `cwd` で渡し、最初の会話をそこで作る。サーバーは今までどおり存在を確かめ、`onboarding.json` に残す。
- 入力欄の上の一行は出さない。

## 理由

- 作業範囲は「知らないと事故になること」（design-system.md §2.7）で、最初に決める場所は初回の案内がいちばん自然。入力欄の上の一行は、送る直前まで何も知らせず、読まれずに送られることもある。
- 選ぶ部品を入力欄の面と同じにすれば、後で入力欄から変えるときも同じ操作で済む。
- ホームで使いたい人の手間は増えない（そのまま「会話を始める」を押せばよい）。

## 影響

- 文書は docs/desktop-onboarding.md（利用可能になるまで・表の「作業フォルダーの指定」）と design-system.md §10。
- 「あとで」で閉じた人は今までどおりホームで始まる（会話画面で変えられる）。
