# 0060 入力欄を Markdown をその場で整える編集欄にし、添付を本文の位置に置く

- 状態: 提案
- 関連: [0059](0059-inline-attachments-markdown-composer.md)（承認済み。送信後の表示・添付の一覧の面・「段階 2 で決めること」）

## 状況

0059 で、自分の発言を Markdown で描き、添付を本文の印（`[添付] パス`）の位置に置く形を承認した（段階 1: 送信後の表示）。段階 2 は入力欄で、次の 4 点を決める必要がある（0059「段階 2 で決めること」）。

- 入力欄の編集欄（整形はその場で整える形を標準にする。エディターの選定・IME・Undo・貼り付け）
- 下書きの保存形式と、位置を持たない旧下書きの読み込み
- 送信本文の組み立て（今は本文の末尾に印を付ける処理）
- 送信中・失敗の添付の扱い

入力欄は `textarea` で、添付は箱の上の札の列（本文の位置を持たない）だった。`web/` はビルドを持たない素の ESM で、外部ライブラリを増やさない規則がある。呼び出し側（下書き・送信・スキル候補・シェルの形・待ちの表示・中断の再開の判定）は `value`・`selectionStart`・`input` イベントを前提にしている。

## 決定

1. **編集欄は自前の contenteditable（`web/md-editor.mjs`）。外部のライブラリは入れない。** ProseMirror などの汎用のエディターは、ビルドの無い ESM・依存を増やさない規則と合わず、正本を「Markdown の文字列」に保つ要件（往復で文字が変わらない）を後から合わせることになるため使わない。
2. **正本は Markdown の文字列で、ソースの 1 行 = 1 ブロック**（`web/md-doc.mjs`）。行の種類（見出し・箇条書き・番号・引用・コード・添付）と、行の記号（`## `・`- `・`> `）・インラインの区切り（`**`・`_`・`` ` ``・URL）はモデルが持つので、`docToMarkdown(markdownToDoc(s)) === s` が常に成り立つ（任意の文字列 6,000 件のテストで確かめる）。読み取れない構造（表・HTML・入れ子の引用の中身）は平文の行のまま残す。
3. **textarea と同じ窓口**（`value`・`selectionStart` / `End`・`setSelectionRange`・`setRangeText`・`placeholder`・`disabled`・`readOnly`・`focus`・`input` イベント）を要素に生やし、呼び出し側を最小の変更にする。`selectionStart` などは Markdown の文字列での位置で答える（スキル候補の `skillToken` がそのまま使える）。
4. **整形は打った時点で整える形を標準にする。** 行頭の `# `・`- `・`1. `・`> `・` ``` ` と、`**太字**`・`*斜体*`・`` `code` ``・`[文字](URL)` を閉じた時点で整える。**整えた直後の「元に戻す」（Ctrl+Z）で記号に戻る**ため、履歴は自前（`createHistory`）にし、整える直前（記号のまま）と直後を別々に積む。ブラウザーの履歴は使わない。範囲選択の間だけ小さな書式バー（B / I / コード / リンク）を出す。
5. **日本語入力（IME）の変換中（compositionstart〜end）は整形も構造の操作もしない。** 変換が終わってから DOM を読み直す。送信のキー（Enter / Ctrl+Enter の設定）は今のまま。
6. **添付は本文の位置の、独立した行の原子。** 印は `[添付] パス`（0059 のまま）で、原子は 1 回の Backspace で外れ、元に戻すで戻る。同じ添付は 1 ファイル 1 か所。送っている途中でパスが無いものは、仮の ID を持つ原子にし（Markdown の文字列には出さない）、届いたらパスを持つ原子にする。札に進み具合（%）・失敗の理由・再試行・外す・やめるを置く。**送っている途中・失敗の添付があるうちは送らない**（送信のボタンの title に理由）。
7. **下書きの形は `{ text, attached, version: 2 }` のまま。** `text` が印を含む Markdown で、位置はそこにある。`attached` は添付の実体（パス・名前・種類・出どころ `from`・大きさ `size`）。印の無い旧下書き（`version` なし）は本文を読んで、添付は「文末に付く」に入れる（位置を推測しない）。印が指すパスが `attached` に無いときは、平文の行のまま残す。
8. **送信の本文は、文中の印を含む Markdown をそのまま送る。** 文中に置いていない添付（「文末に付く」）だけを、今までどおり末尾に `attachmentLine` で足す（印を二重にしない）。`runTurn` の `attachments` は文中の位置の順で全件を渡す。
9. **ホストのファイル（パスのまま渡した添付）も present に載せる。** `presentAttachments` が置き場（uploads）の外を落としていたのは、クライアントの言うパスの中身を読んで会話に載せないため。ADR 0050 で、認証済みの読み取り経路（`/local-file`）が同じ検査（`inspectFile`: UNC・データ置き場を拒否）でホストの任意のパスを読めるようになったので、中身を載せず**パス・出どころ（`origin: host`）・大きさ（`size`）だけ**を載せる present にする。端末から送ったものには `origin: device` と `size` を足す。これで送信後の発言が、ホストのファイルも本文の位置の札にでき、一覧の面が出どころと大きさを出せる。
10. **「編集して再送信」は印ごと編集欄へ戻す。** 文中の位置を保つ。編集で本文から印を消した添付は再送しない。編集欄そのものは今の textarea のまま（同じ編集欄への置き換えは課題）。

## 理由

「送る前に文中のどこを指すか書けない」ことが、0059 で直した表示の問題の根だった。行の記号と区切りを捨てないモデルにすれば、Markdown の文字列が常に正本のまま、整形の見た目・元に戻す・下書き・送信・編集して再送信が同じ文字列を扱える。DOM を正としてブラウザーの編集（打鍵・IME・行の中の削除・スペルチェック）に任せ、構造を変える操作だけをモデルにするので、IME とスマホのキーボードを壊さない。

## 影響

- 入力欄は `<textarea>` ではなく `<div id="prompt" contenteditable>`。`:disabled` では選べない（`aria-disabled`）。ブラウザーのテスト（`tests/browser`）の `inputValue()` は `evaluate(e => e.value)` に替える。
- 古いクライアントが新形式（`version: 2`）の下書きを読むと、本文の `[添付] パス` がそのまま見え、送ると添付の印が末尾に重なる。双方向の互換は保証しない（同じホストの画面は同じ版を配るので、実害は版の違うリモートの窓に限る）。
- 送っている途中の添付の位置は、ページを読み直すと失われる（転送が終わらないため）。届いた添付は、その会話の下書きに「文末に付く」として入る。
- 隣り合う添付の間に文字を入れるには、添付を選んで（矢印・タップ）Enter で行を足す。
- 整形の規則・添付の操作の見え方は [design-system.md](../design-system.md)「入力欄の編集欄」。
- 編集欄は DOM から読んだ文書を版ごとに使い回す（MutationObserver が DOM の変化を知らせる）。文書のブロックは作った後に書き換えず、履歴はブロックを共有する。操作を足すときは、ブロックを書き換える前に写しを取る（`web/md-doc.mjs` の各操作と同じ）。
- 会話の題は本文（Markdown・添付の印つき）からそのままは作れないので、core の `core/prompt-title.mjs` に 1 つ置いた。既に生の本文のまま保存された題は直さない（新しい会話から）。
- ホストのファイルの present の `path` は、渡された文字列のまま持つ（本文の印と突き合わせるため）。読めるかの検査だけが解決したパスで行う。
