# 0132 上限で止まった会話は「解除されたら自動で戻る」だけにする

- 状態: 承認（2026-10-04）。置換（0160）
- 置き換えた: 0093（解除後の動き・12 時間の線・解除時刻が不明なときの扱い・再開待ち行列）、0103（日時の候補の先頭「上限の解除後」）、0094（設定 limitResume）

## 状況

[ADR 0093](0093-resume-after-usage-limit.md) は、上限で止まった会話の自動再開に、解除後の動きの 3 択（自動・知らせて押したら再開・何もしない）、同時に動かす数、新しい枠の使用率の歯止め、メモリの再開待ち行列とその並び順（脇の下の帯と「順番」の面）、別アカウントへ今すぐ移る案内、新しい会話の上限の警告を足した。どれも人が覚えて操作する前提で、止まったまま気付かないと自動で戻らない原因にもなっていた。

あわせて、自動で戻れない場面があった。解除時刻が分からない上限（Antigravity で「Resets in」が無いなど）は予定を置かず、人が再開しても断られ続けた。解除が 12 時間より先（週の上限など）は自動で再開せず、末尾に「解除後の再開を待っています」と出たまま何も待っていなかった。解除時刻が過ぎた後に Pleiad を開き直すと、予定はもう消え、行列はメモリにしか無く、時計の印のまま戻らなかった。解除時刻を過ぎても送信待ちの待ちが解けず、Codex は週の枠が尽きていても一番早い 5 時間枠の解除時刻を使った。

## 決定

**上限で止まった会話は、解除時刻に自動で再開する。**

- 解除時刻に `schedule.json` の予定（`kind: resume`）が直接再開する。解除時刻が 12 時間より先でも置く（12 時間の線を外す）。全部の会話が同時に動き、並び順・同時実行数・使用率の歯止め・メモリの行列は持たない。再び上限になった会話は、新しい解除時刻でまた待つ。
- 解除時刻が分からない上限は、30 分ごとに使用量（各バックエンドの `usage()`。使用量の表示と同じ口）を確かめ、止まった枠が 100% 未満になったら再開する。読めなければ 30 分後にもう一度確かめる。読めないのが 3 回続いたら一度だけ試しに再開し、試しに再開してすぐ再び上限（時刻不明）になるたびに間隔を 30 分 → 1 時間 → 2 時間 … と 6 時間まで伸ばす。判断は止まった枠だけで行う（Codex は主の枠とそのモデルに当たるバケット、Claude は全体の枠とそのモデルの系統の枠。別のバケット・別のモデルの枠は関係ない）。解除時刻がもう過ぎている（取得元が古い）ときも同じ扱いにし、再開してすぐ上限になる往復を作らない。
- 起動時とスリープ解除時に、解除時刻を過ぎた上限の会話（自動再開が入っているもの）をすべて再開する。予定の行が無い会話にも行を置き直す。
- 解除時刻を過ぎたら、上限中の指示を待たせる状態を解く。送った指示はすぐ送られ、人の「再開」も効く。自動を外した会話の送信待ちは、解除時刻に人の操作なしで流れる。解除時刻が分からない会話は、自動再開が入っている間だけ待たせる。
- Codex の解除時刻は、使い切った（100%）枠のうち最も遅く解ける時刻にする。どれも 100% でなければ、一番早く解ける枠のまま。
- 会話ごとの自動再開の切り替えは残す（会話末尾の［再開しない］／［自動で再開する］の 1 か所。操作 `sessions.setAutoResume`）。外した会話は、解除時刻の後に普通の「▶ 再開」で続ける。
- 自動で戻れなかったとき（再開の送信が失敗した・結果不明の未送信がある・受け付けた後に送信が失敗した）だけ、その会話の自動再開を外し、失敗として 1 回通知する。上限になった時点で自動再開する会話は、今までどおり通知しない。解除時刻を過ぎて 2 分たっても自動再開の印が残る会話は、画面が時計をやめて普通の「再開」にする。
- 人が［再開しない］にした会話は、再び上限になっても外したままにする（その会話が普通に完了したら忘れる）。
- 消すもの: 設定 `limitResume`（mode・concurrency・guardPercent）と「知らせて押したら再開」（`limitReady` 通知・`limitResumeReady`・`notifyAtReset`）、歯止め（`limitGuarded` 通知）、並び順と「先頭へ」、再開待ち行列（`core/resume-queue.mjs`）と操作 `resumeQueue.get/set`、脇の下の帯と「順番」の面、入力欄の再開ボタンの ▾ から開く「上限後の再開」メニュー（キャッシュの説明・別アカウントで今すぐ続ける・おすすめ）、会話末尾の「今すぐ ◯◯ で続ける」と「（N 番目）」、新しい会話の上限の警告。別のアカウントで今すぐ続けたいときは、入力欄のアカウントの札で替えて送る（替えると自動再開が外れ、止まった枠の待ちが解けて、送った指示がすぐ流れる。ADR 0093 の「アカウントの自動切り替えはしない」は変えない）。
- 送信予定（`kind: send`。[ADR 0103](0103-scheduled-send.md)）は残す。ただし日時の候補の先頭「上限の解除後（2:30）」は消す（上限中に普通に送れば、解除まで送信待ちで同じ動きになる）。

## 理由

上限は待てば解ける。自動で戻る会話に、人が選ぶ面・設定・通知を重ねるほど、止まったまま気付かない場面が増える。人が方針を変えたいときの逃げ道は、会話ごとの［再開しない］と、入力欄のアカウントの札、指示を書いて送ること（送ればその指示で続く）で足りる。再開の予定を `schedule.json` だけで持てば、メモリの行列と取りこぼしの 3 場面（時刻不明・12 時間超・開き直し）が同じ仕組みで直る。遠い先の解除でも自動で戻すのは、時刻を末尾の行に日付つきで出して見える状態にするため。

## 影響

- ADR 0093 のうち、解除後の動きの 3 択・12 時間の線・解除時刻が不明なら自動再開しない・再開待ち行列（並び順・同時 3 件・使用率の歯止め）の規則を本 ADR で置き換える。上限の検出と保存・上限中の指示の送信待ち・再開で送るもの・永続する予定の形・アカウントの自動切り替えをしない決定は、そのまま有効。ADR 0103 の日時の候補のうち「上限の解除後」を置き換える。ADR 0094 の `limitResume` の設定は無くなる。
- 保存済みの設定 `limitResume`（prefs.json）は読まれなくなる。既に保存された会話の `interrupted.notifyAtReset` も読まれない。12 時間超・時刻不明・「何もしない」で止まっていた会話（自動再開を外した状態で保存されたもの）は、そのまま［自動で再開する］で入れ直せる。
- 既知の制限: 再起動をまたぐと送信待ちは保留に戻るので、自動を外した会話に解除の前に送った指示は、解除の後に人の「再開」で戻す。
- 通知の種類 `limitReady`・`limitGuarded` を消す（ホスト・Android）。古いホストが送る分は新しい Android は表示しない。
- 画面は `docs/design-system.md`「中断と再開」、動きは `docs/design.md`「中断と再開」を今の形に直した。
