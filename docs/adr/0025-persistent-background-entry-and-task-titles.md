# 0025 バックグラウンドの常設入口・委譲タイトル・子孫表示

- 状態: 承認（2026-09-27）

## 状況

会話末尾の稼働表示に入口を置くと、ターンが終わった後に完了した作業へ戻りにくい。委譲した子のタイトルに依頼全文の先頭を使うと、長い依頼では一覧と会話の見出しが読みにくい。子がさらに委譲したタスクも、親会話の一覧では見えない。

## 決定

- 入力欄のすぐ上、右端にバックグラウンドの札を 1 つ置く。稼働中は弧と「バックグラウンド N」、全件終了後は弱い字で「バックグラウンド · 完了 M」。作業履歴の無い会話には行も置かない。会話末尾の稼働表示から入口を外す。委譲された子の会話でも、その子が作った作業について同じ札を出す。
- `ply_delegate` に任意の `title` を加える。依頼元が一覧と子会話に使う短い名前を付ける。空白を 1 つに詰め、最大 40 文字で保存する。無い場合は依頼の最初の空でない行を使う。
- 一覧は「動いている」「終わった」を分け、終わった親を新しい順に 10 件ずつ表示する。子孫は親の直後に深さに応じて字下げし、鉤形の線でつなぐ。区分は最上位の親の状態で決める。
- 完了したネイティブの子は会話履歴の委譲ツールの ID から `findSubagent` で引き直す。Pleiad タスクは保存済みの全件から子会話 ID を辿る。

## 理由

札なら入力中に同じ位置で開け、完了後も履歴へ戻れる。固定の帯は置かないという画面規則にも収まる。依頼元が付けたタイトルを保存時に統一すると、追加の LLM 呼び出しや子会話タイトルの後書きが要らない。子孫を親の下に保つと、委譲の関係が一覧で読める。

## 影響

入口位置に関する [ADR 0021](0021-unified-background-entry.md) を置き換える。サブエージェントと Pleiad タスクの呼び名、詳細の会話表示、承認カードの扱いは継続する。画面の規則は `docs/design-system.md`「バックグラウンド」を正とする。
