# 0096 別の会話への送信と既読を操作の一覧に足し、強い会話を代わりに動かすときは承認カードで聞く

- 状態: 提案

## 状況

[ADR 0094](0094-human-only-five.md) で、Pleiad の機能は承認モード・秘密の値・アカウント・接続先の既定・リモートのペアリングの 5 つを除いて AI も使えることにした。WS のコマンドの `todo` は 0 件になったが、`tests/ops-baseline.json` で `ui-internal`（画面の中だけ）に分けたものの中に、実際の機能が残っていた。このうち送信と既読の系統は次のもの。

- `sendMessage`: 画面の送信。送信待ち（outbox）に積み、走っている会話では順番を待つ。送信 ID の冪等（応答が届かず送り直した同じ ID）・添付・同じ会話の中の巻き戻し（ADR 0091）・承認モードの欄を持つ。
- `runTurn`: 会話を作りながら、承認モードを選んで直に始める古い口。画面は使っておらず、テストとモバイルの偽のホストが使う。
- `messageAction`: 送信待ちの 1 件の取り消し（cancel）と送り直し（retry）。
- `markRead`: 完了を確認した印（既読）。画面は旧版がブラウザーに持っていた分も含めて、`{ reads: [[sessionId, at], …] }` でまとめて送る。
- `saveDraft`（入力欄の下書き）・`watchSession`（この接続が開いている会話の登録）。

bot の会話（`feat/bots-channels`）と、別の会話への送信を `sessions.send`（`{ sessionId, text, reason? }`・write・宛先の承認モードで走る・宛先の履歴に「<送り手> があなたの代わりに送信」）とし、宛先の承認の強さが送り手より強いときは guarded にすることで合意した（2026-10-03。先に main に入った方の定義を正とする）。

別の会話を動かせると、次のことが起きうる。

- 権限の持ち上げ: 宛先の承認モードで走るので、毎回聞く会話の AI が確認なしの会話へ送ると、承認なしで何でもできる会話を代わりに動かせる。
- 往復と増殖: 会話 A が B に送り、B の返答のターンが A に送り返す、を止める人がいない。委譲の親子の間では `ply_task_send` と完了通知の 2 つの道具をまたいで同じことが起きる。1 つのターンが同じ送信を繰り返すこともある。

## 決定

### 操作

| 操作 | WS | 危険度 | 内容 |
|---|---|---|---|
| `sessions.send` | （なし。画面は `sendMessage` のまま） | write（宛先が強いと guarded） | 画面の送信と同じ送信待ちに積む。宛先の会話の承認モードで走る（承認モードは渡さない）。AI・CLI・HTTP の口だけ |
| `sessions.messageAction` | `messageAction` | write（強い会話の送り直しは guarded） | 送信待ちの取り消し・送り直し。画面には今までどおり送信待ちの全部を返す |
| `sessions.markRead` | `markRead`（1 件の形） | write | 既読。`at` を省くと今の完了まで。巻き戻らない |

- **`sendMessage` は WS のまま（`ui-internal`）にし、中身を `sessions.send` と共有する。** 送信 ID の冪等・添付・巻き戻し・承認モードの欄は画面の送信のためのもので、AI に出す入力に混ぜると、AI が承認モードの欄（人だけ）や巻き戻し（会話の記録を書き換える）を渡せる形になる。操作は AI 向けの最小の形にし、送信待ちに積む処理（`core/server.mjs` の `acceptMessage`。走っている会話では順番を待つ・中断で保留になった分を先に戻す）を両方が通る。宛先が実行中のときの扱いは画面の送信と同じになる。
- **`runTurn` は `ui-internal` のまま。** 会話を作りながら承認モードを選ぶ口で、AI が使う形（承認モードは人だけ）にならない。AI が会話を作るのは `sessions.new`、送るのは `sessions.send`。
- **`markRead` のまとめて送る形は操作に寄せない。** 旧版のブラウザーの既読を一度に移すための形（5000 件まで）で、1 件の形だけを `sessions.markRead` を呼ぶ外側にした。どちらも同じ `markReads`（`store.markRead` と `read` の配信・スマホの通知を消す）を通る。
- **`saveDraft`・`watchSession` は画面の中だけ。** 下書きは入力欄の状態（AI が会話を作るときの下書きは `sessions.new` の `draft`）、`watchSession` は WS の接続ごとの購読で、どちらも外へ出す意味が無い。

### 強さの比べ方

- 宛先で次に走るときの承認モード（走っているターンのモードと、予約を含む次のターンのモード）のどれかが、呼び出した会話のモードより強ければ guarded。強いとは、`core/modes.mjs` の範囲（none < readonly < workspace < full）か自律（ask < judge < never）のどちらかが送り手より上のこと。委譲の「子は呼び出し元の強さを超えない」と同じ考え。
- 承認カードは送り手の会話に出る（設定の変更の承認と同じ流れ。ADR 0088）。受領証の元に宛先のモードを入れ、許可までに宛先のモードが変わったら聞き直す。カードには「確認なしでできることが増える」の一行を出す。
- 送り手が bypass・yolo（範囲 full・自律 never）なら、ほかの guarded と同じく確認なしで通し、送り手の会話の記録（`field: op`）に残す。読み取り専用の会話からは断る（`READ_ONLY_MODE`）。会話に束縛されていない呼び出し（外の CLI）は比べる強さが無いので guarded として扱い、今の規則どおり `NEEDS_UI`。
- 送り直し（`sessions.messageAction` の retry）も宛先の会話で走るので、同じ比べ方をする。取り消しは何も走らせないので write のまま。

### 歯止め

承認カードを出す前と送る直前の 2 回確かめ、断ったら送り手の会話の変更の記録に `field: opRefused`（`to` は操作の id、`reason` は code）を残す。

- 自分自身へは送らない（`SEND_SELF`）。
- 委譲の親子の間は送らない。自分が委譲した子へは `ply_task_send`（`SEND_TO_CHILD`）、子から依頼元へは送らない（結果は完了通知で届く。`SEND_TO_PARENT`）。2 つの道具をまたぐ往復を作らない。
- 送信の連鎖は 3 回まで（`RELAY_LIMIT`）。会話ごとに「今のターンが何回目の送信で始まったか」を覚える（送信待ちから始まったターンで決め直す。人の発言は 0、別の会話からの発言はその送信の数。途中送信で渡った分は大きい方）。送るたびに 1 足し、3 を超えたら断る。人が発言すれば 0 に戻る。保存しない（再起動で 0 に戻る）。
- 同じ送り手（会話）から 10 分に 20 件まで（`SEND_RATE`。HTTP は 429）。

### 宛先の履歴

- 送った本文のハッシュと送り手を宛先の会話に残す（セッションの記録の `relayed`。完了通知の `taskNotices` と同じ見分け方で、文言に依らない。新しい方から 500 件）。履歴と流れの `userMessage` に `sentBy`（`by`・`via`・送った会話の `sessionId`・`title`・`backend`）を付け、画面は見出しを「あなた · 「<題>」の AI があなたの代わりに送信」にし、送った会話を開く「開く」を添える（`!` の行の「{agent} に渡した」と同じ並び）。連鎖の数は内部の歯止めなので出さない。
- 宛先の会話の変更の記録に `field: message`（送信待ちの id・理由・誰が・どこから）を残す。
- bot の会話が足すのは、主体が bot のときの追加の確認と、送り手の表示（`sentBy` に `name`・`icon` を足す。画面は `name` があれば題の代わりに出す）だけで、強さの比べ方と歯止めはこの定義を使う。

## 理由

- 画面の送信と同じ送信待ちを通すので、宛先が走っているとき・中断しているとき・上限で止まっているときの扱いを 2 つ持たない。
- 権限の持ち上げは、設定や委譲と同じく「強くなる向きだけ人に聞く」で止める。毎回聞くと bot の会話のやり取りが成り立たず、聞かないと承認モードの意味が無くなる。
- 連鎖の数で止めると、会話どうしの短いやり取り（頼む → 答えを送り返す）は通し、止まらない往復だけを止められる。数え方は送信待ちから始まるターンだけを見るので、送信の経路に 1 か所足すだけで済む。

## 影響

- `core/ops/conversations.mjs` に 3 つの操作・強さの比べ方（`strongerMode`）・歯止め、`core/server.mjs` に `acceptMessage`・`markReads`・`relayed` の記録・連鎖の数。`tests/ops-baseline.json` から `messageAction`・`markRead` が消える。
- `ply_control` の指示文と直のツールは増やさない（3 つとも `catalog`。T4 は ja 1757・en 1656 / 1800 トークンのまま）。
- 委譲の子が別の会話を経て往復するような、道具をまたぐ連鎖（`ply_delegate` で新しい子を作り、その子が送る）は数えない。増えるのは委譲の子で、委譲の上限と使用量で抑えられる。
- 本文のハッシュで見分けるので、人が同じ本文をあとで打つと、その発言にも送り手の印が付く（完了通知と同じ制約）。
- `RELAY_LIMIT`・`SEND_RATE` の値は bot の会話のやり取りを見て変えうる。変えるときはこの ADR を置き換える。
