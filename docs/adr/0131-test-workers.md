# 0131: 通常テストを独立した worker で並列実行する

## 状態

承認（2026-10-04）。

## 状況

通常テストは単体テストとサーバー・WebSocket・Git の結合テストを同じハーネスで順次実行している。Windows の CI はテスト本体に約15分かかる。スイートは環境変数、DOM の代替、モジュールの状態を変更するため、同じプロセスで同時に実行すると相互に影響する。

## 決定

- 通常 CI の Node・OS の3構成を維持し、各ジョブで `--jobs 2` を使う。既定の `--jobs 1` は同じプロセスで登録順に実行する。
- worker は別プロセスにし、その中では1スイートずつ実行する。重いスイートから空いた worker に渡す。各 worker は固有の一時データ置き場を使う。
- 実行元の制御用環境変数をテストへ持ち込まない。本物のデータ置き場を開くことを拒む既存のガードを維持する。
- 登録漏れ・重複・実行漏れ・worker の異常終了は失敗にする。スイートを減らすことで時間を短縮しない。
- 固定秒の待機は、検証する順序を制御できるゲートや状態待ちに置き換える。遅い重複通知がないことなど、時間の経過を観察する必要がある待機は残す。
- CI はスイートごとの時間・判定数・skip を JSON の成果物として保存する。必要に応じて `--shard k/N` で全スイートを決定的に分割できる。

## 理由

ジョブ数を増やさずに待ち時間を減らせる。プロセスで分けることで既存テストの共有状態を隔離でき、既定の順次実行で並列時の問題を切り分けられる。Node の対応下限と配布環境、Windows 固有の挙動の検証も残る。

## 影響

CPU・メモリの同時使用量は増える。時間の重みは実測をもとに更新し、新規スイートは既定の重みで必ず実行対象に含める。子プロセスの後始末は OS ごとに検証する。CI の待ち時間とローカルの計測時間を区別し、並列で失敗が増える場合は `--jobs 1` に戻して原因を調べる。
