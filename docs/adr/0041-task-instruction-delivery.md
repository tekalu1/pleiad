# 0041 委譲の追加指示を配送まで保存する

- 状態: 承認（2026-09-27）

## 状況

`ply_task_send` は追加指示の本文を子の次のターンまで文字列の `queue` に置く。詳細画面は子の履歴だけを読むため、届く前の指示が見えない。失敗・停止・再起動では未配送の本文が消えることもある。

## 決定

各指示に固有 ID、本文、受付時刻、配送状態を持たせて `agent-tasks.json` に保存する。状態は `queued`、`sending`、`delivered`、`dropped`。実行は従来の FIFO のままにし、旧形式の文字列 queue も読み込む。未配送で終わった指示は `dropped` として残す。

一覧配信には待機件数と更新番号だけを載せ、本文は選択中のタスクの詳細を開いたときだけ取得する。子の履歴に現れた指示は通常の user 発言として表示し、同じ本文を繰り返した場合も配送順と ID で区別する。

## 理由

送った人が指示の受付と配送を追えるようにし、届かなかった指示も確認できるようにする。本文を全タスクの定期配信へ載せると、通信量と閲覧範囲が不必要に広がる。

## 影響

保存形式と WebSocket コマンドを追加する。MCP の `ply_task_status` / `ply_task_list` は既存の返り値を保つ。表示は `docs/design-system.md`「バックグラウンド」、保存と配送は `docs/agent-delegation.md` に従う。
