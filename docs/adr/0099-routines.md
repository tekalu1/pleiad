# 0099 ルーティンは実行ごとにチャンネルのスレッドを立て、取りこぼしは最新の 1 回だけ走らせ、承認待ちには期限を付ける

- 状態: 提案

## 状況

決まった時刻・間隔・出来事で bot に仕事をさせたい（毎朝のまとめ、夜の間に失敗した会話の調査）。無人で動くので、承認で止まる・暴走する・動いたのに気づけない、が問題になる。Pleiad が止まっている間は動かせない。

## 決定

- **トリガは 6 種。** 毎日（平日だけの指定つき）・毎週・間隔（時間帯つき）・cron（5 欄。秒は持たない。式は自前で解析し、依存を足さない）・イベント（会話の完了・失敗・あなた待ち）・webhook（0100）。時刻は PC の現地時刻。
- **実行ごとにチャンネルへ根の投稿を立て、bot のそのスレッドの会話で走らせる。** 実行の履歴 = スレッドの並び。状態は「終了」「要確認」（bot が自分で検証して怪しいと付けた）「✕ 失敗」「スキップ（理由）」で、緑の ✓ で成功と見せない。
- **取りこぼしは最新の 1 回だけ。** 起動時に、最後に動いた時刻より後・今より前の予定が 1 つ以上あれば、最新の 1 回だけ走らせ、根の投稿に「Pleiad が止まっていた間の分」と書く。
- **承認待ちには期限（既定 30 分）。** 過ぎたらターンを止め、スレッドに「承認が無かったので取り消しました」と報告する。承認の通知は今の通り（[ADR 0086](0086-notifications-through-relay.md)）。承認モードは作った人の強さまでで、上げるのは人だけ。
- **イベントのトリガは bot・ルーティン・学習の会話から来たものでは動かない。** 自分の実行の失敗で自分が動く輪を作らない。
- **作る・変える。** `routines.create` は AI が作るときは承認カード（guarded）。`update` は頻度を上げる・モードを強くする・対象を広げる向きだけ guarded。`pause` は狭める向きで write。`resume`・`run`・消す操作（`delete`）は guarded。秘密の値の再発行（`rotateSecret`。0100）は human-only。`run` は `dryRun`（計画のモードの使い捨ての会話で走らせ、投稿しない）を持つ。
- **常駐。** 有効なルーティンが 1 つでもあれば、窓を閉じてもトレイに残る（`docs/remote.md` §6.3 の常駐の条件を「リモートが有効 または 有効なルーティンがある」に広げる）。

## 理由

- 履歴をスレッドにすれば、探しに離れずに済み、承認・質問・成果物も Chats と同じ形で見える。
- 溜まった分を全部走らせると、止まっていた間の分が一斉に動いて費用と混乱になる。最新 1 回で「今の状態」へ追いつけば足りる。
- 無人で承認待ちのまま固まるのが一番危ない。期限で止めて報告すれば、人が戻ったときに分かる。
- 採らなかった案: 取りこぼしを全部走らせる、期限なしで待ち続ける（既定の挙動のままだと無人で固まる）、成功を緑の ✓ にする（無人の「成功」は検証されていない）。

## 影響

- **規約:** Claude などのサブスクの認証で、人がいないルーティンを動かすのは、有人の利用より一段踏み込む（公式は Agent SDK で製品を作るなら API キーを求め、消費者規約に自動の手段でのアクセスの禁止がある）。画面からは認証の選択を外してあり、事実をここに書いて、利用者の判断に残す。
- 常駐でトレイに残るので、設定の文言（`desktop.json`）とリモートの常駐の状態に `routines` を足す。
- 止まっていた間の分は最新 1 回しか残らない。
- `INTERRUPT_REASONS` に `timeout` を足す。
