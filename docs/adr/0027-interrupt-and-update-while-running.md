# 0027 中断を会話の状態として残し、実行中でも中断して更新・終了できるようにする

- 状態: 承認（2026-09-27）

## 状況

中断はどこにも保存されなかった。ターンは成功・失敗・中断のどれで終わっても `completedAt` だけを書くので、左パネルの印は同じ未読の丸になり、再読み込みすると会話の「中断した」の行も消えた。続けるには、利用者が自分で「続けて」と打つしかなかった。
更新と終了は、実行中の作業（ターン・承認待ち・サブエージェント・委譲タスク）が 1 件でもあると断っていた（画面の `running` の確認と、サーバーの更新ロック）。断った後は準備済みに戻り、終わるのを待ってもう一度押すしかない。先行版を 1 日に何度も出すので、更新のたびに全部の作業が終わるのを待つことになり、リリースを気楽に出せなかった。

## 決定

- **中断は会話ごとの状態。** ターンが中断で終わったら sidecar に `interrupted: { at, reason }` を書き、次のターンの開始で消す。`at` は同じターンの `completedAt` と同じ値。理由は `user`（中断ボタン）・`update`（更新のため）・`quit`（終了のため）・`hostAway`（ホスト不在の猶予切れ）・`restart`（Pleiad が落ちた・強制終了で、終わりが記録されていないターン）。
- **落ちたターンも拾う。** ターンの開始で `turnStartedAt` を書き、終わりで片付ける。起動時に `turnStartedAt > (completedAt ?? 0)` の会話は `restart` の中断にし、`completedAt` も同じ時刻にする。
- **再開はボタンを押したときだけ（WS `resume`）。** 保留の未送信があれば、それを並びのまま送り直す（「続けて」は送らない）。無ければ理由ごとの文を、見える user の発言として普通の送信経路で送る（`user` は「続けてください」、それ以外は途中だった操作の結果を確かめるよう頼む文）。実行中・中断していない会話では断る。
- **実行中でも更新・終了できる。** 断らずに止まる作業を並べ、「あとで」と「中断して更新」（デスクトップの終了は「作業に戻る」と「中断して終了」）を選ばせる。選んだら全部を理由付きで中断し、実行中が 0 になるのを待ち（上限 30 秒。超えたら理由を出して止める）、今の保存と更新（終了）の手順へ進む。サーバーの更新ロックは安全網としてそのまま残す。
- 委譲の子の会話も独立した会話なので、全部の中断で同じ理由の中断として残り、個別に再開できる。委譲タスクは今どおり取り消し、親の再開で委譲し直すことはしない。
- **「終わったら更新する」予約はしない。**

## 理由

- 止めたことが会話に残れば、止めるのが怖くなくなる。作業を止めやすく、方針を変えやすくするのが狙い（入力欄に文字があれば、送った指示で続く）。
- 3 つのバックエンドとも、次の送信で同じ会話の続きになる（Claude の resume、Codex の同じ thread、agy の `--conversation`）。再開は普通のターンを 1 回送るだけで作れ、特別な API は要らない。
- 「勝手に再開しない」（design.md「作業中のメッセージ送信」）は保つ。送るのは人が押したときだけで、ツールが途中で切れた可能性は文で伝える。
- 更新の断りは「作業を失わない」ためだったが、中断が会話に残り再開できるなら、失うものは途中のツール 1 回分に限られる。承認待ちは中断の既定どおり却下になり、ダイアログに 1 行でそう書く。
- 予約更新は採らない: 作業が終わった直後に勝手に再起動することになり、「作業完了直後の強制適用はしない」と正面からぶつかる。いつ止まるかを利用者が選べなくなる。

## 影響

- `docs/desktop-releases.md` の「作業・承認待ちでは再起動を拒否する」を、中断して更新する形に書き換えた。
- `docs/design.md`「中断と再開」に保存の形・公開の経路・`resume` の規則を書く。画面の形は `docs/design-system.md`。
- WS: `abort` に `reason`、新しいコマンド `resume`、一覧の行・`turnEnd`・`loadSession` に `interrupted`、`turnResult` の aborted に `reason`。
