# 0040 委譲先の使用量を後回しの条件にする

- 状態: 承認（2026-09-27）
- 置き換えた: 0022

## 状況

0022 では後回しの線を超えた候補を除き、基準の段から上だけを見ていた。design × mid の t4 で Claude の全認証が線を超えると、下の段の Codex や Antigravity が使えても委譲が止まった。さらに、5 時間枠の一時的な使用量を週次と同じ重みで見ていたため、週次 64%・5 時間 87% の OZ より週次 83% の認証を優先することがあった。モデルごとの代表理由だけを表示していたので、どの認証が使えないかも見えなかった。

## 決定

- 候補を Claude は認証ごとに「余裕あり」「余裕が少ない」「使えない」に分ける。利用不可、モデル不明、委譲先での再確認による拒否、効く枠の現在の使用率が 100% 以上の場合だけ使えない。5 時間以外の効く枠が `avoidPercent` 以上、週次ペースが高い、使用量が不明・古い場合は除かず後回しにする。
- 5 時間枠（`minutes === 300`）は候補の組分けでは 100% 以上かどうかだけを見る。100% 未満の使用率や不明さは後回しの理由にせず、候補と認証の苦しさがほかの条件で同点のときだけ使用率を比べる。
- 基準の段から上へ各段の余裕あり候補を設定順で探し、無ければ同じ範囲の余裕が少ない候補を段ごとに選ぶ。上の段が全部使えなければ 1 段ずつ下り、各段で余裕あり、次に余裕が少ない候補を選ぶ。tv は tv だけを見る。見た範囲の全候補が使えない場合だけエラーにする。
- 余裕が少ない候補は、使用量が分かるもの、5 時間以外の効く枠の最大使用率が低いもの、週次ペースが低いもの、5 時間の使用率が低いもの、段内の設定順で選ぶ。Claude の余裕ありの認証も最大使用率、週次ペース、5 時間の順で選ぶ。同一人物と確認できる重複認証は 1 つにまとめる。
- 選択時の理由・枠・線、基準より下の段、見送った候補を `routing` と委譲カードに残す。Claude は重複をまとめた後の認証ごとに `skipped` の行と伏せた表示名を残し、選ばれなかった余裕ありの認証には `lower_priority` を付ける。設定、カード、使える候補が無い場合のエラーも認証ごとに理由を出す。エラーには線の値を含め、Claude の行を `- claude:model [伏せた表示名] (段): 理由 …` とする。
- 「別の候補でやり直す」は余裕が少ない候補も選べる。Claude は使える認証を別々の選択肢にし、`retryAgentTask` に `account` を渡す。元の委譲先と同じ backend・model・account の組だけ除き、サーバーでもその認証の状態を再確認する。

## 理由

100% 未満なら作業を受けられるので、線を超えた候補も残す。段の優先順位を保ちながら下の段まで探せば、委譲が止まる場面を減らせる。短期的な 5 時間枠より、週次やモデル系統の週次、Codex の追加枠の余裕を優先する。認証ごとの理由と再試行の選択を同じ判定結果から作れば、画面と実際の委譲先が一致する。

## 影響

- 0022 の「使用量の線で除く／上の段が全部だめならエラー」を置き換える。判定器と種類・難しさの規則は維持する。
