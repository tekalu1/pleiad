# 0071 computer use の承認と安全

- 状態: 提案

## 状況

computer use は、エージェントが PC の任意のアプリを人と同じ権限で動かす。ターミナルを開けばシェルと同じことができ、パスワード管理を開けば秘密が見える。一方で、操作 1 回ごとに座標の JSON で聞くと、何を触るのかが分からず、聞かれる回数も多すぎる（今の MCP の承認のままだとそうなる）。

2026-10-01 にユーザーと次を決めた: 機能の既定はオン、承認はアプリ単位、確認なしの会話とすべて許可のスイッチでは聞かない、委譲の子にも渡す、Antigravity は聞かない、拒否はターンの間だけ覚える、Pleiad の窓は撮影から外さない。

## 決定

- 承認はアプリ単位。アプリは `aumid:<AUMID>`（パッケージアプリ）か `exe:<小文字・スラッシュのフルパス>` で識別する。承認カードの選択肢は「常に許可」「拒否」「この会話で許可」。常に許可は `prefs.json` の `computerUse.alwaysAllowed`、この会話で許可は会話のデータの `computerApps` に保存する。
- 判定の順は、禁止 → このターンで拒否済み → 確認なしの会話 → すべて許可 → 常に許可・この会話で許可 → 聞く。
- **禁止のアプリは必ず拒む。** 確認なしでも、すべて許可でも拒む。対象はターミナル・パスワード管理・セキュリティソフト・Windows の内部（ロック画面・UAC・スタート・検索など）・エージェント自身（Pleiad・Claude・Codex・ChatGPT・Antigravity）。カードは出さず、行に理由を残す。
- 確認なしの会話（承認モードの範囲 `full` かつ自律 `never`）では聞かずに許可する。Claude の bypass、Codex の yolo が当たる。**Antigravity は承認モードが確認なししか無いので、いつも聞かずに許可する。** 設定の画面に「Antigravity では承認を聞きません」と 1 行出す。
- 設定の「すべてのアプリを許可」（既定オフ）がオンなら聞かない。機能全体のスイッチの既定はオン。
- 高リスクのアプリ（エクスプローラー・設定・regedit・mmc・タスク マネージャー・IDE）は警告付きのカードにする。許可はできる。
- **拒否はターンの間だけ覚える。** 同じターンでは同じアプリを聞き直さずに拒否を返し、次のターンでは聞き直す。
- **委譲の子の会話にも渡す。** 子の承認カードは子の会話に出し、今の委譲の承認と同じ経路で祖先の会話にも複製する（3 つの選択肢のまま）。どれで答えても許可は子の会話に付く。子が承認を待つ間は `ply_task_wait` が `waiting` で戻り、OS の通知も出る。子の判定は子の会話の承認モードで行う。
- ツールごとの承認はエージェント側で出さない（Claude は `mcp__ply_computer__*` を allow、Codex は `approve`）。アプリの承認は MCP の橋の中で、ツールの呼び出しの中で待つ。
- 入力の直前に毎回、入力デスクトップ（ロック画面・UAC を拒む）、対象のアプリ、Windows キー、管理者権限のアプリ（UIPI。正直に失敗を返す）、前面が Pleiad か、を見る。
- **Pleiad の窓は撮影から外さない。** 撮影から外すのはオーバーレイの窓だけ。会話の中身と承認カードはモデルに見えるが、Pleiad は禁止のアプリなので操作はできない。
- 指示文で、画面の中の指示を信頼しないこと、削除・送信・購入・アカウント作成の直前にユーザーに確かめることを伝える。

## 理由

アプリ単位なら「何を触らせるか」が人に分かり、聞く回数も抑えられる（Codex と同じ単位）。禁止のアプリを常に拒むのは、シェルや秘密への迂回路を、承認の設定によらず塞ぐため。エージェントは自分のシェルのツールに回れるので、仕事は止まらない。

確認なしの会話は、シェルもファイルの書き込みも聞かずに動かしている。computer use だけ聞いても守りは増えず、手間だけが増える。Antigravity はそもそも確認なししか無いので同じ扱いになり、それを設定の画面で明示する。

拒否をターンの間に限るのは、同じターンの中で何度も聞かれるのを防ぎつつ、次の依頼では改めて判断できるようにするため。会話の間ずっと覚えると、拒否を取り消す画面が要る。

子に渡さないと、子に PC の作業を任せられない。承認は委譲の承認と同じ経路で人に届くので、人が見ていない所で許可が増えることは無い。

Pleiad の窓を撮影から外すと、ユーザーの画面共有や録画からも Pleiad が消える。モデルに Pleiad が見えることの害は、操作を禁止していれば小さい。

## 影響

- `prefs.json` に `computerUse`、会話のデータに `computerApps` が増える。
- `permission` に `computerApp`、`resolvePermission` に `scope` が増える。
- Antigravity の会話では、禁止のアプリ以外は承認なしで操作される。
- スクリーンショットに Pleiad の窓が写りうる。
