# 0058 自分の発言を Markdown で描き、添付を本文の位置に置く

- 状態: 承認（2026-09-29）

## 状況

自分の発言は平文で描いていた（`web/render.mjs` の `plainTextHtml`）。送信すると本文の末尾に `[添付] パス` の行が付き、同じ添付が発言の後ろに大きなカード（`renderPresent`）として並ぶ。添付が増えるほど生の印と大きなカードが続き、どの説明がどの添付を指すのか分からない。入力欄も、添付は箱の上に並び、文中のどこを指すかは書けない。

2026-09-29 にユーザーが、入力欄の Markdown・文中添付と送信後の発言の表示の案（モックと提案の報告）を承認した。実装は 2 段階に分ける。段階 1（この ADR の実装）は送信後の自分の発言・添付の一覧の面・文書。段階 2 は入力欄を整形できる編集欄に替える。

## 決定

1. **自分の発言を Markdown で描く。** AI の本文と同じ描画（`renderMarkdown`。raw HTML は実行しない）にする。ファイルパスのリンク化など今の挙動は保つ。選択・コピー・「編集して再送信」・分岐は送った原文のまま（描画は原文を持ち、原文から作り直す）。
2. **添付の印は `[添付] パス`（`[Attachment] パス`）のままにし、送信時に本文の該当位置へ置く。** Markdown の画像記法（`![](…)`）にはしない。ローカルの Windows パスを Markdown の URL にする変換が要り、エージェントが読む印と履歴の突き合わせ（`attachmentMessageIndex`）を作り直すことになるため。
3. **送信後の添付は本文の位置に縮小で出す。** 発言の後ろの大きな添付カードはやめる。
   - 画像は縮小（最大幅 240px・高さ 144px。狭い画面は 220px 程度）と弱い字のファイル名。間に本文の無い画像は横に並べて折り返す。押すと今と同じ拡大。ほかのファイルは文中の札（押すと右のプレビューパネル）。
   - 置き換えるのは、その発言に実際に結び付いた human の present とパスが一致する印の行だけ。コードブロックの中の印・一致しないパスは消さない。同じ添付は 1 ファイル 1 か所（同じパスの印が続いたら、present の数だけ先頭から置く）。
   - 印が末尾にまとまっている古い形式の発言は、位置を推測せず、同じ部品で本文の後ろに並べる。結び付いた present に印が無いものも末尾に並べる。
   - 発言に結び付かなかった human の present と、AI の present・可視化は今のまま。
4. **発言の下に弱い字の行**: 添付があるときだけ「添付 N 件 ▾」（添付の一覧の面を開く）と「エージェントに渡した原文を見る」（送った本文をそのまま、`[添付]` の行を含めて等幅で見せる）。
5. **添付の一覧の面**: デスクトップは動線の近くに浮く面、700px 以下は下からのシート。名前・縮小・出どころと大きさ（分かるときだけ）・パス、送信後は「開く」「パスをコピー」。段階 2 の入力欄も同じ部品を使う（行の操作を差し替えられる形にする）。
6. **長い発言は畳む。** 約 8 行（見た目の行数の見積もり）と、その直前の段落に付いた添付のまとまりまでを見せ、段落・添付のまとまりの境目で「続きを表示」に畳む。畳まれる側が 3 行に満たないときは畳まない。

## 段階 2 で決めること

この ADR には含めず、段階 2 の着手時に決めて追記する（置換ではなく追記の ADR でよい）。

- 入力欄の編集欄（整形はその場で整える形を標準にする。エディターの選定・IME・Undo・貼り付け・モバイルの選択）。
- 下書きの保存形式（`version: 2`、構造化した document・安定した添付 ID・既存向けの平文 `text`）と、旧 `{text, attached}` の読み込み（添付は「文末に付く」）。
- 送信本文の組み立て（今は本文の末尾に印を付ける処理。文書を順に直列化して印を差し込む形に替える）と、全バックエンド・分岐・編集再送・待ち行列での整合。
- 送信中・失敗の添付の扱い（完了か外すまで送らない）。

## 理由

送信後の表示は、説明と添付が同じ場所にあってはじめて意味が通る。印を文中に置く形なら、エージェントが読む本文はそのままで、履歴の突き合わせも今の仕組み（パスの一致）で足りる。表示だけを変えるので、段階 1 は保存形式に触れず、既存の履歴もそのまま新しい見た目で読める。

## 影響

- 過去の発言も Markdown として描き直される（`# ` が見出しに、`-` が箇条書きになる）。原文は「エージェントに渡した原文を見る」と、選択・コピーで確認できる。
- 印が末尾にある今の送信の形でも、新しい描画はそのまま正しく出る（末尾に並ぶ）。
- `web/timeline.mjs` の `buildItems` は変えない。発言に結び付いた human の present は、画面の側（`web/client.mjs`）が発言に取り込んで別カードを出さない。
- 委譲の子の会話を読む面（読み取り専用の筋）の発言は、今までどおり平文と別カードのまま。
