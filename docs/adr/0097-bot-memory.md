# 0097 bot の記憶は 2 層・markdown 正本で自動に積み、出どころの検査をコードで行い、末尾に差分で渡す

- 状態: 提案

## 状況

bot が過去の指示・直し・判断の理由を覚えていないと、毎回同じことを言い直すことになる（思い出すために離れる）。先行事例の記憶は、勝手に事実を抜く・個別に見えず消せない・他人や Web の文がそのまま永続化される（プロンプト注入）ことで批判されている。キャッシュの面では、記憶を system に置いて変えるたびに、会話のキャッシュが切れる。

2026-10-03 にユーザーが決めた: 記憶は自動で積む（提案・承認の段は無い）。人は各行を直す・忘れる。記憶の材料は、その bot との対話だけでなく全ての Chats・チャンネル・他の bot との会話で、人の指示・直し・判断の理由を重く見る。記憶は毎ターン更新し、ターンの末尾に置く。

## 決定

- **2 層。** 「あなたについて」（全 bot 共通。全会話の人の発言から作る）と「この bot だけ」（役割に固有）。
- **正本は markdown。** `<データ置き場>/memory/user.md` と `memory/bots/<botId>.md`。1 行 1 件、本文は人が読めて直せる、メタ（id・出どころ）は行末の HTML コメントの JSON（読めない行は「出どころ不明」として読む）。変更の記録と墓石は `memory/log.jsonl`（`rev` を持つ）。索引は `memory/index.sqlite`（`node:sqlite` の FTS5 trigram。派生で、壊れたら md から作り直す。使えない版の Node では走査に切り替える）。
- **書くのは bot（`memory.write`）で、自動。** 出どころの検査は**コードで**する: 出どころに人の発言を 1 つ以上含む（チャンネルの人の投稿で外の文を含まないもの、または Chats の user の行で完了通知・代理の送信・proxy でないもの）。引用（`quote`）は**空白を除いて 8 字以上**で、実物の本文に含まれること（1 字の引用で人の投稿のどれにも当たる、という洗浄を断る）。**委譲の子・bot・ルーティンの会話の最初の user の行は人の発言に数えない**（親の AI・仕組みが書いた依頼で、AI の言葉を人の発言に洗えてしまうため）。出どころは、その bot の今のスレッド・会話に**限らない**（記憶は全ての会話から作る決定。範囲を狭めると人の指示を拾えなくなる）。AI の出力は、それを採用した人の発言を一緒に根拠に挙げたときだけ。webhook・Web の文だけを根拠にしたものは作らない（画面には出さない内部の規則）。忘れた記憶と同じ内容（指紋）は作り直さない。300 字まで。URL・コマンドらしい文・「前の指示を無視」型は断る。**bot が `user` 層（全 bot が読む層）へ書くのは 1 ターンに 5 件まで**（暴走・汚染の幅を抑える。超えたら断る）。
- **直す・忘れる・戻すは AI も使える。** `memory.edit` は write、`memory.forget` は消す操作なので guarded、`memory.unforget`（忘れた直後に戻す）は write（human-only は承認モード・秘密の値・アカウント・接続先の既定・リモートのペアリングの 5 つだけ。[ADR 0082](0082-control-surface-principals-and-risk.md)）。ただし**人が書いた行の本文を AI が書き換えるのは guarded**（承認カード）。人がしたか AI がしたかは、記憶の記録（`log.jsonl`）の `by` に残し、一覧に出す。書き手が替わる直しは**元の書き手も `origBy` に残す**（`by` は今の本文を書いた者なので、AI が書き換えた行は人の行として扱わない）。忘れたら墓石を残し、元に戻すは取り消しとして（戻した主体を）記録する。画面は各行に本文・出どころ・［直す］［忘れる］を出す。
- **核の写しは、人が書いた・直した記憶を先に**（`by.kind === 'human'`。層ごとの目安の中で、bot・AI が書いたものを後に。それぞれ新しい更新から）入れる。書き込みを重ねる bot が、新しさで人の古い記憶を押し出さないため。
- **キャッシュの並び。** ツール → 人格（決定的な文。時刻や件数を入れない）→ 核の写し（会話の始まりと圧縮の完了後の最初のターンに 1 回）→ 追記だけの履歴 → **今のターンの末尾**（時刻・記憶の差分・関係する記憶の検索結果）→ 発言。末尾は新しいターンごとに既存の `notes` の口へ入れ、`<pleiad-memory-core>` / `<pleiad-turn-context>` で囲む。履歴の読み出しでは先頭の包みをシステム側の行に分ける（[ADR 0053](0053-system-messages-display.md)）。差分は 20 件まで、超えたら件数と `memory.search` で引けることだけ。途中送信の道では末尾を付けず、差分は次の新しいターンで渡す。
- **夜の整理（P3）は同じ検査を通して自動で書く。** 前回からの新しい人の発言だけを読む。

## 理由

- 末尾に足すだけなら前の方を書き換えないので、キャッシュは毎ターン当たる。核の全文を毎ターン付けると文脈が膨らむので、全文の写しは始まりと圧縮のときだけにする。
- 人が承認する段を無くしても、出どころ（誰の発言か）をコードで見れば、AI の独り言・外の文の永続化は防げる。承認の代わりの安全弁は、見える出どころと人だけの消去。
- 正本が markdown なら、人が読めて書き出せ、索引が壊れても戻せる。

## 影響

- 記憶に載る本文は人の発言の引用を含むので、`<データ置き場>` の秘密と同じ扱い（バックアップ・書き出しに注意）。
- 自動で積むので、誤って覚えた分は人（または承認を通した AI）が見つけて忘れるまで残る。出どころを必ず見せる。AI が直す・消す操作の関所は、記憶の汚染の対策を human-only ではなく guarded の承認と記録で受ける。
- `node:sqlite` が無い版の Node では索引を走査で代える（数百〜数千件なら足りる）。
- 出どころの検査は `memory.write` を通る書き込みにだけ効く。データ置き場の `memory/*.md` をファイルとして直接書ける bot（全部自動のモード）が書いた行は、`sync` が「人の変更」として記録する（`by: human`・出どころなし）。全部自動の bot は何でもできるので防げないが、検査の外であることを承知しておく。
- `memory.unforget` を AI にも出す（全機能は AI も使える決定）ので、人が忘れさせた記憶を AI が戻せる。戻した主体は `log.jsonl` の `by` に残り、画面に出る。忘れた直後だけ戻せる（最後の操作が forget のもの）。
