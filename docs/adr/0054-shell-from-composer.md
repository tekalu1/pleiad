# 0054 入力欄の `!` でホストのシェルを走らせる

- 状態: 提案

## 状況

Claude Code・Codex の CLI には、入力欄の先頭で `!` を打つとシェルのコマンドを走らせ、結果を会話に積む操作がある。Pleiad の入力欄にはこれが無く、`! git status` を送るとただの文としてエージェントに届いていた（Claude の SDK には、本文の `!` をシェルのモードとして扱う経路が無い）。

- 履歴に残った CLI の `!` の行は [ADR 0053](0053-system-messages-display.md) で「あなた」の 1 行（`シェル  ! コマンド`）として出すようにした。入力欄で打つ形は別に決めることにしていた。
- 走らせる口はバックエンドで違う。Claude の SDK には利用者のシェルを走らせる要求が無く、代わりに `SDKUserMessage.shouldQuery: false`（返答を起こさずに transcript へ積み、次に query する user 行と合わせる）がある。Claude Code Desktop の bash モードもこの形を使う（`sdk.d.ts` の `resumeSessionAt` の説明）。Codex の app-server には `thread/shellCommand { threadId, command, timeoutMs }` がある（codex-cli 0.156.1 の `generate-json-schema` で確認。サンドボックスの外・全権限で走り、結果は `source: userShell` の `commandExecution` として流れる）。Antigravity（agy）には渡す口が無い。
- ペア済みの遠隔の端末は、いまもホストの全部を操作できる（[ADR 0013](0013-remote-via-relay-with-noise.md)「端末は当面全権限」）。YOLO に切り替えてエージェントに頼めば、同じことがいまもできる。
- 送信は、送信待ち（outbox）と送り直しの控え（receipts）で、つながり直したときに自動で送り直される。コマンドは冪等とは限らない。

2026-09-28 にユーザーが入力欄の案 A「シェルの行」を承認した。

## 決定

- **入力欄**: 空の欄の先頭で `!` を**打った**ときだけ、欄がシェルの形になる（`!` は欄に残さず、箱の頭に「シェル · 作業ディレクトリ」。字は等幅、送信は ▶「実行」）。貼り付け・下書きの復元では入らない。「入力欄に写す」は、空の欄ならシェルの形でコマンドを入れる（走らせない）。空の欄で Backspace を押すと元の欄に戻る。Enter は改行、Ctrl+Enter で実行（送信と同じ）。頭の行に「文として送る」を置き、押すと `!` 付きの文としてふつうに送る。形は `docs/design-system.md`「入力欄のシェルの形」。
- **ホストで走らせる**: 走るのは、画面を開いている端末ではなく Pleiad のホストの PC。会話の作業ディレクトリで走らせ、標準入力は渡さず、上限は 10 分。遠隔の端末の画面では、頭の行にホスト名を出して、どこで走るかを打つ前に見せる。
- **遠隔の端末**: 使える。できることは今の遠隔（全権限。ADR 0013）と変わらない。変わるのは 1 手で・承認を通らずに走ることなので、ホスト名を見せる。端末ごとに禁じる設定は入れない（ADR 0013 の「端末ごとの権限は当面入れない」）。
- **承認モードを掛けない**: 人が自分で打つ操作であって、AI に任せる範囲ではないため。`plan` の会話でも走る。
- **送り直さない**: シェルのコマンドは送信待ちにも送り直しの控えにも積まない。サーバーは同じ `runId` を 2 度走らせない。つながっていなければ ▶ は押せない。つながりしだい自動で走らせることはしない。
- **エージェントは返答しない**: 結果は会話にすぐ行として積み（走っている間は「実行中 · 経過」「止める」、出力は流しながら）、エージェントには**次の人の発言と一緒に**渡す。見出しは渡す前が「あなた · 次の発言で {agent} に渡す」、渡した後が「{agent} に渡した」。完了通知で再開するターン・圧縮では渡さない。走っているターンへの途中送信でも渡さない（次のターンの始めに渡す）。
- **バックエンドごと**（`capabilities.shell`）:
  - Claude（`'host'`）: Pleiad がホストのシェル（Windows は Git Bash、無ければ PowerShell。ほかは `$SHELL`）で走らせ、結果を会話の「未送の追記」（sessions.json の `shellPending`）に貯める。次のターンの始めに、CLI の `!` と同じ `<bash-input>…</bash-input>` と `<bash-stdout>…</bash-stdout><bash-stderr>…</bash-stderr>` の 2 行を `shouldQuery: false` の user 行として、発言の前に渡す。記録の形が CLI と同じなので、履歴は ADR 0053 の見分けがそのまま `kind: 'shell'` にする。終了コードは記録に入らないので、渡したときに sessions.json の `shellExits`（出力の鍵 → 終了コード）に控え、開き直した履歴に付ける。
  - Codex（`'native'`）: `thread/shellCommand` で app-server に走らせる（`timeoutMs` は 10 分）。記録は Codex の会話に残る。`source: userShell` の item はエージェントのツールのカードにせず、履歴でも `kind: 'shell'`（終了コードつき）にする。スレッドができる前（最初の発言の前）は走らせられない。
  - Antigravity と、シェルを持たないバックエンド: 使えない。`!` を打つと欄に `!` を残したまま「この会話ではシェルを実行できません」を出して送信を止める（黙って文として送らない）。「文として送る」は使える。
  - fake: Claude と同じくホストで走らせる（テストと画面の確認のため）。
- **後始末**: 止める（「止める」）・エージェントの切り替え（予約した設定の適用も）・未送信の会話の削除・サーバーの終わりで、走っている子のプロセスを木ごと止める。エージェントを切り替えたら、渡していない追記は、替えた先もホストで走らせる形なら次のターンで渡し、そうでなければ捨てる。次の送信でエージェントが替わる予約がある会話では、渡す先で使えるかを決める。

## 理由

- `!` を打つ目的はほとんどが「その場で結果を見る」こと。走らせたことは取り消せないので、会話にすぐ残すほうが正直。
- 渡し方（次の発言と一緒）は、Claude の SDK が用意している `shouldQuery: false` そのままで、Codex の `thread/shellCommand` とも合う。見るためだけの `!` でトークンを使わない。
- 送り直しの仕組みに乗せると、同じコマンドが 2 回走りうる。承認カードと同じく、つながり直しで自動で繰り返さない。
- 承認モードは「AI がどこまで任されるか」の軸で、人の操作には掛けない。遠隔で増える危うさは「どこで走るか」が見えないことなので、ホスト名で見せる。
- 使えない会話で黙って文として送ると、CLI から来た人の意図（走らせる）と違うことが起きる。

## 影響

- WebSocket のコマンドに `runShell { sessionId, runId, command, cwd? }`・`stopShell { runId }`、出来事に `shell.start`・`shell.output`・`shell.done`・`shell.handed` が加わる（全部の接続へ流す）。`loadSession` の発言の末尾に、まだ渡していない行と走っている行が `kind: 'shell'` で入る。
- `AgentBackend` に `capabilities.shell`（`'host'` | `'native'`）と、`'native'` の `shell({ sessionId, command, cwd, timeoutMs, signal, onOutput })` が加わる。`runTurn` は `shellAppends`（渡す行の本文）を受け取る。
- 出力（秘密を含みうる）は、次の発言でエージェント（＝LLM の提供元）に渡り、transcript にも残る。CLI の `!` と同じ性質なので、画面には書かず docs に書く。
- 未確認: Claude の `shouldQuery: false` の行が transcript で CLI と同じ別々の user 行として残るか（SDK の説明は「bare user entries」）。Codex の `thread/shellCommand` を止める口（`turn/interrupt` で止まるか）と、ターンが走っている間に打ったときの動き。
