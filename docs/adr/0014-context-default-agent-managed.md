# 0014 コンテキストは既定でエージェント任せ、種類ごとに Pleiad がそろえるを選べる

- 状態: 承認（2026-09-20）

## 状況

指示ファイル（CLAUDE.md・AGENTS.md）・Skills・外部 MCP は、エージェントごとに置き場も読み方も違う。Pleiad が共通にそろえて渡せば、バックエンドを替えても同じ文脈で続けられる。ただしそのためには、エージェント自身の読み込み（ネイティブの読み込み）を止める必要がある。
2026-09-12 の実機の確認（Windows、Agent SDK 0.3.258、Codex CLI 0.153.2）では、止め方が部分的にしか確かめられなかった: Claude は設定を保つと Skill の一覧が残り、祖先の CLAUDE.md も読む。Codex はフォルダーを指定しても Skill が無効にならず、`SKILL.md` まで指定すれば無効になった。
2026-09-15 の設定の画面はツリーとプレビューの 2 列で、「読み込み担当」「探索の設定」、範囲ごとの保存ボタンがあった。

## 決定

- 種類ごと（指示・Skills・外部 MCP）に「エージェントに任せる」か「Pleiad がそろえる」を選ぶ。**既定はエージェント任せ。**
- 1 つの種類の担当は、その場所の home 側と作業場所側に共通にする（片方だけ Pleiad にすると二重に読まれる）。
- 抑止を確かめていない組み合わせでは、Pleiad がそろえるを有効にしない。
- 設定は種類ごとに「すべての場所（既定）」と場所ごとの上書きで持つ。エージェント側の設定ファイルは書き換えない。
- 画面は承認済みの 1 画面（2026-09-20）: 範囲を選び、種類のカードで担当・探す形式・渡すもの（スイッチ）を決め、変更はその場で保存する。ツリー・「読み込み担当」「探索の設定」・保存ボタンは廃止。会話の右パネルに「この会話のコンテキスト」。
- 設定の変更は次のターンから効く（2026-09-23 から、始まっている会話にも）。

## 理由

- 利用者の問いは「どこに何があるか」ではなく「次の会話に何を渡すか」と「この会話に何が渡ったか」。前者は設定、後者は会話の側に置く。
- ネイティブの読み込みを確実に止められない以上、既定で Pleiad がそろえると二重読み込みや漏れが起きる。

## 影響

- 仕様は context-management.md・context-runtime.md、画面は design-system.md §9「コンテキスト」。
- 抑止の確認は、バックエンドの版が上がるたびにやり直す（公式の説明と手元の版の振る舞いが違うことがある）。手順は `node tests/manual/context-probe.mjs`。
