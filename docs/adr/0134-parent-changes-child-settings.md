# 0134 依頼元の AI が、委譲した子のエージェント・モデル・思考の強さを後から替える

- 状態: 提案

## 状況

`ply_delegate` で子の委譲先（`backend`・`model`・`effort`）を決めた後、依頼元の AI がそれを替える口が無かった。子が力不足・使用枠が苦しい・思考の強さが足りないと分かっても、依頼元は止めて委譲し直すしかなく、子の会話の履歴と作業場所を捨てることになった。人は入力欄の「次のターンから適用」（`sessions.setTurnSettings`）と `sessions.setModel` で同じ会話のまま替えられる。ユーザーの依頼（2026-10-04）:「親から子のモデルを後から変更できるようにしてほしい（バックエンドやエフォート含め）」。

## 決定

- **道具は増やさず、`ply_task_send` に省略できる `backend`・`model`・`effort` を足す。** どれかを書けば、`message` を省いて設定だけ替えられる。`message` も書けば、替えてからその指示を積む。子の予約がある間は、走っている子のターンへ指示を途中送信しない（`canSteerNotice`）ので、一緒に積んだ指示は替えた後のターンで読まれる。理由: ply_agents の道具は毎ターン渡るので、道具を 1 本足すより引数 3 つの方が文が短い。権限（自分が委譲した子だけ・読み取り／計画モードの会話からは呼べない）も `ply_task_send` のものをそのまま使える。
- **効く時点。** 子の会話の予約（`nextSettings`。人の「次のターンから適用」と同じ）に入れ、子の次のターンから効く。子が走っていても今のターンは止めない。走っていなければ、次に走るとき（設定だけでは子を走らせない。完了した子もそのまま。例外: 使用枠の上限で止まっている子のエージェントを替えると、人の切り替えと同じく上限の待ちが解け、子の送信待ちが流れる）。同じエージェントのモデルだけは、`sessions.setModel` と同じく走っているターンにも即時に伝える（できるエージェントだけ。返り値の `settings.modelLive`）。
- **エージェントを替えるとき**は、既存の切り替え（`docs/backend-handoff.md`）を通り、子の次のターンで会話の履歴を引き継ぐ。作業場所（cwd・分けた作業場所）はそのまま。
- **子の承認の強さは、委譲のときと同じく親を超えない。** 切り替え先の承認モードは `resolveDelegatedMode` で、親の強さと子の今の強さ（人が下げていればそれ）の弱い方を上限に、収まるもののうち最も強いものに決める。元のエージェントへ戻したときは子の会話の今のモードのまま。収まるものが無い（例: Antigravity は全部自動）なら、`ply_delegate` と同じく親の会話で 1 回だけ承認カードを出し、断ったら何も変えない。Codex の親が `full`／`yolo` 以外なら、これまでどおり `ply_task_send` のたびに聞く。
- **アカウントは替えない。** AI はアカウントを選べない（[ADR 0094](0094-human-only-five.md)）。Claude へ替えるときは子の会話が持っているアカウント（委譲のとき親の会話から継いだもの、自動の振り分けなら選ばれたもの）のまま走る。振り分けの使用枠でアカウントを選び直すと、AI の一言で人のアカウントの使い方が変わるため。接続先は `ply_delegate` と同じ規則（自動・人が選んだ委譲先なら公式、固定なら親の会話から継ぎ、違うエージェントなら公式）。
- **断るとき（何も変えない）。** 子の作業場所のモデルの一覧に無いモデルは `model_unknown`（選べるものを添える）、そのモデルで選べない思考の強さ（`effort_unknown`）、使用量の取り置きで使用枠が満杯と分かっているもの（`quota_full`。取り置きが無い・古いだけでは断らない。固定の `ply_delegate` も使用量では断らないため）、自分が委譲していないタスク、止めている途中のタスク、子のターンが始まるところ、一緒に積む `message` が空白だけ・長すぎるとき、承認カードを待つ間に子の設定やタスクの状態が変わったとき。断る理由はすべて書く前に確かめ、書いた後の失敗（記録の保存・指示の受け付け）では書いた分を前に戻す。
- **記録。** 子の会話の変更の記録に `backend`・`model`・`effort` を by: `agent`・via・bySession（依頼元の会話）で残す（理由「依頼元の AI が変更」）。タスクの記録は `backend`・`model`・`effort`（替えたなら `mode`）を新しい値にし、`routing.target` を新しい委譲先に、`routing.changed`（`{ by: 'parent', at, from, count }`。`from` は最初の委譲先）を足す（今と同じ値なら何も書かず、最初の委譲先へ戻したら印を外す）。子のターンが始まるときは、タスクの記録を子が実際に走る値に合わせる（人が子の予約を取り消した・替えたとき）。委譲カードは新しい委譲先のロゴと「依頼元が変更（元: …）」を出す。画面へは `agentTaskChanged { taskId }` で知らせる。

## 理由

止めて委譲し直すと、子が読んだもの・書いたもの・会話の履歴を捨てる。人の画面にはすでに「同じ会話のまま次のターンから替える」道があり、依頼元の AI に同じ道を開けば、子の続きを活かしたまま委譲先を直せる（人と AI は同じことができる。[ADR 0007](0007-symmetric-ai-and-human.md)）。承認の強さとアカウントは、委譲の入口で守っている規則をそのまま当てる。後から替える道が規則の抜け道にならないため。

## 影響

- `ply_task_send` の入力に `backend`・`model`・`effort` が増え、`message` が省略できるようになる（操作 `delegation.taskSend` も同じ）。`ply_task_status` の `backend`・`model`・`effort` は子の次のターンからの値になる（走っている回は前の値のまま走りうる）。
- 子の会話の変更の記録に `backend`・`effort` の行が出る（画面の「変更の記録」も出す）。
- 自動で選んだ委譲の `routing` は、替えた後は新しい委譲先を指す。選んだ理由（難しさ・飛ばした候補）は最初の委譲のときのもので、`routing.changed.from` が最初の委譲先を持つ。
