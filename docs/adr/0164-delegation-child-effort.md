# 0164 委譲の子の思考の強さは、段・候補ごとに決める

- 状態: 承認（2026-10-08）
- 関連: [0022](0022-delegation-routing.md)（委譲先の自動振り分け）、[0134](0134-parent-changes-child-settings.md)（依頼元が子の設定を替える）、[0163](0163-delegated-child-compaction-threshold.md)（子の自動圧縮）

## 状況

自動の振り分けは子の `backend` と `model` を決めるが、思考の強さ（effort）は決めていない。子の強さは `resolveEffort` が会話の既定（設定 › エージェント設定の強さ。Claude は high）を継ぐので、簡単な子（段 1・2 の Sonnet など）まで high で動き、Claude の使用量が増えている。画面のどこにも「子が何の強さで走るか」は出ない。

強さの語彙はモデルごとに違う（Claude は low〜max で Sonnet に xhigh が無い、Codex は low〜xhigh、Haiku は持たない、Antigravity は強さが `-high` のようなモデル名に入る）。

## 決定

**強さは「段 × 候補」で決め、設定 › 委譲の段ごとの候補に置く。** 画面の形はモックの案 A（承認済み 2026-10-08）: 段の見出しの右に「段の既定」、候補の行の右に「思考 medium · 段の既定」。

- **保存の形**: `delegationRouting.efforts = { <段>: { "*": <段の既定>, "<backend:model>": <その候補だけの上書き> } }`。`tiers` は今のまま文字列の列（強さを埋め込まない。前の版が候補を不正と見て段ごと既定に戻すのを避ける）。値は `low` `medium` `high` `xhigh` `max`、`""` は会話の既定に従う。キーが無ければ組み込みの段の既定。候補の id で結ぶので、並べ替えでも別の候補に付かない。段から外した候補の上書きは読むときに持ち越さず、保存のときも捨てる。
- **既定**: 段 1 = low・段 2 = medium・段 3 = medium・段 4 = high・創作（tv）= 会話の既定。既存の利用者にも告知なしで効かせる（使用量を減らすための変更）。
- **決まり方**（子を作るとき。`core/delegation-routing.mjs` の `decideEffort`）: 候補の上書き → 段の既定 → そのモデルが持つ強さに合わせる。持たない強さは、いちばん近い下の強さに合わせる（xhigh → high。下が無ければ持つ中でいちばん弱いもの）。強さを持たないモデル（Haiku など）と、強さがモデル名に入るモデル（Antigravity の `gemini-3.8-flash-high`。強さはモデル名の段違いで決まり、`--effort` は渡さない）には送らない。**振り分けでは断らない**（固定の委譲の `effort` は今までどおり、持たない値を断る）。モデルが持つ強さは既存のコード（`effortOptions`・各 backend のモデル一覧の `efforts`）から取る（`core/effort.mjs` の `effortCapability`）。
- **検証**: 保存では形だけを見る（段・語彙・候補の id の書式）。モデルが持つかは、モデルの一覧が作業場所・ログインで変わるので、走らせるときに確かめて合わせる。
- **記録**: ply_delegate の返り値・タスクの `routing` に `target.effort`（実際に走る強さ。送らないときは null）と由来 `effortSource`（`override`・`tier`・`conversation`・`model`・`none`、依頼元が替えたら `parent`）、段の既定・上書きなら `effortTier`、モデルに合わせたら元の強さ `effortAsked` を足す。人が選び直した（やり直し）子は、その候補が入っている段（元の段にあればそれ）の値で走る。委譲カードの内訳に「思考の強さ: medium · 段 3 の既定」を出し、使った候補の行の右にも同じ値を出す。
- 委譲の数・深さの上限は外したまま（触らない）。

## 理由

使用量の主因は、簡単な子が会話の既定の強さのまま走ること。強さは仕事の重さ＝段に比例させたいので、段で決める。同じ候補が複数の段に並ぶ（Sonnet は段 2 と 3）ので候補だけでは段ごとに変えられず、Codex の medium と Claude の medium は同じ重さではないので段だけでも足りない。段の既定 + 候補の上書きにして、上書きを使わなければ段だけの形と同じ見た目になる。

保存は別の項目 `efforts` にした。`tiers` の要素をオブジェクトにする案・文字列に `@high` を付ける案は、前の版が不正な候補として段ごと既定に戻す・モデルを見つけられず黙って飛ばすので危険。別の prefs にする案は設定の取得・保存・「既定に戻す」・`settings.set` が 2 系統になる。

## 影響

- 前の版の設定画面から保存すると、新しい版が書いた `efforts` を `unknownKey` で断られる（ダウングレードしたときだけ。読むときは無視して動く）。許容する。
- 簡単な段の Sonnet・Codex の子は low / medium で動くので、出来栄えが変わりうる。気になる人は段の既定か候補の上書きを「会話の既定に従う」にする。
- `delegationRouting` の返り値に、候補ごとの強さの持ち方 `candidates[].effort`（`{ levels, fixed }`）と、エージェントごとの会話の既定 `conversationEfforts` が増える。
- 強さの語彙と合わせ方は画面と共有する（`web/delegation-effort.mjs`）。画面が見せる強さと子が走る強さが同じ答えになることをテストで見る。
