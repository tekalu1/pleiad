# 0072 computer use のロック・待ち・止める

- 状態: 提案

## 状況

PC のマウスとキーボードは 1 組しか無い。2 つの会話が同時に操作すると、片方の文字がもう片方のアプリに入る。委譲の子にも computer use を渡すので（[ADR 0071](0071-computer-use-approval-and-safety.md)）、親子でも奪い合いが起きる。

人は操作をいつでも止められなければならない。止めた後に、押したままのキーやボタンが残ってはいけない。

## 決定

- **同時に操作できるのは PC 全体で 1 つのターン。** 委譲の子も含めて 1 つのロックを使う。ロックは最初の撮影か入力で取り、ターンの終わり（成功・失敗・中断）で放す。承認の問い合わせ・許可の一覧・`wait`・カーソルの位置では取らない。
- 2 つ目は失敗させずに、ツールの呼び出しの中で順番に待たせる。待つ間は会話の行に「別の会話（{タイトル}）が操作中です。終わったら続けます」と出す。**10 分**で打ち切り、「別の会話が操作中のため使えません」を返す。待つ側のターンを中断したら列から抜ける。
- **持ち主の子孫には貸す。** 持ち主のターンの子孫の会話が取りに来たら、待たせずに貸す。貸している間は持ち主の呼び出しが待つ。子のターンが終われば返す。親が子の完了を待つ間に、親子で待ち合って止まらないようにするため。
- **止める**: 物理の Esc（オーバーレイが出ている間だけ握る）と、会話の「止める」。止めたターンには印を付け、以後の computer use の呼び出しをすぐ失敗にして「ユーザーが止めた。このターンでは呼ばず、最終の返答で伝えて」と返す。ターン自体は中断しない。Esc は貸し借りでつながるターン全部を止める。
- Pleiad が自分で送る Esc では止まらないように、送る前に Esc の登録を外し、送った後に戻す。
- ロック画面・UAC の安全なデスクトップでは操作しない。失敗を返すが止めた印は付けないので、解除されれば同じターンで続けられる。
- 押したキーとボタンは main が覚え、止める・ターンの終わり・持ち主の変更・core の終了・アプリの終了・core からの便りが 30 秒途絶えたとき（持ち主がいる間、core は 10 秒ごとに便りを送る）に必ず離す。
- 待つ・止める・ロック画面・禁止・拒否は、会話の表示で失敗に数えない（理由を最後の行に書く）。

## 理由

ターンで持てば、人が依頼した 1 回の仕事の間は他に割り込まれず、終われば必ず放される。待たせるのは、失敗させるとエージェントが諦めるか、無駄に撮り直すから。10 分は、短い操作の仕事が終わるのを待つには足り、固まったターンに引きずられ続けない長さ。

貸し借りが無いと、親がロックを持ったまま子を待ち、子はロックを待って 10 分で失敗する。

止めてもターンを続けるのは、エージェントが止められたことを返答で伝え、ほかの作業（シェル・ファイル）を続けられるようにするため。ターンごと止めたいときは入力欄の「中断」がある。

## 影響

- 待つ呼び出しは最長 10 分かかる。各エージェントの MCP の上限時間をそれより長くする。上限を延ばせないエージェントでは、待ちを分けて「まだ待っています。もう一度呼んでください」を返す（実測しだい。`docs/computer-use.md`）。
- 新しいイベント `computer.state`（`idle` / `running` / `waiting`）と、コマンド `computerStop` が増える。リモートの端末からも止められる。
- 子がロックを待つ間は、委譲の沈黙の通知に数えない。
