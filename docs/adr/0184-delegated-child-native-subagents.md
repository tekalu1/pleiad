# 0184 委譲した子の会話のネイティブのサブエージェントを、バックグラウンドの一覧に子の下の枝として出す

- 状態: 提案（番号は仮。採番し直す）
- 日付: 2026-10-10
- 関連: [ADR 0025](0025-persistent-background-entry-and-task-titles.md)（バックグラウンドの入口と題）、[ADR 0139](0139-thread-subagents.md)（スレッドのサブエージェント）、[ADR 0146](0146-remote-agent-delegation.md)（ホストへの委譲。ホストの孫は別の経路）

## 状況

バックグラウンドの一覧は、今の会話のネイティブのサブエージェントと、`ply_delegate` で作った子（Pleiad タスク）の木を並べる。委譲した子の会話が、さらにネイティブのサブエージェント（孫）を呼んでも、一覧のどこにも出なかった。ネイティブの行は「今の会話」だけに絞られ、深さも親も持たず、木は Pleiad タスクの `taskTree` だけから作られていたため。終わった孫は、今の会話のツール id からしか引き直していなかった。

## 決定

1. **孫は子の行の下に出す**。子（木の中の非ホストのタスク）の会話 `task.sessionId` を `sessionId` に持つネイティブのサブエージェントを、深さ = 子の深さ + 1・`parentSessionId` = 子の会話・`rootLive` = 根の `rootLive` の行にする。字下げ・鉤形の線・「· 委譲 N」（子の `childCount` に数える）・最上位の親の状態での区分・`visibleRows`・`groupByOwner`（Channels のスレッドも同じ）は既存の仕組みにそのまま乗る。今の会話の深さ 0 のネイティブは変えない。
2. **走っている孫は配信、終わった孫は 1 回の読み出し**。走っている分は `state.work.subagents`（全ターンの配信）にある。終わった子は配信から外れるので、子の会話ごとに `sessions.subagents { sessionId, limit: 100 }` を 1 回だけ呼ぶ。履歴のメッセージは読まず、サーバーが `listSubagents`・origin・状態・見出し（最初の発言の最初の行）だけを返す。読み直すのは子の `updatedAt` が変わったときと、走っていそうな孫が残っているときだけ。一覧を開いていない間は直近 1 日に更新された子だけ。同時に 4 つまで。失敗は 30 秒空けてやり直す。人（UI）が `sessions.subagents` を `sessionId` だけで呼べるようにした（`toolId` があれば従来の `findSubagent`）。
3. **孫を選ぶと孫の会話が出る**。`subagentThread` は行の `parentId`（= 子の会話）と `agentId` で `loadSubagent` を引くので、そのまま働く。
4. **数は二重に数えない**。行の key は `a:<会話>:<agentId>`。配信と読み出しは同じ呼び出し（origin）・同じ agentId を 1 本にまとめる（配信を取る）。ヘッダー・チップの数は行の数なので、孫は 1 本につき 1 回。ホストへ委譲した子（`task.host`）は孫をホストの読み出し（`hostTreeRows`）から出すので、ネイティブの孫は足さない。
5. **題は途中で替えない**。走っている間に見た題（委譲ツールの description）を、終わって読み出した行にも使う。読み込み直したあとは、見出し（最初の発言の最初の行）になる。

## 理由

- 子の会話のネイティブのサブエージェントは、依頼元から見れば自分の仕事の一部で、止まっていないか・何を調べているかを見たい。
- 終わった孫のために子の履歴全体を読むと、委譲の数だけ重くなる。サブエージェントの一覧だけなら、子の会話につき 1 回の軽い読みで済み、更新がなければ読み直さない。
- 既存の木・表示・数え方に乗せると、字下げ・区分・Channels の絞り込みを別に作らずに済む。

## 影響

- `sessions.subagents` の返事の各行に `description` が付く（読めなければ `null`）。
- 古い版のサーバーは `sessionId` だけの呼び出しを断る。画面は失敗として扱い、終わった孫は出ない（走っている孫は配信から出る）。
