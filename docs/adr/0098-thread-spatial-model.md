# 0098 スレッドはメインの列に開き、チャンネル・スレッド・右パネルの 3 枚を 2 枚分の窓で見る

- 状態: 提案

## 状況

スレッドの実体は bot の作業の会話で、Chats の会話と同じ道具（可視化のインライン・ファイルのプレビュー・目次・git・内蔵ブラウザー）で見たい。最初の案はスレッドを右パネルに開くものだったが、右パネルはその道具のための場所で、スレッドを入れると同じ道具が場所で違う出方をする。

2026-10-03 に、ユーザーが次を承認した（Chats は今のまま［会話｜道具］の 2 枚で、右パネルを閉じれば会話が全幅）。

## 決定

- **スレッドは右パネルではなくメインの列に開く。** 横に並んだ 3 枚［チャンネルの流れ（4）｜スレッド（6）｜右パネルの道具（4）］を 2 枚分の窓で見る。
  - 右パネルが閉じている → ［チャンネル｜スレッド］。
  - 右パネルを開く → 窓が右へ滑って［スレッド｜道具］（チャンネルは左へ抜ける）。閉じると［チャンネル｜スレッド］へ戻る。
  - スレッドを閉じる（✕）→ チャンネルが全幅に戻る。
  - メインの幅が約 900px 未満のときはチャンネルを出さず、スレッドだけ全幅で出す。360 幅は全画面のまま。760px 以下の右パネルは、Chats と同じ出方（今の全画面の面）で、スレッド用に別の形を作らない。
- **動き。** 読んでいるスレッドを 1 枚の板として `transform` で滑らせるだけ（約 200ms）。スクロール位置・入力中の下書き・入力欄の位置を保つ（中身を作り直さない）。チャンネルは左から差し込む。`prefers-reduced-motion` では動かさずに切り替える。
- **チャンネル側でほかのスレッドを押したとき。** 板は動かさず中身だけを入れ替える。今開いているスレッドのカードを選択中にし、左に、ほかのスレッドで bot が返したこと（未読・状態）が見える。
- **入力欄は左右に 2 つ。** チャンネル側は新しいスレッド用で、押すまで 1 行に畳む。フォーカスは常にスレッド側。
- **見出し。** 左にチャンネルが見えている間は「› スレッド名」だけ。スレッドだけのとき（右パネルを開いている・狭い幅）は「# チャンネル名 › スレッド名」で、チャンネル名を押すと流れに戻る。見出しの入口（目次・コンテキスト・git・ブラウザー）は Chats と同じ。
- **スレッドの中身。** 根の投稿 → 返信。bot のターンの投稿は進捗の本文を同じ投稿で置き換え、下に［会話を開く →］と、作業中は［止める］とこのスレッドのトークンの帯。承認はスレッドの中に Chats と同じカードで出し、どちらで押しても同じ。可視化はスレッドの中にインライン、ファイル・HTML・ブラウザーは右パネル。
- **モーダルは一時的に見るだけのもの**（画像の拡大・可視化を広げる）に限る。

## 理由

- 同じ道具が場所で違う出方をしないほうが、認知負荷が低い。見ながら作業できる。
- 窓を滑らせる形なら、3 枚の関係（チャンネルは見渡す場、スレッドは作業、右パネルは道具）が空間で分かり、右パネルを開閉してもスレッドの位置が変わらない。
- 狭い幅でチャンネルを畳むのは、幅が足りないのにスレッドを細くしないため。
- 採らなかった案: スレッドを右パネルに開く（道具と取り合う）、スレッドをモーダルにする（見ながら作業できない）、右パネルを開いたらスレッドを下へ重ねる。

## 影響

- `docs/design-system.md` に「スレッドの空間モデル」を書く（`.deck[data-deck=feed|split|solo]`）。
- 右パネルの作業場所の基準（`getContext`）は、そのスレッドの bot の会話の作業場所にする。
- Chats の画面は変えない。
