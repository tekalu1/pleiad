# 0021 サブエージェント・Pleiad タスク・裏のコマンドを 1 つの入口にまとめる

- 状態: 置換（0025）

## 状況

裏で動くものの入口が 3 つに分かれていた: 会話の末尾の「サブエージェント N / タスク N / 裏で動いている N」、ヘッダーの「Pleiad タスク」、ヘッダーの「端末」。どれも同じダイアログを別の中身で開いていた。
利用者にとって、ネイティブのサブエージェント（Claude の Agent・Codex の子スレッド）と `ply_delegate` で委譲した Pleiad タスクの違いは意味が無い。終わった子は一覧から外れ、後から開く道が無かった。

## 決定

- 入口は会話の末尾の「**バックグラウンド N**」1 つ。N は動いている本数の合計。ヘッダーの「Pleiad タスク」「端末」は廃止する。
- ネイティブのサブエージェントと Pleiad タスクは、どちらも「**サブエージェント**」と呼ぶ。見分けはエージェントのロゴとモデル名で付ける。
- ダイアログの詳細は、メインパネルと同じ部品（筋・節・ツールカード・考えた内容など）で描く。委譲した子が承認を待っていれば、その場で答えられる。
- 終わった子は、会話の中の委譲のツールカードの「開く」から開く。サーバーは子を生んだツールの id を配り、終わった子は `findSubagent`（ツールの id → 子）で引き直す。
- main の返答が終わっても裏で動いているものがあれば、末尾の行を残す。

## 理由

- 入口が 1 つなら、裏で何が動いているかを探さずに済む（design.md §2.1「思い出すために離れる」を無くす）。
- 仕組みの違い（ネイティブか Pleiad か）ではなく、利用者が判断に使うもの（どのエージェント・どのモデル・状態）で見分ける。
- 同じ部品で描くと、子の会話も普段の会話と同じ読み方ができる。

## 影響

- 画面の規則は design-system.md「バックグラウンド」、設計は design.md「バックグラウンドの統合」。
- ヘッダーに件数を出す場所が無くなる。動いている間は末尾の行が常に見える。
