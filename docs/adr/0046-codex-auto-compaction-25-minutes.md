# 0046 Codex の自動圧縮の既定の待ち時間を 25 分にする

- 状態: 承認（2026-09-27）
- 置き換えた: 0039（Codex の自動圧縮の既定の待ち時間）

## 状況

0039 は、Claude のキャッシュが約 1 時間残ることを前提に、自動圧縮の既定の待ち時間を 50 分にした。Codex はキャッシュがどれだけ残るかを確かめていなかったので、自動圧縮を既定で切り、有効にしたときの待ち時間は Claude と同じ 50 分にしていた。

2026-09-27 に確かめた内容は次のとおり。

- OpenAI の文書（Prompt caching）によると、GPT-5.6 以降のモデルのキャッシュは、最後に書き込むか再利用してから最低 30 分残る（`prompt_cache_options.ttl` は `30m` だけ）。GPT-5.5 以前は `in_memory`（使われないと 5〜10 分）か `24h`（ふつう 30 分前後、長いと 24 時間）。Codex CLI（0.156.1）は保持時間を指定せず、既定の値を使う。
- ChatGPT アカウントでサインインした Codex の記録（rollout の `cached_input_tokens / input_tokens`）を要求の間隔ごとに集計した。GPT-6 系は 30 分前後までほぼ 99〜100% 当たり、35 分を超えると外れが混ざり、数時間を超えるとほぼ外れた。

## 決定

- Codex の自動圧縮を有効にしたときの既定の待ち時間を 25 分にする。
- 既定で切っていることは変えない。Claude の 50 分、全体の既定、予約の扱いは 0039 のまま。

## 理由

放置後の圧縮は、キャッシュが残っているうちに走らせると圧縮そのものがキャッシュ読みで安く済み、以後の送信も小さくなる。50 分では、今の既定のモデルでキャッシュが消えた後に圧縮することになる。30 分では消える時刻とちょうど重なる。25 分なら 5 分の余裕を残しつつ、少し考えたり別の会話を見たりする間には割り込まない。

## 影響

- 保存済みの設定に Codex の待ち時間があれば、その値が使われる。既定を使っている利用者だけが 25 分になる。
- GPT-5.5 以前のモデルで ZDR が有効な組織のように、キャッシュが 5〜10 分で消える環境では、25 分でも間に合わない。その場合も、以後の送信を小さくする効果は残る。
- ChatGPT プランの Codex の利用枠で、キャッシュ済みの入力が安く数えられるかは確かめていない。
