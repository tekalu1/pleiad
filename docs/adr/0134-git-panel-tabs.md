# 0134 git パネルを「変更」と「作業場所」のタブに作り直す

- 状態: 承認（2026-10-04）
- 置き換えた: 0085（決定 5 の WS の読み取りコマンドの数と、決定 7 の右パネル「git」の中身の並び。書く操作を作らないことは維持）、0089（決定 5 のうち、残った分けた作業場所を右パネルに 1 ブロック出すこと。置き場だけが変わり、操作の中身は 0089 のまま）

## 状況

ADR 0085 決定 7 の右パネルは、状態・残っている作業場所（ADR 0089 決定 5）・この会話でしたこと・変更を縦 1 列に積み、コミットの履歴もブランチの分かれも見せなかった。差分は行番号も色も無かった（`docs/design-system.md` の「git の動き」の書き方）。変更はパスの平らな並びで、ステージ済みかどうかが分からず、差分は行番号も色も無かった。分けた作業場所のうち台帳にあるものだけが出て、ふつうの `git worktree add` で作ったものは出なかった。
ユーザーがモック（AsIs / ToBe）で作り直しを承認した（2026-10-04）。

## 決定

1. **タブは「変更 N」と「作業場所」の 2 つ。** 変更の N は選んでいる範囲のファイルの数。パネルの頭（ブランチ ↑↓ · PR、再読み込み、広げる、閉じる）は固定し、下の行（取得時刻・再読み込み・会話で使う）は無くす。Ctrl+Shift+G（macOS は ⌘⇧G）で開閉する。
2. **変更タブは、範囲の切り替え → コミットのグラフ → 選んだ範囲のファイルの一覧。** 範囲は「コミットしていない分」「この会話の間」と、グラフで押したコミット（× で戻る）。グラフは作業ツリーの仮の行を一番上に置き、選んだ範囲を線に沿った帯・太い線・塗った点で見せ、範囲の外は薄くする。会話の始まりの HEAD に「会話の始まり」の印を付ける（最初のターンの撮影の親。撮影が無い会話では出さない）。帯が示すのは差分に入るコミット（`始まりの HEAD..HEAD` と作業ツリー）で、時間の区間ではない。「この会話でしたこと」の節は無くし、コミットを押したときの「この会話で作成 · 会話のこの場所へ」に置き換える。
3. **ファイルの一覧はステージ済みと変更の 2 群（ステージ済みが無ければ見出しごと出さない）、ツリー / 一覧、状態の文字 M / A / D / U / R。** 差分は行番号・語の強調・変わっていない行の畳みと展開・インライン / 左右（広げたときだけ）・折り返し・前後のファイルと変更への移動を持つ。
4. **差分と状態の文字に色を付ける。** 新しい色の族 `--diff-*`（追加は緑・削除は赤・変更は琥珀。面と文字）を `tokens.css` に足し、差分の行・語・行番号の面と、ファイルの一覧の状態の文字・+a −d にだけ使う。lint-design が `web/git.css` の外での使用を落とす。グラフの線は線の族のままにし、緑・赤は使わない。
5. **作業場所タブは、このリポジトリの `git worktree` を全部並べる。** ブランチ・パス・主の作業場所からの先行・未コミットの数と、「ここ」「未取り込み」「使用中」「git worktree」の札。Pleiad の分けた作業場所の操作（取り込みを頼む・退避して消す・残す）は、未取り込みの行を開いた中に置く（`残っている作業場所` の節は無くす）。Pleiad の外で作ったものは読むだけ。
6. **履歴・コミット・作業場所・ステージの区別を読む操作を足す（読むだけ）。** `git.history`（`git log --branches --tags --remotes HEAD --topo-order`。`--all` は使わない。`refs/pleiad/` の撮影が混ざるため。50 件ずつ）・`git.commit`・`git.worktrees`・`git.worktree`。`git.diff` はコミット・2 つのコミットの間・ステージ済み / 変更の区別・名前の変更・前後の行・畳みを開く後ろ側のファイルの全行を選べる。`git.changes` の行はステージの印を持つ。AI・CLI にも同じ操作が出る（上限と cursor、本文の切り詰めは既存の git 操作と同じ）。
7. **書く操作は作らない。** ステージ・コミット・ブランチの切り替え・マージ・PR の作成の画面は引き続き作らない（エージェントに頼む。ADR 0085）。履歴を見せることは、`docs/design-system.md` の「git の動き」にあった「コミットのログ・ブランチの一覧は出さない」形を改める（0085 の決定ではなく、画面の文書の書き方）。
8. **パネルの中のタブを、design-system §2.3「場面切替は無い」の例外に足す。** 脇の Chats / Channels と同じ部品（segmented の pill）。

## 理由

- 変更を見る人が知りたいのは「どのコミットから来た差分か」で、範囲とグラフを 1 つの面に置くと、切り替えても絵が動かず強調だけが線の上を動く。ファイルの一覧がいつも同じ場所（グラフの下）にある。
- 履歴とステージの区別は git を読めば分かる事実で、Pleiad が書く操作を持たなくても、頼む前に状況を判断する材料になる。
- 差分は開発者が追加＝緑・削除＝赤で読み慣れていて、記号の列を目で追わなくてよい。0085 の階調だけの表現は、ダークで削除が明るく見える逆転も起きた。例外は差分と状態の文字に閉じ込め、lint で縛る。
- 作業場所を台帳の外まで出すと、ふつうの worktree と Pleiad の分けた作業場所の違いも、取り込みが要るものも 1 か所で分かる。

## 影響

- ADR 0085 は決定 5（WS の読み取りコマンドが 3 つから 7 つになる）と決定 7（右パネルの中身の並び）が置き換わる。差分の色（`docs/design-system.md` §2.1 の例外）と履歴を見せることは、画面の文書の書き換えとして本 ADR で決める。返答の下の 1 行・頭の行のアイコン・入力欄のブランチ・委譲カードの「変更」の行・隠し ref の撮影は 0085 のまま。
- ADR 0089 は決定 5 の「残ったものは右パネルに 1 ブロック『残っている作業場所』を出し」が置き換わり、作業場所タブの未取り込みの行を開いた中に移る（取り込みを頼む・退避して消す・残すの中身は 0089 のまま）。決定 2 は 0133 が置き換えており、0089 は 0133 と本 ADR の両方の部分置換になる。
- WS に `gitHistory`・`gitCommit`・`gitWorktrees`・`gitWorktree` を足す（画面の内部の口。`PROTOCOL_VERSION` は据え置き）。操作の一覧・snapshot・辞書（ja / en）を更新する。
- `docs/design-system.md` の「git の動き」・§2.1・§2.2・§2.3 と `docs/design.md` の「git の動き」を今の形に書き直す。
