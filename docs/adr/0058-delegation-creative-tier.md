# 0058 新しい画面を tv から外し、tv をクリエイティブ作業に絞る

- 状態: 承認（2026-09-29）
- 一部置き換えた: 0022（段 tv の対象「画像・新規 UX」）

## 状況

0022 では `ux_new`（新しい画面や製品の UX、複雑な UX の作り直し）と `visual` を、どちらも tv（既定の候補は codex `gpt-6-astra`）に振っていた。実際には新しい画面は claude `opus` で十分な品質が出ている。一方 `gpt-6-astra` は使用量の負担が大きく、3D モデリングや生成画像のベクター化のような高度なクリエイティブ作業に取っておきたい。

## 決定

- `ux_new` の既定の段を tv から t4（claude `opus` → claude `fable`）へ移す。難しさによらず `t4 / t4 / t4`（`ux_change` と同じ）。
- tv は `visual` だけに使う。`visual` の定義を「画像・ロゴ・図」から「3D モデリング、生成画像のベクター化、イラスト・ロゴなど、見た目の出来栄えが成果を決める高度なクリエイティブ作業」に変える。図・グラフ・画面のモックは `visual` ではなく、形が決まっていれば `implement`、形を子が決めるなら `ux_change` / `ux_new` とする（ツールの説明の境目に足す）。
- 段 tv の表示名は「クリエイティブ」、`visual` の表示名は「クリエイティブ（3D・ベクター化など）」にする。
- `kind` の値（`visual`）と段の id（`tv`）は変えない。判定器の既定（`ux_new` `visual` は `none`）と、tv が上がらず tv だけを見る規則も変えない。

## 理由

新しい画面は opus で足りるので、高価な astra を使う理由が無い。tv の対象を狭めれば、astra の枠をクリエイティブ作業のために残せる。名前を変えなければ、保存済みの設定を移し替えずに済む。

## 影響

- 保存済みの表（`table`）を持たない利用者は、自動で新しい既定（`ux_new` → t4）になる。
- `table` を保存している利用者は自分の設定が優先されるので、`ux_new` は tv のまま。画面の「種類 × 難しさ」で t4 へ変えられる。
- kind 名・段の id は同じなので、設定の移し替えは要らない。
- 現行仕様は [agent-delegation.md](../agent-delegation.md)、設定画面の表示は [design-system.md](../design-system.md) に記す。
