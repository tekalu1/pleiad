# 0052 システム側のメッセージを「あなた」の吹き出しで出さない

- 状態: 承認（2026-09-28）

## 状況

会話を開き直すと、人が書いていない文面が「あなた」の吹き出しで出ていた。ライブ（ターン中）には出ず、履歴（`getMessages`）だけで起きる。

- Claude の CLI は、圧縮の要約・スラッシュコマンドの行とその出力・`!` モードの入出力・中断・agent teams の teammate の知らせを、transcript に user の行として書く。SDK の `getSessionMessages` はそれらを人の発言と同じ形で返し、見分けに使える `isCompactSummary`・`parentUuid`・`origin` を落とす。
- VS Code は人の発言に開いているファイルの知らせ（`<ide_opened_file>`）を別の text ブロックで足し、Codex Desktop は画面の状態（`<in-app-browser-context>`）を同じ text の先頭に付ける。
- Pleiad の手動圧縮（`/compact`）も、コマンドの行と出力（"Compacted …"）を transcript に残す。SDK 0.3.258 の `includeSystemMessages` は system 行を `message: null` で返すので、開き直したときに transcript から圧縮の区切りを拾えていなかった。
- 別のバックエンドへ切り替えた会話の保存分（`conversations/*.json`）には、これらの行が生のまま残っている。
- Pleiad の完了通知は「タスクの結果で再開」の 1 行で出ていたが、本文を読む手段が無かった。

2026-09-28 にユーザーが種類ごとの見せ方の案を承認した。

## 決定

種類ごとの見せ方（形は `docs/design-system.md`「システム側のメッセージ」）:

- **圧縮の要約**: 発言として出さず、圧縮の区切りの「要約を表示」に入れる。Pleiad の `/compact` の行と出力は出さない。区切りの記録が無い自動圧縮は、要約から区切りを作る。
- **スラッシュコマンド**: 「あなた」の、吹き出しではない 1 行のコマンド表示（`/model opus`）。出力は下の閉じた「出力」に入れる。操作は「ここから分岐」だけ。
- **`!` モード**: 「あなた · Claude に渡した」と `シェル  ! コマンド` の 1 行。出力は閉じた「出力 · N 行」、stderr は失敗扱いにせず「エラー出力」として分ける。終了コードが無いときは何も書かない。操作は「入力欄に写す」（走らせない）と「ここから分岐」。
  - Pleiad の `!` では、`!` のあとにエージェントは返答しない（結果は次の発言と一緒にエージェントへ渡す）。表示は返答を前提にせず、`!` の 1 行と出力だけで完結させる。CLI で作った会話に続く Claude の返答は、ふつうの返答としてそのまま出す。
  - 入力欄で `!` を打つ形（シェルのモード。走らせ方・安全・対応するバックエンド）は、この ADR では決めない。別の ADR で決める。
- **中断**: 吹き出しは出さず、中断の 1 行に置き換える。保存された中断と同じ行として描き、二重にしない。
- **teammate の知らせ**: 「別のセッションからのメッセージ（teammate_id）」の閉じた出来事の一行。待機（`idle_notification`）だけのものは出さない。
- **Pleiad の完了通知**: 今の 1 行を、開くと本文が読める折りたたみにする。ライブのイベント（`taskNotice`）にも本文を載せる。
- **人の発言に混ざる文脈**: `<ide_opened_file>` のブロック、先頭の `<in-app-browser-context>` を外し、残りは人の発言のまま出す。
- **タイトル生成**: Claude の `suggestTitle` の問い合わせを `persistSession: false` にし、会話として残さない。

見分け方:

- サーバーが見分け、発言に `kind`（`command`・`shell`・`compactSummary`・`interrupt`・`teammate`）を付けて画面へ渡す（`core/system-messages.mjs`。`docs/multi-backend.md`「NormalizedMessage」）。画面は `kind` ごとに描くだけで、文面を見ない。
- **文面より行の形・フィールドを優先する。** Claude は transcript の本文から、要約の行（`isCompactSummary`）と区切りの uuid、コマンド・シェルの行の子の出力の uuid を拾って渡す。印があるとき、要約は印だけで見分ける（人が貼った同じ文面を取り違えない）。区切りも transcript の `compact_boundary` の行から読む。
- transcript が無い・読めないとき、保存分、行の形に印が無い種類（コマンドの行・中断・teammate・文脈のタグ）は文面で見分ける。使うのは行の先頭のタグ、固定の中断の文字列、要約の定型の書き出しだけで、使った所をコードのコメントに書く。
- 保存分は書き換えず、読むたびに同じ見分けをかける。
- Pleiad の完了通知は今までどおり本文のハッシュ（`taskNotices`）で見分ける。

## 理由

- 人の発言と見分けられない吹き出しは、誰が何を言ったのかを誤らせる。「編集して再送信」「再送信」が付くので、システムの文面を人の発言として送り直せてしまう。
- 要約は区切りの中身なので、区切りに入れれば 1 万字前後の吹き出しが消え、必要なときに読める。
- `!` のたびに CLI の Claude は返答していた（`respondToBashCommands` の既定）。出力を読んだのはエージェントなので、「Claude に渡した」でその関係を示す。stderr の有無は成否と一致せず、終了コードも記録に無いので、失敗の強調はしない。
- 形の印は CLI の書く文面が変わっても崩れにくい。文面は印が無いときの控えに留める。
- 画面に文面の見分けを置くと、ライブ・履歴・委譲の子の画面・保存分で見分けが分かれる。サーバーで 1 か所にすれば、タイトル生成や委譲の結果の選び方も同じ形を見る。

## 影響

- `NormalizedMessage` に `kind` の付いた形が加わる。`role: 'system'` の発言（`compactSummary`・`interrupt`・`teammate`）は `text` が空で、人の発言として数えない。
- `history.loadTranscript` は要約を `compactSummaries` として分けて返し、`loadSession` が区切りに入れる。
- Claude の transcript を開くたびに、印になる文字列を含む行だけを追加で parse する。
- 入力欄の `!`（シェルのモード）は別の ADR で決める。それまでは、Pleiad の入力欄の `! …` はふつうの発言として送られる。
- 委譲の子への依頼・追加の指示（依頼元のエージェントが書いた user の行）は人の発言のまま。見せ方は別の論点。
