# 0056 コンテキストの見直し: 毎回読み込む指示の量を見せ、見直しを頼めるようにする

- 状態: 承認（2026-09-28）

## 状況

エージェント向けの指示（CLAUDE.md・AGENTS.md）には、「〜すると落ちる、だから〜する」という注意書きが増え続けている。2026-09-28 に数えると、Pleiad のリポジトリで Claude と話す会話は、毎回約 16,200 トークン（`estimateTokens` の見積もり）の指示を読んでから始まっていた。内訳は、ユーザーの指示が約 4,900、作業場所の AGENTS.md が約 7,200、Pleiad が足す分が約 4,100 だった。

- 注意書きの多くは、ツールを直す・環境やフックで塞ぐ・使った瞬間に案内する、のどれかで消せる。文書に残すのが正しいものは少ない。ただし、どれだけ読み込まれているかは、今の画面ではわからない。右パネルはファイル名だけを出し、量を出すのは「Pleiad の指示」のカードだけだった。
- 指示と Skills の本文は、会話を始めるときにもう読み込んでいる（`scanContext` の `content`・`bytes`）。新しく読む仕組みは要らず、数えて見せればよい。
- Pleiad 自身も、Visualize の説明・Skills の一覧・委譲ツールの説明などを毎回足している。これも見せなければ減らす判断ができない。

2026-09-28 にユーザーが、モック（右パネルに量の面を足す形）と次の決定を承認した。

## 決定

### 段階

見直しは 3 段で入れる。この ADR で実装するのは ① だけ。② と ③ は、実装するときにこの ADR の方針で細部を決め、design.md に書く。

1. **量を見せる**（この ADR で実装する）
2. **気になる所を知らせる**: 次の 2 つだけを出す。スコープをまたいで重複した段落と、もう無いパスを指す記述。どちらも言語に依存しない判定で、パネルを開いたときに計算し、保存しない。
3. **見直しを頼む**: 同じ作業場所に、依頼文の下書きを入れた未送信の新しい会話を作る。自動では送らない。下書きには、各注意書きを「ツールを直す → 塞ぐ → 知らせる → 書く」の順で分類すること、変える前に差分を見せて確認を取ることを入れる。

### ① 量を見せる

- **置き場所**: 会話の右パネル（この会話のプラグイン）。作業場所の面のすぐ下に「指示の量」の面を 1 枚足す。既存の面の並びは変えない。
- **数えるもの**: その会話で、毎ターン最初に読み込まれる指示。
  - 自分で書いた指示を、ユーザーと、この場所と親フォルダーに分けて数える。
  - Pleiad が足す分として、Visualize の説明・Skills の一覧・委譲ツールの説明・Pleiad の指示・コンテキストの案内・ブラウザーの説明を数える。
  - 条件付きの rules・Skills の本文・MCP のツール定義・auto-memory・会話の履歴は数えない。
- **数え方**: 既存の `estimateTokens`（web/token-estimate.mjs）を使い、「約 N」と出す。実際のトークナイザーは使わない。
- **形**: 3 つに分けた積み上げの横棒と、凡例の数字を出す。
  - 目安の線は、自分で書いた分（ユーザーとこの場所の合計）にだけ引く。
  - 超えたら、何倍かを 1 行で知らせる。会話は止めない。
  - 目安の既定は 5,000 で、設定で変えられる。
- **Pleiad が足す分**: 開くと内訳が見える。利用者が直すものではないので、見せるだけにする。
- **エージェント任せの指示**: Pleiad は中身を渡していないので、そのエージェントが読む規則で Pleiad が探した結果を数える。合計の横に「推定」の札を付ける。
- **行ごとの量**: 右パネルの指示の各行と、設定のコンテキストの指示の各行の右端に「約 N」を足す。
- **書き換えない**: この面はファイルを変えない。

## 理由

- 量が見えなければ、注意書きを減らす判断のきっかけがない。数字と目安の線があれば、書き足すたびに増えていることがわかる。
- 目安を自分で書いた分にだけ引くのは、利用者が直せるのはそこだけだから。Pleiad が足す分も一緒に目安に入れると、利用者に直せない超過を知らせることになる。
- Pleiad が足す分を隠さないのは、Pleiad も減らす側だから。
- Pleiad が判定するのは、言語に依存しない構造（重複・パスがあるか）だけにする。「修正済み」や古い日付は言語と書き方に依存し、古いことが要らないことを意味するわけでもない。意味での判断は、③ でエージェントに任せる（design.md「失敗の見分けはコードで」と同じ考え）。
- 見直しを頼むとき、今の会話ではなく新しい会話にするのは、今の会話の文脈を汚さず、人が依頼文を読んでから送れるようにするため。
- design.md 2.1 の「見るために離れる」に当たる。今は、何がどれだけ読み込まれているかを知るには、ファイルをエディターで開きに行くしかない。

## 影響

- 右パネルと設定のコンテキストの指示の行に、トークン数が加わる。
- 目安の値が設定に加わる（既定 5,000）。
- 会話ごとに、Pleiad が足した文の量を数える必要がある。どこで数えて画面へ渡すかは実装で決め、design.md に書く。
- ② と ③ は、この ADR を満たす形で後から足す。
