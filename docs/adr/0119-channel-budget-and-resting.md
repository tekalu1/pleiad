# 0119 bot どうしの呼びかけは回数ではなくチャンネルの予算で止め、使用量の上限に当たった bot は「休憩中」にする

- 状態: 提案
- [ADR 0117](0117-thread-replies-and-implicit-wake.md) の「bot どうしの呼び合いは人が書かないまま 6 回で止め、『あなたが書けば続けます』を出す」（D6）を置き換える

## 状況

[ADR 0117](0117-thread-replies-and-implicit-wake.md) で、bot が bot を起こすのは人が書かないまま 6 回まで、超えたら「あなたが書けば続けます」をスレッドに残すと決めた。書き方の事故（全角の `＠` の起こし合い）を費用がかかり続ける前に止めるためだった。その後、bot を呼ぶ `@` は行頭の半角だけになり、事故そのものは起きにくくなった。

回数の上限は、往復の長さで止まる。調べ物を分担する 3 体が真面目に話し合っても 3 往復で止まり、短い相づちの往復でも同じ 6 回を使う。止めたい理由は費用なのに、数えているのは回数だった。

2026-10-04 に、ユーザーが次を決めた。

| 項目 | 決定 |
|---|---|
| 歯止め | 回数の上限（`CHAIN_LIMIT`・`ThreadState.chain`・「あなたが書けば続けます」）を外し、予算で止める |
| 単位 | チャンネルの 1 日の予算と、スレッドへの配分 |
| 数える分 | 人が呼んだ分も含めて全部 |
| % の元 | その bot のバックエンドの週の枠（`ply_usage` と同じ出どころ）が候補。決めて理由を書く |
| bot への見せ方 | 毎ターン残りを渡す。続けるか・言うかは bot が文脈で決める。「80% で必ずまとめる」のような型は付けない |
| 使い切ったら | bot どうしの呼びかけだけ休止。人が呼べば答える。Pleiad からお知らせは出さない |
| 黙る自由 | bot が「ここでやめる」と判断したら、文章なし・リアクションだけで終えてよいと指示文で伝える |

あわせて、使用量の上限に当たった bot の扱いを直す。Antigravity は上限を普通の失敗（`Individual quota reached. … Resets in 4h14m6s.`）で返し、Pleiad はそれを bot 名義の作業中の投稿に「失敗しました: <英語の生の文>」と書いていた。上限の後も bot の一覧は「待機」のままで、休憩中の bot に `@` してもターンが走って同じ失敗を繰り返し、呼び手には故障か無視に見えた。

## 決定

- **回数の上限を外す。** `CHAIN_LIMIT`・`ThreadState.chain`・「あなたが書けば続けます」の知らせと、人格の固定の文の「続けて呼べるのは 6 回まで」を消す。`ThreadState.calls`（起こした回数）は数えて見せるだけのまま。
- **予算の単位はチャンネルの 1 日と、1 スレッドの配分。** チャンネルの定義に任意の欄 `budget = { daily, perThread }` を持つ。`daily` は 1 日の予算（週の使用枠に対する %。`null` は予算なし）、`perThread` は 1 スレッドが使える分（`daily` に対する %）。既定は 1 日 5%・1 スレッド 50%（1 スレッド 2.5%）。日付はこの PC の現地の日付で、変わると 0 から数える。
- **% の元は、その bot のバックエンドの週の使用枠。** 枠は `ply_usage`・設定の「使用量」と同じ取得（server の `providerQuota`・`quotaCache`）の、その bot のモデルに効く週の枠（委譲の振り分けと同じ `windowsFor`）のうち、いちばん使われているもの。**ターンが使った % は、トークンの割合で配る**: 週の枠 1% あたりのトークン = この PC の Pleiad がその枠の期間（解除の時刻の 7 日前から）に同じバックエンドで使ったトークン ÷ 枠の使用率。ターンのトークン（入力・出力・キャッシュの合計）をこれで割る。使用率が 1% 未満・枠が読めない・記録が無いときは最後に分かった値を使い、それも無ければ数えない（止めもしない）。
- **数える分は全部。** bot のターン（人が呼んだもの・ルーティンを含む）が終わるたびに、`origin` をたどった根のスレッドの `ThreadState.spend = { day, percent }` に足す（bot が流れへ書いて新しいスレッドを作っても、数えるのは 1 か所）。DM は数えない（DM では bot どうしが起こし合わない）。チャンネルの今日の分は、そのチャンネルのスレッドの今日の `spend` の合計。
- **残り** = min(1 スレッドの配分 − 根のスレッドの今日の分, チャンネルの 1 日の予算 − チャンネルの今日の分)。**0 になったら、bot どうしの呼びかけだけ起こさない**: bot の投稿の `@`（返事・`channels.post`）と、呼んだ bot へ返す返事。人の投稿と、人が承認した `channels.wake` は起こす。使い切っても Pleiad はお知らせを出さない。
- **残りは毎ターン bot に渡す。** 末尾の文脈（`<pleiad-turn-context>`。記憶の差分・時刻と同じ包み）の最後に「このスレッドの予算の残り: n%（チャンネルの今日の残り: m%）」と、使い切ると bot どうしの呼びかけでは相手が起きない（人が呼べば答えられる）ことを書く。数えられないバックエンドは「不明」。何 % でどうするかの型は付けない。
- **黙る自由。** 人格の固定の文に、言うことが無い・ここでやめると決めたら、文章を書かずに（`channels.react` のリアクションだけでも）ターンを終えてよいこと、文章が無ければ投稿は残らないこと、予算の残りが末尾で届くことを書く（`guide.bot.quiet`）。文章を書かずに正常に終わったターンは、作業中の投稿（`…`）を消し、呼んだ bot へも返事を返さない（今までの動きを、テストで確かめて固定する）。
- **設定と見え方。** `channels.update` の `budget: { daily?, perThread? }`（渡した欄だけ変わる）。AI が外す・上げるのは guarded（bot が自分のチャンネルの歯止めを外せない）、下げるのは write、人はどちらも write。チャンネルの「メモ・設定」に「予算: 1 日 n%・1 スレッドまで n%」とヒント（今日の使用）を置き、スレッドの帯には、Chats の入力欄の上の文脈のメーターと同じ細いメーター（分母は「このスレッドが今日使ってよい量」= 1 日の予算 × 1 スレッドの配分。押すと bot ごとの内訳）を出す。週の枠の % を絶対値で並べると、Claude の週の枠は 1% で約 3 億トークンあるので「0.04% / 2.5%」が 0 に見えるため、配分に対する割合にして小数を切り捨てない。トークンの数字はキャッシュ読みを除き、キャッシュは別に見せる。
- **使用量の上限は `limited` にそろえる。** Antigravity の上限の文（`quota reached`・`RESOURCE_EXHAUSTED`・`rate limit` など）は `turnResult` の `limited` にし、`Resets in 4h14m6s` から解除の時刻を出す（Claude・Codex は前から `limited`）。
- **上限で終わったターンは、bot の発言に上限の文を書かない。** 何も書けていなければ作業中の投稿を消し、bot が書いた分は `stopped` で残す（「止めました」も足さない）。そのスレッド（DM）に Pleiad のお知らせ（system の投稿）「<bot> は使用量の上限に達したので、<時刻> ごろまで休みます。それまでの @ には答えられません」を出す。予算切れと違い bot は話せないので、ここは Pleiad が知らせる。上限で止まったターンそのものは、Chats の会話と同じく「上限で止まった会話の再開」（`limitResume`。既定は解除の後に順に再開）の設定どおりに続きが走る（止まった依頼は失われない）。
- **休憩中。** 上限に当たった bot と、同じバックエンド・同じモデルの bot は、解除の時刻まで休憩中（メモリだけに持つ）。休憩中の bot への `@`（人・bot・呼んだ bot へ返す返事・ルーティン）は**配らず、依頼は預からない**。その場所（スレッド・DM）で休憩 1 回につき 1 回だけ、Pleiad のお知らせ「<bot> は使用量の上限で <時刻> ごろまで休んでいるので、この依頼は届けていません。再開したら、もう一度呼んでください」を出す。`bots.overview` は `restingUntil`（解除の時刻）を返し、画面は作業中・あなた待ちを優先し、それ以外で休憩中なら「休憩中」と出す。解除の時刻が分からない上限は、時刻なしで知らせて休憩中にはしない。

## 理由

- 止めたいのは費用なので、費用で数える。回数では、長くても安い相談と短くても高い作業を区別できない。
- **% の元を週の枠にした**のは、利用者が費用を見ている単位がそれだから（設定の「使用量」・`ply_usage`）。トークン数は利用者に読みにくく、バックエンドごとに重さが違う（同じ 1 万トークンでも、モデル・キャッシュで枠の減り方が違う）。5 時間の枠は 1 日のうちに何度も戻るので、1 日の予算の分母にならない。
- **ターンの前後で使用率を読み比べない**のは、正しく配れないから。使用率は粗く（Codex は整数、取得は 1 分の取り置き）、短いターンは 0 になる。同じバックエンドで同時に走るターン（別の bot・人の Chats の会話）が、それぞれ増えた分を丸ごと自分のものにする。トークンの割合で配れば、その期間に Pleiad が使ったトークンの中での割合で使用率を分けることになり、bot の分を足すと、画面の使用率のうち bot が使った分の目安になる。Pleiad の外（同じアカウントの CLI など）の使用は使用率にだけ入るので、bot の分は多めに出る（予算としては安全側）。
- 割り出しに使う枠を「そのモデルに効く枠のうち、いちばん使われているもの」にしたのは、止まるのはその枠だから（Opus の枠が先に尽きる人には、Opus の bot は Opus の枠で数える）。
- 数えられないときに止めないのは、使用枠を読めない間に、人が分担を頼んだ bot どうしが急に動かなくなるのを避けるため。歯止めは［止める］（ADR 0109）が残る。
- 予算をスレッドの配分とチャンネルの 1 日の 2 段にしたのは、1 つのスレッドの長い往復がチャンネルの 1 日を使い切って、ほかのスレッドの bot が呼び合えなくなるのを避けるため。既定の 1 日 5% は、1 週間毎日使い切っても週の枠の 35%（ほかの作業の分が残る）。
- 根のスレッドに数えるのは、bot が流れへ書いて新しいスレッドを作るたびに配分が増える抜け道をふさぐため（ADR 0109 の［止める］が origin で派生にも届くのと同じ考え方）。
- 使い切ったときに Pleiad が知らせないのは、残りを毎ターン bot に渡しているので、bot が自分の言葉で「ここまでにします」と言える（あるいは黙れる）から。Pleiad の札が会話を割ると、0117 の「あなたが書けば続けます」と同じく仕事を止める札になる。
- 保存を新しい表・ファイルにしなかったのは、設定は上限の決まったチャンネルの定義（`index.json`）、使った分はスレッドの行（DB の `channel_threads`。1 スレッド 1 行・1 日分だけ）に収まるから（ADR 0115）。形式番号は変わらない。
- 休憩中の依頼を預からないのは、解除が数時間後になることが多く、その頃には依頼の前提が変わっていることがあるため（預かった依頼が知らないうちに走ると驚く）。呼び手は知らせを見て、解除の後に呼び直すか、別の bot に頼める。休憩中をバックエンド・モデルでまとめるのは、上限は会話ではなく枠に当たるから。
- 採らなかった案: 回数の上限を残して数を増やす（費用で止める理由が残らない）、ターンの前後の使用率の差で数える（上）、トークン数で予算を書かせる（利用者の単位でない）、「80% でまとめる」の型を指示に入れる（bot の判断を型にはめる。ユーザーが外した）、使い切ったら Pleiad が知らせる（上）、休憩中の依頼を預かって解除後に自動で配る（上）。

## 影響

- 予算の無いチャンネル（`daily: null`）・使用枠を読めないバックエンド（fake・取得の失敗が続くとき）では、bot どうしの呼び合いは人の［止める］まで続く（ADR 0109 の状態）。既定では予算があるので、ふつうのチャンネルは止まる。
- 数えるのはこの PC の Pleiad の記録なので、週の枠の期間の途中から Pleiad を使い始めた週は、1% あたりのトークンが少なめに出て、bot の分は多めに出る（安全側）。
- `ThreadState.spend`（任意の欄）とチャンネルの `budget`（任意の欄）を足し、`ThreadState.chain` は読まなくなった（古い行に残っていても害は無い）。古い版に戻すと、予算は読まれず、6 回の上限に戻る（`chain` は 0 から数え直す）。
- 休憩中はメモリだけなので、再起動すると忘れる。忘れた後の最初の `@` はまた上限に当たり、休憩中に戻る（その 1 回は bot の会話のターンが走る）。
- 上限の知らせ・休憩中の知らせは system の投稿なので、bot を起こさない。人格の固定の文が変わるので、Antigravity の会話は次のターンに人格の更新の文を 1 回受け取る（ADR 0109）。

## 追記（2026-10-04）: 黙ったことを表すだけの文は投稿しない

- 状況: 「文章を書かずに終えたら投稿は残らない」としていたが、Claude Code は文章の無い終わりを許さず、Claude の bot は「（なし）」や括弧だけの一言を必ず書いた。それが投稿として残り、黙る自由が使えなかった。
- 決定: bot の固定の文（`agent:guide.bot.silent`）で、黙るときは文章なしか、本文を `[[no-reply]]` だけにすると伝える。ターンの投稿を確定するとき（`finalizePost`）と途中経過では、この印を本文から外し、印だけの部分を落とす。
  つないだ本文の全体が括弧だけの 20 字までの一言（「（なし）」「(no reply)」）か省略の記号だけなら、文章なしと同じに扱い、投稿を残さない（`core/bots/silence.mjs`）。
- 理由: 決まった印なら、言語やモデルの言い回しに左右されずに確実に見分けられる。印を守らないときの代表的な書き方（括弧だけの一言）も拾うが、本当の返事を消さないよう、改行・URL・`@`・コード・括弧の外の字を含むもの、かぎ括弧・疑問符・絵文字だけの返事は残す。
- 影響: ターン中に書いた文章を順につなぐ形（0.7.3）はそのままで、黙る印の部分だけが抜ける。`channels.post` で返事を書いたターンの最後の一言が黙る文でも、書いた返事の後ろに足さない。括弧だけの短い返事（「（了解）」など）も投稿されなくなる。
