# 0019 製品名を Pleiad に変え、更新とデータのための識別子は変えない

- 状態: 承認（2026-09-26）

## 状況

製品名を Ply から Pleiad に変え、同時に非公開の旧リポジトリから public の `tekalu1/pleiad` へ移した（現在のツリーを履歴なしで移した）。改名前の版を使っている利用者の自動更新・データ・ショートカットを壊さずに移す必要があった。

## 決定

- 表示名（`productName`、画面・窓・通知・ショートカット・アンインストールの一覧）と配布物の名前は Pleiad にする。
- 次は変えない:
  - `appId: jp.ply.desktop`（AUMID とアンインストール情報のキーが決まる。変えると別のアプリとして並んで入る）
  - package.json の `name: agent-host`（Electron の userData と更新のキャッシュの置き場が決まる）
  - Windows の実行ファイル名 `Ply.exe`（変えるとショートカットが作り直され、タスクバーのピン留めが切れる）。入れ先の既定も `Ply` のまま
  - 署名証明書の発行元名（`CN=Ply Evaluation …`）、`PLY_*` の環境変数、データ置き場（`~/.agent-host`）と `AGENT_HOST_*`、MCP のサーバー名・ツール名（`ply_agents`・`ply_delegate` など）
- 旧リポジトリからは一度だけ「橋渡し版」を配る。橋渡し版に焼き込む更新フィードは `tekalu1/pleiad` で、次の版から新しいリポジトリの更新を受け取る。`tekalu1/pleiad` の最初の版は橋渡し版より新しい番号にする。
- 新しいリポジトリでも同じ評価用の署名証明書（同じ発行元名）を使う。

## 理由

- アプリは更新の署名を発行元名で照合するので、発行元名を変えると旧版が更新を拒否する。
- 識別子は利用者から見えず、変える利点より壊れるもの（更新・データ・ピン留め）のほうが大きい。

## 影響

- 内部の名前に Ply・agent-host が残る。新しく足す識別子も、既存の名前と揃える。
- 手順は desktop-releases.md。
