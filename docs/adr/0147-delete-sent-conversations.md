# 0147 送った会話も Pleiad の記録から消せるようにし、ネイティブの会話は残す

- 状態: 提案

## 状況

会話を消す口は、未送信の会話（`sessions.deleteUnsent`。WS は `deleteUnsentSession`）と、夜の整理・心拍の隠れた会話の片付け（`host.deleteHidden`。[ADR 0127](0127-hidden-conversations-quiet.md)）しかなかった。一度でもターンが走った会話は、サーバーが「送信済みのセッションは削除できません」で断る。2026-10-06、最初のターンで transcript が作られないまま session id だけ保存された Claude の会話（resume できず毎回落ちる。不具合は 81b66676 で直した）を、ユーザーは一覧から消せなかった。

ユーザーの決定（2026-10-06）:

1. 消すのは Pleiad の記録だけ。Claude Code の transcript（`~/.claude/projects` の jsonl）・Codex の rollout・Antigravity の会話など、ネイティブの会話は消さない（`claude --resume` や使用量の調査から引き続き見えるように）。バックエンドの `deleteSession` は呼ばない。
2. 確認の後すぐ消し、戻せない（ゴミ箱は作らない）。確認には、戻せないこと・エージェント側の履歴は残ることを書く。

調べた事実:

- 一覧（`core/server.mjs` の `sessionList`）は、各エージェントのネイティブの一覧と Pleiad の記録を合わせる。`wrapBackend` の `listSessions` は、Pleiad の記録が持つネイティブの id だけを隠す。記録だけを消すと、残したネイティブの会話が「ネイティブだけの行」として一覧に戻ってくる（ADR 0127 が隠れた会話をネイティブごと消した理由と同じ）。
- 会話ごとの Pleiad の記録は 20 か所ほどある（DB の行・本文・提示・撮影・git の隠し ref・引き継ぎの写し・内蔵ブラウザーの設定・予約・承認の結果・通知など）。

## 決定

- **操作 `sessions.delete`**（guarded・`scope: session`・画面と MCP の一覧と CLI `pleiad sessions delete <id>`。WS は `deleteSession`）を足す。送った会話も未送信の会話も消せる。`sessions.deleteUnsent` は今の形のまま残す（互換。画面の未送信の会話の「下書きも削除する」はそのまま使う）。承認カードの言葉は新しい組 `conversationDelete`（「{エージェント} が会話を削除しようとしています」/ 削除を許可。`loosens` は付けない）。カードの一文は「会話「…」を Pleiad から消します。元に戻せません。エージェント側の会話の記録は残ります。」
- **ネイティブの会話は消さず、一覧から隠す。** 消した会話が持っていたネイティブの id（今のものと、エージェントの切り替え・巻き戻しの前の区間）を DB の表 `deleted_natives`（`backend`・`native_id`・`session_id`・`at`。1 つのネイティブの会話 1 行）に覚え、`wrapBackend` の `listSessions`・`getSession` が隠す。Pleiad の記録を持たない「ネイティブだけの行」（id がネイティブの id）も同じ印で消せる。表は後から足す表（`LATE_TABLES_SQL`）で、形式番号は上げない（無くても失う記録は無い。古い版では消した会話のネイティブの会話が一覧に戻るだけ）。
- **一緒に消すもの**: sidecar（DB の `sessions`・`session_fields`・`context_entry_refs`）、会話の記録（`conversations` の行・`conversations/<id>.json`・引き継ぎの写し `handoff-<hash>.json`）、提示の記録（`presents/<id>.jsonl`。添付・present・可視化の写し）、computer use の撮影（[ADR 0075](0075-computer-screenshots-in-data-dir.md)）、git の撮影の ref（`refs/pleiad/turn/<id>/`。会話が使った作業場所ごとのリポジトリ。[ADR 0085](0085-host-reads-git-and-turn-snapshots.md) の forget）、内蔵ブラウザー（agent-browser）の会話ごとの設定とソケットの置き場、自動圧縮の予約・上限の解除後の再開の予約、設定の変更の承認の台帳の分（ADR 0088）、まだ知らせていない完了・スマホの通知。
- **残すもの**:
  - 使用量の記録（`usage_records`）: 5 時間・7 日の集計と bot・チャンネルの予算の履歴。会話を消しても使った量は変わらない。
  - 委譲のタスクの記録（`agent_tasks`）: 依頼元に届けた結果と、子の使用量の出どころ。消した子のタスクは記録に残り、追加の指示・やり直しは、子の会話を作り直さずに失敗で返す（「委譲した子の会話は削除されています」）。
  - 会話に結び付いた worktree: ユーザーの変更が入っている。消すときに片付け（settle）も呼ばない。worktree の画面（git パネルの「残っている worktree」）は今までどおり出し、取り込みを頼む会話が消えていれば「取り込みを頼む」を押せなくする（`mergeSessionId` を null）。
  - 添付のファイル（`uploads/<id>/`）: 残したネイティブの会話と、分岐した会話の提示がパスで指している。
  - 記憶（`memory/`）と夜の整理の進みの行: 人の発言から学んだもので、会話とは別に記憶の画面で扱う。
- **断る条件**（`CANNOT_DELETE`。承認カードを出す前と、消す直前の 2 回）: 走っている・準備中（切り替え・分岐）・承認や質問を待っている（ターンが終わった後に残る設定の承認のカードも）・裏の作業がある（Codex のバックグラウンド端末・入力欄の `!` のシェルの行）・委譲の子として終わっていない（完了の通知が届いていないものを含む）・委譲した子が終わっていない・送信待ちや送信予定がある会話と、bot の会話。AI は自分の会話を消せない（`DELETE_SELF`）。
- **委譲の親子**: 親を消しても子の会話とタスクの記録は残す。子は脇の一覧に出さず「Pleiad タスク」から開く作りなので、依頼元の会話が一覧に無い子は脇の一覧に出し、子の画面の「依頼元に戻る」は出さない。子を消しても親は変えない（親の履歴の完了通知は残る）。
- **bot の会話は対象外**（`session.deleteBot` で断る）。Channels のスレッド・DM・ルーティンの会話はスレッドの状態（`channel_threads` の `sessions`）・bot の DM（`dmSessionId`）・送り先（`sendTargets`）が会話の id を持ち、脇の一覧に出ない（あなたを待っている間だけ出る）。隠れた会話の片付けは ADR 0127 の `deleteHidden` が持つ。
- **画面**: 会話の行のメニュー（右クリック・行の「…」・開いている会話のタイトル行の「…」は同じメニュー）の最後、未送信の会話の「未送信のセッションを削除…」と同じ場所に、送った会話では「セッションを削除…」を出す。押すと、状態の削除と同じ形の確かめ（メニューの見出しに折り返す問い「「…」を削除しますか。元に戻せません。エージェント側の会話の記録（Claude Code の transcript など）は残ります。」と「やめる」「削除する」）を出す。消している間の行（「削除中」・縮むアニメーション・失敗の跳ね返りと「もう一度」）は未送信の削除と同じ。消した会話を開いていた画面（リモートの端末を含む）は、`sessionsChanged` の `deleted` で新しい会話の画面へ移る。

## 理由

- ネイティブの会話を残すのはユーザーの決定。Pleiad の外のツール（`claude --resume`・使用量の調査）にとって、ネイティブの会話は Pleiad の持ち物ではない。
- 消した印を DB の行にしたのは、件数とともに増える記録だから（[ADR 0115](0115-records-in-sqlite.md)）。ネイティブの会話を消さない以上、隠す印が無いと一覧に戻る。会話の id ではなくネイティブの id で持つのは、一覧に戻ってくる行の id がネイティブの id だから。
- `sessions.deleteUnsent` を残したのは、MCP・CLI・WS の既存の呼び出しと承認カードの言葉（未送信の会話）を変えないため。新しい操作は未送信の会話も受けるので、AI・CLI は `sessions.delete` だけを使えばよい。
- 断る条件を広く取ったのは、消した会話へ後から書き込む経路（委譲の完了の通知・承認の結果の届け先・シェルの行の終わり・送信待ち）が、sidecar を欠けた形で作り直すため。止めるか終わるのを待てば消せる。
- 使用量・タスクの記録を残すのは、集計と依頼元の履歴が会話の有無で変わらないようにするため。worktree と添付を残すのは、ユーザーの変更・ファイルを Pleiad の判断で失わないため（worktree は画面から片付けられる）。
- 確かめをメニューの見出しにしたのは、状態の削除（「「…」を削除しますか。…」）と同じ部品で、メニューの位置から離れずに読めるため。未送信の削除の子メニュー（「下書きも削除する」）は、戻せないことを書く場所が無い。
- 採らなかった案: ゴミ箱・取り消し（ユーザーの決定で作らない）、ネイティブの会話ごと消す（ユーザーの決定）、`sessions.deleteUnsent` を広げる（名前と言葉が未送信の会話を指し、既存の呼び出しの意味が変わる）、消した子の `delegation` を外して普通の会話にする（他の会話の記録を書き換える）。

## 影響

- WS に `deleteSession` が増える（`PROTOCOL_VERSION` は据え置き）。古い画面は使わない。
- 操作 `sessions.delete` が増える（`tests/ops-surface.snap.json`）。CLI の終了コードは `DELETE_SELF`・`CANNOT_DELETE` が 4（拒否）。
- DB に表 `deleted_natives` が増える（既にある置き場には、最初に会話の記録を開くときに足す）。
- 消した会話が使った状態（グループ名）が、ほかに使われていなければ候補から消える（候補は会話の記録の履歴から集めるため）。
- 消した会話の id を指す記録（使用量・委譲のタスク・worktree の台帳・記憶の `via`）は残る。画面は消えた会話を開く口を出さない。
