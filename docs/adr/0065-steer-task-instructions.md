# 0065 委譲の追加指示を、走っている子のターンへ途中送信で渡す

- 状態: 提案

## 状況

`ply_task_send` の追加指示は、子のターンが走っている間は待機（`queued`）に置かれ、そのターンが終わってから新しいターンとして送られていた（[ADR 0044](0044-task-instruction-delivery.md)）。依頼元が「向きを変えたい」「これも足したい」と気付いたのは子がまだ作業している最中なのに、指示は子が結果を出し終えるまで読まれず、その結果は古い指示のまま返っていた。

人の「作業中のメッセージ送信」と、委譲の完了通知は、すでに走っているターンへ `control.steer` で渡している（`docs/design.md`、[ADR 0057](0057-deliver-completion-notice-live.md)）。追加指示だけが待機していた。

## 決定

1. **走っている子のターンへ途中送信する。** `ply_task_send` が指示を `queued` で受け付けた（保存できなければ断る）後、タスクが `running` で、子が委譲の実行中のターンとして走っており、`control.steer` を持ち、完了通知と同じ条件（`canSteerNotice`。圧縮のターン・中断や終了に向かうターン・途中送信を持たないバックエンド・次ターンの設定の予約・子の会話の人の送信待ちが無い）を満たすとき、待たずに `control.steer` で渡す。満たさなければ今までどおり待機し、次のターンで送る。
2. **順序と二重を守る。** 後ろに待機の指示があるとき、前の途中送信が「渡った」合図を待っている間は、後の指示を途中送信しない（追い越しと、渡らなかった前の指示が後ろに回ることを避ける）。
3. **状態は受理と「渡った」を分ける。** `queue` から外して `sending` にしてから渡す。合図の無いバックエンドは受理で `delivered`。合図を後から出すバックエンド（Claude・Codex）は、`userMessage.delivered` で `delivered`。受理されない（false）なら `queued` に戻す。結果不明（throw）は送り直さず `dropped` とし、`ply_task_send` の返り値に確かめるよう促す `warning` を添える。
4. **渡らなかった指示は待機へ戻し、次のターンで 1 回だけ送る。** `userMessage.dropped`、または合図が来ないまま子のターンが終わったとき（結果の確定より先に片付ける）は `queued` に戻す。人の発言と違い、親からの指示なので送り直してよい。指示の ID（`task-send-<指示 ID>`）で合図を照合し、渡った後に遅れて来た捨てられた合図では戻さない。止めたタスクへ戻すときは生き返らせず `dropped` にする。
5. **子の会話には通常の user 発言として出す。** outbox は通さない。`steerConfirms` のバックエンドでは `userMessage` に `pending: true` を付け、渡らずに終わったら `userMessage.dropped` で下げる。履歴にはバックエンドの記録が入る。
6. 走っている回に渡した指示は、その回の結果が新しい指示も反映するものとして扱い、完了通知はその回の完了で 1 回とする。

## 理由

追加指示の目的は、子の作業を途中で正すこと。子が終わるまで読まれないと、依頼元は古い指示の結果を待ってから直させることになり、時間と使用量を無駄にする。人の途中送信と完了通知が同じ経路をすでに持つので、新しい配送の仕組みは要らない。

一方で、指示は人の発言と違って「二重に届く」より「届かない」ほうが依頼元にとって扱いやすい場面はあるが、渡らなかった指示を黙って捨てると依頼元は気付けない。そのため、渡らなかった確かな場合（受理されない・捨てられた・合図なし）は待機へ戻して 1 回だけ送り、結果が本当に不明な場合（throw）だけ、重ねて送らず依頼元に確かめさせる。ID での照合が、合図が遅れたときの二重配送を防ぐ。

## 影響

- `createAgentTasks` が `childSteerable`・`steer` を受け取り、`steered`・`settleSteers` を公開する。読み手は `core/agent-tasks.mjs`・`core/server.mjs`（`steerInstruction`・`childTarget`・`liveInstructions`）に限られる。保存形式は変えない（指示の状態は `queued` / `sending` / `delivered` / `dropped` のまま）。
- `ply_task_send` の返り値は、結果不明のときだけ `warning` が付く。それ以外は今までと同じ。
- 画面（作業ダイアログの詳細の「依頼」の下）は状態に従って出る。途中送信で渡った指示は、合図待ちの間だけ送信中、渡れば子の履歴の user 発言に代わる。見た目の変更はしない。
- 同じ子への指示を続けて送ると、前の指示が合図待ちの間の 2 通目は待機して次のターンになる（Claude は次のツール結果の区切りまで合図が出ない）。
- 結果不明（throw）の指示が実際には届いていた場合、詳細には「未配送」と履歴の user 発言が並び、その後ろの指示の送信中の判定が 1 つずれうる。
- 実機（本物の Claude・Codex）での確認は未実施（fake で確かめた）。Claude は入力を閉じた後（ターンの終わり際）は受け付けず、その指示は待機のまま次のターンで送る。Codex の `turn/steer` は `expectedTurnId` が決まる前は false になる。
