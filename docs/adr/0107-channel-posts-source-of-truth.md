# 0107 チャンネルの投稿の正本は Pleiad のデータ置き場に置き、発言者の欄を持つ

- 状態: 提案

## 状況

[ADR 0005](0005-source-of-truth-for-sessions.md) は、会話の正本をエージェントのネイティブの保存に置き、Pleiad の sidecar は「ネイティブに持てないもの」だけを持つと決めた。チャンネルの投稿は、どのエージェントの会話でもない（複数の bot と人が同じ場に書く）ので、ネイティブには持てない。

投稿には、誰が書いたか（人・bot・Chats の会話の AI・ルーティン・システム）、リアクション、スレッド、編集と削除、既読がある。ルーティンが毎日書くチャンネルは投稿が増え続ける。

## 決定

- **投稿の正本は `<データ置き場>/channels/` に置く。** ADR 0005 の「ネイティブに持てるなら」の例外で、チャンネルの投稿はネイティブの会話から作り直せない。
  - `index.json`: チャンネル・DM の定義と既読（全体で 1 つの直列化キュー。`writeAtomic`）。
  - `<channelId>.jsonl`: 追記だけの操作の記録（1 行 1 操作: 投稿・編集・削除・リアクション）。読むときに畳む。最後の行が壊れていたら捨てて読む。チャンネルごとに直列化する。
  - `threads.json`: スレッドの状態。`inbox.json`: bot へ届ける前の出来事（保存できなければ受け付けない。委譲のタスクの台帳と同じ）。
- **すべての投稿は発言者の欄 `author` を持つ。** `human` / `bot { botId }` / `agent { sessionId }`（Chats の会話の AI が操作の一覧で書いた）/ `routine { routineId }` / `system`。人と bot と AI を同じ操作で書き、発言者は呼び出しの主体から Pleiad が決める（呼び出し側の自己申告にしない）。
- **id は Pleiad が出す。** 接頭辞 + 時刻の base36 + 乱数 6 字（`c_` チャンネル・`p_` 投稿・`b_` bot・`m_` 記憶・`r_` ルーティン・`h_` webhook・`i_` 届ける前の出来事）。並べ替えやすく、推測されにくい。
- **メンションは投稿の時点で解いて保存する。** `mentions` は botId と `'you'`。あとで bot の名前が変わっても壊れない。
- **新しいファイルは全部 `version: 1` を持つ。** 読めない版は読み込まずに画面へ出して止める。`data-schema` の形式番号は上げない（既存のファイルには任意の欄を足すだけ）。

## 理由

- 毎回全体を書き直す形式（`conversations/<id>.json`）は、毎日書くチャンネルで重い。追記だけなら壊れても最後の 1 行を失うだけで済み、編集・リアクションも操作として積める。
- 発言者を投稿の側に持たせると、記憶の根拠の検査（人の発言だけを根拠にする。0109）・通知・表示の分け方が 1 か所で決まる。
- 正本を Pleiad に置けば、バックエンドを替えても・bot を消しても投稿は残る。

## 影響

- バックアップ・移行は `channels/`・`bots.json`・`memory/`・`routines.json` を含める。
- 古い版に戻すと、新しいファイルは無視される（bot の会話が Chats の一覧に並ぶ以外は壊れない）。
- 投稿が大きく増えたときの整理（古い分の畳み込み）は今回は持たない。
