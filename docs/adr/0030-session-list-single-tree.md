# 0030 会話一覧をひとつのツリーにし、分岐点の札で兄弟を見分ける

- 状態: 承認（2026-09-27）

## 状況

2026-09-27 の UX 監査で、会話一覧がキーボードで使いにくいことが分かった。行は役割の無い `div tabindex=0` で読み上げでは名前しか分からず、Enter では開けるが Space は効かず、居場所の輪はブラウザー既定の 1px だった。状態の見出しのボタンと全部の行が Tab の順に並ぶので、13 件で 24 回の Tab が要り、数百件では一覧を抜けられない。Ctrl+B と Shift+F10 も、見つける手がかりが開閉ボタンの title しか無かった。

会話の中の分岐点の札は、fork した枝が親の題を継ぐため同じ名前が並び、「0 件の続き」まで同じで、押す前に区別できなかった。根の枝の既定名「はじめの流れ」は、ユーザーのレビューで分かりにくいとされた。

## 決定

- 会話一覧（`#groups`）を `role=tree` のひとつのフォーカスにする。状態の見出し・グループの器・行を `treeitem` にし、指している項目は `aria-activedescendant` で伝える（`web/tree.mjs` と同じ形。roving tabindex にしない）。Tab 1 回で入り、1 回で抜ける。見出しのアイコン・＋・… と行の … は `tabindex=-1` にしてマウスとタッチに残し、キーボードからは Shift+F10 のメニューで同じことをする（見出しのメニューに「この状態で新しいセッション」を足す）。
- 矢印は指す項目を動かすだけで、**会話は開かない**。開くのは Enter と Space。`web/tree.mjs` は選ぶとプレビューするが、会話一覧で開くと読み込みと未確認の消去が走るため、ここは分ける。
- 指している項目は 2px の青い輪（キーボードのときだけ）、開いている会話は今までどおりの白い面と `aria-selected`・`aria-current` で、2 つを別々に示す。
- 一覧にキーボードのフォーカスがある間だけ、脇の下に操作キーの一行（↑↓ 移動 · Enter 開く · Shift+F10 メニュー · Ctrl+B サイドバー）を出す。マウスとタッチでは出さない。設定にキーの一覧のページは作らない。
- 分岐点の札は、名前が兄弟とぶつかるときだけ、1 行目を分岐後の最初の自分の発言の抜粋、2 行目を「枝 N · M 件」にする。ぶつからない札と今いる枝の 2 行目（「現在の会話」）は変えない。札の幅は並びの間隔に合わせて最大 92px にする。
- 根の枝の既定名を「はじめの流れ」から「オリジナル」に変える（英語は従来どおり Original）。

## 理由

一覧は数百件になりうるので、件数によらず Tab の回数が一定の形でないとキーボードで使えない。コンテキストのツリーで同じ形を使っており、操作の覚え方をそろえられる。行の高さと 1 行あたりの情報は変えず、足すものはキーボードで触っている間だけにしたので、マウスとタッチの見た目は変わらない。

札の見分けは、題を書き換えずに（design.md「暗黙の自動更新はしない」）、枝ごとに違う唯一のもの（分岐後に自分が書いたこと）で示す。ぶつかるときだけにしたのは、ふだんの札を長くしないため。

## 影響

画面の規則は `docs/design-system.md` §4.1「キーボード」と §7 を正とする。検索中に今の会話が一覧から消える問題（監査の M1）と、一覧の行の似た題名の見分け（M5 の前半）は、ユーザーの判断で直さない。読み上げは Chromium のアクセシビリティツリーで確かめたが、NVDA などの読み上げソフトでの確認はまだしていない。
