# 0125 静かなスレッドを bot ごとのエピソードにし、新しい会話へ一度だけ申し送る

- 状態: 実装
- 関連: [0109](0109-bot-and-dispatch.md)・[0110](0110-bot-memory.md)・[0117](0117-thread-replies-and-implicit-wake.md)・[0118](0118-memory-strength-and-learner-runs.md)

## 状況

bot の会話はスレッドごとに分かれる。これは並行して話せる一方、新しいスレッドでは前の話題の続きが分からない。夜の整理が残す意味記憶だけでは、「さっき何を話し、誰が何を引き受けたか」を伝えきれない。

## 決定

- スレッドの投稿・編集・bot のターン終了から 3 分静かになったら、そのスレッドで話した bot ごとに要約を作る。作業中・承認待ちならさらに待つ。再起動後は最近 14 日から bot ごとに新しい 5 スレッドまでの予約を組み直す。要約を作っている間に投稿が増えたら保存せず、静かになるのを待ち直す。
- 要約は `ThreadState.digest[botId]` に本文（500 字まで）・作成時刻・最後の投稿の時刻・対象投稿の指紋を持ち、スレッド単位の DB 行に保存する。投稿を変えなければ同じ要約を作り直さない。人の根拠となる投稿がすべて消されたら要約も外す。
- 要約の材料は taint のない人の投稿と、その bot 自身の確定済み投稿だけ。ほかの bot・agent・ルーティン・system の本文は入れない。前の要約は更新時の文脈としてだけ渡す。モデルには話題・人が決めたこと・分担を 500 字以内に要約させ、未確認の bot の発言を人の決定にしないよう指示する。
- 同じ learner のバックエンド・モデル・読み取りモードで、要約と長く残す記憶の候補を 1 ターンで得る。候補はその bot の層に限り、出どころを人の投稿に結び、既存の `memory.write` / `memory.edit` の検査を通す。決定・約束・印象的な直しは種類と重みを付ける。出どころに通らない候補は残さない。
- 新しいスレッドの bot 会話の最初のターンに、最近 5 スレッドまでの id・チャンネル名・安全な根の題・要約の冒頭を `<pleiad-bot-recent>` で渡す（全体で約 1,300 字まで）。詳細は `channels.read` を使うよう添える。現在のスレッドとアーカイブされたチャンネルは除く。本文は既存の包みのエスケープ規則を使う。
- 申し送りは核の写しの後、今のターンの文脈より前の `notes` に入れる。会話の sidecar の `recentDelivered` を、ターンが渡ったときにだけ立てる。圧縮で核の写しを渡し直しても、申し送りは繰り返さない。

## 影響

新しいスレッドの最初の入力に、最近の話題として約 1k トークンが増える。以後のターンでは増えない。要約作成には、スレッドが静かになったときに安いモデルの入力（最大 12k 字の投稿と既存の記憶）と短い JSON 出力を 1 回使う。モデルが使えないときは既存の要約を残し、15 分後に再試行する。

思い出した回数で強める、古いエピソードを週・月単位にまとめ直す、忘れる候補を表示する処理は次の段階で扱う。`digest` の作成時刻と `fingerprint`、既存の記憶の種類・重みはそのために残す。
