# 0113 bot が別の会話へ送るときは、`sessions.send`（ADR 0104）に bot の検査と送り手の名前・アイコンだけを足し、道具の承認は押さない

- 状態: 提案

## 状況

「あなた待ちの質問のうち、決まりで答えられるものに答えておいて」「夜の間に失敗した会話を調べて、朝にまとめて」のような仕事は、bot が Chats の会話を読み（`sessions.search`・`sessions.read`）、必要なら送れることを要する。送った発言は人の発言と見分けがつかなければならず、道具の承認まで代わりに押せるなら承認モードの意味が無くなる（[ADR 0082](0082-control-surface-principals-and-risk.md)）。

2026-10-03 にユーザーが決めた: 代わりに送るのは P3 に入れる。送れる会話は bot ごとに限る。道具の承認を bot が代わりに押すことはしない。「他の会話に送る」は既定で ON。

別の会話への送信は、先に main に入った [ADR 0104](0104-send-to-another-conversation.md) が `sessions.send { sessionId, text, reason? }` として定義した。AI 全般が使える write で、宛先の会話の承認モードで走り、宛先の承認が送り手より強ければ guarded（承認カード）。自分自身・委譲の親子への送信、3 回を超える連鎖、10 分に 20 件を超える送信を断る。送った本文のハッシュと送り手を宛先の会話（`relayed`）に残し、履歴と流れの `userMessage` に `sentBy` を付ける。操作の一覧の作業とは「先に main に入った方の定義を正とし、後の方は bot の検査と表示だけを足す」と合意していた（2026-10-03）。

## 決定

- **操作・危険度・強さの比べ方・歯止め・送信の経路・宛先の履歴は ADR 0104 の `sessions.send` のまま使う。** bot のための別の操作・別の送信の経路・別の見分けの記録は作らない。
- **主体が bot に束縛された会話のときだけ、検査を 2 つ足す。** bot の「他の会話に送る」（`sendToOthers`）が ON であること、宛先が送れる会話（`sendTargets`）に入っていること。危険度の判定（ADR 0104 の強さの比べ方）は bot でも先に同じようにし、そのあとでこの 2 つを確かめる。ADR 0104 の歯止めと同じく承認カードを出す前と送る直前の 2 回確かめ、断ったら送り手の会話の変更の記録（`field: opRefused`）に残す。
- **送れる会話。** 「他の会話に送る」が ON のとき、人がその bot に示した会話（チャンネル・スレッド・DM の本文で人がリンクした・名指しした会話）と、その bot 自身が作った会話。bot のページに題・出どころ・外す操作を出す。人が外した先は再提示でも自動復活せず、設定からの明示的な追加で戻せる。OFF なら送れない。ON にする・送る先を足すのは範囲を広げる向きで、AI がするときは `bots.update` の guarded（[ADR 0108](0108-bot-and-dispatch.md)）。
- **送り手の表示。** ADR 0104 の `sentBy` に bot の `name`・`icon` を足す。画面は ADR 0104 のとおり `name` があれば会話の題の代わりに出す（「<アイコン> <名前> があなたの代わりに送信」）。見分けは ADR 0104 の `relayed`（本文のハッシュ）のまま。
- **道具の承認を bot が押す口は作らない。** 承認モードは人だけが変える（`bots.setMode`。[ADR 0094](0094-human-only-five.md) の承認モード）。

### 参照と除外の保存

人の投稿・編集の本文にある完全な会話 ID（リンク内も含む）と、一意な題を引用符で囲んだ名指しを解決する。同名や曖昧な自然文は解決しない。チャンネル・DM のメンバー、スレッドの参加 bot と @ された bot が対象。過去の投稿全体は遡及走査しない。bot が `sessions.new`・`sessions.fork` で作った会話も対象とする。

`sendTargets` は有効な宛先の一覧。任意欄 `sendTargetSources` に `shown`・`created`・`manual` を残し、一覧から外した先も出どころを消さないことで自動復活を防ぐ。操作の入力ではこの出どころを受け取らない。bot の取得結果の任意欄 `sendTargetDetails` に題と出どころを返す。失敗の code は `BOT_SEND_DISABLED`・`BOT_SEND_TARGET`。

## 理由

- 送信の経路と歯止めを 1 つにすれば、宛先が走っている・中断している・上限で止まっているときの扱いや往復の止め方が、bot の会話と普通の会話で食い違わない。
- 送れる範囲を示された会話に限れば、bot が関係ない会話へ書き込む事故が減る。ON でも示されていなければ送れないので、既定 ON と安全が両立する。
- 承認を押せない限り、送った先の危険度はその会話の承認モードが決める（強ければ ADR 0104 の承認カード）。
- 採らなかった案: bot だけの送信の操作と経路（ADR 0104 と二重になる）、全会話へ送れる、bot の権限で承認も押す、送った発言を人の発言として出す。

## 影響

- 実装: `core/ops/conversations.mjs` の `sessions.send` の歯止めに bot の 2 つの検査を足し、`sentBy` に `name`・`icon` を載せる。
- 代わりの送信の見分けには ADR 0104 の `relayed` を使い、`proxySends` は保存しない。
- 記憶の出どころの検査（[ADR 0109](0109-bot-memory.md)）は、`sentBy` の付いた発言を人の発言として数えない。
- 同時の途中送信で本文のハッシュが合わなければ人の発言に見える制約は ADR 0104 と同じ。
