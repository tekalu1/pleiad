# 0102 発言の「編集して再送信」「再送信」は、分岐ではなく同じ会話の中で巻き戻して送り直す

- 状態: 承認（2026-10-03）
- 関連: [0005](0005-source-of-truth-for-sessions.md)（セッションの正本の所在。変えない）・[0060](0060-markdown-composer-inline-attachments.md) の項目 10（編集して再送信は印ごと編集欄へ戻す。変えない）・[0053](0053-system-messages-display.md)（システム側の文面は再送できない扱いを保つ）

## 状況

自分の発言の「編集して再送信」「再送信」は、対象の発言の手前までを複製した**子の会話を作って切り替え**、そこで送っていた（`fork(…, { beforeMessageId })`）。次の問題があった。

- 言い直すだけで会話が増え、脇の一覧に子が並ぶ。画面が 2 度動く（枝を伸ばす、切り替える）。
- 子は `nativeId: null` で始まるので、最初のターンはネイティブの会話を新しく起こし、履歴を JSON の引き継ぎ文で食わせる。起動が遅く、プロンプトキャッシュが効かず、ツール呼び出しの構造も失われる。
- 押しても何が起きるか分からない（分岐になる手がかりが無い）。

実機で確かめた事実（2026-10-03。[message-fork.md](../message-fork.md)）: Claude は `query({ resume, resumeSessionAt, resumeDropsTurn })` で同じ session id・同じ JSONL のまま巻き戻せ、巻き戻した先のモデルは捨てた発言を見ない。Codex は `thread/rollback` が無く `thread/revert`（ターン単位・paginated のスレッドだけ）に替わっていて、以前に作った legacy のスレッドは `thread/fork { beforeTurnId }` で切るしかない。Antigravity に巻き戻す口は無い。

## 決定

- **基本は同じ会話の中で送り直す。** 対象の発言とその後ろ（返答だけでも）は消え、新しい本文が同じ会話に続く。会話の id・脇の一覧の行・画面は切り替わらない。メニューの項目（編集して再送信・再送信・ここから分岐）は今のまま。
- **送り直すと消えるものが 1 つでもあれば、対象の発言の直下に帯を出す**（編集でも再送信でも同じ部品・同じ位置）。［取り消し］［分岐して送る］（副）［送り直す］（主・右端）。文は「この後のやり取り（あなたの発言 N 件と返答）は、送り直すと消え、分岐して送ると残ります。」（後ろが返答だけなら「この後の返答は…」）。ファイルを変えた返答が消える範囲にあれば「ファイルの変更は、どちらを選んでも元に戻りません。」を添える。押した時点では何も消さず（消える範囲を薄く見せるだけ）、消えるのは送った瞬間。後ろに何も無いときは帯を出さず、すぐ同じ会話で送り直す。
- **実行中のターンがあるときは、帯の主を［止めて送り直す］にする。** 止めてから巻き戻して送る。分岐して送るは元のターンを止めない。
- **「分岐して送る」は今の分岐の経路をそのまま使う**（`fork(…, { beforeMessageId })` → 子へ切り替えて送る）。分岐は人が選んだときだけ起きる。
- **「元に戻す」は作らない。版の切り替え（‹ 1/2 ›）も作らない。** 残したいときの手段は「分岐して送る」が目の前にある。捨てた続きをホストが退避しておく要件が無くなる。
- **サーバーの操作は `sendMessage` の `rewind: { beforeMessageId, stopRunning? }` の 1 つ。** 排他（`forking`）・切り口の決定・提示の切り取り・送信待ち・委譲・渡し済みの控え・中断の印の整合・巻き戻しの適用は 1 回の操作にまとめ、受け付けは同じ `messageId` の再送でも巻き戻し直さない。送り直しの完了は `rewind` イベントで他の画面にも知らせる。
- **巻き戻し方はバックエンドごとに決め、失敗はホスト管理に落とす**（`wrapped.rewind`・`wrapped.runTurn`）:
  - Claude（`capabilities.rewind: 'resumeAt'`）: 次のターンが `resume + resumeSessionAt（残す最後の発言）+ resumeDropsTurn（捨てる発言）` で葉を付け替える。JSONL は次のターンまで動かないので、sidecar の `rewind { backend, nativeId, at, drops }`（保留の印）で履歴を見かけ上切って返す。印は「捨てる発言がまだ鎖にある間だけ」効く（次のターンが葉を移せば自然に効かなくなる。古い印で今の会話を切らない）。最初の発言・今のネイティブの区間の外の発言・切り口が見つからない・`resumeDropsTurn` の拒否は、ホスト管理（`nativeId = null` + 次のターンの引き継ぎ）に落とす。拒否は繰り返し再試行しない（SDK の注意）。
  - Codex（`'thread'`）: 今すぐ `thread/revert { beforeTurnId }`。断られたら（legacy）`thread/fork { beforeTurnId }` で別スレッドに差し替える（会話の id は同じ。`nativeId` を替え、残す発言の uuid は付け直しになるので画面は読み直す）。発言がターンの先頭に無い（ターンの途中に差し込んだ送信）・どちらもだめならホスト管理。
  - Antigravity・ホスト管理・引き継ぎ済みの会話: Pleiad の履歴を切り、生きている agy のプロセスを手放し、次のターンで引き継ぐ（画面上は同じ会話）。ネイティブだけの会話は、同じ id の記録を作る（元のネイティブの id は一覧から隠れる。`switchBackend` と同じ作り）。
- **巻き戻しで整えるもの**: 切り口より後の提示（添付・可視化。「ここから分岐」と同じ選び方）・送信待ち（送れていないものは全部）・切り口より後に生まれた委譲の子（取り消し、完了通知は届けない。子の会話そのものは残る）・ターンの外の裏の作業・渡し済みの控え `contextSession.delivered`（捨てる）・中断の印と止めたもの・切り口より後の圧縮・渡さなかった `!` の行・hooks の発火の記録・文脈量の表示。下書きと、渡していない `!` の結果は残す。検証は、止める・取り消すより前に済ませる。
- **委譲された作業の会話（子）は、同じ会話では送り直さない**（分岐して送るだけ）。委譲タスクの結果・状態が、巻き戻した履歴と食い違うため。

## 理由

- 同じ会話で巻き戻せば、時間（新しいネイティブの起動と大きな引き継ぎ文）も会話の質（ツールの構造・キャッシュ）も得をする。実機で、Claude は巻き戻した先のモデルが捨てた内容を覚えていないことを確かめた。
- 帯で選ばせるのは、「消える」と「残る」を結果の隣で見せるため（メニューの項目名だけでは伝わらない）。後ろに何も無いときは毎回 1 手増やさない。
- 保留の印を「捨てる発言が鎖にあるか」というデータから導くのは、送信がキャンセルされた・再起動した・別の端末が読んだ、のどの場合も古い印が残って害を出さないようにするため。
- 退避・版の切り替えを作らないのは、データの持ち方・切り替え・整合・画面で上書きの 1〜1.5 倍の追加になり、分岐して送るが入口として足りるため。

## 影響

- `fork(…, { beforeMessageId })` は「分岐して送る」だけが使う。`upToMessageId`（ここから分岐）は変わらない。
- 0005（正本）は変わらない。Claude の履歴の正本は JSONL のまま、Pleiad は保留の印で次のターンまでの見かけを切るだけ。
- 巻き戻したあとの JSONL には、捨てた枝が残る（害はない）。Codex の revert は永続の履歴を置き換える。
- 使用量の推計（Claude の cost-state は JSONL の末尾から読む）は、実機の確認で巻き戻したターンの推計が妥当だった（0 以上・桁違いにならない）。
- ファイルの変更は戻らない（作業場所は同じ）。帯がそれを知らせる。
- 実機での確認: Claude は `tests/e2e/rewind.mjs` で、巻き戻した先のモデルが捨てた発言を覚えていないことを見た。Codex も同じ e2e で、paginated の `thread/revert` と、legacy のスレッドの `thread/fork { beforeTurnId }` への差し替えの両方で、捨てた発言を覚えていないことを見た。
