# 0020 文言は辞書に置き、直書きの日本語はラチェットで減らす

- 状態: 承認（2026-09-26）

## 状況

画面・サーバー・エージェント向けの文言が日本語で直書きされていた。英語でも出せるようにしたいが、一度に全部を置き換えるのは無理で、置き換えている間にも新しい直書きが増える。

## 決定（2026-09-23）

- i18next（版を固定）。キーは意味のキーで、日本語が正本。辞書は `web/locales/<言語>/<名前空間>.json`、名前空間は `ui`・`server`・`agent`・`desktop`。対応言語は ja と en。
- 段階的に置き換える。段階 0 は土台と検査だけで、既存の日本語の画面の見た目は変えない。
- **直書きの日本語はラチェットで縛る。** `tests/lint-i18n.mjs` がファイルごとの件数を基準（`tests/i18n-baseline.json`）と比べ、増えたら失敗、減ったら基準を下げるよう求める。基準を上げる更新は拒む。どうしても直書きする行は理由付きの印を付ける。
- エージェントに渡す文は、画面の言語ではなく**会話の言語**で渡す。会話の言語は最初のターンで決め、以後は変えない。
- 失敗の見分けは文言ではなくコード（`code`・`reasonCode`・`messageKey`）で行う。内部の目印も言語に依存させない。
- ログは訳さない。会話の中身・状態の名前も訳さない。

## 理由

- ラチェットなら、置き換えの途中でも新しい直書きが増えず、減った分は戻らない。
- 弱いモデルは指示の言語に引きずられるので、エージェント向けの文は会話の言語に揃える。途中で変えないのは応答の一貫性とプロンプトのキャッシュのため。
- 文言で判定すると、訳した途端に分岐が壊れる。

## 影響

- 仕様は design.md「多言語対応」、訳語は i18n-glossary.md。AGENTS.md の開発規則に辞書の使い方がある。
