# 0006 core から web へは正規化したイベントだけを流す

- 状態: 提案

## 状況

v1 の `core/session.mjs` は生の SDK のメッセージを web へそのまま流し、`web/client.mjs` が Anthropic の API のストリームの型（`content_block_start` / `text_delta` …）を直接読んでいた。バックエンドを並べる（0004）うえで、これが唯一かつ致命的な境界の穴だった。

## 決定

- `sdk` イベントを廃止し、バックエンドに依らない正規化したイベント（`text.delta` / `text.end` / `thinking.*` / `tool.start` / `tool.result` / `activity` / `turnResult` / `permission` など）だけを流す。
- バックエンドごとの差は core（`core/backends/*`）で吸収する。画面はバックエンドの種類を見て分岐しない（違いは `capabilities` で受け取る）。
- 形を変えたら `PROTOCOL_VERSION` を上げ、画面は `ready` の版で gate する。2026-09-11 に 2 にし、以後も同じ方針で上げている。
- 境界の原則は design.md §4 のまま: ツールは core、core はイベントで知らせるだけで、今の状態を抱えない。

## 理由

- 境界を塞げば web の大部分（当時 2800 行）がほぼ無傷で残る。
- 画面が 1 つの形だけを知っていれば、バックエンドを足しても画面の変更が要らない。
- 採らなかった案: 画面でバックエンドごとにストリームを読み分ける（バックエンドを足すたびに画面が増える）。

## 影響

- イベントの表は multi-backend.md §2.2。
- 新しいバックエンドは、正規化したイベントを出すこととテストの共通契約を満たすことが条件になる。
