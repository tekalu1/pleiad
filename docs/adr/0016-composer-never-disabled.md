# 0016 入力欄を disabled で待たせない

- 状態: 承認（2026-09-25）

## 状況

新しい会話を作っている間・履歴を読み込んでいる間・接続するまで、入力欄を `disabled` にして待たせていた。見た目が変わらないまま打鍵が黙って捨てられ、スマホではキーボードが閉じ、変換中の IME が切れた。

## 決定

- 入力欄は `disabled` にしない。
- 新しい会話を作っている間は書けるまま。送信も押せ、押したら字を保ったまま `readonly` にし、会話ができしだい送る（取り消せる）。
- 書いても保てない間（別の会話を開いている・初めて接続するまで）は `readonly` と `aria-busy` にし、150ms を越えたら箱の中に待ちの表示を重ねる。送信は押せない。
- 読み込みに失敗したら欄を書けるように戻し、「もう一度読む」を出す。送信は読み込めるまで押せない。
- 新しい色は足さない。

## 理由

- 打った字が黙って消えるのは、待たされるより悪い。書けるなら書かせ、送れないなら理由を見せる。
- 短い待ち（150ms 以下）で表示がちらつかないよう、待ちの表示は遅らせて出す。
- ユーザーは複数の案から「提案」の形を選んだ。

## 影響

- 画面の規則は design-system.md「入力欄の待ち」、実装は `web/composer-wait.mjs`。
