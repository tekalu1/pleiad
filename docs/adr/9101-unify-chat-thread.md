# 9101 チャットとチャンネルを統合する（チャット = スレッド・脇は 1 つ・入力欄は 1 つ）

- 状態: 提案（画面の形はユーザーが承認（2026-10-06。統合モックの 01・02・03・06 と「決めてほしいこと」）。データの扱いの決めは承認待ち）
- 仮番号。main に入れる直前に振り直す。

## 状況

チャット（Chats）とチャンネル（Channels）は、別の脇（札「Chats | Channels」。[ADR 0107](0107-side-chats-channels-tabs.md)）・別の画面（[ADR 0111](0111-thread-spatial-model.md)）・別の入力欄（[ADR 0116](0116-channel-composer-attachments.md)）になっていた。同じ作業の会話が 2 つの見た目に分かれ、どこで何が起きているかを 1 か所で見られない。スレッドの入力欄には Chats の機能（設定のチップ・送信の日時・`/`・`!`・送信待ち）が無く、宛先の bot は `@` を打つか暗黙の規則でしか決まらない。スレッドの投稿には Chats の発言の操作（コピー・ここから分岐・編集して再送信・原文）が無い。

ユーザーの承認（2026-10-06）:

- 脇を 1 つにし、札をやめて並べ方の切り替え「チャンネル｜状態」にする。切り替えでメインの面は替えない。
- 入力欄を 1 つの部品にし、どのスレッドでも今のチャットの入力欄の仕様にする。先頭に宛先のチップ（bot を選ぶ／bot なし）。
- 会話はすべてスレッドの画面で開く。今の Chats の会話は「一時チャット」（どこにも属さない会話の置き場。当初の案の名前は「ホーム」）のスレッドにする。
- Chats にあってスレッドに無かった投稿の操作を足す（デグレしない）。分岐は新しいスレッドにする。
- チャンネルのスレッドでも「bot なし」を選べる。一時チャットの流れは普通のチャンネルの流れと同じ形にする。

## 決定

1. **一時チャットのスレッドの正本は今の会話（session）そのもの。** 投稿ログへ載せ替えない（データの移行をしない）。bot のスレッドは今のまま（投稿 `.jsonl` + `ThreadState` + bot ごとの会話）。
2. **一時チャットは `home: true` の普通のチャンネル**（新しい `kind` にしない）。保存の名前は予約語 `home`、画面の名前は「一時チャット」/ "Quick chats"。最初に bot へ話しかけたときに作る（op の `channelId: 'home'` がこれを指す。宛先の bot はメンバーに足す。改名・アーカイブはできない）。会話のスレッドはチャンネルの記録に載せず、画面が会話の一覧から合成する（流れも、最初の発言を根の投稿に見立てて普通のチャンネルと同じ形で合成する）。自動では消えない。心拍の居場所にしない。
3. **脇は 1 つで、1 つのデータから 2 つの並べ方を出す。** チャンネルの並べ方（一時チャット・チャンネルの見出しと最近のスレッド・Bots・ルーティン）と状態の並べ方（利用者の状態のグループ。bot のスレッドは 1 スレッド 1 行）。スレッドの索引は `channels.threads`、スレッドの状態は `channels.setThreadStatus`（会話と同じ状態の器）。ADR 0107 を置き換える。
4. **見ている場所を 1 つのアドレスにまとめる**（`{ channelId: 'home' | id, sessionId?, threadId?, postId?, uuid? }`。web/view-address.mjs）。通知・検索・脇の行はこれを通り、再読み込みでも同じ場所へ戻る。
5. **入力欄は 1 つの部品**（web/composer/composer.mjs）。宛先のチップの bot を選ぶと、モデル・承認モード・作業ディレクトリのチップはその bot のこのスレッドの会話の値を出し、変えるとそのスレッドだけに効く（bot の既定を変えても上書きしない）。チャンネルのスレッドの「bot なし」は、人格・記憶・心拍を持たない組み込みの bot（`Bot.plain`）で、dispatch の経路は普通の bot と同じ。名前で `@` できず、記憶・エピソードを書かず、予算・止める・暗黙の宛先は普通の bot と同じ。
6. **投稿に Chats と同じ操作。** 分岐は新しいスレッド（系譜は `ThreadState.branchOf`。`origin` とは別の欄にする）。編集して再送信は同じスレッドの中で、取り下げの記録と、bot の会話ごとの巻き戻し（[ADR 0102](0102-rewind-in-place.md)）。

## 理由

- 移行が要らず、Chats の機能（分岐・巻き戻し・圧縮・目次・会話内検索・送信待ち・送信予定・下書き・状態）を失わない。全会話を投稿ログへ載せ替える案は、移行の規模と、それらの機能を投稿の上で作り直す重さに見合わない。
- 一時チャットに型を足さないことで、予算・`@`・派生元など、チャンネルを前提にした決まりをそのまま使える。
- 分岐をスレッドの中の枝にすると、bot ごとの会話の枝と投稿の枝を同時に持つことになる。`origin` を分岐に使うと、［止める］と予算が親のスレッドと結ばれてしまう。

## 影響

- ADR 0107（脇の 2 タブ）を置き換える。ADR 0111（入力欄が 2 つ・「会話を開く」）と ADR 0116（Chats の添付は切り出せない）を改める。
- design-system §2.3 の「場面切替」の例外は git のタブだけになる（並べ方の切り替えは面を替えない）。
- 新しい操作: `channels.threads`・`channels.setThreadStatus`（ほかは段ごとに足す。docs/channels.md「操作」）。`ThreadState` に任意の欄（`status`・`readAt`・ほか）を足す（DB の形は変えない）。
