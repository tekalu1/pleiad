# 0038 脇の一覧の保存待ちには弧を使わず、語の上に光を通す

- 状態: 承認（2026-09-27）

## 状況

design-system.md §4.6 は「待っている印は `runMark()` の弧だけを使う」と決めていた。脇の一覧では、会話を別の状態へ移す・削除する・作る操作の保存待ちに、行の時刻の位置へ弧と「移動中」などの語を出していた（状態名の変更・削除では見出しに「移動中 1/3」）。

同じ一覧で、弧は「ターンが動いている会話」の印でもある（§6）。行の同じ欄に同じ部品が出るので、移している会話が動き出したように見えた。実行中の会話を移すと、弧が 2 つ並んだ。一覧は動いている会話を目で拾う場所なので、弧の意味が 2 つあると拾えない。

## 決定

- 脇の一覧（会話の行と状態の見出し）の保存待ちには弧を置かない。語（「移動中」「削除中」「作成中」「移動中 1/3」）だけを置き、語の上をタイトル生成と同じ光が通る。
- 光は色を足さず、字（`--ink`）に mask の濃淡を 1.6s で左から右へ流す。reduced-motion では止めて `--ink-weak` の字にする。
- 状態の見出しは、語以外（アイコン・名前）だけを薄くする。
- 一覧の弧は、動いている会話（と、畳んだ見出しの中に動いている会話があること）だけを表す。
- 一覧の外（会話を開くときの末尾の節・入力欄・メニュー・設定の「保存中」）の弧は今のまま。

## 理由

- 回る弧を「エージェントが動いている」に限れば、一覧を見るだけで実行中の会話を拾える。
- 横に流れる光は、タイトル生成と履歴の骨組みで「中身を用意している」の意味ですでに使っている。新しい動きや色を足さずに済む。
- 行の中で語の位置は変えないので、行の高さや並びは変わらない。
- 会話を開くときの弧は、押した会話の中に「履歴を読み込み中」と一緒に一瞬出るだけで、取り違えにくい。変更は一覧に限った。
- ユーザーがモックで案 A（語の上を光が通る）を選んだ。案 B（語は静止し、行の下端に光を走らせ、見出しには進み具合の棒を出す）は採らなかった。

## 影響

- `web/side.mjs` の `pendingLabel()` と `web/style.css` の `.pending-glint`。
- design-system.md §4.6 の「待っている印は弧だけ」に、脇の一覧の例外を書いた。
