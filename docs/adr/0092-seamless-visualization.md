# 0092 会話内の可視化を返答の地に揃える

- 状態: 承認（2026-10-03）

## 状況

成功した可視化は灰色の提示カード、見出し行、内側の余白、iframe の中身という複数の面で囲まれ、返答の文章から浮いて見えた。題と操作は常に上にあり、可視化が続くと画面の密度も上がる。

## 決定

- 対象は成功した `kind: visualization` の会話カードだけ。灰色の面・見出し行・内側の余白を外し、上下 20px、左右 4px の広がりを付ける。iframe 内の文書の body 余白はこの用途だけ 4px にする。
- ホバーのある端末では、触れたときとフォーカスが入ったときだけ、可視化の範囲に `--line` の 1px の輪郭と、右上に掛かる 3 操作の pill を出す。常時の輪郭は置かない。題は figure の読み上げ名と iframe の title に残す。操作は iframe の後の DOM 順に置き、読み上げ名付きの group にする。
- ホバーの無い端末では輪郭を出さず、図の下に「可視化 · 題」と操作を常に置く。動きを減らす設定では不透明度の遷移をなくす。
- 高さが 900px に達し、枠内にスクロールの続きがある間だけ、枠内の下端 36px をフェードする。底では消す。
- 画像・テキスト・旧 HTML・エラーや切り詰めの注記、右パネルと保存・単体の写しの包みは変えない。開く操作の行き先は [ADR 0079](0079-html-opens-in-inapp-browser.md) に従う。

## 理由

成功した可視化を返答の内容として読めるようにしつつ、操作時には輪郭で範囲を示す。タッチでは操作と題の行を下に置くことで、図の内容を覆わずに操作を見つけられる。

## 影響

- 成功した可視化の題は PC の画面上では常時見えない。読み上げとタッチの行には残る。
- 長い可視化は従来どおり最大 900px で枠内スクロールし、続きの印が加わる。
- 保存した HTML と右パネルは従来の余白を保つため、会話内の表示と横の余白が異なる。
