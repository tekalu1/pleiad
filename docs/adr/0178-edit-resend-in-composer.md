# 0178 「編集して再送信」は発言の場所に別の編集欄を開かず、いつもの入力欄を「編集中」にする

- 状態: 承認（2026-10-09。利用者が承認）
- 日付: 2026-10-09
- 置き換える: [ADR 0102](0102-rewind-in-place.md) の画面の部分（発言の場所に出す編集欄と、その直下の「送り方の帯」`web/resend-band.mjs`）。巻き戻して同じ会話で送り直すという意味と、サーバーの巻き戻し（`rewind`・バックエンドごとの方式）は変えない
- 関連: [ADR 0157](0157-unify-chat-thread.md) の決定 6（スレッドの投稿の編集して再送信。スレッドでも同じ形にそろえる）、[ADR 0060](0060-markdown-composer-inline-attachments.md) の項目 10（添付は印ごと入力欄へ戻す。変えない）、docs/design-system.md「発言の操作 › 送り直し」、docs/message-fork.md

## 状況

「編集して再送信」は、発言の吹き出しの場所に別のテキスト欄（`message-edit-input`）を開き、その下に送り方の帯を出していた。次の問題があった。

- 入力欄が 2 つになる。編集欄は素のテキスト欄なので、入力欄の Markdown 編集・添付の札・貼り付け・`@` や `/` の候補が効かず、添付は生のパスの行として見えた。
- 送るボタンも 2 組になる（入力欄の円い送信ボタンと、帯の［送り直す］）。どちらが何を送るのかが分かりにくい。
- 編集欄を開いたまま入力欄に書いていた文は、どこへ行くのかが分からない。
- スレッドの投稿は編集の面を持たず、再送信すると添付が落ちていた。

## 決定

1. **別の編集欄を作らない。** ⋯ › 「編集して再送信」を選ぶと、いつもの入力欄（Markdown の編集部品）に元の本文と添付（札）を入れ、入力欄が「編集中」になる。`message-edit-input` は廃止する。スレッドの入力欄も同じ部品で同じ形にする（`web/composer/edit-mode.mjs` を Chats とスレッドが共有する）。
2. **入力欄の上に帯を出す。** 「{時刻} の発言を編集中」と元の発言の先頭の一行、［元の位置へ］［取り消す］、消えるものの文（「この後のやり取り（あなたの発言 N 件と返答）は、送り直すと消え、分岐して送ると残ります。」など）、書きかけを脇に取ったことの文。元の発言には「編集中」の札を付け、後ろの行は薄くする（不透明度 .42）。
3. **書きかけは確かめずに脇へ取り、戻す。** 入力欄に書いていた文（本文・添付・送信の予約の構え）は編集に入る時に脇へ取り、送り直したあと・取り消したあと・分岐して送ったあとに入力欄へ戻す。
4. **ボタンは字付き。** 主は［送り直す］（右端）、副は［分岐して送る］。実行中の返答があるときの主は［止めて送り直す］。後ろに消えるものが無いときは［送り直す］だけ。円い送信ボタン・送信の予約（▾）・中止ボタンは編集中は出さない。360px（入力欄の幅が 480px 以下）ではボタンを入力欄の枠の中の 2 段目に置き、主が残りの幅を取る。
5. **編集中に別の発言の編集を選んだとき。** 直していなければ黙って切り替える。直していれば帯の中で「続ける／切り替える」を聞く（初めのフォーカスは［続ける］）。
6. **Esc は 1 回で取り消す。** Ctrl/⌘+Enter = 送り直す、Ctrl/⌘+Shift+Enter = 分岐して送る。日本語入力の変換中は受けない。
7. **再送信**（本文はそのまま）も、後ろに消えるものがあるときは同じ形（入力欄が編集中になり、フォーカスは［送り直す］）。後ろに何も無いときは今までどおり、すぐ同じ会話で送り直す。
8. **編集中の状態は書きかけと一緒に保存する。** 会話を切り替えても、読み込み直しても続く（Chats は下書き `edit`、スレッドは下書きの `edit` を投稿の読み込み後に戻す）。サーバーの下書きには、対象の発言の id と時刻・先頭の一行・脇に取った書きかけだけを通す（`sanitizeDraftEdit`）。
9. **動き。** 編集に入った時に入力欄の枠を 1 回だけ光らせる（`note-flash`）。`prefers-reduced-motion` では動かさず、太さ 2px の枠で示す。
10. **読み上げ。** 帯は `role="group"`（名前「編集中」）。入力欄の `aria-describedby` が帯を指す。始まりに「{時刻} の発言を編集中です。…」と知らせ、フォーカスは入力欄の本文の末尾へ置く。
11. **スレッドでも同時に変える。** 再送信で添付が落ちていた不具合も直す（`channels.resend` へ添付を渡す）。

## 理由

- 編集と普段の入力で部品を分けないほうが、入力欄の機能（Markdown・添付・貼り付け・候補）が編集でもそのまま使え、見た目と操作の数が減る。元の本文が見えたまま直せる（発言の場所の吹き出しは残す）。
- 「送る場所は 1 か所」にして、主のボタンの字（［送り直す］）で円い送信の「新しい発言を送る」との違いを見せる。消える範囲は帯の文と薄くした行で、押す前に見える。
- 書きかけを黙って捨てず、確かめずに脇へ取ることで、編集に入るたびの確認を無くす。編集の状態を書きかけと同じ置き場に持つので、読み込み直しや会話の切り替えで失われない。
- スレッドと Chats で同じ部品を使えば、操作・文言・不具合の直しが 1 か所で済む。

## 影響

- `web/resend-band.mjs` の画面の部分（帯・編集欄）は廃止し、入力欄側の `web/composer/edit-mode.mjs` に置き換える。サーバーの巻き戻し（`rewind`・`rewindPlan`）と `sendMessage` の `rewind` 引数は変えない。
- 発言の操作の試験は `tests/browser/message-actions.cjs` を入力欄の編集中の形に書き直した。
- docs/design-system.md「発言の操作 › 送り直し」と docs/message-fork.md を、この形に書き換えた。
