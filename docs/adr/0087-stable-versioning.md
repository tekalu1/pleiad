# 0087 デスクトップ版の番号を semver にし、beta を先行版だけに使う

- 状態: 提案

## 状況

デスクトップ版は `0.1.0-beta.1` から `0.1.0-beta.73` まで、`-beta.N` を通し番号として増やしてきた。機能追加も修正もすべて beta の連番で出すので、番号から変更の大きさが読めない。公開の GitHub では全部が Pre-release になり、正式な版（Latest）が一つも無い。

更新の受信先は、版に `-` が付いていれば `beta`、無ければ `stable` が既定になる（`desktop/updates.cjs`）。ただし `init()` は起動のたびに今の受信先を `updates.json` へ保存していたので、beta の版で起動した利用者は全員、自分では選んでいないのに `channel: "beta"` と記録されている。このまま `0.1.0` を出すと、記録が優先されて全員が先行版の受け取りのままになる。

## 決定

1. **番号は semver。** 次の版を `0.1.0`（beta 卒業）にし、以後は `0.MINOR.PATCH` で進める。機能追加は MINOR、修正だけは PATCH、データ形式・設定の互換性が切れる変更は MAJOR を上げる。`1.0.0` は、正式な認証局の署名で一般向けに配ると決めたときに上げる。
2. **`-beta.N` は先に試してほしい版にだけ付ける**（例 `0.5.0-beta.1`）。GitHub では Pre-release、正式な版は Latest として出す（`scripts/release-publish.mjs` は元からこの分け方）。先行版の次の正式な版は `-beta.N` を外した同じ `MAJOR.MINOR.PATCH` にする。
3. **タグは `vX.Y.Z` と `vX.Y.Z-beta.N` の両方で配布のワークフロー（`Evaluation release`）を動かす。** 発火は `v[0-9]*` にして、Android の `android-v…` では動かさない。
4. **既存の利用者の受信先を一度だけ戻す。** `updates.json` に記録の形式を示す印 `channelChoice: 1` を足す。印の無い記録の `channel` は利用者の選択とみなさず、今の版から決まる既定に戻す。印は、設定で受信先を切り替えたときに付けて保存する。印が付いた `channel` は版が変わっても尊重する。起動時の保存は既定の受信先に印を付けない。
5. **受信先の既定は変えない。** 「先行版も受け取る」にチェックが無い利用者は stable を受け取る（今のコードでもそう動く）。Android のリリースは `--latest=false` なので、デスクトップの Latest を奪わない。

## 理由

- 連番の beta では、どの版が機能追加でどの版が修正か、互換性が切れたかが番号に出ない。利用者への説明にも使いにくい。
- 先行版を残すのは、全員へ配る前に先に試してもらう道が要るから。それは `-beta.N` と Pre-release の分け方で足りる。
- 印を使うのは、既存の `channel` が「利用者の選択」と「起動時の自動保存」を区別できず、記録だけでは選んだのか書き込まれたのか分からないため。印が無ければ選択ではなかったとみなせる。
- 先行版の版（`-` あり）では、印が無くても結果は今と同じ（beta）になる。移行で変わるのは、`0.1.0` 以降の正式な版で起動した、印の無い記録だけ。
- 受信先を変えない保存（自動確認・自動ダウンロードの切り替え）で印を付けないのは、そのとき付けると、先行版で起動した人の既定の `beta` が選択として固定され、次の正式な版でも先行版を受け取り続けてしまうため。

## 影響

- 以前に自分で「先行版も受け取る」を選んでいた利用者も、移行では区別できず stable に戻る。`0.1.0` へ更新した後に、設定で選び直す必要がある。
- `0.1.0` の公開時に、先行版の最後（`0.1.0-beta.73`）の利用者は semver 上で `0.1.0 > 0.1.0-beta.73` なので、受信先が beta でも stable でもそのまま `0.1.0` へ更新できる。
- `0.1.0` へ上げる作業（`package.json`・`package-lock.json` の 2 か所・`releases/0.1.0.json`・`npm run release:prepare`）は、リリースのときに行う。手順は `docs/desktop-releases.md`「バージョンと原稿」。
- `README.md` とサイトの「Beta」の表記は、この決定では変えない。署名が自己署名のままである間は、配布の位置づけを別に決める。
- 運用の今の形は `docs/desktop-releases.md`「バージョンと原稿」「自己署名の配布」「配信停止と先行版」。
