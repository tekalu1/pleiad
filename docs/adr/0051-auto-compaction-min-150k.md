# 0051 自動圧縮の全体の既定の最小トークンを 150k にする

- 状態: 承認（2026-09-28）
- 置き換えた: 0039（自動圧縮の全体の既定の最小トークン）

## 状況

0039 は、自動圧縮の全体の既定を「オン・最小 40k トークン」にした。最小トークンは会話の文脈の量（`contextWindow.usedTokens`）と比べる。

2026-09-28 に、放置後の自動圧縮が実際に得になっているかを過去の記録で確かめた。分かったことは次のとおり。

- `usedTokens` は、システムプロンプト・ツール・指示の固定の前置き（Pleiad の会話で中央値約 43k）を含む。そのため 40k はほぼすべての会話を対象にしていた。
- 前置きは圧縮しても残るので、圧縮後の大きさは 41k〜75k までしか縮まない。一方で要約の出力は毎回かかる。小さい会話ほど、圧縮後に利用者が戻ってこない割合も高い。
- 放置時点の文脈が 150k 未満の会話（81 件）は、合わせて約 −2.8M トークン相当の損だった。150k 以上の会話は得になっていた。

## 決定

- 自動圧縮の全体の既定の最小トークンを 150k にする。
- 全体の既定のオン、Claude・Codex の入切と待ち時間、予約の扱いは 0039・0046 のまま。

## 理由

最小トークンを 150k にすれば、差し引きで損になる会話を対象から外し、得になる会話だけを圧縮できる。圧縮の回数が減るので、要約による品質の低下の危険も減る。縮む見込みの量でしきい値を決める方がより筋はよいが、まずは既定の値を変えるだけで大きく改善する。

## 影響

- 保存済みの設定に最小トークンがあれば、その値が使われる。既定を使っている利用者だけが 150k になる。
- 文脈が 150k 未満の会話は、放置しても自動では圧縮されない。手動の圧縮は変わらない。
