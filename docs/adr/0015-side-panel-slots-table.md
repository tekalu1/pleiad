# 0015 右パネルの枠は 1 つ、何を出すかは表だけが決める

- 状態: 承認（2026-09-25）

## 状況

右パネルはファイルのプレビュー、可視化、この会話のコンテキストに使われる。モードを切り替える関数の中で部品を出し入れしていたため、ファイルの次に可視化を開くとツリーの枠が残るなど、前のモードの部品が漏れた。可視化とファイルは同じ面に出るが、読む対象が違う（可視化は会話に保存された写し、ファイルはホストの今のファイル）。

## 決定

- ファイル・可視化・コンテキストは同じ 1 つの枠を使う。**どのモードで何を出すかは `web/side-panel.mjs` の表（`fileSlots` / `visualizationSlots` / `customSlots`）だけが決める。**
- 枠は `applySlots` で渡された部品だけを並べ、渡されなかった部品は必ず隠す。モードを切り替える関数の中で部品を出し入れしない。
- 見出しの横に小さく種類の印「ファイル」「可視化」を置き、写しか今のファイルかを見分ける（新しい色は使わない）。コンテキストには印を出さない。
- 可視化とファイルで同じ操作（表示の切り替え・広げる・パス・保存・会話で使う）は同じ処理を共有する。

## 理由

- 出す部品を 1 か所の表にすると、新しいモードを足しても前のモードの部品が漏れない。表をテストで直接確かめられる。
- 写しと今のファイルを取り違えると、古い内容を今のものと誤解する。

## 影響

- 部品の表は design-system.md「右パネルの枠」。`tests/unit/side-panel.mjs` がモードごとの表と、渡さない部品を隠すことを確かめる。
