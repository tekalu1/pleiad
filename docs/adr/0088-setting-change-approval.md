# 0088 設定の変更は settings.set に集め、承認が要る会話では受領証つきの承認カードで聞く。呼び出しは承認を待たずに返り、結果は会話へ届く

- 状態: 承認（2026-10-03）

## 状況

[ADR 0081](0081-control-surface-registry.md)・[0082](0082-control-surface-principals-and-risk.md) の段階 2。AI が Pleiad の設定を変えられるようにし、関所を緩める変更は会話の承認モードで決める。0082 が決めたのは判定の表と「承認カードを出す」までで、次は決まっていなかった。

- 承認カードの流れ（待ち方・拒否・会話の終了・同じ設定への重なり・再起動）
- 「同じ変更の取り違え・再送を防ぐ」受領証の具体
- 設定の変更をどこに集めるか（画面の `setPref` は 80 行の `if` の連なりで、AI の口と検査も配信もずれる）
- 各設定の危険度と、秘密・human-only の扱い

最初の案（同じ ADR の提案）は、呼び出しが人の答えを 300 秒まで待ち、時間切れ・ターンの中断・呼び出した側の切断でカードを取り下げる形だった。この形では、人が席を外している間にカードが消えて AI がやり直しを繰り返し、MCP の待ち上限（330 秒）をほかの Pleiad の MCP（60 秒）より長くする必要もあった。

## 決定

- **設定の変更は設定の一覧（`defineSetting`）に集める。** 書ける設定は `normalize`（値の検査と書いたあとの値）と `write`（保存と配信）を持つ。`settings.set { key, value, reason?, backend? }` と、画面の WS コマンド `setPref`（`settings.set` の `legacyCommand`）は同じ定義を通る。`setPref` の中の個別の検査は持たない。
  - `store.setPref` を直に呼ぶのは、`savePref`（prefs.json への書き込みの出口）・起動時の修復・自動圧縮の 3 か所だけにし、印（`ops-allow-setpref`）を数えて増やせなくする（`tests/lint-ops.mjs`）。prefs に書くキーは全部設定の一覧にあり、「未移行」の欄は持たない。
- **危険度は設定ごとに決め、関所を緩める向きだけ guarded にする。** 承認モードと既定のアカウント（`claudeAccount`）は human-only（agent には無い設定と同じ）。全体の構成（ブラウザーのプロフィール・委譲の振り分け・Pleiad の指示・コンテキストの既定）は guarded。表示・既定の選択・自動圧縮は write。確認の切り替え・サイトの許可・computer use は write で、`riskOf` が緩める向き（オン → オフ・「常に許可」が増える・有効にする / 全アプリ / 常に許可を足す）だけ guarded に上げる。`riskOf` を持つ設定は向きごとの例（`riskExamples`）を書き、テストが突き合わせる。値が変わらない呼び出しは危険度を上げず、承認も聞かない。
  - 既定のアカウントを human-only にするのは、変えると新しい会話が別の契約・課金で動くため（0082 の表の「アカウント」）。0081 の段階 1 は write にしていた。
- **承認カードは会話の `askPermission` に `settingChange` を足して出す。**
  - 中身は `{ op, key, requestId, rows, note?, loosens, reason?, receipt, agent }`。`rows` は変わった項目の前後（JSON の文字列）、`loosens` は `riskOf` が上げた変更か、`reason` は AI が書いた理由。`toolName` は `ply_control`、「常に許可」は出さない。
  - 型は [ADR 0073](0073-computer-use-ui.md) の computer use の承認カードと同じ（見出し「{エージェント名} が設定を変えようとしています」・設定画面と同じ名前と値・「理由: …」・確認を減らす変更のときだけ ⚠ と 1 行・ボタンは「拒否」「変更を許可」）。置き場は会話の単独のカードで、ツールの行の下には置かない（カードはターンが終わっても残り、終わったターンの塊は閉じて隠れるため）。リモート・モバイルは同じ `permission` イベントと `resolvePermission` なので同じカードが出る。委譲の子の承認は既存の仕組みで祖先の会話へ写る。
- **呼び出しは承認を待たずに返る。** カードを出したら、すぐ承認待ちを返す: `{ status: 'pending', code: 'PENDING_APPROVAL', requestId, message }`（`message` は会話の言語で「まだ変わっていない・結果は後でこの会話に届く・待たずに続けても応答を終えてもよい・同じ変更を繰り返し求めない」）。MCP では `isError` にしない。HTTP（CLI）は 202 と `{ ok: true, pending: true, result }`。エージェントは作業を続けても、ターンを終えてもよい。
- **カードは期限なしで残る。** 人が答えるか、Pleiad が取り下げるまで。ターンの終わり・中断・会話の停止・host の不在（猶予切れ）では取り下げない（ターンを止めている承認ではないので、`askPermission` に `detached` を付けて待ちの片付けから外す）。走っている作業の数（デスクトップの終了と更新を止める `count`）にも、中断・自動圧縮・委譲の子の「承認待ち」の判断にも数えない。会話の一覧の「承認待ち」の印と `app.running` の `waiting` には数える。
- **人の答えで決着し、結果をその会話へ届ける。**
  - 許可: Pleiad が実行する。書く直前に前の値を読み直して受領証を作り直し、合わなければ同じ `requestId` の新しいカードで聞き直す（2 回まで。変わり続けたら `STALE` として結果を届ける）。実行の失敗（`INVALID` など）も結果として届ける。
  - 拒否: 実行しない。
  - 結果は 1 つの文（`[Pleiad 設定の変更の結果 / {requestId}]`・`結果: 許可|拒否|失敗|取り下げ`・説明。会話の言語。辞書の `agent:ops.settingNotice.*`）にし、委譲の完了通知（[ADR 0057](0057-deliver-completion-notice-live.md)）と同じ届け方で渡す: 走っているターンへ途中送信で渡せればそこへ、渡せなければ会話が空いてから新しいターンで。人の送信待ちを優先する決まりも同じ。届けた文は人の発言と見分ける印（`taskNotices` のハッシュ）を残す。
  - 画面へは決着 `settingApproval { requestId, outcome }` を配り、どの端末のカードも 1 行に畳む。
- **同じ会話・同じ設定（設定でない操作は同じ操作）への承認待ちが重なったら、新しい要求で古いカードを置き換える。** 古いカードは取り下げ、古い要求の結果（取り下げ。「新しい要求で置き換えた」）を届ける。別の設定の要求は置き換えない。
- **再起動はまたがない（承認カードはメモリだけ。ほかの承認と同じ）。** 答えを待つ要求と届ける前の結果は台帳 `<データ置き場>/setting-approvals.json` に残し、次の起動で、待っていた要求を「再起動で取り下げた」結果に変えて届ける。届け方は委譲の完了通知と同じく多くても 1 回（送る前に `delivering` を保存し、渡ったか分からないまま落ちたら送り直さない）。
- **受領証で変更を照合する。** 受領証は `sha256(操作 + 引数 + 承認時の前の値)`。カードに添えて出し、(1) 画面の `resolvePermission` は出したカードの受領証を返さなければ受け取らない（`RECEIPT_MISMATCH`。別の変更への答え・再送を防ぐ）、(2) 許可のあと実行の直前に作り直して照合する（上の聞き直し）。
- **待ちの上限はほかの Pleiad の MCP と同じ。** 呼び出しは待たないので、`ply_control` の MCP（Claude・Codex の `tool_timeout_sec`・agy の中継）と CLI の待ちは既定の 60 秒にする。
- **配信と記録。** 設定を変えたら、既存の配信（`prefs`・`autoCompactionSettings`・`delegationRoutingChanged`）に加えて `settingsChanged { keys, by, via?, bySession? }` を全画面へ配る（配信の無かったコンテキストの既定のため）。会話に束縛された呼び出しは、その会話の変更の記録に `field: 'setting'`（前後の値は 300 字まで。画面の変更の記録には出さない）を残す。記録は許可して実行したときに残る。
- **CLI。** `pleiad settings set <key> <value>`（value は JSON として読み、読めなければ文字列）。会話に束縛された CLI は会話の規則に従い、承認が要れば結果の文（`--json` なら承認待ちの JSON）を出して終了コード 6（受け付けて承認待ち。まだ変わっていない）で終わる。束縛されない CLI の guarded は `NEEDS_UI`（終了コード 4）。`STALE` などの断りも 4。
- `sessions.fork`・`statuses.setIcon`・`statuses.create` は write（人間は全部に触れるので agent も同じ）。画面の `fork`・`setStatusIcon`・`createStatus` と同じ関数を通る。

## 理由

- 検査・保存・配信を設定の一覧に 1 つだけ持てば、口を増やしても（画面・MCP・CLI）ずれない。0081 の「一覧から生成すれば定義は 1 つで済む」の続き。
- 緩める向きだけを聞くのは [ADR 0031](0031-confirm-before-unifying-mcp.md) の「広げる向きだけ確認」と 0082 の決定の具体化で、狭める変更や無害な既定の選択で人を止めない。
- 待つ呼び出しは、人の都合（席を外す・後で見る）とエージェントの待ち上限がかみ合わない。待たずに返し、カードを期限なしで残して結果を会話へ届ければ、人はいつ答えてもよく、エージェントは時間切れでやり直しを繰り返さない。届け方は委譲の完了通知で確かめた仕組み（途中送信・空いてからの新しいターン・人の送信待ちの優先・多くても 1 回）をそのまま使う。
- 重なった要求を置き換えるのは、同じ設定に答えの違う 2 枚のカードが並ぶと、どちらに答えたかで結果が食い違うため。新しい方がエージェントの今の意図。
- 受領証は [ADR 0049](0049-hooks-pleiad-managed.md) の確認票と同じ考えで、承認した内容と実際に書く内容を同じものに保つ。承認の間に別の口が値を変えたとき、古い前提への許可で書かない。カードが期限なしで残ると承認と実行の間が長くなりうるので、照合はなおさら要る。

## 影響

- 設定を足すときは `defineSetting` に危険度（と `riskOf`・`riskExamples`）・`normalize`・`write` を書く。足し忘れは `ops-coverage` が落とす。危険度の変更は `ops-surface` の snapshot（`settingPolicy`）の差分に出る。
- `registry.invoke` は承認が要る呼び出しで `{ ok: true, pending: true, result }` を返す。`deps.approve` は `{ pending: true, requestId }` をすぐ返し、許可のあとで渡された `proceed()`（受領証の照合と実行）を呼ぶ。
- 結果の通知は画面で「設定の変更の結果（変更した / 拒否した / 変更できなかった / 取り下げた）」の開ける 1 行になる（`web/task-notice.mjs` の `parseSettingNotices`）。
- `ply_control` の文の量（T4）は ja 約 1730・en 約 1630 トークンで、上限 1800 は上げない。
- 承認なしのモードの会話からの guarded は黙って通る（記録は残る）。0082 のとおり。
- 届いた結果は空いた会話に新しいターンを起こす（委譲の完了通知と同じ）。エージェントは、許可されたあとに元の依頼の続きを進められる。
