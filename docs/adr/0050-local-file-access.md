# 0050 ローカルファイルの読み取りを作業場所で制限しない

- 状態: 提案

## 状況

可視化・ファイルプレビュー・ダウンロード・Markdown の画像・ファイルの操作は、起動フォルダーや会話の作業場所などを読み取りの許可範囲としていた。隣の worktree にある HTML など、ホスト上に実在する成果物でも表示できない。

これらの経路へ認証してアクセスできる画面・LAN の利用者・ペアリング端末は、エージェントにファイルを読ませることもできる。作業場所の境界は、この相手に対するファイルの機密性を保証する境界にはならない。

## 決定

認証済みのファイル読み取り経路は、作業場所にかかわらずホストの絶対パスを受け付ける。可視化の取り込み、プレビューとその資源・一覧・ツリー、`/local-file`、ファイル操作、文書内の相対リンクの基準となる `base` に共通の検査を適用する。

- UNC パスと Windows のデバイスパス（`\\server\share`、`//server/share`、`\\?\UNC\`、`\\?\`、`\\.\`）は、`realpath` を呼ぶ前に文字列で拒否する。リンクの解決後も再検査する。
- Pleiad のデータ置き場（`store.dataDir`、既定 `~/.agent-host`、`AGENT_HOST_DATA` で変更可能）とその配下は拒否する。添付の `UPLOAD_DIR`（`uploads`）だけは許可する。対象と置き場を実パスに解決して比較し、ジャンクションや 8.3 名の別名を扱う。Windows の比較は大小文字を区別しない。uploads から保護対象へ戻るリンクも拒否する。
- 認証、別 OS のパスの拒否、相対パスの解決規則、ファイル種別とサイズの上限、可視化の HTML・UTF-8・1 MiB の条件を維持する。
- 作業場所を基準にした表示の相対化とツリーの基準は維持する。表示用の roots は読み取りの許可に使わない。
- エクスプローラーで表示・OS で開く操作は、従来どおり中継を経ないループバックの画面に限る。

## 理由

成果物の場所と会話の作業場所が異なるだけで、表示やダウンロードが妨げられることをなくす。

UNC は Windows で開くだけでも相手へ SMB 認証が送られ、NTLM ハッシュが漏れるおそれがある。`realpath` 自体もネットワークに触れるため、実パスの検査だけでは足りない。

データ置き場には中継のホストの鍵やアカウントの秘密の写しがある。トークンが漏れた際、会話に読み取りの跡を残さず直接抜き取られる経路を塞ぐ。添付は画面で表示・保存するためのファイルなので例外とする。

## 影響

作業場所外のファイルやそこへ向くリンクを表示できる。拒否理由は `network-path` と `protected-data` で表し、`outside-workspace` は使わない。既存の可視化の写しと保存形式は変えない。保存済みの可視化を開く専用経路は、従来どおり記録から写しを作る。

この検査はエージェント自身のファイルアクセス権を制限するものではない。Hooks やコンテキスト設定の読み書きに設けた別の範囲検査も変更しない。
