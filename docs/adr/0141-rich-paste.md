# 0141 貼り付けの HTML を書式・画像ごと入力欄へ入れ、外の画像はホストが取りに行く

- 状態: 承認（2026-10-06）

## 状況

入力欄の貼り付けは、`text/plain` があればその字を、無ければ `text/html` の字だけを入れていた（[ADR 0060](0060-markdown-composer-inline-attachments.md)）。Web ページ・チャット・ドキュメントからコピーした見出し・太字・リンク・リスト・コードは平文に落ち、HTML の画像は何の知らせもなく消えた（貼った本人は、画像も入ったと思ったまま送りうる）。コードの冒頭には「HTML そのものは入れない（外の画像を読みに行かせない）」とあった。

ユーザーの依頼（2026-10-06）:「クリップボードのリッチテキスト（HTML）を、書式と画像ごと入力欄へ貼れるようにする」。調べた事実（Chromium 151・Edge 154 のヘッドレスで、選択 → Ctrl+C → 別ページの入力欄で Ctrl+V を実測）:

- ビットマップが無い HTML の画像は `<img src>` にしか無い。`src` は http(s) の絶対 URL（相対 URL はコピー元で絶対化）か `data:`。画像を右クリックでコピーしたとき・スクリーンショットは `clipboardData.files` にビットマップが入り（HTML も一緒に来る）、今の経路で添付になる。
- **画面からは外の画像を読めない**（CORS。画面の `fetch`・`<img>` → canvas はどちらも失敗する）。Electron の main の `net.fetch` は CORS なしで取れるが、窓の信頼表（`desktop/window-trust.cjs`）はローカルの窓にしか IPC を許さず、リモートの窓・モバイル・ブラウザー版では使えない。
- **コピー元のページは、`copy` イベントで任意の HTML（と独自の MIME）をクリップボードへ積める。** 貼り付けの `<img src>` は信頼できない入力で、貼った本人の知らないうちに外へのアクセスの宛先を持ち込める。
- Slack の添付画像は `<img>` ですらなく、認証つきの URL（`Authorization` ヘッダーが要る）を指す空の枠。取れないが、取れないものは黙って消す（下の決定 4）ので特別な扱いは要らない。
- `Ctrl+Shift+V` では `paste` の `types` が `text/plain` だけになる（HTML・独自 MIME が消える）。

## 決定

1. **出どころで分けない。** クリップボードの `text/html` に構造（見出し・リスト・引用・pre/code・`strong`/`b`/`em`/`i` の要素・リンク・画像・表）があれば、`text/plain` があっても HTML を優先し、入力欄の形（Markdown と文中の添付の札）に直して入れる。Slack・Google ドキュメントなどの専用の処理は作らない。構造の無い HTML（色付きの `span` だけの VS Code・ターミナルなど）は今まで通り `text/plain`。style だけの太字・斜体は、ほかに構造があるときだけ読む（エディターの色分けを書式にしない）。色・フォント・大きさ・下線・余白・非表示の要素・`script`・`style`・`iframe`・フォームの部品は捨てる。変換は `web/html-paste.mjs`。
   - 往復で崩れない形を選ぶ: 表は `| a | b |` の行にして**区切りの行（`| --- | --- |`）を足す**（入力欄は平文の行のまま持ち、送ったあとの描画が表にする）。取り消し線は `~~字~~` のまま（入力欄は解釈せず、描画が読む）。字の中の `` * ` [ ] \ `` と語の外の `_`、行頭の `# - > 1.` は `\` で逃がす（入力欄は `\` を字として残すので、逃がした `\` は見える）。リンクは http・https・mailto だけ（`[字](URL)`。URL の `(` `)` と空白は `%28 %29 %20`）。字が URL に見えて行き先が違うリンクは、行き先も字で添える。
   - シェルの形（先頭 `!`）の間・コードブロック・インラインコードの中は今まで通り字だけ。クリップボードにファイルがあるとき（画像の「コピー」・スクリーンショット）は今まで通りファイルだけを添付し、HTML は捨てる。HTML は DOM に入れず `DOMParser` で読むだけ（外の画像を画面に読み込ませない）。
   - 貼り付けた直後の知らせの一行は出さず、書式の取り込みを切る設定も足さない。戻すのは Ctrl+Z（貼り付けごと。取り込み中の札も取得もやめる）、平文で貼るのは Ctrl+Shift+V。
2. **画像。** 小さな画像（幅・高さの指定が 32px 以下・2em 以下・絵文字の class）・非表示のものは札にせず alt の字にする（指定が無くても、取り込んだ後の実寸が縦横とも 32px 以下の画像はホストが置かず、札は取れなかったときと同じく静かに消える）。ほかの `<img>` は、`data:` ならその場でファイルにして今の添付（断片送り）の経路へ、`https` ならホストが取りに行く（決定 3）。http・相対・blob・SVG の画像は取りに行かず alt の字にする。1 回の貼り付けで札にするのは 20 枚まで（超えた分は何も残さない）。貼った位置に文中の添付の札を置く。取りに行く間は「取り込み中」の札（今の送信中の札と同じ部品。取得元のホスト名を等幅の弱い字で添え、取りやめられる）、取れたら画像の札に替わる。同時に取りに行くのは 3 枚まで。取り込み中の札が残っている間は送れない（今の送信中・失敗の添付と同じ規則と見た目）。連続する画像の札が 3 つ以上続くところは、小さなタイル（72×54）にして横へ並べる（1 行 = 1 つの札は変わらない。1・2 枚は今の大きさ）。
3. **取りに行くのはホスト（core）。** 操作 `attachments.importImage`（WS は `attachImport`）と `attachments.cancelImport`（`attachImportCancel`）を `core/ops/` に定義する（危険度は write・画面だけ。MCP・CLI には出さない: AI に任意の URL を取りに行かせない。[ADR 0081](0081-control-surface-registry.md)）。置き場と返す形（`{ path, bytes, kind }` と `mime`・`name`）は添付と同じ（`<データ置き場>/uploads/<会話>/…`。[ADR 0050](0050-local-file-access.md)）。守りは `core/image-import.mjs`:
   - **https だけ。公開アドレスだけ**（名前の解決先がプライベート・ループバック・リンクローカルなどなら断る。IP の直書き・リダイレクト先も毎回検査）。検査器は `core/mcp-url-guard.mjs`（基準の MCP を持たない `publicOnly`）、名前の解決の答えに接続を固定する（DNS rebinding の対策）のは `core/pinned-fetch.mjs`。ユーザー情報つき・非 http(s) の URL も断る。
   - Cookie・Referer・認証ヘッダーを付けない。リダイレクトは 5 回まで。
   - 1 枚 10 MiB（`Content-Length` を信じず、読みながら数えて切る）・15 秒（順番待ち・名前の解決・読み切るまで全部を数える。名前の解決は止められないが、時間切れで失敗にして枠を空ける）。同時に取りに行くのはホスト全体で 6 件まで。超えた分は断らず 100 件まで順番を待つ（超えたら断る）。
   - 画面がやめた（札を外した・元に戻した）ものは、順番待ちなら取りに行かず、途中なら切り、置いたあとに届いたやめるは置いたファイルを消す（まだ届いていない importId のやめるは覚えておき、あとから届いても取りに行かない）。画面が結果を捨てたとき、ファイルが残らない。断った理由の文は取り込み用の文言（画面には出さない）。
   - 先頭のバイトが png・jpeg・gif・webp・avif のものだけ置く（SVG・HTML・実行ファイルは置かない。拡張子は中身から決める）。縦横とも 32px 以下のもの（追跡ピクセル・絵文字。ヘッダーから読む）は置かない。ファイル名は呼び出し側の名前（alt）から作り、URL からは作らない。
   - テスト専用の緩め: `AGENT_HOST_BACKENDS` が `fake` だけのときに限り、`AGENT_HOST_IMAGE_IMPORT_TEST_ORIGIN` に渡した origin のホストがループバック（127.0.0.1・::1・localhost）なら、検査をやめ、どの https の URL もその origin へ向け替える（ブラウザーでの確認用。本物のバックエンドと並べたとき・ループバックでない origin は無視する）。
4. **取れなかった画像は黙って消える。** 札は 160ms で薄れて外れる（動きを減らす設定では即座）。失敗の札・知らせ・理由の表示・失敗の読み上げは出さない。読み上げは、貼った 1 回につき「画像 N 件を取り込んでいます」と、終わったときの「画像 N 件を取り込みました」だけ。残った画像の札が、入った画像。外れた札は戻す・やり直しの記録からも消す。
5. **2 か所**: Chats の入力欄と Channels の入力欄（どちらも同じ編集欄 `web/md-editor.mjs`。Channels は別の `paste` の受け口を持つが、ファイルが無いときは編集欄の貼り付けに任せる）。取り込みの共通部分は `web/paste-images.mjs`。
6. `web/md-editor.mjs` の「HTML そのものは入れない（外の画像を読みに行かせない）」のうち、**「HTML は字だけにする」を置き換える**（HTML は構造を読んで入力欄の形にする）。「HTML を DOM に入れず、外の画像を画面に読み込ませない」は保つ。

## 理由

- 出どころで分けると、チャットだけ・ドキュメントだけに効く処理が積み上がり、コピー元ごとに壊れ方も違う。構造の有無で分ければ、同じ規則で通り、構造の無い（エディターの）HTML は今のまま壊さない。
- 画面は CORS で外の画像を読めず、Electron の main はリモート・モバイルで使えない。ホストなら全部の接続が同じ口で使え、既存の置き場・URL の検査の部品をそのまま借りられる。取りに行くのはホストの PC のネットワークからなので、検査（公開アドレスだけ・毎回・接続の固定）と上限が最低線になる。貼り付けの HTML は信頼できない入力で、貼るだけで取りに行く以上、守りは取りに行く側が持つ。
- 取れなかった画像を知らせないのは、貼った本人が残った札で入った画像を確かめられ、認証つきの画像（取れないのが普通のもの）で毎回知らせが出るとかえって邪魔になるため。
- 画像を Markdown の `![](URL)` のまま本文に残さず、取り込んで添付（ローカルのパス）にするのは、送信後の描画が外の URL の画像を勝手に表示しない方針（`web/render.mjs` の `safeImg`）と合うため。

## 影響

- 貼り付けは、構造のある HTML なら `text/plain` の字と違う結果になる（見出し・リスト・太字・リンクが入力欄の整形になる）。違うときは Ctrl+Z か Ctrl+Shift+V。
- core に外へ取りに行く口が増える。取る条件・上限は上の決定の守りで固定し、`tests/unit/image-import.mjs` が確かめる。データ置き場への書き込みは `tests/data-writes-allowlist.mjs` の許可リストに載せた（1 枚 10 MiB・同時 6 件・1 回の貼り付けで 20 枚）。
- 取り込み中の札はページを読み直すと失われる（取れた画像は下書きに残る）。別の会話へ移っていても、取れた画像はその会話の下書きの「文末に付く」に積まれる（ファイルの添付と同じ）。
- 見た目と動き（取り込み中の札・タイル・外れる札）は [docs/design-system.md](../design-system.md)「入力欄の編集欄」。
