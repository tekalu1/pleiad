# 0116 チャンネルの入力欄は Chats の入力欄の操作に揃え、添付は投稿の `attachments` と本文の印で持つ

- 状態: 提案

（番号は仮。並行するブランチの ADR と重なるので、main に入れる直前にその時点の main の最大の次から振り直す。）

## 状況

Channels の投稿の入力欄（流れ・スレッド。`web/channels/ch-composer.mjs`）は、字の欄こそ Chats と同じ編集欄（[ADR 0060](0060-markdown-composer-inline-attachments.md)）だったが、画像・ファイルを付けられず、貼り付け・ドロップも効かず、書きかけは同じ画面の中でしか残らなかった（流れの入力欄はチャンネルを替えても字が残り、スレッドの書きかけは再読み込みで消える）。ユーザーの声は「画像とかファイルとか投稿できないし、結構使いにくい。チャットの方の仕様に合わせたい」。

2026-10-04 にユーザーが決めた: 揃えるのは入力そのものの操作（添付・キー操作・自動で伸びる行・メンションの補完・書きかけ）。Chats の入力欄のモデル・エフォートの選択は持ち込まない（モデルは呼ばれた bot の設定で決まるため）。

## 決定

- **操作は Chats と同じ。** 添付はクリップ・貼り付け・ドロップ（板の上）で付け、字の欄の中の位置に札（原子）として置く。送っている間は札が進み具合（%）を出し、中止・再試行・外すを持つ。字の欄の上に「添付 N 件 ▾」の入口と一覧の面。送っている途中・失敗の添付があるうちは送らない。送信は Ctrl/⌘+Enter（Enter は改行）。行は 1 行から中身に合わせて伸び、上限はマウス 10 行・タッチ 6 行。Chats の入力欄と共有する部品は、字の欄（`md-editor.mjs`）・断片の送り手（`attach-upload.mjs`）・一覧の面（`attachment-list.mjs`）・札と本文の描き方（`user-message.mjs`）・同名の札の見分けと行数の上限（`composer-layout.mjs`）。
- **持ち物は入力欄ごと。** 添付の状態（実体・送っている途中のもの）と一覧は入力欄 1 つ分の持ち物として `web/channels/ch-attachments.mjs` に置く。Chats 側の同じ働き（`web/client.mjs`）は会話・下書き・送信待ちに結び付いていて切り出せないため、移さない（部品は共有し、状態の持ち方だけが別）。
- **添付は 2 つで持つ。** (1) 本文に Chats と同じ印の行 `[添付] パス`（画面の言語で `[Attachment]`）。bot へは本文のまま包み（`<pleiad-channel>`）の中に入って届くので、bot の会話へ渡る形は Chats で添付を渡すのと同じ（エージェントがパスから自分の道具で読む）。印の位置が札の位置になる。(2) 投稿の任意の欄 `attachments: { path, name, kind, mime, size, origin }[]`（上限 50 件）。画面が札・画像を描くための記録で、中身は載せない（画像は `/local-file` で配る）。`channels.post` が `attachments: { path, name?, mime? }[]` を受け、実物（置き場の中のファイル・読んでよいホストのファイル。[ADR 0050](0050-local-file-access.md)）を確かめてから載せる。読めないものが 1 つでもあれば投稿を断る。AI（bot を含む）も使える。
- **中身はホストの置き場へ。** `<データ置き場>/uploads/<チャンネルの id>/`（Chats は会話の id の下）。投稿を消すと記録の `attachments` は外れるが、置き場のファイルは消さない（会話の添付と同じ）。
- **書きかけは端末に残す。** 入力欄ごと（流れはチャンネル、スレッドはスレッド）に、字（印の行つき）と添付の実体を localStorage に持つ。60 件まで、古い方から捨てる。再読み込み・別のチャンネルへの切り替えで残る。
- **@ の解析は印の行を見ない。** 印の行のパスにある `@` を呼びかけに数えない。
- **Channels の画面に落としたファイルは Chats の入力欄へ入れない。** Chats の受け口は `main` 全体にあるため。

## 理由

- 入力欄の操作が 2 通りあると、覚えることが増え、直すのも 2 か所になる。部品を共有し、決まり（印・順番・行数の上限）を同じにすれば、Chats の入力欄で直したことがそのまま効く。
- 添付の渡し方を Chats と同じ印にすれば、bot の側に新しい読み方を足さず、既存の包み・履歴・記憶の出どころの検査（印の行も本文）がそのまま働く。dispatch（bot の起こし方）は変えない。
- 描画用の記録を別に持つのは、本文の印だけでは「そのパスが何で、画像か、どこから来たか」を描くたびに引けず、ホストのファイルの読み取りの検査（ADR 0050）を通っていない文字列を札にしないため。
- 採らなかった案: Chats の添付の状態ごと `client.mjs` から切り出して共有する（8000 行の画面の下書き・送信待ち・会話の作成に絡み、直す範囲が広すぎる）。投稿に画像の中身（data URI）を載せる（追記だけの記録 `<channelId>.jsonl` が大きくなる。ADR 0115 の考え方）。bot の会話の履歴にも `present` を出す（bot の起こし方の経路に手を入れることになる。必要になったら別に決める）。

## 影響

- 保存の形: `<channelId>.jsonl` の `post` の操作に任意の欄 `attachments` が増える（足すだけ。読めない版・移行は無く、`DATA_SCHEMA` は上げない。この欄を知らない版は無視する）。消した投稿は `attachments` を外す。
- 操作: `channels.post` の入力に `attachments`（辞書 `agent:ops.channels.post.attachments`、`tests/ops-surface.snap.json` を更新）。
- `docs/channels.md` の「データ」「操作」「画面」、`docs/design-system.md` の「チャンネルの流れ」を更新した。
- 画面の確認は `tests/unit/channels-composer-ui.mjs` と `tests/browser/channels-composer.cjs`。
