# 0037 外部エージェントの版への依存を記録と形の検知で扱う

- 状態: 提案

## 状況

Codex・Claude Code・Antigravity は利用者が導入して更新する。Pleiad は公開された接続口に加え、Codex の rollout と Claude Code の transcript など、公開の互換性が保証されない形を読む。上流の更新で一部の補助情報だけが取れなくなることがある。

## 決定

バックエンドごとの接続口、最後に検証した版、必要な最低の版、非公開形式への依存を [multi-backend.md](../multi-backend.md) の一つの表に記録し、リリースごとに見直す。古い版が実害を生む機能に限って最低の版を設ける。非公開形式が読めない、または期待する形と異なる場合は、バックエンド・種類・検知した版・検証した版・時刻のみを、大きさに上限のあるデータ置き場の診断ログへ同じ組合せにつき一度記録する。会話の結果は変えない。

## 理由

- 全バックエンドに最低の版を決めて弾く方法は、利用者が管理する CLI の更新を一律に強制する。Antigravity の `/usage` のように古い版で依頼がモデルへ送られる実害がある箇所には有効なので、その箇所だけに使う。
- 検証した版の記録は、問題を調べる起点になる。ただし新しい版の動作を保証しないため、形の不一致も検知する。
- 接続時の機能検出は公開 API の有無には使えるが、rollout や transcript の全ての行が必要な形で残ることまでは確認できない。
- 新しい版の先行試験は有用だが、利用者が任意に更新する CLI の全リリースを先回りできない。リリース時に確認した範囲を記録する。
- 上限の版を設けて新しい版を弾くと、未検証でも動く更新まで止める。補助情報の形式変化は診断ログで発見する。

## 影響

非公開形式の一部が変わっても、会話は続ける。診断ログは `AGENT_HOST_DATA/backend-shape-errors.log` に置き、64 KiB を超えたら古い行を落とす。古い行が消えた組合せは、再発時に再記録されうる。診断対象にした形以外の変化は検出できない。
