# 0093 解除時刻が分かる使用量の上限から自動で再開する

- 状態: 承認（2026-10-03）。解除後の動き・12 時間の線・解除時刻が不明なときの扱い・再開待ち行列は置換（0132）
- 置き換えられた: 0132（解除後の動き・12 時間の線・解除時刻が不明なときの扱い・再開待ち行列）

## 状況

Claude の上限は `rate_limit_event` または `assistant.error: rate_limit` で届くが、以前は正常終了として扱われ、完了通知と未確認の丸が出た。中断した会話は人が一つずつ再開するしかなかった。[ADR 0036](0036-interrupt-and-update-while-running.md) は、人が止めた作業や更新で止めた作業について「再開はボタンを押したときだけ」と決めていた。

## 決定

- 上限を独立した `limited` の結果と `interrupted.reason: limit` にする。解除時刻、枠、アカウント、バックエンドを会話に保存する。
- 解除時刻が分かり、12 時間以内なら、既定で解除後に自動再開する。上限で止まっている間の指示は API に渡さず、送信待ちに置く。人は会話ごとの自動再開を外せる。全体設定は「自動」「解除時に知らせて人が再開」「何もしない」。解除時刻が不明か 12 時間より先なら自動再開しない。
- 自動再開で送り直すのは、保留・配送失敗の指示、続いて待っていた指示。これらが無ければ、上限で止まった後の続きを求める見える指示を送る。結果不明の指示があれば自動で送らない。最初の指示は重ねない。
- 解除後の再開は、委譲の子を親より先に、通常の会話は最後に人が送った順に並べる。同時に 3 件まで走らせ、新しい枠の使用率が 50% に達したら未開始の再開を止める。実行中のターンは止めない。再び上限になれば新しい解除時刻で並べ直す。
- アカウントの自動切り替えはしない。Claude の別アカウントで続ける操作は人だけが行う。
- 永続する予定はデータ置き場の `schedule.json` に `{ id, kind, sessionId, at, createdAt, by }` と必要な属性を保存する。段階 1 は `kind: resume` を使う。起動時と PC のスリープ解除時に期限を確かめ、遅れても再開する。送信予定の `kind: send` は段階 2 で追加する。

## 理由

解除時刻が分かる上限は、ツールの中断結果が不明な人手の停止と違い、再開条件が明確である。送信待ちの順序と結果不明の確認を維持しながら自動で続けられる。並行数と使用率の歯止めにより、解除直後に多数の会話が一斉に新しい枠を使わないようにする。

## 影響

ADR 0036 の「再開はボタンを押したときだけ」は、`user`・`update`・`quit`・`hostAway`・`restart` の中断に適用する。`limit` は本 ADR の規則に従う。`docs/design.md` と `docs/design-system.md` は今の挙動に更新する。
