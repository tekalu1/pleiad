# 0039 会話の圧縮と文脈メーター

- 状態: 承認（2026-09-27）。Codex の自動圧縮の既定の待ち時間は置換（0046）、全体の既定の最小トークンは置換（0051）、予約を置くターンは置換（0067）、予約をメモリだけで持つことは置換（0068。提案）
- 置き換えられた: 0046（Codex の自動圧縮の既定の待ち時間）、0051（全体の既定の最小トークン）、0067（予約を置くターン）、0068（予約をメモリだけで持つこと）

## 状況

Pleiad は Claude の一時的な圧縮中表示だけを扱い、圧縮の完了・失敗、文脈窓の占有、再表示できる区切りを持たなかった。指示・Skills・MCP の入口を「コンテキスト」と呼んでおり、モデルのコンテキスト窓と取り違えやすかった。利用者は 2026-09-27 に UI の形を承認した。

## 決定

- 指示・Skills・MCP の入口は利用者向けに「プラグイン」／“Plugins”と呼ぶ。内部識別子、`ply_context`、エージェント向け文言、モデルの「コンテキスト長」は変えない。LLM の窓の使用量は「文脈」、会話を縮める操作は「圧縮」と呼ぶ。
- 文脈の量と圧縮の予定・実行中・失敗は入力欄の**上**の一行に置く。文脈メーターは使用量のヘッダーチップから分け、押すと圧縮と設定のメニューを出す。履歴には前の発言を残したまま圧縮の区切りと、得られた場合の要約を置く。会話メニューと `/compact` 候補も手動操作の入口とする。脇の行は予定時刻または次の送信までの「圧縮済み」を示す。
- core が `compaction`（開始・完了・失敗、manual / auto / idle、前後トークン、要約、失敗理由）と `contextWindow`（使用量・窓）へ正規化する。Claude は SDK の境界・状態・フック・使用量、Codex は app-server の通知・item・tokenUsage を使う。Antigravity は手動操作とメーターを出さず、自身の圧縮に任せる。`checkpoint` が圧縮を意味する証拠を得るまでは完了に読み替えない。
- 圧縮の境界はネイティブ履歴にあればそれを優先する。Claude の `compact_boundary` と Codex の `contextCompaction` item は開き直すたびに読み、Pleiad の会話 sidecar に残した trigger・要約・失敗理由を重ねる。ネイティブ境界が読めない場合と失敗時には sidecar の記録で補う。ネイティブ履歴の発言は表示の正本として保つ。渡し済みの指示本文の控えは**圧縮の完了後**にだけ消す。
- 正常終了した利用者ターンごとに、会話につき一つの予約を置く。全体の既定はオン・最小 40k トークン、Claude はオン・50 分、Codex はオフ・有効化時の既定 50 分。子の会話、承認待ち、文脈量不明、会話ごとの除外、実行中は対象外。次の送信・ターン開始、手動圧縮、未送信会話の削除、バックエンドの切替、設定による対象外への変更、キャンセルで予約を取り消す。画面で別の会話へ切り替えるだけでは取り消さず、放置した会話を裏で圧縮する。予定時刻から 8 分を超えた発火は見送り、失敗の再試行と圧縮後の再予約はしない。予約はメモリだけで持ち、Pleiad の再起動で消える。

## 理由

利用枠と文脈窓を別の場所に置くことで、割合の意味を読み分けられる。圧縮の結果を保存すると、過去の発言を読み返すときにも境界が分かる。Claude のキャッシュ保持は約 1 時間を想定して 50 分を既定とした。Codex と Antigravity のキャッシュ保持は未確認なので、Codex の自動圧縮は既定で切る。

## 影響

圧縮イベントと文脈量を受け取れないバックエンドでは自動予約を作らない。Antigravity の `checkpoint` と Codex の要約・実機の動作は、識別できる材料を得てから追加確認する。
