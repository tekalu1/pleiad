# 0085 ホストが git を読み、ターンの始まりと終わりを隠し ref に撮る

- 状態: 承認（2026-10-03）。決定 5（WS の読み取りコマンドの数）と決定 7（右パネル「git」の中身の並び）は置換（0134）
- 置き換えられた: 0134（決定 5・決定 7）

## 状況

エージェントが git で何をしたか（ブランチを作った・ファイルを直した・コミットした・PR を出した）は、今は会話のツールの行と本文にしか残らず、「ツール実行 9」に畳まれて埋もれる。
人はコードを常には見ない。普段は目に入らず、気になったときに「ブランチ・変更・コミット・PR」が分かればよい。

材料の調査（2026-10-01）で分かったこと:

- ホストは git を一度も叩いていない。`core/` にあるのは `.git` の有無の `fs.stat` だけ。
- 差分の元データはエージェントごとに違う。Claude の Edit は `old_string` / `new_string` を持つが、Codex の `fileChange` はパスだけ。エージェントによらず確実なのは **git の作業ツリー**だけ。
- 「この会話の間」の差分の基準を前のターンの終わりにすると、ターンの間にユーザーが外で行った `git pull` などがエージェントの変更に化ける（T3 Code の不具合報告）。基準は「ターンの始まり」に撮り直す。
- 隠し ref 方式は「いつ消すか」を最初から決めないと `.git` に溜まる（同じく T3 Code の報告）。

## 決定

1. **ホストが git を読む。** `execFile('git', …)`（シェルを通さない）・`windowsHide`・タイムアウト数秒・`GIT_OPTIONAL_LOCKS=0`・`GIT_LITERAL_PATHSPECS=1`。読み取り系のサブコマンドの許可表（`rev-parse` `status` `log` `diff` `for-each-ref` `ls-files` `rev-list` ほか）の外は呼び出し側の誤りとして投げる。書くのは次の隠し ref とそのための一時 index・commit オブジェクトだけ。
   cwd は検証済みの会話の cwd（会話の無い下書きは、どれかの会話が使ったことのある場所だけ）。`git rev-parse --show-toplevel` でルートを取り、パスはルート相対で扱う。git が無い・git 管理外・時間切れは例外にせず「情報なし」（画面は何も出さない）。会話ごとに直列化し、cwd ごとに 2 秒のキャッシュ。取り直しはターンの終わり・cwd の変更・会話を開いたとき・パネルの再読み込み。
2. **ターンの始まりと終わりの作業場所を隠し ref に撮る。** `refs/pleiad/turn/<会話 id>/<n>-start` と `-end`。一時 index（本物の index を写したもの）の上で `add -A` → `write-tree` → `commit-tree`（親は HEAD、作者は Pleiad、署名なし）→ `update-ref`。ユーザーの index・HEAD・ブランチ・作業ツリーには触れない。
   - **書き込みの範囲（読むだけより上）のターンで、作業場所が git のときだけ。** 圧縮のターンでは撮らない。始まりの撮影が 6 秒で終わらなければその回は撮らずに始める。
   - 新しい会話は id が決まってから ref を書く（n は既存の最大 + 1）。
   - 何も動かなかったターンは `-end` を書かず、最初のターン以外の `-start` も消す（会話の最初の `-start` は「この会話の間」の基準なので残す）。
   - **保存期間は 30 日。** 撮影のたびに、その作業場所の古い ref を掃除する（プロセスごとに 1 回）。会話を消す口ができたら、その会話の ref も一緒に消す（`forget`）。
   - 「この会話の間」の差分は、最初の `-start` と今の作業ツリーの比較。「このターン」は `-start` と `-end`。
3. **返答の下の 1 行（要約）は、git の状態が動いたターンにだけ出す。** ファイルの変更（始まりと終わりの撮影の差）・コミット（HEAD の変化）・ブランチの作成や切り替え・PR のどれかがあったターン。会話に保存する present の 1 種（`kind: 'git'`、`git: { branch, files, add, del, commits, pr, … }`。`at` はターンの終わりの時刻）にして、ライブも履歴も並びも既存の present の仕組みに乗せる。
4. **「この会話でしたこと」は会話に流れたツールの結果から拾う**（`core/git-timeline.mjs`）。`git checkout -b` / `git switch -c` の引数・`git commit` の結果の `[branch hash] subject`・`gh pr create` の結果の URL。構造化されていないので文字列の読み取りで、拾えなかったものは出さない（推測で作らない）。
5. **WS のコマンドは読み取りの 3 つ**: `gitStatus`（状態。`summary` で会話の間の合計も）・`gitPanel`（状態・したこと・変更の一覧）・`gitDiff`（1 ファイルの統一差分。構造化して返す）。画面の内部の口なので `tests/ops-baseline.json` では `ui-internal`。互換のある追加なので `PROTOCOL_VERSION` は据え置く。
6. **委譲の子の変更を依頼元へ事実として返す。** 子のタスクの完了時に、子の作業場所の会話の間のファイル・コミットがあれば `row.git` に持ち、完了通知に 1 行 `変更: <branch> · N ファイル +a −d · コミット k` を添える（変更が無ければ載せない）。`ply_task_status` / `ply_task_wait` は `git`（構造）と `gitSummary`（同じ 1 行）を返す。
7. **画面**（`docs/design-system.md`「git の動き」）: 返答の下の要約行・頭の行のアイコン（コミットしていない変更があれば点）・入力欄の作業場所のチップのブランチ・右パネルの新しいモード「git」（`web/side-panel.mjs` の `gitSlots`）・委譲カードの「変更」の行。脇の会話の行には何も足さない。マージ・PR 作成の画面は作らない（エージェントに頼む）。

## 理由

- 画面に出すのは「結果どうなったか」だけで、ツールの一覧（何をしたか）とは混ぜない。人は気になったときに 1 タップで辿れればよい。
- 差分をエージェントごとの断片（Edit の old/new）から組み立てると、Codex で出ず、同じファイルへの複数の編集が断片のままになる。作業ツリーの撮影ならエージェントによらない。
- 基準をターンの始まりにすれば、ターンの間にユーザーが外で行った変更や、同じ場所で動いた別の会話の変更がエージェントの変更に化けにくい（同時書き込みの帰属は諦め、時間の境界で分ける）。
- 一時 index に本物の index を写してから `add -A` するので、変更の無いファイルは再計算されず、ユーザーのステージ・index のロックと競合しない。
- 隠し ref なら、ブランチ一覧・履歴・`git status` に出ない。ユーザーのリポジトリへの書き込みにはなるが、ref 名で見分けられ、30 日で消える。

## 影響

- `.git` に `refs/pleiad/` と commit・tree・blob のオブジェクトが増える（`git gc` で整理される。ref を消せば到達不能になる）。.gitignore に無い大きな未追跡ファイル（ビルド成果物など）も blob として入り、ref が残る 30 日の間は消えない。大きなリポジトリでは `add -A` の時間がターンの始まりと終わりにかかる（始まりは 6 秒、終わりは 6 秒で諦める。始まりに間に合わなかったターンは、基準が遅れるので撮らない）。
- `AGENT_HOST_GIT_SNAPSHOTS=off` で撮影だけを止められる（テストが開発中のリポジトリの `.git` に ref を残さないため。状態と変更の一覧の読み取りは止めない）。
- `docs/agent-delegation.md` の「Pleiad が自動的に worktree を作成・マージする機能ではない」は変わらない。分けた作業場所（`git worktree`）はパネルに札を出すだけで、作成・削除・マージは作らない。worktree の自動作成・退避・掃除は別の決定（`temporary/reports/git-worktree-ux-research.md` のフェーズ 3〜4）。
- 要約の present は会話の分岐（fork）にも写る。
- 書き込みの範囲を持たない会話（読むだけ・計画のみ）は撮らず、要約も出ない。パネルの「コミットしていない分」は撮影なしでも出る。

採らなかった案:

- ターンごとに `git stash create` で撮る案（未追跡を含められない）。
- パッチをデータ置き場に保存する案（バイナリと未追跡に弱い）。
- 前のターンの終わりを基準にする案（上記のとおり外の変更が化ける）。
- 要約を毎ターン出す案（変更の無いターンの行は雑音になる）。
- 脇の会話の行に git の印を足す案（印の種類がもう多い）。
