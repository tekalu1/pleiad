# ADR 0171: ホストに任せた子の停滞通知を依頼元で判定する

状態: 提案

関連: [0146](0146-remote-agent-delegation.md)、[0170](0170-delegation-background-notify-not-stop.md)。0170 の決定 6 のリモート例外を、活動の写しを送れる新しい版について変更する。

## 状況

ホスト側のタスクの親は `remote:<deviceId>:<sessionId>` という仮の ID で、依頼元の会話はホストにない。ホスト側の `deliverSilence`・`deliverCommand`・`deliverBackground` はこの ID への通知を成功として捨てていた。端末側の写しも完了通知だけを扱い、長い無音やコマンド、裏の作業待ちを調べなかった。

## 決定

ホストは実行中の子の活動時刻、出力時刻、実行中のコマンド（最大 8 件）、ロック待ち、裏の作業待ち（最大 8 件と最初の通知に添える返答の先頭 4,000 字）を `task.telemetry` に載せる。活動イベントごとには送らず、変化があれば最大 30 秒に 1 回の状態の便りにまとめる。端末は `version: 1` の写しだけを受け、手元のタスクと同じ閾値、文面、通知済みの印を用いて依頼元の会話へ届ける。題には `⇄ <ホスト名>` を添える。

承認待ち・ロック待ちを無音に数えない。裏の作業待ちにはその専用の通知を使い、無音と長いコマンドの通知は重ねない。完了後、オフライン中、`hostLost` の間は判定せず、復帰したホストの新しい状態を受けて再開する。古いホストの便りには `telemetry` がないため完了通知のみになる。古い端末は追加項目を無視する。

## 理由

通知の受け取り可否と重複防止の印は依頼元の会話を持つ端末で管理できる。ホストから通知文そのものを送る案は、端末の会話が受け取れないときの再試行と二重配送の調整が別途必要になる。活動の写しなら既存の `task` の同期にも乗り、切断後の追いつきも同じ経路で扱える。

## 影響

活動の写しが変わったタスクにつき、最大 30 秒に 1 通の状態の便りと端末側の行の更新が増える。通知は写しの到着分だけ遅れうる。ホストの時計が端末と大きくずれている場合、経過時間の判定にもずれが出る。
