# 0154 エージェントの Chrome の窓は最小化せず、画面の外に見えない窓として置く

- 状態: 承認（2026-10-07）

## 状況

[ADR 0148](0148-agent-browser-in-chrome.md) は、会話ごとの専用の窓を `chrome.exe --profile-directory --new-window` で開き、すぐ `ShowWindow(SW_MINIMIZE)` で最小化すると決めた。第 3 段の実機の受け入れ（agent-browser 0.38.1、Chrome 154）で、最小化した窓では agent-browser の主な操作が効かないと分かった。`screenshot` が止まる、`click` が 5 秒かかって効かないことが多い（それでも `✓ Done` を返す）、`set viewport` が失敗する。

別の PC の確かめ専用の Chrome（空のプロフィール）で、置き方を 10 通り以上比べた（2026-10-07、各操作 3 回、`temporary/reports/window-placement.md`（その PC の上））。focus emulation は `Emulation.setFocusEmulationEnabled(true)`、表の「FE」はその略。

| 置き方 | screenshot | click | set viewport | 映像 5 秒 | 利用者から見えるか |
|---|---|---|---|---|---|
| 最小化（0148） | 2.0〜3.1 秒 | 5.0 秒 | 失敗 | 0 フレーム | タスクバー・Alt+Tab に出る |
| 最小化＋FE | 2.3〜2.6 秒 | 0.45〜0.68 秒 | 失敗 | 465 | 同上 |
| 全部の窓の一番後ろ | 79〜105 ms | 5.0 秒 | 効く | 0 | 他の窓を全部最小化すると見える |
| 一番後ろ＋FE | 74〜78 ms | 30 ms | 効く | 465 | 同上 |
| 画面の外＋FE | 87〜103 ms | 28〜33 ms | 効く | 466 | タスクバー・Alt+Tab に出る |
| 画面の外＋タスクバーから外す＋透明度 0＋FE | 95〜120 ms | 32〜38 ms | 効く | 474 | 見えない |

- 最小化は FE を付けても描画が止まり、`set viewport` が失敗する。最小化以外では、FE を付けると click が 5 秒から 30 ms 前後に戻り、映像も届く。FE を付けたセッションを外すと元に戻る。
- 透明度 1/255 は撮影でうっすら見えた。0 は見えない。
- どの置き方でも、`tab tN` が送る `Page.bringToFront` は窓を前に出して前面を取る。最小化は解ける。画面の外の窓でも前面を取る。中継で握りつぶすと、前面を取らず、操作は全部効いた。
- ページの `window.open` も前面を取る。タブで開くと窓を前に出し、`popup` 指定だと新しい窓が画面の左上に出る。
- FE の費用: 120 fps のアニメーションのページで 1 コアの 10〜24 %（FE 無しの hidden は 1〜2 %）。
- `Target.createTarget` に画面の外の `left` を渡すと、15 枚中 11 枚は最初から画面の外に出た。4 枚は一瞬、既定の位置に出た。
- 受け入れで見た「screenshot が 30 秒止まる」は、この確かめでは再現しなかった（窓は `createTarget` で作った。`chrome.exe --new-window` 経由は未測定）。

## 決定

### 置き方

- エージェントの窓は**最小化しない**。0148 の `ShowWindow(SW_MINIMIZE)` を、次の 4 つの組み合わせに置き換える。
  - 通常の窓のまま、**画面の外**（仮想デスクトップの右の外）に置く。
  - `WS_EX_TOOLWINDOW` で**タスクバーと Alt+Tab の一覧から外す**。
  - layered の**透明度 0**、`WS_EX_TRANSPARENT` で**マウスを素通しにする**。
  - **focus emulation** を窓のタブごとに保つ。
- 窓は Pleiad の映像（0148 の右パネル）と「引き継ぐ」でだけ見える。利用者が自分でこの窓を探して触る道は無い。
- focus emulation を保つのは、エージェントのターンの間と、右パネルで映像を見ている間だけ。それ以外は外す（隠れた窓のページが CPU を使い続けないため）。

### 置き方を崩す命令と窓

- エージェントの `Page.bringToFront`・`Target.activateTarget` は、中継が **Chrome へ送らずに成功で返す**（agent-browser の「今のタブ」は自分の側で持つので、操作は変わらない）。
- エージェントの窓から開いた窓（`window.open` の `popup`）にも同じ置き方を当てる（`targetCreated` の `openerId` で見つける）。
- 引き継ぎの外でエージェントの窓が前面を取ったら、Pleiad がすぐ前の窓へ返す。
- モニターの増減、DPI の変更、スリープからの復帰で窓が画面の中へ寄せられても、透明度 0 なので見えない。Pleiad は画面の構成が変わったときに置き直す。

### 引き継ぎと開き方

- **引き継ぐ**: Pleiad が窓を見える形に戻す（透明度・`WS_EX_TOOLWINDOW`・マウスの素通しを外す）。そのうえで、Pleiad の窓のある画面の中へ動かし、前に出す（前に出す手段は 0148 のまま）。**戻す**: 画面の外の見えない窓に戻す。
- 0148 の自動の一時停止は外す。0148 は「前面にあるエージェントの窓で人が入力したら止める」としたが、窓は引き継ぎの外では見えず、触れない。人が操作するのは引き継いだときだけになる。引き継ぎの外で前面を取ったときは、上のとおり前の窓へ返す。
- **開き方**: 最初の窓は 0148 のとおり `chrome.exe --profile-directory --new-window` で開く。題の nonce で HWND を見つけたら、最小化する代わりに上の置き方を当て、前面を取っていたら前の窓へ返す。一瞬見える問題を `--window-position` などで避けられるかは、第 4 段で確かめる。2 枚目からは `createTarget` に画面の外の位置を渡す。

## 理由

- 最小化は FE を付けても `set viewport` が失敗し、描画も止まる。agent-browser の操作が全部効く置き方は、最小化以外に FE を足したものだけだった。
- 一番後ろに置く案は、利用者が他の窓を全部最小化すると見え、画面の中で場所を取る。画面の外だけでは、タスクバーと Alt+Tab に出て利用者が迷う。透明度 0 を足せば、画面へ寄せられた場合も見えない。
- `SW_HIDE` も操作は全部効いた。採らないのは、Chrome が後で自分で表示しうるか確かめていないため。
- `bringToFront` を握りつぶすのは、利用者の前面を取らないという 0148 の前提を、エージェントの命令で崩させないため。前に出すのは人が引き継いだときの Pleiad だけ。
- 自動の一時停止を外すのは、見えない窓では「人がたまたま前に出して入力した」が起きず、誤って止めるほうが害になるため（`window.open` で前面が一瞬移ったときの入力で止まる）。

## 影響

- 0148 の次の部分を置き換える。
  - 専用の窓の開き方の `ShowWindow(SW_MINIMIZE)`（この ADR の置き方にする）。
  - 映像の転送の「focus emulation を常に付ける」（ターンの間と映像を見ている間だけにする）。
  - 自動の一時停止（外す）。
- 0148 の本文は書き換えず、状態の行に追記する。
- `Page.bringToFront`・`Target.activateTarget` を中継の握りつぶしの一覧に足す。内蔵ブラウザーの中継には足さない（第 7 段で消えるため）。
- OS の層（ADR 0153 の `desktop/chrome-os/`）に「隠して置く」「見える形に戻す」「前面を前の窓へ返す」の 3 つの口を足す。
- 第 4 段（会話ごとの専用の窓）は、この置き方で作る。計画の `launchWindow({minimize:true})` は直す。
- 確かめが要るもの:
  - `chrome.exe --new-window` 経由の窓での操作。
  - Chrome が自分で窓のスタイルや位置を戻すことが無いか（全画面・再起動の後のセッションの復元）。
  - モニターの構成が変わったとき。
  - `window.open` で前面が移る間の入力の行き先。
