# 0022 委譲先の自動振り分け

- 状態: 承認（2026-09-26）

## 状況

`ply_delegate` は委譲先の `backend` を親のエージェントに書かせていた。どこへ渡すかは利用者が各自の指示ファイルに振り分け表（仕事の種類 × 委譲先）と「使用量が 80% 以上のものは避ける」を書き、エージェントが `ply_usage` を読んで選んでいた。表の読み違いと使用量の見落としが起き、指示ファイルごとに同じ表を持つことにもなっていた。

## 決定

- `backend` を書かなければ Pleiad が委譲先（backend・model・Claude のアカウント）を選ぶ。**既定で有効。** `backend` を書けば今までどおり固定。
- 仕事の種類 `kind`（9 種類）は親のエージェントが**必ず**申告する（固定のときも記録のために書く）。
- 難しさは外部の判定器が 6 つの手がかり（原因探し・やり方の選択・長い手順・部品の多さ・共有物への書き込み・安全の最終確認）に真偽で答え、Pleiad の規則で low / mid / high に数える。判定器へ送るのは `kind` と依頼文だけ。既定は OpenRouter の Jev（`typesafe/jev-1.13`）、設定で Cerebras（`qwen-3.8-27b`）や「判定しない」を種類ごとに選べる。
- 種類 × 難しさ → 段（t1〜t4、画像・新規 UX は tv）→ 段の候補を左から、使用量の枠（避ける線 80%・週次のペース 1.2・取得から 15 分）で飛ばしながら選ぶ。全部だめなら 1 つ上の段、それでもだめならエラーで返す。**委譲先・アカウントは判定器に決めさせず、コードで決める。**
- 選んだ理由（種類・判定器・手がかりと確率・難しさ・段・委譲先・飛ばした候補と理由・使用量の取得時刻・判定の失敗理由）を `routing` として返り値・タスク・子の会話に残す（0007: 暗黙の変更をしない）。
- 判定器のキーは互換の接続先と同じ秘密の置き場に置き、画面には `hasKey` だけ返す。**キーの登録が外部送信の同意**で、キーが無ければ外へは何も送らず難しさは mid とする。

## 理由

- 検証（実例 41・合成 5 の 46 件と、定義を決めた後に集めた 30 件）で、判定器に使用量と振り分け表を渡して委譲先まで決めさせると、ほぼどの判定器も正解率が下がった（使用量で飛ばす判断と Claude のアカウント選びで崩れる）。判定を層に分け、判定器には手がかりだけを答えさせ、委譲先はコードで決める形にした。
- 種類を判定器に当てさせるより、親が申告するほうが確か（親は依頼の意図を知っている）。判定器は難しさの手がかりに絞った。
- Jev は確認用の 30 件で委譲先の正解 86.7%（規則で数えた正解に対して）、p50 188ms / p95 378ms、1 件 約 $0.00008。Cerebras の Qwen は規則の正解に対して 96.7% だが、直感の難しさを正解にすると Jev と同じ 77%。速さと費用で Jev を既定にし、Cerebras は選べる予備にした。
- 残る課題は判定器より規則: 規則と直感の難しさの一致は 67% で、ずれの多くは「直感では高いのに規則では中」。実際の委譲の記録（`routing` と、失敗・やり直し）を貯めて規則と閾値を見直す。

## 影響

- `ply_delegate` の `kind` が必須になり、`backend` は任意になった。指示ファイルの振り分け表は要らなくなる。
- 振り分けのために、サーバーが使用量を定期的に（5 分ごと・委譲の直後）取り直す。
- 仕様は agent-delegation.md「委譲先の自動振り分け」。設定の画面（設定 › 委譲・委譲カードの理由）は次の段で作る。
