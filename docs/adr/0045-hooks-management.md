# 0045 Hooks をコンテキストの 4 つ目の種類として管理する

- 状態: 承認（2026-09-27）

## 状況

Claude Code・Codex・Antigravity（agy）は、どれもイベントに合わせてコマンドを実行する hooks を持つ。置き場所（ユーザーとプロジェクト、JSON と TOML）、形（Claude と Codex はイベント → matcher group → handler、agy は名前 → イベント → handler）、止め方（Claude は個別に止められない、Codex は定義の hash ごとに信頼を審査して `/hooks` で止める、agy は名前の `enabled`）がそれぞれ違う。
Pleiad の会話はこれらのエージェントを起動するので、ネイティブの hooks はそのまま動く。一方で、どこに何が登録されていて、会話で何が起きたかを Pleiad から見る手段が無かった。コンテキスト（指示・Skills・外部 MCP）の画面は「次の会話に何を渡すか」と「この会話に何が渡ったか」を扱っているが、hooks はその外にあった。

2026-09-27 の UX 提案（設定のカード・行の詳細・追加と編集のシート・写す／そろえる前の確認・会話の右パネル・狭い画面）をユーザーが承認した。

## 決定

- **hooks をコンテキストの 4 つ目の種類として扱う。** 設定 › コンテキストに「Hooks」のカードを足し、会話の右パネルにも面を足す。部品と見た目は他の種類と同じ（担当の 2 択・ユーザーと作業場所の 2 段・行と行の詳細・`<dialog>` のシート）。
- **担当の 2 択は「設定を誰が用意するか」の意味にする。** どちらでも実行するのはエージェント。
  - エージェントに任せる（既定）: 各エージェントの元の定義を読む。利用者が明示した編集だけを元のファイルへ書く。効く範囲はその設定のスコープ全体（Pleiad 以外から起動した会話を含む）。
  - Pleiad がそろえる: Pleiad 独自の登録を、選んだエージェントの Pleiad から始める会話へ渡す。第 1 段では選べず、選べない理由を表示する。
- **抑止のために元のファイルを書き換えない。** 元のファイルへ書くのは、利用者がシートやスイッチで明示した編集だけ。書く前に書き先ごとの差分を見せる。
- **止める操作はエージェントごとに正直に出す。**
  - Claude Code: 定義を残したまま 1 件だけ止める設定が無いので、スイッチを出さない（「登録あり · 個別停止なし」）。削除して退避する偽の「オフ」も作らない。
  - Codex: 信頼の審査を代行しない。信頼状態を安全に取れない間は「取得できません」とし、`/hooks` を案内する。停止のスイッチは出さない。
  - agy: 名前単位の `enabled` をスイッチにし、元のファイルへ書く。同じ名前の全イベントに効くことを示す。
- **管理者・プラグイン・Skill の定義は編集も抑止もしない。** 読める範囲で読み取りのみの行にする。
- **会話の右パネルは受け取った事実だけを出す。** 設定で見つけた定義は「登録あり · 読み込み未確認」まで（有効・実行済みに格上げしない）。発火はエージェントから通知を受け取れたものだけを「発火の記録」に出し、受け取れない接続は「観測できません」とする。記録が無いことを未実行の証明として扱わない。
- **段階を分ける。**
  1. 見える化とネイティブ編集（3 エージェントの探索・出どころ・定義の保持・伏せ字、command 型の追加・編集・削除、agy の名前単位の停止、Codex の `/hooks` 案内、Claude の発火の記録）
  2. 他のエージェントへ写す（agy を含む。対応イベントの限定変換・エージェント別の matcher・入出力の変換・Codex の再審査・写す前の確認）
  3. Pleiad がそろえる（正本・revision・ネイティブの抑止・注入・会話への記録。二重実行を防げる組み合わせだけ提供する）

## 理由

- hooks は「エージェントへ何を渡すか」の一部で、出どころと対象の管理はコンテキストの仕事。最上位の設定ページを増やさず、既存の担当・段・行の考え方にそろえたほうが、種類ごとに責任を選ぶ理解を保てる。
- 実行の主体はいつもエージェントなので、担当を「実行する者」の意味にすると誤解を生む。「設定を用意する者」と読めば、2 択を残したまま将来の「そろえる」も同じ場所に置ける。
- 止め方がエージェントごとに違う以上、全行に同じオン・オフを置くと、押しても止まらない・Pleiad からだけ止まったように見える、という嘘が生まれる。止められないものは止められないと書くほうが、利用者が本当の止め方（削除・`/hooks`・`enabled`）へたどり着ける。
- hooks はコマンドを自動で実行する。元のファイルを黙って書き換えたり、観測していない実行を「実行済み」と表示したりすると、利用者が知らないうちに実行範囲が変わる。ADR 0031（広がる前にその場で確かめる）と、右パネルは渡した事実だけという既存の原則に合わせた。
- 採らなかった案: 3 列固定の一覧（長いコマンドが窮屈で、イベントと handler の関係が見えにくい。切り替えで残した）、名前だけで重複をまとめる（スコープと条件が違えば別の実行）、第 1 段から「そろえる」を並べる（ネイティブの抑止と注入を検証していない）。

## 影響

- 探索と書き込みは `core/hooks-config.mjs`（`scanHooks` / `readHook` / `hookTargets` / `saveHooks`）。書き込みは `core/mcp-config.mjs` と同じく revision で競合を見つけ、JSON は他のキーを残し、TOML は hooks の表だけを置き換え（できなければ書き直しの許可を求め）、一時ファイルから rename する。
- 設定のカードとシートは `web/hooks-card.mjs`、右パネルは `web/session-context.mjs`。形は docs/design-system.md「コンテキスト」の「Hooks」、動きは docs/context-management.md「Hooks」と docs/context-runtime.md「Hooks」。
- Claude の会話は `includeHookEvents` で hooks の開始と応答の通知を受け、会話に `hookRuns` として残す（出力は持ち出さない）。
- `context-scans.json`（形式 3）の `kinds` には第 1 段では hooks を入れない。担当は固定で、保存する設定が無いため。形式の移行は、担当や除外を保存する第 3 段で決める。
