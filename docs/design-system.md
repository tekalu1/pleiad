# デザインシステム

### 入力欄の設定（2026-09-23）

入力欄の下の行は「添付・作業ディレクトリ・モデル・承認モード・中断・送信」。設定は 3 つのチップにまとめる（`web/composer-controls.mjs`。承認済みのモックは [composer-controls.html](mockups/composer-controls.html)）。
「どこで」= 作業ディレクトリ（フォルダーのアイコン + 末尾の名前、等幅。全体のパスは title）、「誰が・どれだけ考えて」= モデル（「Opus 5.5 · high」）、「どこまで任せるか」= 承認モード（盾のアイコン + 名前）。
チップは button。押す（Enter / Space）と上へ浮く面が開き、Esc でチップへ戻る。面の外を押すと閉じる。一覧の中は ↑↓ で移る。面の幅は画面に収める（360px の画面でもはみ出さない）。

- **チップの字は全部同じ色・太さ。** 「既定から外れた設定を青く太く」はやめた。既定が何か見えないまま色だけ変わっても判断材料にならないため。
  代わりにチップは**実際に使う値**を出す。「既定に従う」でも、既定が当たるモデル・段を解決して名前で出す（Claude は SDK の `supportedModels()` と CLI の既定の段、codex は `config/read` と `model/list`、Antigravity は `agy models` を起こしたときの agy のログの選択。`core/backends/antigravity-models.mjs`）。解決できないときだけ「既定」と書く（Antigravity は「既定（agy の設定）」）。段が決まらない（既定の段が分からず既定に従う）ときはチップに段を書かない
- 差を付けるのは 1 箇所だけ: 承認モードが確認なし・制限なし（`core/modes.mjs` の軸で範囲 full・自律 never。YOLO）のとき、チップと一覧の行に ⚠ と強い字（`--ink-strong`、太字）。色は足さない
- 一覧の「既定」は右端の弱い字の札（面も色も付けない）。既定の行を選ぶと値は `''`（既定に従う）で保存し、既定が変われば追従する
- 作業ディレクトリの面: 上にパスの入力欄（Enter で決める。自由に打てる）→「最近の作業ディレクトリ」（末尾の名前 + 全体のパス + いつ使ったか。今のものに ✓）→「フォルダーを選ぶ…」。
  デスクトップ版は OS のダイアログ（`plyDesktop.chooseFolder()`）、ブラウザー版は面の中に簡易ブラウザー（サーバーの `listDirs` がフォルダーの名前だけを返す。`..`・ドライブ・「このフォルダーにする」）。読めないフォルダーは面の中に理由の一文を出す。文言はどちらも「フォルダーを選ぶ…」だけ
- モデルの面: 「エージェント」（2 つ以上あるときだけ。区切りボタン）→「モデル」（版付きの名前 + 補足。既定が当たる行に「既定」）→「エフォート（考える量）」→「Claude のアカウント」（従来アカウントを出していた会話だけ）。
  エフォートは段のスライダー。段はモデルが対応するものだけ、目盛りの下に既定の段の印「既定」、既定から動かしたら「既定に戻す」。段を選べないモデル（Haiku など）は無効にして「◯◯ は段を選べません」（理由が分かるものはその理由。CLI エージェントの接続先など）。
  既定の段が分からないとき（Codex の互換の接続先、など）は**「既定」の段を作らない**（本当の段ではないため）。既定に従っている間はつまみを出さず「既定（◯◯の設定に従う）」と書き、動かすと段が決まり、「既定に戻す」で外せる
- Antigravity: `agy models` の表示名を使い、段違いの id（`gemini-3.8-flash-high` / `-medium` / `-low`）は系統ごとに 1 行（「Gemini 3.8 Flash」）にまとめる。段はエフォートのスライダーで選び、送信時に同じ系統の段違いの id を `--model` に渡す（agy の `--effort` は段違いを選ぶことと同じで、`--model` と同時には渡さない）。段違いの無いモデル（`claude-sonnet-4-6` など）は段を選べない。以前の会話が持つ段違いの id もそのまま使え、その系統の行に ✓、段はその id の段
- 互換の接続先（Claude Code・Codex。2026-09-23。承認済みのモックは [compat-endpoints.html](mockups/compat-endpoints.html) の案 A）: 3 つのチップのまま。
  モデルの面は「エージェント」→「接続先」→「モデル」→「エフォート」→「Claude のアカウント」→ 下に文字だけのボタン「接続先を管理…」。入力欄の行に専用の欄は置かない。
  「接続先」の先頭は「公式」（補足「Anthropic · ログイン中のアカウントで使う」／「OpenAI · ChatGPT のログインで使う」）、下に登録した互換の接続先（補足「Anthropic 互換 · ホスト」「Responses 互換 · ホスト」）。
  新しい会話の既定の接続先に「既定」の札。確認に失敗している接続先は名前の前に ⚠、補足に「⚠ 確認に失敗しています」（警告色は使わない）。消えた接続先を選んでいる会話は「削除された接続先 / 選び直してください」の行を残し、入力欄の上に一文。
  互換の接続先を選んでいる間は、節の下に弱い字の 1 行「使えないもの: 使用量 · Fast mode · 料金の目安 · Web 検索（不明）」（Codex は「使用量 · Web 検索 · 料金の目安」）。
  モデルの節は検索と ID の入力を兼ねる欄（placeholder「検索、または ID（空ならメインの ◯◯）」。Enter で決める。空ならメインのモデル）＋接続先の一覧（メイン → 今のモデル → 一覧の順。メインの行に「既定」の札、Claude は Opus・Sonnet・Haiku 相当に割り当てた行に右寄せで役割名）。一覧に無い ID は Enter でそのまま使う。↓ で一覧へ移り、行で Enter。一覧の下に操作の注記は置かない（§2.7）。
  **モデル ID の表示**（互換の接続先の全箇所で同じ。`web/compat-models.mjs` の `compatModelLabel`）: 字は表示名（`anthropic/` の名前空間は残りに `/` があるときだけ隠す。末尾の `[1m]` は外して、字の横に小さな「1M」の札 `.cbadge`＝中立の灰の pill・弱い字・等幅）、title は送る ID。札を置けない字だけの場所（「次のターンから適用」など）は「（1M）」。一覧取得で display_name・コンテキスト長が取れた接続先では、候補の 2 行目に「Cohere: Command A+ · コンテキスト 256K」（取れない接続先では出さない）。
  **検索**: 大文字小文字を区別しない部分一致、空白区切りは AND（表示名・送る ID・display_name のどれに当たってもよい）。描くのは先頭 50 件だけで、残りは弱い字の「ほかに N 件。文字を入れて絞り込んでください」。当たらなければ「一覧にありません。Enter でこの ID をそのまま使います。」。
  チップは「接続先 · モデル」（段が決まっていれば「 · 段」。モデルは表示名で 1M は札。長い接続先名・モデルは真ん中を詰める。段は削らない。全体（送る ID）は title）。
  エフォート: Claude の互換の接続先は「思考を送る」がオフなら無効にして「送らない（接続先の設定）」。オンの接続先と Codex の互換の接続先は既定の段が分からないので「既定」の段を作らない。
  Claude のアカウントの節は消さずに、互換の接続先では選べない見た目（弱い字・✓ なし）＋「互換の接続先ではアカウントを使いません」の 1 行。
  接続先を変えるとモデルは接続先の既定（メイン）に戻る。エージェントを変えると、変えた先の既定の接続先（設定で「既定にする」を押したもの。無ければ公式）。右クリックメニューにも「接続先（次のターン）」
- 変更は従来どおり「次のターンから適用」欄に出して取り消せる。右クリックメニューも同じ語彙（版付きの名前。「既定に従う（Opus 5.5 (1M)）」）

### Claude のアカウント（2026-09-22）

会話入力欄のモデルの面（「入力欄の設定」）に「Claude のアカウント」の節を置く。先頭は「ログイン中」（既定。「既定」の札）。既定以外も字の色は変えない。変更は「次のターンから適用」欄に出して取り消せる。セッションの右クリックメニューにも同じ選択肢を置く。アカウントを 1 件も登録していない（かつ選んでもいない）会話には出さない＝従来と同じ見た目。選んでいたアカウントが消えた会話は「削除されたアカウント」と表示し、入力欄の上に選び直しの一文を出す。
登録は設定の「エージェント設定」の Claude Code の行の「アカウント」から開く。面・カード・入力欄・確認は設定の管理の面の部品（`web/manage-panel.css` の `.mp-panel` など。互換の接続先の管理と共通）を使い、トークンは伏せ字の入力欄で受けて保存後は表示しない。削除はその場の確認（`.mp-confirm`）で行う。
追加は「表示名 →『ブラウザーで認可する』（塗りのボタン。この面で唯一の主要操作）」。押すと一覧の下に進み具合のカード（`.mp-card`）が出て、「1. ブラウザーで…『承認』を押してください」「2. ブラウザーに表示されたコードを貼ってください」とコードの入力欄・送信を並べる。開かないとき用のリンクを弱い文字で添える。トークンの登録が済んだら同じカードで「使用量の表示を認可」へ続ける（「あとで」も選べる）。各アカウントの行には「トークン登録済み · 使用量の表示: 認可済み／未認可」を小さく出し、「トークンを発行し直す」「使用量の表示を認可（認可済みなら、使用量の認可をやり直す）」「編集」「削除」を文字だけのボタンで置く。トークンの手動貼り付けは追加・編集のフォームの折りたたみ（`details`）に残す。使用量の画面では未認可のアカウントの見出しの下に案内文と「使用量の表示を認可」を出す（2026-09-23）。
トークンの持ち主が使用量の認可と別のアカウントのとき（サーバーの `tokenCheck` が `mismatch`、または別の登録と同じアカウントの `sameTokenAs`）は、その行の下の `.mp-confirm` の面に ⚠ と強い字（`.mp-warn`。`--ink-strong`・太字、警告色は使わない）で「このトークンは「個人用」のアカウントで発行されています（使用量の認可は …）。ブラウザーで claude.ai のログインを切り替えてから、トークンを発行し直してください。」と出し、「トークンを発行し直す」を添える。認可の完了のカードでも同じ一文と「閉じる」「トークンを発行し直す」を出す（2026-09-23）。

### 互換の接続先の管理（2026-09-23）

設定の「エージェント設定」の Claude Code・Codex の行に文字だけのボタン「接続先」を置き、押すと同じページの下に管理の面（`.mp-panel`。`web/compat-endpoints.mjs`）を開く（Claude のアカウントと同じ開き方。もう一度押すと閉じる）。
- 説明文は最小限（§2.7）。冒頭の説明段落・一覧の下の保存先の段落は置かない。
- 一覧: 先頭は「公式（ログイン中のアカウント）」の行（消せない・編集しない。「既定にする」だけ）。互換の行は `.mp-card` に、名前・URL・最後の確認の結果（「✓ 確認済み（日時）」または ⚠ と強い字で「⚠ 確認に失敗: 理由（日時）」）・「メイン:」のモデル（Codex は「モデル:」）の 4 つだけ。
  認証方式・キーの保存場所・全役割のモデル・使えないもの・思考の送り方は一覧に出さない（編集の画面で見る）。
  操作は文字だけのボタン「既定にする」「接続を確認」「編集」「削除」（削除はその場の `.mp-confirm`「「◯◯」を削除しますか。選んでいる会話は選び直しが必要になります。」）。新しい会話の既定にできるのは「既定にする」を押したときだけ（入力欄で選んでも既定にはならない）。
  キーを暗号化できない起動のときだけ、末尾に強い字の 1 行「この起動ではキーを暗号化できません（本人だけが読めるファイルに保存します）。」
- 追加・編集は同じ面の中で 5 段（上に進み具合「✓ 種類 · 2. 接続情報 · 3. 接続を確認 · 4. モデル · 5. 保存」。今の段は `--ink-blue`）。
  段ごとの説明文は置かない（§2.7）。欄の下の補足も原則置かない。
  ① プリセットの格子（`.mp-preset`。名前＋短い補足。選んだものは紙の面＋影）②名前・URL（combo。プリセットと地域違いの URL を候補に。下の一文は書き間違いのときだけ「末尾の /v1 は要りません。」「<リソース名> を実際の値に置き換えてください。」）・API キー（伏せ字＋「表示」。下に「キーは OS の資格情報に保存します。」の 1 行。キー不要のプリセットでは出さない）・「詳しい設定」（`details`。認証の送り方の区切りボタン: Claude は 自動（確認で判定）/ Bearer / x-api-key、Codex は Bearer / api-key ヘッダー。プリセットの既定から変えているときだけ開いておく）
  ③結果は `.mp-result`（成功は「✓ つながりました · モデル N 件」だけ。注意があるとき（確認のモデルが受け付けられなかった、一覧が取れなかった）だけ行を足す。失敗は ✕ と強い字で理由と、直す手がかりの短い行。Codex で Chat Completions だけの先は理由と「LiteLLM などで Responses API に変換すると使えます。」）
  ④ Claude は役割の割り当て 4 欄（メイン・Opus・Sonnet・Haiku 相当。combo で一覧から選ぶか入力。欄の字は表示名＋「1M」の札、title は送る ID。候補は検索できる 2 行の combo（下の §4.4）で、数百件でも先頭 50 件だけ描く）と「詳しい設定」（コンテキスト長、「思考を送る」と 1 行「Claude 以外では失敗することがあります。思考が必須のモデル（kimi-k2.7-code など）ではオンに。」）、Codex は既定のモデルとコンテキスト長。空の役割は保存のときにサーバーが理由付きで断るので、先に説明しない
  塗りのボタンは「接続を確認」か「保存」のどちらか 1 つだけ（確認が通ると「保存」に替わり、横に文字だけの「もう一度確認」）。確認前は、ボタンの左に弱い字で「確認で短い応答を 1 回だけ生成します（わずかに料金がかかることがあります）」（料金のことはここで 1 回だけ）。URL・キー・認証を変えると確認前に戻り「接続情報が変わりました。もう一度確認してください。」
- 使えない機能の出し方: ① 入力欄のモデルの面の接続先の節の下の 1 行 ② 設定 › 使用量のエージェントのカードに「接続先 ◯◯」の見出しと「使用量は表示できません。残高は ◯◯ の管理画面で確認してください。」（ローカルは「使用量は表示できません（ローカル）。」）、末尾に「互換の接続先の分の参考費用は当てになりません（単価が不明）。」
  互換の接続先の会話で Web 検索のツールが失敗したら、そのカードの下に弱い字で「この接続先（◯◯）では Web 検索を使えません。」と文字だけのボタン「接続先の詳細」（`.tc-note`）

### アプリの更新（2026-09-18）

左サイドバーの会話一覧の下に、ダウンロードの進捗バーと取得できた進捗%を表示する。会話のフォーカスを移さない。
更新準備が完了すると同じ位置の通知を「更新を見る」「あとで」に切り替える。

設定の「アプリ情報・更新」に進捗、最終確認、変更内容をまとめ、再起動を選ぶとその場に保存・再起動の確認を出す。
主要操作は同時に一つ。更新の設定はチェックボックスで、自動確認・自動ダウンロード・先行版を選ぶ。
面は既存surface、補足はink-weak。失敗はその場の文章と再試行で示し、警告色や自動で開くモーダルは使わない。

### ファイルプレビュー（2026-09-15）

ファイルリンクは右パネルで開き、ファイル記号と「表示中」で開いている対象を示す。パネルは `--surface-0`、本文は `--surface-paper`。既存の文字・ボタン・角丸を使う。会話と本文は独立してスクロールし、境界のドラッグ／左右キーと「広げる」で幅を調整する。1150px以下で左右に並べる間は会話一覧を畳み、760px以下は全面プレビューと「会話へ」に切り替える。閉じる／Escは元のリンクへフォーカスを戻す。全面表示では背景をinertにする。

名前・相対パス・原文切替・完全パス・再読み込みを上、取得時刻・保存・会話で使うを下に置く。本文だけがスクロールする。未対応・欠損・読取不可は本文位置に理由を表示し、保存できる場合は保存操作を残す。詳細は [ファイルプレビュー](file-preview-proposal.md)。

### 発言の操作（2026-09-15）

発言の下に「ここから分岐」、ユーザー発言には「編集して再送信」「再送信」を並べる。
ホバー・キーボードフォーカスで表示し、タッチ画面では常に表示する。狭い幅では折り返す。
編集欄は吹き出しの面・角丸・余白を使い、添付名と取り消し・紙飛行機の送信ボタンを置く。
根で分岐した会話も、最初の発言より前に枝の切り替えを表示する。

コードは共通ブロックの右上に言語とコピー操作を置く。ボタンはホバー・フォーカスで表示し、タッチ画面では常に表示する。
コピー成功時は短時間チェックに変え、クリップボードが使えないときは本文を選択して手動コピーを案内する。
コード本文と操作列を分けることで、長いコードや言語名とボタンの重なりを防ぐ。既存トークンだけを使う。

### 使用量（2026-09-14）

設定メニューの「使用量」に3種のエージェントを並べる。使用率と残率を同じ行に置き、その下にプログレスバー、リセット日時を表示する。枠の名称・期間・モデル名を省略せず、色だけに意味を持たせない。取得できなかった値は「不明」、時刻を過ぎた枠は「更新待ち」と表示する。面は既存の surface、数字・補足は既存の ink を使う。狭い画面では使用率の行を折り返し、表を横にはみ出させない。

### エフォート（2026-09-14）

会話入力欄のモデルの面（「入力欄の設定」）に「エフォート」を段のスライダーで置く。段はエージェント・モデルに応じて取得し（`efforts` の `''` に既定の段 `resolvesTo`）、既定の段に「既定」の印。変更は既存の「次のターンから適用」欄に表示し、取り消せる。セッションの右クリックメニューにも同じ選択肢を置く。狭い画面では入力欄の操作列を折り返す。

互換の接続先（Claude Code・Codex）の仕様は `docs/design.md`「互換の接続先」。エージェント設定内の接続先の管理と、会話入力欄の接続先／モデルの選択を分ける。

### 作業中の送信（2026-09-12）

実行中も発言の「⑂ ここから分岐」を使える。保存済みの履歴を分岐先に引き継ぎ、元の実行は続ける。
保存前の発言や未完了ツールを含む位置では、その場に再試行の案内を表示する。
子の作成と履歴取得が成功してから選択を切り替える。

実行中も送信ボタンと Ctrl+Enter を使える。通信で受領を確認する短い間だけ同じ会話の送信を無効にする。受領までは入力を保持し、成功後もその間に編集された下書きは消さない。

入力欄の上に送信待ちを順番に並べ、本文・配送状態・取り消しを表示する。送信待ちの配送状態は待っている理由で書き分ける（この会話の作業待ち「作業が終わると自動で送信」、前のメッセージ待ち）。何も走っていない会話に「作業が終わると」とは出さない。保留・失敗・結果不明の場合は再送を出す。結果不明は、会話の確認と再送による重複の可能性をそのメッセージに表示する。リロードや別セッションからの復帰でも復元する。配送後は通常のユーザー発言として会話に入り、ライブ表示に「AIへ送信済み」を添える。面・文字は既存トークン、待機欄は最大180pxでスクロールする。

## 1. 空気

製品名は **Pleiad**（プレイアド。プレアデス星団の一つで、複数のエージェントを一つの群れとして束ねる）。旧名は Ply。
左上に A / FOLD のシンボルと A1 / QUIET の文字ロゴを並べる。
正本は `web/brand/pleiad-icon.svg` と `web/brand/pleiad-wordmark.svg`。文字もパスで持ち、フォントに依存しない。
文字ロゴの P と l は旧 Ply の文字ロゴの形をそのまま使い、e・i・a・d を同じ筆致で足した。
縦線は幅 20（P は 19）、鉢の横方向の太さ 18・上下 16、ベースライン 86・x ハイト 27（viewBox の高さ 104）。
a・d の鉢は P の鉢を左右反転した形で、l・i・a・d の右下は l と同じはねで終える。表示は高さ 24px（幅 79.8px）。
画面では SVG の `use` で参照し、既存の色トークンで明暗テーマに追従する。単独ファイルでは濃紺と青になる。
favicon は `web/favicon.svg`（青い角丸の地に白いシンボル）。ページタイトルは `Pleiad`。
セッション一覧のエージェント表示はロゴのみ（3種とも14px、縦横比維持）。名前はツールチップと読み上げ用に残す。
Codex は OpenAI Blossom、Claude Code は Claude マーク、Antigravity は Antigravity マークを使う（出典は `web/brand/README.md`）。
3種とも背景なしの透過表示。OpenAI は明テーマでは黒、暗テーマでは白（`--ink-brand`）。Antigravity は Google の青（`--ink-antigravity`。暗テーマでは明るい青）。右上ヘッダーにはエージェント名を重複表示しない。
狭い画面ではロゴの下に操作ボタンを並べ、双方を表示する。

参考にしたのは「ほぼ白に近い青みグレーの地に、濃い青の線と文字、ごく稀に赤紫の一本線」という構図。
色そのものより、**面がほとんど無彩色で、意味は線と文字が担っている**という配分を借りた。

| 要素 | UI での役割 |
|---|---|
| 薄い青みグレーの地 | `--surface-3`（`#dcdee8`）と、白側へ寄せた `--surface-0/1/2`。脇のパネルは `--surface-0`、会話は白 `--surface-paper` |
| 濃い青 | `--ink-blue`（リンク・今いる枝・効いているフィルター・選んだ印 ✓）と `--fill-primary`（主要操作。唯一の塗り） |
| 青 | `--line-blue`（今いる枝・伸びる枝・フォーカスの輪） |
| 淡い青 | `--line-strong`（分岐点の曲線・リンクの下線） |
| 赤紫 | `--ink-mark`。**「あなたを待っている」だけ**に使う差し色 |

本文の文字色は黒ではなく濃い紺 `#1c2247`。地が白でも、線と文字が同じ族に見える。

**形は全部曲線。** 会話の筋と枝が曲線なので、部品の角も立てない（`--r-s` 8 / `--r-m` 14 / `--r-l` 20 / `--r-pill`）。
ボタン・入力欄・候補一覧・札は pill、カード・面は 14〜20px。四角い要素は表のセルと等幅のコードだけ。

「有機的」は曲線・`--ease-organic`・枝分かれ・走っている弧の揺らぎで出す。「デジタル」は 1px の筋・等幅の数字
（`tabular-nums` を body 全体に）・脇のパネルに敷いた 24px 間隔の点・考えている間に線の上を走る光で出す。
グロー・ネオン・影の多用はしない。

## 2. 守る原則

### 2.1 「薄い色地 + 同系の濃い文字」の札を作れないようにする

- 面（`--surface-*`）は無彩色〜青みグレーのみ。OKLCH の彩度 C が 0.015 未満であることを lint が確かめる
- 文字（`--ink-*`）は本文・強い・弱い・青 の 4 種と差し色 1 種。面と文字で同じ語幹のペアを**命名として持たない**
- 有彩色の面は `--fill-primary` ただ 1 つ。文字は必ず `--on-fill`。「薄い面に濃い同系文字」は構造的に組めない

### 2.2 枠線を使わない。片側の線も使わない

区切りは**余白・面の階調・配置**で作る。入力欄・カード・ボタン・表・コードのどれにも枠は無い。
`border-left` のような片側の線は、意味を持たせても持たせなくても使わない。

| 意味 | 表し方 |
|---|---|
| 選ばれているセッション | 行が白（`--surface-paper`）へ持ち上がる。脇の地はグレーなので面の階調で分かる |
| あなたを待っている | 筋の節が ◆（差し色）になり、見出しの一語が差し色。一覧では ◆ + 「承認待ち」 |
| 走っている | 白い弧が回る（§6）。色ではなく動き |
| 完了・未確認 | 実行中の弧と同じ位置に直径9pxの静止した青い丸。`--ink-unread: #5665cd`（明暗共通）。会話を開いて確認すると消える |
| 失敗 | 行の面を一段持ち上げ（`--surface-1`）、太字の「✕ 失敗 · exit 1」。色は付けない |
| サブエージェント・Pleiad タスクの状態（作業ダイアログの行、2026-09-22） | 行の左端に 14px の印。実行中 = 回る弧（§6。走っている間だけ DOM に置く）、完了 = 静止したチェック、失敗 = 静止した ✕（ツールカードの「✕ 失敗」と同じ語彙）、停止 = 静止した短い横線、分からない = 印なし。弧と同じ線幅 1.6・端は丸・`currentColor`。塗りの円を含まない線画なので青い丸（完了・未確認）と形で見分けられる。各印に `role="img"`・`aria-label`（実行中 / 完了 / 失敗 / 停止）・`title`。Pleiad タスクは queued・cancelling・waiting も弧、cancelled・interrupted は横線で、文字の状態はそのまま残す |
| 放置 | 記号 ◌ と等幅の日数。失敗ではないので警告色を使わない |
| diff | 記号の列（+ / −）と面の階調。追加は白地 + 本文色、削除は `--surface-3` + 弱い文字 |
| 効いているフィルター | 文字（アイコン）が青くなる。囲みも下線も無い |
| 入力欄の設定（既定かどうか） | **色で示さない。** チップは実際に使う値を出し、一覧の既定の行に弱い字の「既定」の札。例外は確認なし・制限なしの承認モードだけ（⚠ と強い字） |
| 決着したカード | 節が ◇ になり、全体が 55% に沈む。触れば戻る |

線そのもの（`--line-*`）が残っているのは、会話の筋・枝・分岐点の曲線・フォーカスの輪・リンクの下線だけ。
どれも「枠」ではない。

### 2.3 必要でない限り採用しない

無いもの: 場面切替、脇の「セッション」の見出し、↻、状態の見出しの ▾ と件数、接続状態のフッター、topbar の状態欄、「送信」の文字。

- 接続状態は**困っているときだけ**出す。切れたら脇の下に「接続が切れた。再接続している…」の一行が現れ、戻れば消える。
  平常時の情報（host・プロトコル・遅延）は設定にも表示しない
- ボタンの既定は文字だけ。ホバーで面が付く。塗りは主要操作（送信・許可・回答する）にしか使わない。1 画面に 1 つ
- 「拒否」「中断」のような、押せるが主張しないものは薄い面（`.btn-quiet`）
- 「中断」はターンが走っている（または承認・回答を待っている）ときだけ出す
- 触れたときだけ現れるもの: 発言の「⑂ ここから分岐」、状態の ＋、アイコン未設定の状態のアイコン枠

### 2.4 人間が入力する箇所は同時に選択肢も提示する

標準の `<select>` `<datalist>` は使わず、独自のプルダウン（combo、§4.4）を全部の入力に使う。
入力欄をフォーカスすると候補が浮く。候補は履歴・既出の値。選んでも、そのまま打ち込んでもよい。↑↓ Enter Esc で操作できる。

| 適用先 | 候補 | 打ち込んだとき |
|---|---|---|
| 作業ディレクトリ（入力欄のチップの面。「入力欄の設定」） | 最近使ったディレクトリ（いつ使ったかを添える）・「フォルダーを選ぶ…」 | そのパスを使う |
| 状態 | 既出の状態と件数 | 新しい状態がその場で生まれる（design.md §6） |
| モデル・承認モード（入力欄のチップの面） | 版付きのモデル名（Opus 5.5 …）/ 都度確認 / auto / 編集は自動 / 計画のみ（挙動を添える） | 選ぶだけ（打ち込まない） |
| 設定 › コンテキストの場所の追加・探す場所 | 最近の会話の場所（いつ使ったか） | そのパスを使う |
| 外部 MCP の名前・コマンド・URL・環境変数名 | エージェントの登録にあるもの（名前を選ぶとつなぎ方も写す） | 打ち込んだ値を使う |
| 入力欄のカーソル位置の `/` | スキル（名前・引数の書き方・説明・見つかった場所。§4.4 の `.clist` と同じ面） | 候補を確定するとその位置に `/名前 ` が入り、続けて引数や別のスキルを打てる |

`/` の候補は、コンテキスト画面と同じ探索結果（`core/context-scan.mjs`）から `skillList()` で作る。
文中・改行後・2つ目以降の `/` でも、カーソルがスキル名の中にある間は候補を出す。日本語の直後は空白なしでも使える。URL・ファイルパスの内部では出ない。
確定時はカーソル位置の `/名前` だけを置き換え、前後の文章・他のスキルを保持する。既存の空白は増やさず、カーソルを確定したスキルの後ろへ戻す。
確定は Enter / Tab / クリック。Ctrl+Enter は候補が開いていても送信のまま。
一致が無いときは「一致するスキルがありません」を出して閉じない（打ち間違いに気付ける）。

### 2.5 状態はアイコン。ラベルに固定で紐付けない

- 状態は SDK の tag（自由文字列）。**既定のアイコンはフォルダ**（インライン SVG、線幅 1.6、弱い色。触れると本文色）
- グループごとに絵文字を設定できる（見出しのアイコンを押して選ぶ、§4.2）
- アイコンは SDK に無いので sidecar `~/.agent-host/statuses.json` に `{ [statusId]: { icon } }` で持つ。
  人間が選んでも AI が渡しても同じ場所に入る（design.md §2.2）。改名で移り、削除で捨てる
- 「走っている」は状態ではなく事実なので、状態のアイコンは動かない。走っている印はセッションの行に付く

### 2.6 分岐は会話の中で起きる（§7）

### 2.7 説明文は最小限（2026-09-23）

- 見出し・ラベル・ボタン・状態（「✓ 確認済み」「⚠ 確認に失敗: 理由」）・プレースホルダーで伝わることは、段落や欄の下の補足で繰り返さない
- 文として残すのは「知らないと事故になること」（料金がかかる、選び直しが要る、暗号化できない、など）と「失敗の理由」だけ。どれも 1 行の短文。同じことは画面の中で 1 回だけ
- 仕組みの説明（どの URL に何を送るか、なぜそうなっているか）は画面に書かず、docs に書く。既定のまま使うことが多い設定は「詳しい設定」（`details`）に畳む
- その状況のときだけ出す文（URL の書き間違い、暗号化できない起動）は、状況が無ければ出さない

## 4. 部品

### 4.1 脇のパネル（セッション一覧）

```jsonc
// バックエンド（正本）
session: { id, title, status /* tag。自由文字列 or null */, cwd, lastModified, parent }

// sidecar ~/.agent-host
statuses.json: { "進行中": { "icon": "◐", "createdAt": "…" } }   // 状態のアイコンと、人が作った時刻。既定はフォルダ
sessions.json: { [id]: { statusChangedAt, history, parent, ungrouped, … } }   // ungrouped = 人がグループから外した印

// host（localStorage。端末ごとでよい）
{ "filter": { "dir": "D:\\work\\my-app" | null, "status": "進行中" | null /* 状態なし */ | undefined /* 絞らない */ },
  "collapsed": ["状態なし"], "expanded": ["<根の sessionId>"], "theme": "auto|light|dark" }
```

**言葉を 2 つに分ける。** 見出し = **状態**（`status` の値ごと）。器 = **グループ**（fork でつながった会話のまとまり）。
「状態を変える」は見出しの話、「グループを作る／解除する」は会話のまとまりの話。同じメニューに並んでも読み分けられる。

見出し = `status` の値ごと。**tag が使われた時点でその状態が存在する**。人が右クリックの「新しい状態を作る」で先に作った空の状態は、
`statuses.json` にある限り存在する（セッション 0 件でも出る。削除で消える）。最後に「状態なし」。
見出しに出るのは「今どれかのセッションに付いている状態」と「`statuses.json` にある状態（`listStatuses` の `kept`）」だけ。
履歴にだけ残っている旧名（改名・削除の前の名前）は combo の候補には出るが、見出しにはしない（削除した状態が空のまま残らないため）。
順序は `listStatuses` の順（既出順 = 初めて使われた順、`firstUsedAt`）。並べ直すのはサーバだけで、脇はその順に従う。

| 部品 | 見た目 | 挙動 |
|---|---|---|
| ヘッダー | 左に Pleiad のアイコンと文字ロゴ、右に ＋ と設定 | ＋ = 新しいセッション（§4.3 の引き継ぎ）。設定 = 配色（自動/明/暗）と接続情報 |
| 検索 | 白い pill、プレースホルダ「検索」 | タイトル・状態・作業ディレクトリの部分一致。フィルターとは独立（AND） |
| フィルター | 検索の右に漏斗のアイコン。効いていると青 | 押すと浮く面に絞り込みの欄と「作業ディレクトリ」「状態」の候補（件数付き）。面は画面の 60% まで、超えたら中でスクロール。単一選択、2 軸は AND。選ぶと検索欄の下に札（`場所 chaxx ×` `状態 進行中 ×`）が出て、× で外す |
| 状態の見出し | アイコン（触れると薄い丸）+ 名前（太字）+ ＋（触れたとき） | 名前を押すと畳む。アイコンを押すとアイコン選択（§4.2）。右クリックで「アイコンを変える」「名前を変更」「新しい状態を作る」「削除」。一覧の空白の右クリックでも「新しい状態を作る」。＋ = この状態で新しいセッション |
| 行 | 見出しから 16px 右に下げる。タイトル + 印 + 時刻（等幅）+ 作業ディレクトリ末尾 | 押すと選ばれ白へ持ち上がる。選択中も状態の combo は出さない。状態変更は右クリックメニューに集約する。右クリックでメニュー。つかんで別の状態へ落とすと状態が変わる（「状態なし」へ落とせば外れる） |
| fork の印 | タイトルの前に枝の印（12px、線幅 1.8、弱い色） | fork で生まれた会話に付く。**グループから外しても、状態を変えても消えない**（「誰かの続き」という事実は変わらない）。押せない、見るだけ |
| グループの器 | chevron + 根のタイトル。畳んでいる間は下の行に要約。開くと面が `--surface-2` へ一段沈み、中の行がさらに 16px 右に下がる | fork した会話（根とその子孫）をひとつの器に入れる。**見出しはフォルダの役目だけで、選べない**（押すと開閉。開閉は `expanded` に残る）。枝の枝も同じ器に平らに入る（入れ子の器は作らない）。既定は畳んだ状態。今いる会話が中にあれば開いて出し（人が畳むまで）、畳んだままなら見出しの面を白へ持ち上げて場所を示す。右クリックで「グループを解除」「グループの状態を変更」「根の会話を開く」。つかんで別の状態へ落とすと**グループごと**移る |
| グループの中の行 | ふつうの行と同じ。根の行も**自分の題をそのまま出す**（先頭に並ぶことが根の印） | 根の会話はこの行から開く（見出しからは開かない）。器の見出しと同じ題が並ぶが、**題を別の文字に置き換えない**（置き換えると、根の会話の名前が変わったように読める）。中の行は根と同じ状態なので、行に状態は出さない |
| グループの要約（畳んでいる間） | 印（弧・衛星・未確認・◆）+ 状態と件数（`進行中 3`） | 開かずに中の様子が読める。**枝の本数は出さない**（件数がそれを兼ねる）。承認待ちは文言を出さず ◆ だけ（2 件以上なら数を添える） |
| つかんでいる間 | 掴んだ行・見出しは白 + 影（`--shadow`）で持ち上がる。落とせる状態は面が `--surface-1` に、落とせる器は `--surface-3` に一段動く | 線は引かない。空になった状態はこの画面に残る（「まだ無い」） |
| 元に戻す | 脇の下に一行（白い面、`--shadow`）。下端からは少し浮かせる。右端に×（閉じるだけで、取り消さない）。押すか、閉じるか、次の操作か、12 秒で消える | 状態が黙って動く操作（グループの出入り・移動・解除・作成）のあとに出す。1 本ずつ元の状態と所属に戻す |
| 走っている | 白い弧（§6） | ターンが走っているセッションに付く。畳んだ見出しの中に走っているものがあれば見出しに同じ弧 |
| 裏で待っている | 衛星（§6.1） | main は返答済みで、裏の subagent などだけが動いているセッション。点の数が本数（3 まで）。畳んだ見出しは、走っているものが無く待っているものがあるときだけ衛星 |
| 承認待ち | ◆ + 「承認待ち」（差し色） | 承認・質問を待っているセッション |
| 放置 | ◌ + 日数（等幅） | `statusChangedAt` から 7 日動いていない。状態が付いているものだけ |
| 接続断 | 脇の下に一行「接続が切れた。再接続している…」 | 切れている間だけ |

絞っているときは空の状態を出さない。絞っていないときは全部の状態を出す（空なら「まだ無い」）。

#### グループ（fork でつながった会話のまとまり）

**グループは持ち物ではない。** 次の 3 つで決まる（`web/family.mjs`。サーバは `core/server.mjs` の `canGroup` で同じ規則を持つ）。

1. 親子でつながっている（fork の `parent`）
2. **状態が根と同じ**
3. 人が外していない（sidecar の `ungrouped`）

だから操作は 2 つしかない。**状態を変える**と出入りし、**外した印**を付け外しする。覚えるのは 3 の印だけ。

| したいこと | 操作 | 起きること |
|---|---|---|
| 枝を別の状態へ | 行をつかんで別の状態へ落とす／行の右クリック「状態を ◯◯ に」 | 状態が変わり、グループから出る。その 1 本だけが動く |
| 枝を外すだけ | 行を今と同じ状態の空きへ落とす／「このグループから外す」 | 状態はそのまま。同じ見出しの下に単独の行として並ぶ |
| 戻す・入れる | 外にある行を器へ落とす／「「◯◯」のグループに入れる」 | **状態が根に揃い**、器に入る。ひとつの操作にまとめる |
| グループごと移す | 見出しをつかんで別の状態へ落とす／見出しの「グループの状態を変更」 | 中の会話も一緒に状態が変わる（サーバが根の移動として広げる） |
| まとめて作る | 根の行の右クリック「枝をまとめる」 | 散らばった枝の印を外し、状態を根に揃える。まとめる相手が無い行にはこの項目を出さない |
| 解除する | 見出しの右クリック「グループを解除」 | 全員に外した印を付ける。状態はそのまま。**解除は覚える**（自動で作り直さない） |

fork した枝は**親の状態を引き継いで生まれる**（`core/server.mjs` の fork）。そうでないと生まれた瞬間に親のグループから外れる。
AI が `set_status` で状態を変えたときは、その会話 1 本だけが動く（人の操作と違い、グループごとには広げない）。

器は**絞り込みを通った行だけ**で組む。親が絞り込みで消えていれば、枝は入れる一番近い祖先に付く（状態が違う枝を飛ばして根に付くこともある）。
付ける先が無ければその枝が根になり、自分の状態の見出しの下にただの行として出る（検索で枝だけが当たったときはこの形）。
枝の順は器の中でも同じ規則（放置が先、あとは新しい順）。器そのものは中で一番新しい行の時刻で並ぶので、枝が動けば器ごと上に来る。
操作モック: [fork-grouping.html](mockups/fork-grouping.html)（器の形）、[fork-grouping-actions.html](mockups/fork-grouping-actions.html)（出入り・作る・解除する）。

### 4.2 アイコン選択（絵文字ピッカー）

浮く面（312px、角丸 14、影）に上から: 検索欄（打つと即絞り込み。日本語・英語どちらでも当たる。絵文字を貼ると先頭にそれが候補として出る。Enter で先頭の候補）→ カテゴリのタブ（アイコンだけ。押すとその節へスクロール）→ 「最近使った」（localStorage、16 件）+ カテゴリごとの格子（8 列、セル 30px、絵文字 20px。触れると薄い丸、押すと確定）→ 「既定に戻す」（フォルダ）。
絵文字の一覧は `web/emoji.mjs`（外部依存なし。8 カテゴリ、1 件 = [絵文字, 英語の語, 日本語の語]）。
重いので起動後の空き時間に `import()` で先読みし、押した瞬間は面と弧（§6）を先に出す。カテゴリの格子は一度作った DOM を使い回す。
選ぶと sidecar の `statuses.json` に入り、「既定に戻す」で消える。絵文字は色を持つが、状態の識別に人間が選んだものなので許す。

### 4.3 新しいセッションの引き継ぎ

**絞り込み中に作られるセッションは、その条件を引き継ぐ。**

| 起点 | 状態 | 作業ディレクトリ |
|---|---|---|
| ヘッダーの ＋ | フィルターの状態（絞っていなければ無し） | フィルターの場所（絞っていなければ入力欄の今の値） |
| グループの ＋ | そのグループの状態 | フィルターの場所（絞っていなければ入力欄の今の値） |

会話は空。引き継いだ状態と作業ディレクトリは入力欄のチップに入っている（会話の頭に説明の一行は出さない）。
「新規」を押した時点でホストのセッションIDを作り、状態・タイトル・作業場所・エージェントを保存する。
ネイティブ実行は最初の送信時に作り、以後も同じホストIDを使う。未送信の行は別セッションを開いても消さない。

### 4.4 combo（独自プルダウン）

`web/combo.mjs`。DOM: `<label class="combo [up] [mono] [right]"><input><ul class="clist" hidden></ul></label>`
（静的な入力欄は index.html にこの形で書き、動的に作るものは `createCombo()` が骨組みごと作る）。

- フォーカス / クリックで候補が全部出る。打ち込むと部分一致で絞る（完全一致なら全部出す）
- ↓ ↑ で候補を移動、Enter で確定（候補を指していなければ打ち込んだ値で確定）、Esc で閉じる。候補のクリック（mousedown）でも確定
- blur で閉じて確定。100ms 遅らせるのはクリックを取りこぼさないため
- 既定から外れた値でも字の色は変えない（以前の `.loose` は廃止。「入力欄の設定」）
- 候補は `options()` が返す `{ value, label?, hint?, sub?, badge?, search?, title? }` の配列。補足（hint）は等幅の弱い文字。
  `sub` は 2 行目の弱い字（互換の接続先のモデルの display_name など）、`badge` は字の横の小さな札（「1M」。確定した値に札があれば入力欄の右にも出す）、`search` は絞り込みにだけ使う字、`title` は送る値（字が表示名のとき）
- 絞り込みは大文字小文字を区別しない部分一致で、空白区切りの語は AND（`web/search-terms.mjs`）。数百件になりうる候補（モデルの一覧）は `limit` で先頭の数十件だけ描き、末尾に選べない弱い字の行「ほかに N 件。文字を入れて絞り込んでください」。`emptyText` を渡すと、当たらないときに自由入力の案内を出す
- 打った字は、今の値の表示のまま（触っていない）なら値を変えない（表示名が同じ候補があっても取り違えない）。value → label の順に一致すればその候補
- 向き: 画面の下にあるものは上へ浮く（`.up`）、脇のものは下へ
- **変えられないときは無効の見た目**（`disabled`）: 文字は `--ink-weak`、cursor は default、触れても面が付かず候補も開かない。
  入力欄のエージェント・モデル・作業ディレクトリは実行中も次のターンの分を予約できる（チップは無効にしない）。
  選択専用の入力はホバー時 pointer、編集・候補検索中は text。無効なものは default

### 4.5 会話

- `.thread` の左 12px に 1px の縦線（SVG `line`、`--line`）。発言は筋の上の節（直径 7px、`--surface-3`）。
  発言の入れ物 `.mw` は「左 72px の溝 + 中身」の 2 列で、筋（x=20）・節・分岐点の曲線は溝の側に置く（溝の中に文字は無い）。
  中身は枝を畳むために `overflow:hidden` を持つが、節は外にあるので切られない
- 待っているカードの節は ◆（`--ink-mark`）、決着したら ◇（`--ink-weak`）
- 利用者の発言は `--surface-2` の 20px 角丸、最大 680px、左寄せ（筋に乗せるため）。AI の返答は面なし、最大 860px
- 発言に触れると右上に「⑂ ここから分岐」
- md: 見出し・表・コード・引用に枠は無い。表は `--surface-1` の面に見出し行 `--surface-3`、偶数行 `--surface-2`。
  コードは `--surface-2`、言語札は右上の `--surface-3`。引用は `--surface-1`。インラインコードは `--surface-2` で文字色は本文のまま
- ツール呼び出し: 動詞のラベル（読む・探す・編集・実行）+ 等幅の本文色 + 補足 + 右端に結果（弱く）。
  失敗は行の面を `--surface-1` に持ち上げ、太字の「✕ 失敗」。出力・差分は折り畳み
- 承認カード・質問カード: `--surface-1` の 20px 角丸。見出しの一語（「承認を待っている」「答えを待っている」）が差し色、
  ツール名は等幅の本文色。操作は「許可」「回答する」だけ塗り、「拒否」は薄い面、「常に許可」「答えずに進める」は文字だけ。
  左端に「許可しないと、このターンは止まったまま」。決着後は節が ◇、全体が 55% に沈み、結果の一行だけ残る
- 入力欄: 添付（画像は 56px の角丸の縮小、それ以外はファイル名の札。× で外す。押すと `<dialog>` で大きく見る）、
  `--surface-1` の本文（フォーカスで `--surface-2`。高さは中身に追従: 最小 3 行、最大は画面の 40%）、下の行に
  クリップ（ファイルを選ぶ。ドロップ・貼り付けも同じ列に入る）・作業ディレクトリ・モデル・承認モードのチップ（「入力欄の設定」）・
  中断（走っているときだけ）・送信（塗りの円 + 紙飛行機）。
  **添付は送るまで会話に出ない**。送信で `runTurn` の `attachments` に載り、core が present として会話に流す（AI の提示と同じ経路）
- 稼働表示（考えている・ツール名・経過時間・サブエージェント N）は会話の筋の末尾の節。走っている間だけあり、
  新しい発言が来るとその下へ移る。節の代わりに弧（§6）が筋の上に載る。固定の帯や流れる線は置かない。
- 送信が届かずに戻された（`turnEnd` の `requeued`）ときは、出した吹き出しを引っ込めて送信待ちに戻す。改めて送られると吹き出しが出る
- 会話の画像（present）は押すと同じ `<dialog>` で大きく見る（閲覧だけ。面は白、枠線なし。× / Esc / 外側のクリックで閉じる）

## 5. lint で縛るルール

`node tests/lint-design.mjs <file...> [--strict] [--json] [--selftest]`。`npm test` の `design-lint` が
`web/tokens.css web/style.css web/tools.css web/index.html` を `--strict` で検査し、違反があれば落ちる。

| id | 何を落とすか | 既定 / strict |
|---|---|---|
| `color-literal` | `#hex` `rgb()` `hsl()` 名前色 が、トークン定義以外の色プロパティに直書きされている | 既定 |
| `same-hue-pair` | 同じ規則の `background` と `color` を（テーマごとに）解決して OKLCH に落とし、面の C≥0.015 かつ 文字の C≥0.06 かつ 色相差<45° | 既定 |
| `tinted-surface` | `--surface-*` の値が C≥0.015 | 既定 |
| `paired-token` | `--x-bg` と `--x-fg`/`-text`/`-color`/`-ink`/`-line`、または `--x-bg` と有彩色の `--x` | 既定 |
| `one-sided-line` | `border-top/right/bottom/left(-width/-style/-color)` の単独指定、`inset` の影で片側に置いた線。角丸と `transparent` は拾わない | 既定 |
| `unknown-token` | 色プロパティの `var(--x)` が未定義 | 既定 |
| `border-use` | 見える枠線（`border*`、`0`/`none`/`transparent` 以外）。要る箇所は同じ行に `/* allow-border: 理由 */` | strict |
| `family` | `background` は `--surface-*`/`--fill-*` のみ、`color` は `--ink-*`/`--on-fill` のみ、線と影は `--line-*`/`--surface-*`/`--shadow`、`text-decoration` は `--line-*`/`--ink-*`、SVG の `fill`/`stroke` は `--line-*`/`--ink-*`/`--fill-*`/`--surface-*`/`currentColor` | strict |
| `fill-without-on-fill` | `background:var(--fill-*)` の規則に `color:var(--on-fill)` が無い | strict |
| `token-outside-root` | テーマの 3 スコープ以外に色リテラルを持つトークン定義 | strict |

閾値の根拠: 面の彩度 0.015 は、旧配色の札の面（C≈0.026–0.029）と新しい面（C≈0.005–0.014）を分ける谷。
文字の彩度 0.06 は無彩色の文字を巻き込まない高さ。色相差 45° より近ければ同系（補色や青地に赤文字は対象外）。

既知の穴: `@supports`・`@layer`・`:is()` の入れ子は素通し。`outline` は枠線に数えない（フォーカスの輪のため）。

## 6. 走っている印

**点滅しない。回る。色は本文の文字色。**

- **弧だけ**: 台（暗い円）は置かない。色は `--ink`（ライトでは濃い紺、ダークでは明るい）。白い弧 + 暗い台の案は
  利用者が「黒い円は要らない。中身だけにして色は文字色と一緒に」と退けた。文字と同じ色なので、どの面の上でも文字と同じ強さで読める
- **弧**: 半径 5、線幅 1.6（アイコンと同じ）、端は丸。円周 ≈ 31.4。一覧の行・畳んだ見出し・稼働表示・アイコン選択の待ち、全部 `runMark()` が作る同じ部品
- **動き**: 先端と尾の角度を毎フレーム JS が決める。**どちらも単調非減少**。止まりかけることはあるが戻らない。弧が短くなるのは尾が追いつくとき

```
head(t) = θ(t)                          θ'(t) = ω·(1 + a1·sin(2πt/T1) + a2·sin(2πt/T2 + φ))   a1 + a2 < 1 なので θ' > 0
tail(t) = min(θ(t − τ), head − gmin)    尾は先端が τ 秒前に居た場所を追う。単調な関数の min は単調
弧の長さ = head − tail                  下限 gmin、上限 ≈ vmax·τ
ω 180°/s（1 周 2s）  a1 .6 T1 2.4s  a2 .3 T2 1.7s φ 1.1  τ .65s  gmin 24°
```

| 値 | 理由 |
|---|---|
| ω 180°/s | 1 周 2 秒。1 秒だと忙しく、3 秒だと止まって見える |
| a1 .6 / a2 .3 | 最遅 18°/s（ほぼ止まる）〜最速 342°/s。止まる瞬間があるから生き物に見える。合計 < 1 で逆転しない |
| T1 2.4s / T2 1.7s | 2 つの揺らぎを重ねると同じ形が 20.4 秒に 1 度しか戻らない |
| τ .65s | 弧が 24°〜約 220° の間を呼吸する。1 周を超えない |
| gmin 24° | 弧が消えて見えない瞬間を作らない |

`prefers-reduced-motion` では静止した 3/4 周（0°→270°）。回らなくても「途中」の形で走っていると分かる。
実装（`web/arc.mjs`）: `.run` 要素の `<path>` を 1 本の rAF ループでまとめて更新する（要素数に依らず 1 ループ）。
document から外れた印は忘れ、残りが無ければループを止める。印は走っているときだけ DOM に置く（CSS で隠すだけだと回り続ける）。
この規則は**動く印**（弧・衛星）のためのもの。作業ダイアログの完了・失敗・停止の印（§2.2、`stillMark()`）は静止していて rAF に載らないので、終わった行に置いたままでよく、この規則とは矛盾しない。

### 6.1 裏で待っている印（衛星、2026-09）

2026-09-17: ターンが完了し、バックグラウンド端末だけが残った場合は衛星・AIの経過時間を出さない。
会話一覧は通常の完了時の表示とし、会話ヘッダーの「端末 · 件数」から稼働中の端末を開く。
サブエージェントの結果待ちは引き続き衛星で示す。手動の状態タグは変更しない。
バックグラウンド一覧の行は詳細表示専用。停止は隣の独立したボタンで行い、行クリックでは停止しない。
端末詳細にはコマンド、作業場所、起動時刻、取得できた出力を表示する。出力は表示中に更新し、終了後は最後の取得内容であると明記する。

main が返答を終え、裏の subagent などだけが動いているとき（ターンの `phase` が `waiting`、multi-backend.md §2.2）。
ターンはまだ終わっておらず、送れば途中送信になる。弧のままだと「まだ考えている」と読めてしまい、
消すと「終わった」と読めてしまう。その間を表す。承認済み案 A（`output/visualizations/bg-wait-mark.html`）。

**弧と同じ場所・同じ色で、線ではなく点が回る。** 点の数は裏で動いている本数（3 個まで）。`satMark(n, title)` が作る。

```
angle_i(t) = θ(t·0.5) + i·360/n + 14·sin(1.3t + 2.1i)     θ は弧と同じ関数（§6）
点 i の位置 = 中心 (7,7) から角度 angle_i、半径 4.6（14×14 の viewBox）
```

| 値 | 理由 |
|---|---|
| 点の半径 1.45 | 直径 2.9 は弧の線幅 1.6 の 2 倍弱。14px の中で「点」と読める最小。線と同じ細さだと弧の欠片に見える |
| 軌道の半径 4.6 | 弧の半径 5 より少し内側。4.6 + 1.45 = 6.05 < 7 で viewBox から出ない。同じ場所に居る「同じ族の印」に見える |
| θ(t·0.5) | 弧と同じ揺らぎの関数を半分の速さ（平均 1 周 4 秒）で回す。同じ族に見え、急いでいない＝待っていると読める |
| i·360/n | 点を等間隔に置く。本数が形で分かる |
| ±14°、1.3 rad/s | 点ごとに前後して間隔が詰まったり開いたりする。揺れが無いと剛体の回転（読み込み中の輪）に見える |
| 位相 2.1i | 点ごとに揺れをずらす。同じ位相だと全部が揃って動き、揺れが消えて見える |
| 上限 3 | 4 個以上だと 14px の円周では点がつながり、輪に見える |
| 色 `currentColor`（`--ink`） | 弧と同じ。色で意味を足さない（§2.2） |

使う場所: 一覧の行（`裏で N 本が動いている`）、畳んだ状態・グループの見出し（中に動いている行が 1 つでもあれば弧、無くて待っている行があれば衛星）、
会話末尾の稼働表示（見出しは「サブエージェントを待っている」。「サブエージェント N」の文字ボタンはそのまま）。
2026-09-22: 「サブエージェント N」の N は走っている子（状態が分からない子を含む）だけを数える。走っている子が無く、同じターンで終わった子だけが残っているときは「サブエージェント · 終了 N」として、ダイアログから結果の会話を読めるようにする。

ターンの外に残った裏の作業（multi-backend.md §2.7 の会話単位の background）も、待てるもの（§2.2 の `behindOfTasks`）があれば衛星にする。
今これを出すのは Codex のバックグラウンド端末だけで、端末は数えないので衛星は出ない（上の 2026-09-17）。

`prefers-reduced-motion` では静止し、点は真上から等間隔に並ぶ。実装は弧と同じ 1 本の rAF ループが `<circle>` の `cx/cy` を更新する。
弧と同じく、待っている間だけ DOM に置く。

## 7. 分岐

通常の続きと fork を、共通の会話の先で同じ高さのノードとして並べる。分岐点自体にはノードを置かない。
2026-09-11 承認済みモック `temporary/design-system/mock-branches-parallel.html` に合わせた実装。

1. **配置**。共通発言の後に高さ176pxのグループを置く。分かれ目は y=16、選択ノードは y=96、下の会話軸への接続は y=176。現在の枝が x=20。その他は同じ高さで横に並び、数が多いときはグループ内で横スクロールする。
2. **表示**。現在の枝は青く塗ったノードと「現在の会話」。生成中のノードも青くする。その他は淡い輪、名前、続きの件数。分岐中の会話軸の節もエッジと同じ青に揃える。承認待ちの◆は従来の意味を保つ。長い名前は省略し、title と読み上げ名で全文を確認できる。会話の末尾に選択ノードを別途置かない。
3. **作成**。実際の子セッションが作れたら、780msでその枝の線を伸ばし、後半で先端ノードを現す。伸び終わってから新しい枝をメインにする。成長中は元の会話が選択されたまま。API が失敗した場合は元の会話を残してエラーを示す。
4. **切り替え**。選択先の履歴を先に取得する。共通の本文を保持し、選択したノードと以前のメインを560msで横に入れ替える。共通部分まで本文を畳んだり線を巻き戻したりしない。本文は420msでフェードし、タイトル・入力先も選択先に揃える。共有DOMの発言UUIDは選択先のUUIDに更新する。
5. **曲線**。上下とも三次ベジェで縦の接線を持つ。下側も移動中はS字で会話軸へ追従し、軸に着いたら縦線になる。加減速は `cubic-bezier(.22,.72,.18,1)`。`prefers-reduced-motion` では即時切り替え。
6. **系譜と更新**。枝はセッション。`parent.atMessage` または共通接頭辞で境界を決める。複製UUIDの違いは役割・本文・ツール名で照合する。家族の履歴は `loadSession` の `outline`（uuid・役割・本文・ツール名だけ）で読む。全文を運ぶと大きな会話のある家族で数十MBが流れ、開いた瞬間に固まる（実測 57.2MB → 1.9MB）。空の枝にも選択肢を残す。ライブDOMが複数履歴をまとめる場合は最寄りの既存アンカーを使い、線を落とさない。切り替え中の系譜更新は完了後に再取得する。
7. **通常の会話**。初期化時に必ずSVGの筋を作る。追記とResizeObserverの両方で再配置するため、初回会話でもリロードなしに線が出る。筋は分岐グループの上下で区切り、動くノードの裏に直線を残さない。
8. **キーボード**。Tabでノードへ、Enterで切り替え。左右矢印で同じグループを移動、Home/Endで両端へ。操作中は二重切り替えを防ぐ。選択状態は `aria-pressed` でも示す。
9. **スクロール**。作成・切り替えのアニメーション開始前に、分岐点・エッジ・ラベルが会話欄内に収まる最小限のスクロールを行う。上下には24pxの余白を取り、会話欄が小さいときは分岐点側を優先する。分岐操作中は末尾追従とブラウザーのスクロール補正を抑え、入力欄へのフォーカスでも位置を動かさない。

計算は `web/branches.mjs`、ノードの表示・曲線・加減速は `web/branch-view.mjs`、会話の入れ替えと通知の同期は `web/client.mjs` が持つ。

## 9. 仮置き・未決

### 設定の画面（2026-09-15）

設定はモーダルをやめ、画面全体に出す。歯車を押すと脇のセッション一覧が設定メニュー（エージェント設定／使用量／外観／コンテキスト／アプリ情報・更新）に、会話が選んだページに入れ替わる。今のダイアログの 2 列構成を画面に広げた形で、pill 列や横タブは置かない。理由: コンテキストの探索結果はツリーとプレビューの 2 列で、900px のダイアログに収まらない。

左列は脇と同じ面（`--surface-0` + 点のグリッド）のまま、ロゴの位置に「会話に戻る」を出す。Esc でも戻り、元の歯車へフォーカスを返す。見出し「設定」は左列に 1 つ、右列の上はページ名だけで、行の高さ・字下げ・選んだページが白へ持ち上がる規則はセッションの行と同じものを使う。狭い画面は body の列幅がそのまま効き、ページ側は左右の余白だけを会話に合わせる。

会話は `display:none` ではなく `visibility:hidden` で伏せ、設定のページをその上に重ねる。消すと筋のスクロール位置と入力欄の高さが失われるため。ページの中身と要素 ID は変えず、置き場所だけを移す。更新の適用中は途中で再起動するので、その間だけ「会話に戻る」と左メニューを止める。「Pleiad へようこそ」は独立した dialog のまま。

### コンテキスト（2026-09-20。承認済みモック `docs/mockups/context-unified.html`）

2026-09-15 のツリー（左）とプレビュー（右）の 2 列、「読み込み担当」「探索の設定」、スコープごとの保存ボタンは廃止し、次の 2 つにした。理由: 利用者の問いは「どこに何があるか」ではなく「次の会話に何を渡すか」と「この会話に何が渡ったか」で、前者は設定、後者は会話の側にある。

#### ② 設定 › コンテキスト（`web/context.mjs`・`web/mcp-config.mjs`）

1 列の 1 画面。上から、説明の一行、「設定する範囲」の独自プルダウン、種類のカード 3 枚（指示ファイル・Skills・外部 MCP）、「探す場所を増やす（任意）」の折りたたみ、保存の知らせ。

#### ① 会話の右パネル「この会話のコンテキスト」（`web/session-context.mjs`）

会話の頭（最初の発言の下）に札「指示 2 · Skills 14 · MCP 3（1 件つながらない）」（エージェント任せの種類は「MCP はエージェント任せ」、固定後に変わっていれば「· 変更あり」）。`--surface-1` の pill、弱い文字、触れると本文色。押すとファイルプレビューと同じ右パネル（`web/file-preview.mjs` の `openPanel`。幅・Esc・狭い画面の全面表示・閉じたときに札へフォーカスを戻すのを共有し、道具の列と下端は出さない）に開く。タイトル行の「コンテキスト N」も同じパネルを開閉する（札は長い会話ではスクロールで見えなくなるため）。

パネルは脇と同じ地に白い面を並べる: 開始後に変わったときの知らせ（「開始後に 1 件変わりました」「AGENTS.md が 14:31 に更新」、主要操作「新しい内容で会話を続ける」、「差分を見る」で行の差分を − / + の記号と面の階調で出す）。**次の送信で自動的に読み込み直すので、この知らせは送信を止めない**（「新しい内容で会話を続ける」は送信を待たずに今すぐ反映する操作。読み込み直したことは会話にも一行出る）。ほかに、antigravity で扱わなかった理由、種類ごとの面（「Pleiad が渡した／案内 n 件／つなぐ n 件」は青い字、「エージェント任せ」は弱い字）。MCP は文字色の小さな丸（接続中は塗り、まだ・外したは中抜き）と一言（接続中 · ツール 4 · 呼び出し 3 回／ログインが必要です／✕ つながりませんでした · 理由）、「ブラウザでログイン」「この会話では外す」「戻す」。末尾に「次の会話から変えたいとき この場所の設定を開く →」。色だけに意味を持たせない（丸の塗り分けには必ず文字が付く）。

- **差し色の意味を「あなたを待っている」1 つに固定した。** 失敗は面と太字で足りると判断した
- **本文の文字色を濃い紺にした。** 長文の可読性は実機で確認する
- **ダークの面は青みを落とした無彩色。** `tinted-surface` の閾値 0.015 を暗い面にも同じに適用したため
- **走っている弧の周期（2s / 2.4s / 1.7s）** は目で確かめて決めた。複数の行に並んだときの騒がしさは実機で確認する
- **状態の combo は履歴の行には出さない。** 全行で右クリックの「状態を変更」を使う
- **分岐点の札は曲線の右に絶対配置。** 枝が 5 本以上同じ節から分かれると縦に 130px を超える。実機で確認
- **提示 HTML（iframe）は `--surface-1` の面の中に置く。** 白い iframe を白い地に直に置くと溶けるので、面の階調で区切る（線は引かない）
- **lint は試作。** `@supports`・`@layer`・`:is()` の入れ子は素通し
- 提示カード・右クリックメニューは同じ規則で起こしてある


## 10. 対話中の操作改善（2026-09-11）

アプリ設定は左メニューとページの 2 列。左メニューにエージェント設定・外観・コンテキスト・「アプリ情報・更新」を置く。当初はネイティブ `dialog` のモーダル（最大幅900px）だったが、2026-09-15 に画面全体へ移した（§9「設定の画面」）。
「アプリ情報・更新」にはバージョン、更新状況と操作、確認・ダウンロードの設定、受け取る更新、リリースノートを置く。
更新があるときだけ設定アイコンに小さな点を付ける。更新後の案内は脇の短い通知とし、モーダルやオンボーディングを自動で開かない。
Esc と「会話に戻る」で会話へ戻り、元の設定ボタンへフォーカスを戻す。設定ボタンは歯車アイコン。
接続先・プロトコル・遅延と使い方ガイドは表示しない。オンボーディングは独立した最大幅640pxの画面に分け、
初回またはエージェントが全て未設定の場合に表示する。初回表示の記録はサーバーに保存する。
詳細と業務パターンの検討表は `docs/desktop-onboarding.md`。

承認済み `docs/mockups/ux-proposal.html` のうち任意位置分岐以外を実装。Codex の分岐拡張は issue #3。

- ユーザー向けの呼称は「エージェント」。APIの `backend` キーは維持する。
- エージェント・モデル・作業ディレクトリはセッション単位の `nextSettings` としてサーバーに保存。入力欄の上に「次のターンから適用」・変更内容・「取り消す」を残す。実行設定の常時表示は置かない。完了だけでは適用せず、次の送信準備で検証して適用する。作業ディレクトリは実行中も編集でき、保存時と送信時に存在を確認する。履歴の移動・再読み込みでも予約を復元する。
- モデルと承認モードは変更先の候補を使う。エージェント変更時は変更先の既定モデル・保存済み既定承認モードを選ぶ。変更先の承認モードは `nextSettings.mode` に予約し、次のターンに適用する。エージェント変更予約がない場合は既存の承認モードのライブ変更を維持する。取り消しや元のエージェントへの変更では、変更先の承認モード予約を破棄する。
- 下書きの本文と添付ファイル参照はサーバーに保存し、ブラウザーにも復元用コピーを持つ。保存中／保存済み／保存失敗を入力欄に表示。新規も通常の行と同じ右クリックが使え、未送信のセッションだけ削除操作を出す。
- コンテキストメニューは約150msのホバーで右へ展開。離脱後約250msの猶予を置き、画面の端では左へ返す。クリック／タップ、↑↓・→・←・Home/End・Escにも対応。
- メニュー内の入力欄にフォーカスがある間は、ポインター離脱・別項目のホバーで入力欄を閉じたり置き換えたりしない。外側クリック・通常のEnter/Escでは確定・終了できる。日本語などのIME変換中は、メニュー・候補入力・検索・タイトル編集でEnter/Esc/矢印を独自操作に使わない。
- エージェントフィルターは複数選択OR、場所・状態とはAND。検索欄下の条件から個別解除。適用後に対象外になった会話も開いたまま保ち、「フィルター対象外」と解除操作を表示する。
- 稼働ノードは軸 x=20 の末端に直径36pxの円を置き、内部に既存の弧を18pxで表示する。面は会話と同じ `--surface-paper`、輪郭は `--line-strong`。これは会話の末端だけの拡張で、一覧の小さい弧は台なしを維持する。円は行の上端から2px内側に収め、輪郭も切れないようにする。筋は実測した円の外周で止める。動きを減らす設定は既存の静止弧に従う。
- 空のセッションに「まだ発言が無い」などの補足文は表示しない。

### 会話内の可視化（2026-09-14）

新しい可視化は既存の提示カードに「可視化」とタイトルを表示する。高さは内容から120〜900pxへ追従する。見出し行の右には、パスをコピー・HTMLをダウンロード・サイドパネルに表示の3つを**アイコンだけ**で置く（名前は title と aria-label。見出し行に3語を並べる幅が無い）。旧HTMLの静的な表示と高さ選択は保持する。詳細は [可視化仕様](visualize.md)。

拡大はダイアログを作らず、ファイルと同じ右のプレビューパネルで開く（2026-09-16）。読む面は会話の横の一枚に集約し、広げる・幅変更・狭い画面の全面表示・Esc をファイルと共有する。**「プレビュー／原文」の切り替えもファイルと同じ**（2026-09-16）。可視化の原文は会話に残っている HTML で、行番号付きの同じ面（`sourceView`）で見せる。取り直す先が無いので、再読み込みと「会話で使う」だけは出ない。パネルの枠の操作（広げる／会話と並べて表示、閉じる／会話へ戻る）と、パス欄のコピーもアイコン。文字のままにするのは、状態を選ぶ「プレビュー／原文」と、下端の「保存」「会話で使う」。**枠と密な道具はアイコン、名前の要る操作は文字**で分ける。
