IMPLEMENTATION NOTES / 提案の境界

モデル選択に混ざった接続設定を、独立させる。

既存設定から自然に移行

現在の providers を「接続先」、defaultModel を「モデル」として表示。既存の provider ID と OAuth プロファイルは維持します。ワークスペースの上書きがあれば設定元と実際の適用値を表示し、暗黙にユーザー設定で上書きしません。

初期対応は ChatGPT ログイン、OpenAI、Anthropic、両形式の互換 API。既存の高度な接続設定は保持し、未対応の編集操作は案内付きにします。

実装前に詰めること

現状の procway-code は API キーを環境変数名で参照します。キー入力を提供するにはホスト側の安全な資格情報保存と子プロセスへの注入が必要です。ブラウザー保存や設定 JSON へのキー直書きは避けます。

接続確認はモデル列挙など生成しない API を優先。推論が必要なら送信内容と課金可能性を事前表示します。共有 serve の切り替えが実行中の別会話に干渉しないよう、接続単位の分離または待機制御が必要です。

この HTML は UX 提案です。接続確認の成功・失敗、ログイン、保存、送信はすべてブラウザー内の再現です。再読み込みで初期状態に戻ります。
