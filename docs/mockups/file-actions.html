提案 · 2026-09-23

ファイルの操作とプレビュー周りの見直し

AI が送った画像のパスが分からず、保存もできない件と、ブラウザーで開く・フォルダーを開く・右パネルのツリーのメニュー・メッセージ内のパスの自動リンクの 4 点を一緒に扱います。調査の結果、提案の方針、操作できるモック、決めていただきたいことの順です。

1 · 調査の結果

できないことと、その理由

要望今の動き足りない理由
画像のパスが分からない・保存できない 画像は 3 つの経路で届く（本文の ![](C:\…png)、Codex の生成画像、利用者の添付）。押すと拡大表示が開くが、表示されるのは画像と説明文だけ。 画像の要素がパスを持っていない（URL の中に埋まっているだけ）。拡大表示にも右パネルにもつながっていない。保存用の口（/local-file?download=1）は既にあるので、画面側の変更だけで直せる。
HTML をブラウザーで開く 右パネルでは、隔離した枠の中で表示できる（スクリプトも動く）。相対リンク・外部の読み込み・画面遷移は動かない。 OS を操作する口がサーバーにもデスクトップ版にも無い。Pleiad のアドレスで HTML をそのまま配信すると、中のスクリプトが他のファイルを読み出せてしまうので、その方法も使えない。
格納フォルダーを開く 無い。右パネルで分かるのは「パス」を押したときのフルパスとコピーだけ。 同上（OS を操作する口が無い）。
右パネルのツリーの ⋯ と右クリック ツリーの行は押すと開き、ダブルクリックで畳む。それ以外の操作は無い。 ツリーの部品（web/tree.mjs）にメニューを付ける仕組みが無い。右クリックメニューの部品（web/context-menu.mjs）は左の会話一覧でしか使っていない。
メッセージ内のパスを押せるようにする 押せるのは Markdown のリンク [名前](パス) だけ。`web/render.mjs` や地の文の D:\…\a.html、ツールカードの対象ファイルは文字のまま。 今のパスの読み取りは「スキームが無ければ全部パス」とみなす緩いもの。書き手が明示したリンクの中なら困らないが、地の文に使うと Node.js や and/or までリンクになる。自動リンク用に厳しい判定を別に作る必要がある。

もう一つの前提として、Pleiad は別の端末から開く使い方（遠隔）を検討中です。「フォルダーを開く」「ブラウザーで開く」はサーバーのある PCで動くため、遠隔の端末から押すと、見ていない PC の画面でエクスプローラーが開くだけになります。

2 · 方針

ファイルが見える所には、どこでも同じ操作を置く

① 1 つのメニューにまとめる

ファイルに対する操作は同じメニューにまとめます。⋯ ボタン・右クリック・Shift+F10 のどれでも開き、中身は場所によらず同じです。場所ごとに違う操作を覚える必要がありません。

  • 右パネルで開く
  • ブラウザーで開く（HTML のみ）
  • エクスプローラーで表示
  • パスをコピー／相対パスをコピー
  • 保存／会話で使う

② パスは必ず見えるようにする

画像の下に所在の一行（ファイル名のリンク + フォルダー）を常に出します。ファイル名を押すと右パネルで開き、フルパス・保存・ツリーが揃った状態になります。拡大表示の下端にもフルパスと操作を並べます。

③ OS の操作は同じ PC の画面でだけ

「エクスプローラーで表示」「ブラウザーで開く」は、デスクトップ版または同じ PC のブラウザーからのときだけ表示します。遠隔からの要求はサーバー側でも断ります。遠隔ではコピーと保存がその代わりになります。

④ 自動リンクは誤りを出さない範囲から

最初はパスと断定できるものに限ります。インラインコードの中のパス、地の文の Windows の絶対パス、ツールカードの対象ファイル、添付の元パスです。見た目は今のファイルリンク（▧）と同じにします。

4 · 自動リンクの判定

リンクにするもの・しないもの

判定は web/file-reference.mjs に厳しい関数（例 looksLikePath）を新しく置いて行います。今の fileReference はサーバーも使っているので挙動を変えません。存在確認は押したときに右パネルで行い（無ければ「見つかりません」と表示）、描画時にはサーバーへ問い合わせません（生成中は受信のたびに描き直すため）。

場所リンクにするリンクにしない
ツールカード（読む・書く・編集）の対象、添付の元パス全部（必ずファイルのパスなので）—
インラインコード `…`中身全体が 1 つのパスで、次のどれか: C:\ D:/ 始まり ／ ./ ../ 始まり ／ 区切りを含み、最後が既知の拡張子（web/render.mjs、docs/a.md:42）npm test、feat/remote、application/json、/api/foo、~/x（サーバーが解決しない）、拡張子なしの 1 語
地の文Windows の絶対パスだけ。ASCII のパスの文字で止め、末尾の 。、)., は外す（D:\a\b.pngを開いて → D:\a\b.png）Node.js、and/or、2026/09/23、12:30、URL、空白を含むパス（`…` か Markdown のリンクで書いてもらう）
コードブロック・既存のリンクの中—全部（書き手の意図を変えない）

行番号（a.mjs:42・#L42）は今のリンクと同じく、右パネルでその行へ移動します。相対パスは発言した時点の作業ディレクトリで解決します（今の仕組みのまま使えます）。

5 · 安全と作り

OS を操作する口の作り

  • 判定はサーバー、実行は OS 側。WebSocket に revealPath と openPath を足します。パスは右パネルと同じ許可範囲（作業ディレクトリ・添付・Codex の生成画像）の中にあるか、実体を解決した後の値で確かめます（既存の inspectFile）。
  • 遠隔からの要求はサーバーが断ります。接続元がループバックかどうかを接続ごとに記録し、「OS 操作ができるか」を画面へ伝えます。遠隔対応（feat/remote）と衝突しないよう、この判定は 1 か所にまとめます。
  • デスクトップ版は Electron の shell.showItemInFolder と shell.openExternal(file://…) を使います。サーバーから本体へ依頼する経路は既存の外部 URL を開く経路と同じ形です。
  • ブラウザー版（npm start）の Windows では explorer.exe /select,"…" を、シェルを通さずに引数をそのまま渡して起動します（windowsVerbatimArguments）。cmd /c start は & を含むパスでコマンドが注入されるため使いません。explorer.exe は成功しても終了コード 1 を返すことがあるので、終了コードでは失敗と判定しません。
  • 「開く」は HTML に限ります。既定のアプリで開く操作を広げると、.bat や .lnk がそのまま実行されてしまうためです。それ以外の種類は「エクスプローラーで表示」だけにします。
  • HTML を Pleiad のアドレスでそのまま配信することはしません（中のスクリプトが Cookie を使って他のファイルを読めてしまうため）。

段階

段 1 · 画面だけ（サーバーの変更なし）

  • 画像の所在の一行、拡大表示の下端（コピー・保存・右パネル）
  • ファイル操作のメニュー（コピー・保存・会話で使う・右パネル）を右パネルの頭・ツリー・画像・リンクに
  • パスの自動リンク

段 2 · OS の操作

  • revealPath / openPath、接続元の判定、デスクトップ版の経路
  • メニュー・下の行・拡大表示に「エクスプローラーで表示」、HTML に「ブラウザーで開く」

主に触るファイル: web/render.mjs・web/file-reference.mjs・web/file-preview.mjs・web/tree.mjs・web/client.mjs（拡大表示とメニューの共有）・core/server.mjs・新規 core/os-open.mjs・desktop/main.cjs。テストは自動リンクの正例と誤りの例、XSS、許可範囲の外・シンボリックリンクでの脱出・遠隔からの要求の拒否。

6 · 決めていただきたいこと

3 点

1. 画像を押したとき

  1. 今と同じく大きく見る。下端に所在と操作を足す推奨 — さっと見る体験は変えず、パスは所在の一行でも分かる。
  2. 右パネルで開く（大きく見るのはやめる） — 操作は右パネルに揃うが、見るだけの用途で会話の幅が狭くなる。

2. 地の文の自動リンクの範囲

  1. Windows の絶対パスだけ推奨 — 誤りがほぼ出ない。相対パスはインラインコードで書かれることが多い。
  2. 地の文の web/render.mjs のような相対パスも — 拾える数は増えるが、feat/remote のような誤りを完全には避けられない。

3. 遠隔から見ているときの「ブラウザーで開く」

  1. 出さない推奨（段 2 の時点） — 右パネルの表示と保存で代える。
  2. 見ている端末の新しいタブに、隔離した枠で開く — 遠隔対応が形になった後に検討。
