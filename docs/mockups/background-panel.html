バックグラウンドの統合 — 調査と提案

サブエージェント・Pleiad タスク（他エージェントへの委譲）・裏で動くコマンドを、会話末尾の「バックグラウンド」1 つの入口と 1 つのモーダルにまとめる案。

1. いまの入口（調査）

入口置き場・出る条件開くもの詳細の見え方
「サブエージェント N」「裏で動いている N」「タスク N」会話末尾の稼働表示の文字ボタン。ターンが走っている間だけ（activity.work() client.mjs:738）作業ダイアログ。3 つのうちどれか 1 つの一覧を優先順で開く（client.mjs:747）サブエージェントはダイアログ内で会話を読める（簡易表示・開いた時点の 1 回読み）
「Pleiad タスク · N」ヘッダー。この会話の委譲が 1 件でもあれば（完了済みも）同じダイアログの「Pleiad タスク」表示行を押すと子の会話へ画面ごと移る（依頼元から離れる）
「端末 · N」「バックグラウンド · N」ヘッダー。裏の作業（Codex の端末・Claude の Bash の run_in_background）が残っていれば作業ダイアログの一覧コマンド・作業場所・出力（表示中は取り直す）
  • 同じ #workDialog を 3 つの入口がそれぞれ違う中身で開く。末尾の「タスク N」から開くとサブエージェントが見えず、「サブエージェント N」から開くと委譲したタスクが見えない。
  • モデル名がどこにも出ない。サブエージェントの行はメッセージ数と最終時刻だけ、タスクはエージェント名と状態だけ。
  • ダイアログの会話表示は .m を並べただけ（client.mjs:2210）。筋・節・時刻・考えている箱・画像や可視化・稼働表示がなく、動いている子を開いても続きが流れてこない。

  • 入口は末尾の「バックグラウンド N」だけ。ヘッダーの「Pleiad タスク」「端末 / バックグラウンド」は外す（取り消し線）。
  • N は動いている本数の合計（サブエージェント + 委譲 + コマンド）。種類ごとに別のボタンへ分けない。
  • main の返答が終わっても、裏で動いているものがあれば末尾の行を残す。見出しは「裏で 2 本が動いている」、印は衛星（§6.1）。端末だけなら印は出さない（§6.1 の 2026-09-17 の決めのまま）。
  • ヘッダーから入口が消えるので、ターン後に残る Codex の端末・委譲の止め口はこの行が引き継ぐ。
  • 全部終われば末尾の行は消える。終わった分は、会話の中のツールカード（委任・委譲・実行）から開く。押すと同じモーダルでその項目が選ばれた状態になる。
  • カードには状態の印（完了 ✓ / 失敗 ✕ / 停止 −）とモデル名が付くので、開かなくても結果とどのモデルだったかは読める。

3. モーダル（一覧 + 詳細）

幅 左の行を押すと右が切り替わる
バックグラウンド動いている 3 · 終了 2
会話として開く
依頼文をコピー
依頼元の発言へ移動
  • 一覧は 2 つに分ける: 「サブエージェント」（ネイティブのサブエージェントと Pleiad タスクを区別しない）と「コマンド」（Bash の裏実行・Codex の端末）。動いているものを上、終わったものを下。
  • サブエージェントの行: 状態の印 · 依頼の一行 · 経過時間 / 2 行目にエージェントのロゴ + モデル名（+ エフォート）と状態。承認待ちだけ差し色（「あなたを待っている」、§1）。
  • コマンドの行: 印 · 等幅のコマンド · 経過時間 / 2 行目に種類と作業場所。止めるのは詳細側の「停止」だけ（行を押しても止まらない、§6.1 の決めのまま）。
  • 詳細はメインパネルと同じ部品で描く: 筋と節・発言者と時刻・Markdown・考えている箱・ツールカード（失敗の持ち上げ）・画像 / 可視化・末尾の稼働表示（弧と経過時間）。動いている子は表示中に続きが流れてくる。
  • 委譲した子が承認を待っていれば、その承認カードをモーダルの中で押せる（子の会話へ移らずに済む）。子の会話を丸ごと開きたいときは ⋯ の「会話として開く」。
  • 入力欄は置かない（読む・止める・承認するだけ）。

5. 実装の見通し

  • server: work.subagents に model を足す。Pleiad タスクは既存の記録で足りる。
  • 入口: activity.work() の 3 択をやめ、3 種の合計で 1 つのボタンにする。#agentTasksEntry・#backgroundEntry と関連の辞書を外す。ターン後に裏が残る間は末尾の行を残す（今の activity.hide() の条件を変える）。
  • 詳細の描画: いちばん大きい作業。メインの append・userMsg・考えている箱・renderPresent・稼働表示は描く先が thread 固定なので、描く先を引数で渡せる形に切り出す。Pleiad タスクは子が普通の会話なので、その会話の読み込み（履歴の再生）をモーダルの筋へ流せば同じ見た目になる。ネイティブのサブエージェントは loadSubagent の結果を同じ部品で描く。
  • 表示中の更新: Pleiad タスクは子の会話のイベントをモーダルにも配る。ネイティブのサブエージェントは今の running の配信（4 秒ごとの一覧）に合わせて読み直す。
  • docs: design-system.md の「Pleiad タスク」節と §6.1 の入口の記述、design.md の作業ダイアログを書き換える。

6. 決めたいこと

  • 全部終わった後の入口: 案はツールカードから開く（上の「すべて終わった」）。ほかに「次の発言まで末尾に『バックグラウンド · 終了 N』を残す」もできる。
  • 委譲した子への追加の指示: 案はモーダルでは読むだけ。送りたいときは「会話として開く」。
  • 一覧の並び: 案は「サブエージェント / コマンド」の 2 区分。区分なしで起動順に混ぜる手もある。
