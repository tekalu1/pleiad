初回起動ダイアログの UX 改善

初回起動時の不要な設定・過剰な要求を削ぎ落とし、デザインシステム（枠線なし・薄い色地なし・絵文字なし）に完全に準拠したシンプルな初期画面へ再設計します。

01 / ANALYSIS

なぜ初回ダイアログで「不要な設定」と感じるのか？

現在の実装（web/index.html および web/onboarding.mjs）を詳細に調査した結果、初回起動でユーザーに負担を与えている原因が明確になりました。

不要な設定 1

作業フォルダー（cwd）の指定自体が不要

初回モーダルで「フォルダーの絶対パス」を入力させていますが、そもそも初回ダイアログで作業フォルダーを設定させる必要がありません。

サーバー起動時のカレントディレクトリ（作業場所）でそのまま会話を開始すれば十分であり、変更したい場合もチャット画面の入力欄下に常設されている「作業ディレクトリ」からいつでも変更できます。初回モーダルでの設定は完全に削除すべきです。

構造の矛盾 2

見出しと中身のチグハグ

「2. 作業場所を選ぶ」という見出しの直下に、なぜか「エージェント選択ボタングループ」が配置されています。

ステップ1でエージェントを並べた後、ステップ2のフォルダー欄の上で再度エージェント（Claude / Codex / Antigravity ...）を選ばせる2段構えになっており、利用者に混乱を与えています。

情報過多 3

管理画面（agentControls）の丸見え

設定メニュー内の「エージェント管理UI」がそのまま初回モーダルに流し込まれています。

使わないエージェントの「未インストール」「ログイン」ボタンや、「接続先を設定」「インストール・ログイン状態を再確認」ボタンまで並んでおり、初回起動時に見せるべき情報量を超えています。

形式的ステップ 4

空虚な「3. 最初の依頼を伝える」

ステップ3と銘打っているのに入力欄すらなく、単なる説明文があるだけです。

実質的にはモーダルの「会話を始める」ボタンがあるだけであり、ステップ数を無駄に「3ステップ」に見せて心理的ハードルを上げています。

02 / INTERACTIVE MOCKUPS

As-Is（現状） vs To-Be（改善案）

操作できるモックです。改善案（To-Be）では作業フォルダー設定を完全に撤廃し、エージェントを選ぶだけの極限までシンプルな構成にしています。

Pleiad へようこそ

エージェントと作業場所を選んで、最初の会話を始めましょう。

1. エージェントを接続する

利用するエージェントを1つ準備します。各サービスのアカウントや利用契約が必要です。

エージェント

Codex 未ログイン
procway 未ログイン
Antigravity 未ログイン
問題点: 設定画面の管理パネルがそのまま表示され、使わないエージェントのログアウトや再確認ボタンまで並んでいて煩雑。
2. 作業場所を選ぶ

資料や成果物を置くフォルダーを指定してください。

問題点: 「2. 作業場所を選ぶ」という見出しの下なのに、なぜかエージェント選択ボタンが置かれている。
問題点: そもそもチャット画面で変更できるため、初回モーダルで手入力させる必要性が全くない。
3. 最初の依頼を伝える

会話に目的・使う資料・完成条件を書いて送信します。操作の承認や追加の質問には、会話内で回答できます。

問題点: 入力欄はなく単なる説明文。ステップとして分ける意味がない。

04 / ARCHITECTURE

実装変更箇所

既存のバックエンド API やセッション管理の互換性を維持したまま、安全に変更できます。

1. web/index.html

#onboardingDialog 内の不要な h3 見出し階層、#setupAgents、フォルダー入力欄（#setupCwdCombo, #setupCwd, #chooseFolder）を完全に削除し、シンプルなエージェント選択リスト #setupAgentList に一本化します。

2. web/onboarding.mjs

フォルダー入力（cwdCombo）の管理とバリデーションを撤去。起動時の cwd をそのまま completeSetup に渡すか省略可能とし、ログイン済みエージェントを自動選定して即座に完了できるようにします。

3. core/server.mjs

completeSetup コマンドにおいて、msg.args?.cwd が指定されなかった場合は process.cwd()（サーバーの作業ディレクトリ）をそのままフォールバック採用します。
