# 会話の途中でバックエンドを切り替える

入力欄の「バックエンド」は既存の会話でも選べる。ターンが終わってから切り替え、次の送信から新しいバックエンドで続ける。実行中・承認待ちの切り替えは受け付けない。中断する場合は停止完了を待つ。

## 保存と実行

`core/conversations.mjs` がバックエンドを包み、初回の切り替え時に会話をアプリ管理へ移す。既存の会話IDは維持し、各実行区間の `{ backend, nativeId }` を別に保存する。切り替え先では常に新しいネイティブセッションを作る。元のバックエンドへ戻る場合にも、間に進んだ会話を含めて新しく始める。同じバックエンドで続ける通常のターンはネイティブの再開を使う。

正本は `AGENT_HOST_DATA`（既定 `~/.agent-host`）。`conversations.json` は索引（バックエンド、ネイティブID、分岐点、info）だけを持ち、発言とツールの記録は `conversations/<会話ID>.json` へ会話ごとに分ける。切り替え時、ネイティブID確定時、ターン終了時に、索引と変更のあった会話のファイルだけを一時ファイルから置換して保存する。読み出しは開いた会話の本文だけを遅延読み込みし、一覧・タイトル・状態は索引だけで答える。理由: 全会話を1ファイルに持つと1回の保存で全履歴を書き直すことになり、履歴が増えるほどターンごとに固まる（実測 104MB / 保存1回あたり約0.9秒）。画像生成の巨大な結果本文は保存時に保存先パスの参照へ置き換える。messages を含む旧形式の `conversations.json` は初回読み込み時に自動で分割へ移す。切り替えていない既存セッションは従来のネイティブ履歴を使う。

一覧では実行区間を隠し、会話を一行にまとめる。イベントと承認要求は会話IDへ戻す。メッセージには生成元のバックエンドを記録する。タイトル・状態・cwdを保ち、モデルと承認モードは切り替え先の既定（承認モードは最初の選択肢）へ戻す。過去の権限承認は移さない。

## 引き継ぐ内容

ユーザーとアシスタントの発言、ツールの入力と取得できる結果全文、提示・添付の記録を渡す。表示用のツール結果は引き続き2,000文字に制限するが、引き継ぎ用取得ではこの制限を外す。思考ブロックは引き継ぎプロンプトへ入れない。

全文を `handoff-<会話IDのハッシュ>.json` に保存し、短い会話はプロンプトにも全文を載せる。60,000文字を超える場合はユーザー指示の冒頭と直近の発言のプレビュー、全文ファイルのパスを渡し、続行前に全文を読むよう指示する。自動要約による意味の保証はしない。切り替え先がファイルを読める実行環境を前提とする。

引き継ぎ用の説明は履歴上のユーザー発言には表示しない。ツールの過去の実行は記録として渡し、再実行する命令にはしない。同じcwdの実ファイルを共有し、変更前に現状を確認させる。

## 境界

- 実行中のプロセス、承認、非公開の推論状態、バックエンド固有の内部状態は移さない。
- ネイティブCLIで見えるのはその実行区間。統合された会話はagent-hostで読む。
- 管理済み会話の分岐は保存した履歴を切って新しい会話を作る。分岐UIの提供可否は引き続きバックエンドのcapabilitiesに従う。
- サブエージェントの操作は現在の実行区間に向ける。
- 強制終了時の外部副作用と履歴保存を一つのトランザクションにはできない。保存したネイティブIDとネイティブ履歴から回復するが、履歴を取得できない場合は実ファイルの確認が必要。

画面では、エージェントを変える予約をしたとき「次のターンから適用」の欄に、引き継ぐもの・引き継がないもの（過去の承認・考えた内容・元のエージェントだけが持つ状態）・変わるもの（モデルと承認モード）を 1 行と「詳しく」で示す（design-system.md「入力欄の設定」）。
